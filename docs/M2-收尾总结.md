## 3. 验收期间闭环的问题

| 问题 | 已完成处理 |
| --- | --- |
| NapCat 登录后未知用户、OneBot 不初始化 | 按实际契约生成 timeout 对象，启动前校验并提供既有配置修复 |
| 消息服务管理页被旧心跳挡住 | 页面访问独立核对宿主与监听进程，不以 QQ/插件在线替代管理页可用性 |
| 独立 AstrBot 环境需要重装 | 按锁定依赖重建，保留数据、静态资源和工作台集成 |
| 小弹窗或高缩放下保存按钮被挤掉 | 内容区与固定操作栏分离；覆盖主窗口之外的编辑与选择弹窗 |
| 编辑窗口关闭后文字丢失 | 保存成功后才关闭，失败或资源忙保留正文；增加取消、快捷保存和退出提示 |
| 用户需要紧急结束全部相关程序 | 增加独立强停通道，正常停止仍核对归属，强停不自动执行 |

这些修复已进入代码和交接记录。后续回归需保留相应测试，尤其不能只测主窗口而遗漏编辑弹窗。

## 4. 收尾后保留的边界

- 只支持本地单用户及配置的本人好友私聊；群聊和其他联系人尚未开放。
- 记忆仍由用户显式写入，召回采用本地规则；没有自动提取或向量语义检索。
- 没有联网知识更新、后台自主学习或人格自我演化。
- 暂不提供通用的人格合并、历史擦除或自动恢复数据库操作。
- 紧急强停会影响普通 QQ 及相关 TRPG 服务；它是明确授权的紧急例外，不能替代正常启停或迁移流程。

上述属于当前范围，不作为未解决的 M2 缺陷。若发现验收回归，应单独记录并修复，不以清空数据规避。
