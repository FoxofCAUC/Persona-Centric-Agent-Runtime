# 召回配套.0：范围、复用与实施合同

2026-11-15。依据[认知与召回指导](PCAR-认知与召回优先级开发指导.md)，作者明确要求提交推送MaiBot研究方案，随后完成召回配套.0—.2，收尾并准备.3连续体验与接入。本合同冻结本次实际实现范围；.3结束后才进入[独立表达改造](PCAR-MaiBot表达改造施工方案.md)。

## 1. 边界与交付

.0冻结领域与参数、来源和上游清单；.1交付纯计算、持久事件、时间与恢复；.2交付真正分层的候选生成、冷资料找回、相关性排序、采用反馈与解释。全部在独立人工实例验证，当前日常人物和正式库不作为测试材料。

.2提供可运行的`RecallSupport`及`recall_context`适配器；.3负责持续真实体验、生产上下文装配／来源重检接入、默认启用及用户读感验收。本次不能把仅加一个排序分数算作分层完成，也不提前宣布已改善正式角色聊天。

候选代码版本0.2.0rc3，结构28。结构27旧召回表只读保持，本次使用`recall_support_*`版本化派生层；不恢复旧高级召回、来源权威判定或大型百科依赖。源资料仍是现有SQLite领域记录，不新建第二套事实或人格数据库。

## 2. 单元、来源与范围

| 输入适配器 | 单元及有效性 | 时间和来源含义 |
| --- | --- | --- |
| 正式记忆memory | 现行memory版本、source引用及既有可用性规则；更正／撤回／隔离／有效期优先 | 来源事件时间与首次登记时间分开；热度不改变事实可信度 |
| 对话经历dialogue | 具体用户或人物事件，沿用原回合、平台及撤回边界；QQ语义主稿不当作已发内容 | 用户陈述与助手发言分型；自己的自述不单独证明用户事实 |
| 原生知识native | 现行可读来源，包括已由既有流程接纳的可读导入；状态复用原生更正／撤回 | 公共来源内容／版本与私人角色热度分开；未知原始时间保持空值 |

现有可用的导入材料通过上述正式记忆、对话或可读知识适配器进入；被标记待复核的导入不绕过原政策。本次不增加新的文件／多模态导入格式，不重新启用已退役知识生产链。

每个单元绑定人格、用户、渠道、bot／peer完整范围；是否跨会话由查询的session限制决定，不能因公共正文可复用就共享角色使用热度。知识来源多处出现时只增加合法定位关联，不重置优先级；一个定位失效时可用同范围另一合法定位。

长来源按4096字符稳定片段登记，单元包含偏移，具体片段的消费不强化整份文档。记忆修订沿用其root关联，来源内容／版本变化登记新单元，首版不继承旧版热度。选材对同一lineage去重；跨域的不同概括仍分别保留其证据身份，不把概括当成新的独立事实。

单位ID、引用、有效性与原始材料是业务真相；索引中的文本仅用于候选，选中与消费时重新读权威来源。永久删除源记录同步删除派生片段／词项／事件；软撤回仍保留历史审计，但不能经冷层重新出现。

## 3. 冻结政策v1

| 项目 | 本次值或含义 |
| --- | --- |
| 初始优先级 | 0.65，以首次合法登记时刻为衰减锚点；不补造历史回忆 |
| memory／dialogue／native半衰期 | 90／30／14天，不同来源类型分开管理 |
| 活跃阈值 | 大于0.20为活跃，达到阈值转休眠；休眠不删除原文 |
| 有效回忆贡献 | 成功上下文采用0.12、用户有证据提及0.18、输出有来源片段支持0.24 |
| 同根交互 | 同一单元只采用最强已证明贡献；更强证据升级时重算差额，不连乘 |
| 独立交互 | 每次真实、独立、有效回忆正向强化，无上游访问冷却屏蔽 |
| 历史初始化 | 旧使用记录未知，不凭材料年龄一次性让全库休眠；重复登记不刷新锚点 |
| 时钟 | UTC；回拨不倒退；超过30天的突跳记录异常并等待明确确认后计算优先级衰减，停机自然时间在确认后计入 |
| 来源有效期 | 独立于注意力时钟检查；冻结优先级衰减不能延长已到期来源的可用性 |
| 顺序恢复 | 乱序／迟到事件按有效时间及稳定根ID重新折算，最多5000条单元事件；超预算原子失败，不能半写 |

计算采用惰性时间衰减和饱和强化。检索、预览、同步、重复扫描、摘要维护都不算回忆；失败、取消、未知的模型消费不强化。真实用户提及有其独立证据，可不依赖主回复成功，但不能只凭词语碰巧相同自动当作确认的用户回忆。

首版显式提及需要绑定已受理用户事件及能在用户原话和合法单元中同时定位的引用片段；上下文采用必须绑定同根已完成attempt、context_uses和本次选材记录。输出支持需要同时能定位源片段与实际回复中的引文。它们是可观察证据代理，不宣称证明模型内部因果或理解质量。

## 4. 检索合同

普通查询首先在当前范围的活跃集合中通过词项索引生成候选，不读取并逐条评分全库原文后再裁切。默认返回8个单元、候选预算64，允许返回上限32、预算上限256；当前实现每次SQL检索采用250ms进度预算，预算中断与无结果分开。

显式历史查询、指定deep，或活跃证据不足时查询休眠集合；活跃阶段预留候选预算，防止活跃常见词挤掉必需冷资料。排序先看本轮相关性，再在相关材料中比较优先级。默认候选数实际收缩的证据与“找回旧事”证据分别保留。

必需源可通过required_ids绕过注意力降权，但仍检查范围、版本、撤回及有效期。人物核心、明确约定、精确引用及当前任务等现有必需装配继续由原合同保证，不把这些状态交给普通优先级决定。

返回包含查询／范围／政策身份、检索层、深搜原因、已检查候选数、排除原因、选择及版本。冷层结果区分未搜索、找到、无结果、权限拒绝、撤回、过期及版本变化；预算耗尽明确失败。持久解释保存身份和哈希，不复制资料正文。

同步采用权威表的keyset分页，可在一条长来源的片段间恢复，每批最多256个来源片段，并限制扫描行数。同步完成后可从游标继续新增行；历史行原位更正由显式restart重扫更新，未重扫期间旧版本会在实时校验中被拒绝，不继续使用。周期更新调度属于.3接入准备。

## 5. 复用及接入接口

直接复用A-Dawn/A_memorix在MaiBot固定版本`478f671e64467121fd3e39205c8d3507b5ce0bd6`内的生命周期纯实现，保留其AGPLv3文件及来源说明。PCAR单独适配政策、来源领域、一次有效消费、范围和恢复；访问采用无冷却的正向强化，不照搬默认每小时冷却或关系图传播。详见[复用台账](research/召回配套-上游复用台账.md)。

主要接口：`register`从权威引用登记，`synchronize`分页同步，`select`分层检索，`inspect`查看有效状态，`record`结算根交互，`confirm_time`确认异常时钟。`recall_context.prepare`输出本轮资料块和采用元数据；`record_completed`只接受同根成功调用及选材身份，重复调用不重复结算。

表达改造沿同一根交互使用本次单元／选材身份，未来多个模型或多个气泡不能制造多次强化；完整主稿与实际发言的衔接由.3及表达E0保持来源合同。本次不改变已验收的联网判断和人物提示。

## 6. 退出与.3准备

.0完成条件为本合同、固定来源／许可、领域映射和有限政策可核对。.1完成条件为纯计算和数据库事件恢复、幂等及时间异常有证据。.2完成条件为索引先分层、相关性优先、可找回冷资料、实时来源处置、采用反馈及解释可运行，并通过迁移／备份和定向回归。

.3准备交付：人工跨域材料、连续对话脚本、候选资料包／采用接口、固定质量观察点、失败与停止规则、升级／回退说明。真实连续体验与正式接入单列为下一阶段，不由离线结果代填通过；用户本轮的默认授权用于完成.0—.2及其必要修复，无需重复等待批准。
