# 召回配套.3 连续体验与接入准备

2026-11-15。前置.0—.2已交付范围合同、生命周期底座、分层选择、来源适配和采用反馈。当前候选0.2.0rc3／结构28；正式角色未启用新召回排序，.3真实连续体验尚未执行。

## 可直接使用的准备

在独立数据目录运行：

```powershell
& $Python -B -X utf8 -m experiments.recall_preparation --root $NewEvidenceDirectory
```

该命令要求目标为空且在源码之外，创建公开人工人物、七个记忆单元、旧资料／新话题／范围拒绝的确定性探针，以及24轮连续脚本。不会带入正式角色或密钥，不调用模型。200天生命周期间隔仅是夹具本地时钟，不修改系统时间或真实账本。

本轮已生成并验证的实例在所选数据目录`tmp/recall-0-2-20261115/continuous-preparation-v1`。`continuous-materials.json`列出跨话题、口味更正、撤回旧偏好、联网新题／复用、普通闲聊和重启观察点。它是待执行材料，不是已经通过的真实文本。

## 接入时要关闭的事项

1. 在真实上下文装配中调用`recall_context.prepare`，将本次实际资料块与选材身份一起进入同一attempt的`context_uses`及Manifest；普通候选不挤掉原精确引用、核心设定或必需约定。
2. 将新单元及来源版本加入派发／提交前来源复检。库函数已支持选中和消费时复检，正式聊天接点仍需覆盖“模型等待期间发生更正撤回”的窗口；不能只依赖事后反馈拒绝。
3. 成功主回复调用`record_completed`，失败／取消／未知不强化；独立用户提及使用受理事件和可定位片段，未来表达层与气泡沿同一根交互合并结算。
4. 将分页同步、历史更新重扫和索引修复接入既有受管运行时。继续一个权威库和既有后台，不另建调度器。维护扫描不能制造回忆或收费循环。
5. 用原v8和新召回候选做同材料对照。候选预算、遗漏、跨角色泄漏、事实来源、用户读感及费用分别观察；离线性能不代填长期质量通过。
6. 结构27→28已有实际旧代码升级、业务摘要、备份／恢复、整库人工迁移证据。结构28不能直接交给v0.1／rc2读取；正式接入前补齐保留新增业务的回退验证，不能拿旧结构27回退成绩覆盖本候选。

## 有限真实验证草案

先做两组各三轮的接入冒烟，再执行本准备的24轮连续体验；分别登记主要回复、Jev、原生资料任务、查找前发言及必要修复位置。建议主要新回复上限30，修复另留最多6个全新位置；辅助请求预算须在.3开始时按实际触发条件和价格一并固定，不能把主要轮数当物理调用总数。

原稿首次文本、选材解释、成功采用、取消／失败／未知、tokens及金额分开保留；成功及未知物理调用不重放。出现数据串角色、权限泄漏、重复有效提交／发送、受理消息丢失或确定的来源复活时停止真实派发并保存断点。可恢复故障的有界恢复先在隔离夹具覆盖。

需要实际模型或当前角色可见资料时沿用本次目标中已给出的授权，在已确定范围内推进；仅实际缺失的系统权限、必须由用户操作的授权弹窗或外部不可用条件形成硬阻断，不再为同项普通操作反复确认。

.3的正式接入和真实体验完成后，再对输入／内部处理／主稿输出封口，接续MaiBot表达改造E0。当前没有提前开启表达模型、工作台重写、QQ或G-AUTO。
