# M6.2 情境表达与结构化回复实施计划

[路线图](施工总计划/02-总施工路线图.md) · [使用与开发状态](M6.2.md) · [验收手册](acceptance/M6.2-情境表达与结构化回复验收手册.md) · [架构](architecture.md)

## 阶段目标

本阶段承接 M6.0 角色资料及 M6.1 持久输入，交付受控的情境表达和可校验的语义回复批次。主要目标是让闲聊、纠错、技术求助、支持请求和轻松语气得到相称表达；创作者填写的场景样例能在相关情境下提供参考；结构化回复可追溯、可导出，并在现有桌面与 QQ 全文投递路径中保持兼容。

当前代码基线为本地 `main@e03aee9`。实现中版本为 `0.6.2.dev1`、数据库结构 9、全量导出格式 6；桥接仍为 0.4.0。M6.2 源码和离线专项/回归已实现，真实模型体验、桌面实际按钮、正式迁移及 QQ 送达尚未验收。M4 O01–O03、M5 P09，以及 M6.1 显式续跑和实际 QQ 送达继续待补。

## 数据及行为合同

1. 回复模式按人格和入口保存为版本化交互政策：`legacy_full`、`context_full`、`context_structured`。默认 `legacy_full`；只有管理员显式切换后新受理的请求才使用新模式。请求受理时固定模式版本，之后的设置变更不影响已受理输入。
2. `legacy_full` 保持兼容全文行为；`context_full` 使用确定性本地情境线索和适配角色样例，但仍生成普通全文；`context_structured` 在一次主要模型调用中请求一个严格 JSON `ReplyBatch`，包含 1–3 段，每段至多 8000 字符、合计至多 12000 字符。段落不要求凑满，代码围栏等结构必须完整。
3. 情境解析器只做本地词法匹配，版本化且可审计；至多提供两个弱提示，不诊断用户心理、意图或真实状态，不增加模型调用，不覆盖事实、权限、创作者边界、关系和状态。
4. 角色表达样例仅用于风格参照。按启用状态和情境线索确定性选择；示例不作为必须复述的台词，不扩大输入预算，也不能覆盖更高优先级约束。
5. 结构解析严格校验字段白名单、类型、段数、长度、重复 JSON 字段和可见未闭合代码围栏。失败不自动修补、不二次调用；记录模型用量和明确失败状态，不把原始结构 JSON 作为用户回复或上下文事件。
6. 校验成功时，回复全文和语义段与完成状态原子持久化。桌面和 QQ 在 M6.2 仍按既有完整文本路径投递；分片投递账本、投递确认和不确定发送处置属于 M6.3。
7. 旧请求的空回复模式快照按 `legacy_full` 解释，不回填历史。显式重试遵循既有 M5/M6.1 语义，保留旧尝试和上下文记录，并按现有规则使用当前模型/设定；不得把旧失败回复伪造为结构成功。
8. 回复批次纳入人格全量导出格式 6，导出不得包含模型凭据。桥接令牌不得修改回复模式；仅管理员 API 可以操作版本化政策。

## 测试与验收

机器测试必须覆盖三种模式、默认兼容、受理快照、情境弱提示、表达样例选择、严格 JSON 合同、段数/长度/代码围栏、一次主调用、无效响应用量保留、批次原子写入、失败状态、权限与幂等、结构8→9迁移及回滚、导出内容与旧历史兼容。测试顺序为 M6.2 专项、M6.1/M6 受影响测试、全量 `unittest` 一次；运行时须避免在仓库生成 `__pycache__`。

真实验收使用隔离测试人格，分别检验自然闲聊、明确纠错、技术长答、支持请求和轻松语气，并与旧模式对照。确认模式默认值、无效结构无泄漏、同一输入一次主调用、代码和列表保持可读。实际工作台点击、正式数据库迁移/恢复、真实模型调用及 QQ 实际送达分别记录；真实费用沿用现有授权和限额，连续五次模型失败或明确 QQ 服务中断时停止等待恢复。真实数据和证据留在 D 盘 `exports/acceptance/`，不提交 Git。

本轮目前只完成代码与离线专项/受影响回归，不启动正式服务、不升级正式数据库、不发 QQ 消息，也不调用真实付费模型。以上真实验收仍是退出条件。

## 明确不做

不做 M6.3 片段投递账本、分片发送、流式输出、运行中取消、自动重试、自动情绪推断或人格演化；不启用 Session 生命周期、Thread、向量检索或联网搜索；不自动切换正式入口模式，不增加供应商、模型额度或桥接权限。M4 O01–O03、M5 P09 和 M6.1 未完成条件继续保留。M6.2 通过后再进入 M6.3 片段投递，不能据此标记整个 M6 完成。
