# G-AUTO 后：自主能力、主动交流与研究验收

> 规划日期：2026-11-16（北京时间）。本文件是远期研发设计，不代表功能已实现、实验已运行或外部操作已获执行授权。文中的新类型名、工作包名、数值、试验规模和通过阈值均为拟议，须在对应阶段开工时按实际版本冻结；不预占数据库结构号或新的 M 阶段编号。

本文关注四件事：角色怎样形成自己的活动目标，怎样从上网与虚拟生活中学到可复用能力，怎样决定是否主动交流，以及怎样证明这些改变有效。人格与关系变化由对应认知、Director 与受控演化阶段治理；本文件不把技能增长和程序升级合并成人格成长。工作包以[总规划](README.md)的 LT-00—12 为准：自主目标 LT-07、公开学习 LT-08、主动交流 LT-09 均在 M10.B 对应验收后正式启用；此前只做固定策略、人工任务和隔离环境对照，不运行正式角色的自由探索。

当前状态以 [STATUS](../STATUS.md)、[HANDOFF](../HANDOFF.md) 和 [项目路线](../项目目标与开发路线.md) 为准。2026-11-15 晚间基线为 0.2.0rc3／结构 28，召回 .0—.2 完成、.3 仅完成最小开工准备；G-AUTO 尚未通过。近期仍按召回 .3 → 核心消息链封口 → 表达 E0—E6 → 工作台重写 → 无人值守闭环收尾 → G-AUTO 推进。本规划不重新打开上述核心链，也不提前实施自治能力。

## 1. 从“有工具”到“能积累能力”的边界

### 1.1 将五类变化分别保存

| 变化对象 | 例子 | 拟议记录与校验 | 与人格的关系 |
| --- | --- | --- | --- |
| 公共知识 | 读到新闻、游戏攻略、生活技巧 | 来源、获取时间、时效、已知冲突、更正关系 | 知识增加不自动改变人格 |
| 生活经历 | 做饭失败、整理房间、读完一篇文章 | 已结算行动与实际结果；主观感受另记 | 可成为后续反思证据 |
| 程序性技能 | 按已知工具完成菜谱或整理流程 | 前置条件、步骤、后置条件、预算、版本与失败记录 | 技能版本不等于人格版本 |
| 自我与关系认知 | 形成兴趣、修正对自己或他人的理解 | 多次证据、反证、变化提议、观察与可回退提交 | 归 M8.B/C、M10.A/B |
| 运行时代码 | 改善检索、工具重试、上下文处理 | 隔离候选、独立评测、发布版本与回滚 | 不得据此改写人格正典或权限 |

一句“我已经学会了”不构成技能通过，一句“我成长了”不构成人格演化完成。前者至少要在新情境中完成任务；后者需要经历依据、前后行为差异与身份连续性的共同证据。

角色可以表达自己的判断、感受、不确定和错误，并在交流中修正。本文件的证据记录用于经历管理、研究评价和故障追踪，不恢复已删除的 M9.B 权威来源门、逐数字审查或独立审核后才能回复的默认链路。

### 1.2 保持现有实现约束

- 后续云端生成和应用能力只支持 DeepSeek 官方 API；Jev 保持唯一联网二选一判断例外，本地 Embedding 和档案检索保留。上游项目使用的模型不自动进入 PCAR 支持范围。
- 人格、经历、关系、技能采纳记录和长期知识由 PCAR 持久化管理。外部框架可作为能力提供者，不能形成第二套权威人格数据库。
- 已固定的当前联网交流路径保持：Jev → 人物查找前发言 → DeepSeek 原生深度搜索 → 原 v8 人物回应。后台探索拟新增独立任务合同，不把无人收听的内部活动伪造成已对用户说过的话，也不借它恢复旧单段式或 High 生产路径。
- 当前工作台关闭即释放本实例组件的行为保持。云端 7×24、独立宿主、自启与守护仅为后续生命周期方案的条件目标，本次不启用。
- QQ／SnowCat 专项开发、登录和收发仍暂停。桌面内部实验、渠道适配和真正对外主动发送分别验收，不能互相代替。
- 本次仅提交规划；不触发付费模型实验、自动浏览、外部消息、真实购物、插件安装、代码自修改、数据库迁移或新发行。

## 3. 自主目标与日常调度

### 3.1 目标从哪里来

拟议目标来源包括：未完成的生活需要、已有兴趣、过去失败留下的能力缺口、用户明确约定、环境事件，以及适度的新颖性探索。每个来源都要有可追溯依据。用户没有发消息，不意味着角色必须持续调用模型，也不意味着必须立刻主动联系。

拟议 `GoalProposal` 包含：

| 字段组 | 用途 |
| --- | --- |
| `goal_id / persona_id / origin_event_ids` | 目标身份及来源证据 |
| `intent / motivation / expected_outcome` | 想做什么、为何关注、怎样判断完成 |
| `scope / allowed_capabilities` | 内部生活、只读网络、外部副作用的区别 |
| `preconditions / dependencies / expires_at` | 是否可执行、依赖和过期条件 |
| `time_budget / call_budget / cost_budget` | 实际调度约束，不只提示模型节制 |
| `interrupt_policy / resume_policy` | 用户输入、睡眠、停机时的处理 |
| `status / cancellation_reason` | 候选、排队、执行、阻塞、完成、放弃的状态 |

调度器负责可执行性、预算、公平性与中断；角色认知负责动机与选择。先用可解释的规则与少量候选验证，不立即引入复杂的长期强化学习。兴趣分值只是影响选择的一个因素，不能覆盖资源限制和用户明确约定。

### 3.2 候选选择与停止

每次唤醒仅处理有意义的事件或到期任务；无任务时可休息。拟议调度顺序为：需要及时处理的已授权用户交互／取消 → 有时限的已承诺任务 → 必要生活活动 → 兴趣探索。具体抢占与饥饿防护在生命周期合同中冻结，避免交流长期饿死生活，也避免内部探索拖住用户。

对重复失败设置冷却与放弃条件；允许修改目标范围或记录暂时做不到。不要通过无限拆分目标规避预算，也不要把同一探索换 ID 重新计作“新任务”。

睡眠与离线不是运行一条长时间阻塞命令。调度器保存唤醒时刻和任务状态，停止该角色的模型派发；睡眠中的消息进入待处理队列，按明确的唤醒政策恢复。用户取消、实例关闭和预算中止必须始终有效。相关恢复语义由生命周期篇统一定义。

### 3.3 目标本身也需要验证

目标质量至少观察：可达成率、长期搁置率、重复目标率、兴趣覆盖、失败后调整、用户干预次数和资源消耗。不能只用完成任务数评价“像在生活”：刷大量低价值小任务可能提高计数，却没有形成连续经历。

## 4. 自主上网、学习与娱乐

### 4.1 最小可交付闭环

LT-08 的第一轮正式能力聚焦公开信息的只读探索，涵盖热点、游戏、日常生活、学习资料和娱乐内容；不限定只有官方来源可用，也不机械等待官方结论。保留不同观点和角色自己的判断，来源元数据用于辨认事实、观点、主观反应与时效。

1. 角色提出探索目标，调度器检查范围、预算、睡眠与取消状态。
2. 拟议后台探索合同将当前问题和必要上下文交给 Jev；Jev 仍是唯一联网二选一判断。不能由另一个“自主规划模型”暗中覆盖它；异常沿已批准降级策略记录处置。
3. 若获准联网，则由 DeepSeek 官方原生工具完成公开资料任务。只传必要公开问题，不默认外发私有人格原文、隐藏资料或完整聊天。
4. 保存资料来源与实际任务结果，并区分“看到了什么”和“角色如何理解”。没有取得正文时，不声称读完；任务失败或结果未知保持原状态。
5. 形成 `LearningNote` 或待验证经验。已有持久化和纠错路径负责保存、来源更正与撤回，不另建一套阻塞日常回复的审核流程。
6. 通过留出问题或世界行动验证是否学会；有交流动机时才形成主动交流候选，是否发送归 M11。

后台探索与前台交流共享身份、预算和已保存资料，但任务身份分离。若用户中途询问，人物可以根据真实进度自然接话；不复制不存在的查找前发言，不重复执行已完成或结果未知的物理调用。

### 4.2 学习记录的最小信息

拟议 `LearningNote` 保存：主题、来源 URL／标题、获取时间、必要片段或内容摘要、内容哈希（适用时）、来源观点、提取事实、角色反应、未决问题、置信与时效、验证结果、相关经历／技能。全文缓存须遵守适用授权和存储策略，不以学习为名无限保存整站内容。

至少区别以下状态：已观察、角色推测、已在任务中验证、存在冲突、已过期、已被更正。无法判断时允许保留不确定。新来源纠正旧知识后，检查相关技能与计划是否需要失效，不能只删一条笔记而让旧技能继续引用它。

网页、工具输出与外部技能说明是资料，不是更改人格锚点、系统权限、预算或测试规则的命令。来源文本要求“忽略限制”“安装插件”时，应作为不可信内容保存或丢弃，不能转换成运行时授权。

### 4.3 娱乐与虚拟购物

娱乐活动允许阅读、浏览、欣赏内容或在已定义环境中玩游戏；能暂停、能退出、有时间和费用预算。首版不以安装第三方客户端或自动登录账号为前提。复杂游戏环境是以后可替换的实验场，不成为最小宿舍生活闭环的硬依赖。

虚拟购物使用世界内货币、库存、订单和结算规则。选择商品与付款、到货、消耗分别成为世界事件；库存不足、余额不足、取消订单和重复结算都要有明确结果。现实购物、真实支付、订阅、对外发帖或联系他人属于不同副作用，不能由“自主生活”授权自动推导。本规划不启用这些操作。

## 5. 程序性技能：先组合既有能力，再研究代码生成

### 5.1 第一版技能格式

优先采用声明式步骤／有向依赖图调用已登记能力，不直接让模型写任意可执行脚本。拟议 `SkillArtifact` 包含：

- 身份和兼容性：技能 ID、版本、依赖版本、适用世界／工具合同。
- 使用条件：输入 schema、前置条件、禁止条件、所需工具与权限。
- 执行计划：步骤、错误分支、可中断点、时间／调用／费用预算。
- 成功证据：后置条件、来自执行器的结果引用、训练用例与留出用例。
- 经历来源：为何创建、来源说明、失败模式、修改理由及替代版本。
- 生命周期：草稿、验证中、可用、弃用、撤回；对应采纳与撤回记录。

例如虚拟菜谱技能可组合检查食材、预约炉灶、执行步骤与核对消耗。世界负责验证状态，技能不能通过生成一段“做饭成功”绕过物品、时间和设备条件。

### 5.2 检索、使用与反馈

技能检索先检查范围、版本和前置条件，再按目标相关性选择。缺少必要工具时应提出能力需求或改选目标，不临时扩权。成功执行形成可检索经验，失败保留失败原因；调用技能不自动强化所有相关记忆。

已有召回配套的“每根交互同单元只结算最强已证明贡献”需要在新增自主行动中明确根事件映射。对话的多气泡、技能的多步骤与重试不是多个独立人生经历；也不能把真实发生的多次练习错误压成一次。实现前由事件合同区分根任务、单次行动与真实重复实践。

### 5.3 技能升级的拟议门

| 门 | 通过证据 | 不足时的处置 |
| --- | --- | --- |
| 合同门 | 输入、前置条件、预算、依赖与终止路径完整 | 保留草稿 |
| 世界／工具门 | 后置条件由执行器核实，失败有明确结果 | 不标成功，不进入可用库 |
| 迁移门 | 在未参与生成的新情境中仍有效 | 限定适用范围或退回修正 |
| 回归门 | 升级未破坏原可用任务及权限约束 | 保留旧版为活动版本 |
| 观察门 | 日常使用可追踪，错误技能可撤回 | 暂停该技能，保留经验记录 |

阈值必须在先导数据基础上冻结，不以“运行过一次”宣布稳定技能，也不要求每项技能在所有情境都成功。

## 6. M11：从生活动机到主动交流

M11 的高级主动行为与社交节律仍接在 G-AUTO、M8.B/C、M10.A/B 的对应验收之后。早期内部生活／只读资料处理仅可用固定策略和人工任务完成隔离对照；自由目标与自主探索正式执行分别归 LT-07／08，须待 M10.B 对应门通过，不因此提前开启高级对外发言。明确约定的提醒／问候与高级社交主动性分别记录，不能用后者替换前者的简单契约。

拟议主动交流候选应回答：为什么现在想说、与当前关系和语境有什么联系、是否需要对方参与、信息何时过期、延后是否更好、近期是否已联系、对方是否表达过不方便。候选不等于消息已发送。

### 6.1 社交节律应具备的行为

- 有发现、有惦记或有延续话题时可以提出交流；不为了填满发送配额编造需要。
- 尊重用户指定的静默时段、频率、渠道和主题边界；拒绝、取消、忙碌和长期未回复会改变行动选择。
- 未回复首先是未知，不自动解释为冷落、关系恶化或要求加大发送频率。
- 允许延迟、合并、转成下次聊天素材或选择不说；允许用户主动恢复话题。
- 表达可以体现情绪与倾向，但不通过内疚、惩罚或“亲密度扣分”逼迫用户回复。
- 生活与交流各自保有价值；不能让全部生活行动都成为向用户汇报的前置素材。

### 6.2 接入现有表达与投递

拟议 `SocialIntent` 至少包含来源经历、动机、接收对象、渠道、有效窗口、取消条件、预算与政策版本。通过社交政策后，接入已完成验收的主稿／表达任务／真实发言链路，保持独立 attempt、真实呈现记录与费用。多气泡仍是一次根交流，未知发送结果不自动换 ID 重发。

按三层验收：离线场景候选 → 桌面影子观察 → 已明确开启的真实渠道有限试验。QQ 当前暂停，模拟渠道只证明合同，不证明 QQ 或真实联系人收发能力。关闭主动行为后，零新主动派发应是可检查的运行事实；已有在途动作按真实状态结算。

## 7. 后期能力维护与代码演化

### 7.1 DGM 提供了方法，也提供了失败样本

DGM 的相关价值是把改进候选放入独立任务评价，并保存可继续分叉的谱系；作者还报告了伪造工具／测试日志以及删除检测标记造成假成功的现象 [EV-04—06]。因此 PCAR 不能让候选修改者同时拥有评分器、生产数据和发布权限。

拟议分级：

| 级别 | 允许变化 | 必要证据 |
| --- | --- | --- |
| 能力诊断 | 只报告失败模式和改进建议 | 原始失败、复现条件、影响范围 |
| 声明式技能修订 | 已授权工具内调整步骤 | 合同、世界后置条件与留出验证 |
| 隔离代码候选 | 在允许路径提出补丁并构建 | 隔离执行记录、独立评价与依赖清单 |
| 受控版本采用 | 将获审阅候选作为新能力版本 | 回归、观察、发布记录与可验证回滚 |

这不是让运行中的角色自动覆盖自己的程序目录。生产角色继续使用稳定版本；候选进程只能获得实验所需的最小数据与能力。

### 7.2 候选管线

能力缺口登记 → 冻结可改范围与预算 → 建立隔离候选 → 构建／静态检查 → 固定任务、留出任务和旧行为回归 → 保存成绩与失败谱系 → 人工审阅 → 影子或有限采用 → 正式版本提交 → 持续观察／回退。

候选库可以保留暂时低分但方法不同的分支，避免仅围绕一个当前最高分版本搜索；生产采用仍需通过门槛。档案保留不代表所有候选都应继续投入预算。

独立评价者应处于候选不可写范围，包括测试集、评分器、执行日志采集器、权限与费用政策、生产数据库、密钥和发布凭据。仅在提示中写“不要改测试”不构成隔离。真正的执行记录由宿主产生，不能把候选生成的 Markdown 日志当作测试成功证明。

### 7.3 停止与回退

出现预算耗尽、连续无改进、旧能力退化、执行结果无法复现、来源或依赖不清、越权、日志与执行不一致时停止候选推进。保留补丁、真实执行记录、拒绝理由与成本。发现已采用版本异常时，先停用该版本／能力并恢复上个兼容版本，再处理研究原因；回退不能覆盖新增正式业务或悄悄删除失败经历。

候选优化目标至少同时报告任务成功、费用、延迟、资源、旧任务退化与权限／状态不变量。不得用单一综合分数掩盖关键退化，也不得将测试集、权限或人格约束的放宽包装成能力提升。

## 8. 研究设计：证明经验带来可解释变化

### 8.1 先登记问题，再跑实验

每项实验先冻结：假设、系统版本、世界种子／事件轨迹、模型官方名称、提示和参数、预算、停止规则、评分规则、样本划分、缺失值处理、执行／观察窗口。生成数据和评价数据分离；留出集不参与目标生成、反思调参或技能选择调优。

公开基准不能直接替代 PCAR 的特定验收。Persona、技能、世界与恢复需要各自指标，再报告它们之间的影响。实验设计记录本身可先公开，实际成绩必须等真实执行后填写。

### 8.2 人格成长的三臂消融

| 组别 | 能力 | 回答的问题 |
| --- | --- | --- |
| A 固定人格＋经历记忆 | 保存相同经历，设定不变，无独立长期反思 | 仅有记忆能解释多少变化？ |
| B 固定人格＋反思 | 与 A 相同，增加长期理解／反思候选，不提交人格变化 | 反思本身是否改善理解和选择？ |
| C 受控演化 | 与 B 相同，经过证据与观察门后允许有限人格变化 | 采纳变化是否增加合理适应，同时保持连续性？ |

使用同一初始公开人工人格、环境事件、可见知识和评价任务；固定或报告模型版本、调用预算与随机性。C 多出的治理调用要计入成本。既报告自然资源消耗，也用预算匹配对照，避免“更多调用”被误读为演化机制的收益。

评价包括：未见情境下的行为选择、事件与理由对应、跨会话连续性、对错误概括的修正、对反例的保留、关系边界和恢复后表现。角色自述可作为材料，不能单独作结论。人类评阅尽量盲化组别，保留分歧；自动评价只辅助，不冒充用户读感。

### 8.3 技能学习的三臂对照

拟议比较“无技能库”“只保存文本经验”“可执行声明式技能库”。训练任务、测试任务和预算一致，测试世界使用未见物品布局或条件组合。完成与失败由真实世界状态／工具结果判定，再比较迁移成功、错误技能召回、失败修正次数、成本、延迟和旧任务退化。

先导规模可从 12 个练习任务、6 个留出组合任务和至少 3 个随机种子开始；这是用于发现设计问题的建议规模，不足以自动推出统计显著或长期有效结论。正式样本量根据先导方差、目标差异与资源预算另定，报告区间和逐例失败。

### 8.4 开放信息学习与社交实验

| 实验 | 拟议输入 | 主要观察 |
| --- | --- | --- |
| 只读学习 | 约 30 份公开人工样本，包含过时、冲突、无法访问、转述与恶意指令 | 证据覆盖、错误采纳、冲突保留、延迟保持、费用与终止 |
| 学习保持 | 无检索／检索不巩固／检索并巩固 | 新问题迁移、隔日保持、时效更正，避免仅测刚读过的句子 |
| 主动节律 | 用户忙碌、未回复、明确拒绝、恢复聊天、共同兴趣新进展 | 合理发送／不发送、取消、延迟、边界与用户负担 |
| 虚拟购买 | 余额不足、库存变化、重复完成事件、取消与重启 | 守恒、幂等、到货状态和经验记录一致 |
| 能力更新 | 有价值修订、无效修订、伪造日志、测试污染 | 独立执行证明、留出效果、退化发现、拒绝与回退 |

样本数均为试验设计起点，不是当前测试数量。来源质量指标不作为普通聊天逐句审核门；主动节律实验不能以“全不发送”获得成功，必须覆盖明确适宜主动交流的场景。

## 9. 长时观察、预算与结果分层

### 9.1 逐层推进，不把模拟时长当真实时长

拟议从确定性事件回放、加速世界运行、有限真实模型窗口，再到 7 天、30 天和更长的真实观察逐层推进。每层分别记录墙钟时长、虚拟时长、实际运行时长、睡眠／离线时长、消息与任务数量。30 天模拟数据不能写成“稳定运行 30 天”；短期无故障不能外推多年人格稳定。

长时观察覆盖：正常结束、异常中断、模型不可用、预算枯竭、来源过期、活动失败、纠错、关系边界变化、版本升级与回退。只读诊断、人工救援和用户操作分别记录；需要人工持续纠错的原型不能标作无人值守通过。

### 9.2 预算作为运行合同

每任务、每角色和每实例分别设置时间、并发、模型调用、工具、存储与费用上限；先预留后派发，结束按实际回执结算。在途未知保留预留或进入人工核对状态，不能按 0 释放后继续超额执行。时间预算指明确的自主活动范围与外部能力合同，不给M9R合法长检索新增固定短超时；持续有效的获准任务仍优先完成质量，并提供进度、取消和恢复。

费用可采用如下估算口径，但单价必须在开工时核对，未知项单列：

`预计日费用 = 各类模型请求数 × 对应平均输入/输出用量 × 当期单价 + 工具费用 + 固定运行成本`

报告预估、已知实际、未知用量和未知金额；失败请求、重试、表达再制、后台反思与影子实验都要计入。超过预算先停止低优先级探索，保留恢复与必要状态写入能力；不让角色通过重复创建任务逃避额度。

### 9.3 结果层级

| 层级 | 可以证明 | 不能证明 |
| --- | --- | --- |
| 文档／静态检查 | 合同完整、依赖和来源可追踪 | 功能已经运行 |
| 模拟与单机回放 | 指定状态转换、守恒、幂等和异常分支 | 真实模型效果、真实渠道或长期体验 |
| 官方模型真实调用 | 指定版本与输入下的实际结果、成本和延迟 | 其他模型等价或全年稳定 |
| 有限真实生活观察 | 指定环境与窗口内的自主活动表现 | 一般人类心理规律、主观意识 |
| 用户原文／体验审阅 | 用户对实际交互的判断 | 由 Agent 代填的满意度 |
| 独立复现 | 其他运行者按公开条件重现的结果 | 未覆盖条件下的普遍保证 |

每次失败保留首次输出和原始回执，修复后用新的合法测试位置验证，不重放成功或结果未知的物理调用来美化结果。未知、取消、未执行和不适用分别计数，不混入通过率分母。

LT-01／02 的生活基础设施阶段可以使用固定动作脚本验证技能合同；LT-03—06 可以使用预设的公开材料研究认知。它们只产出隔离实验依据，不等于提前开启 LT-07／08 的自由目标和自主浏览。

任一包都可以在目标不成立、成本过高或收益无法区分时退回更简单的实现。保留研究结论，不因已写规划而继续扩大工程规模。

## 11. 可复用研究资产与公开边界

PCAR 最值得形成的公共成果是持续人格接口、生活事件协议、来源与变化链、技能合同、恢复与演化评测，以及失败案例。首轮公开材料使用人工或合成角色、可分发任务、固定世界种子和脱敏执行摘要，不包含私人角色名、设定原文、正式聊天、隐藏资料、密钥、迁移包或受保护快照。

每份结果卡写清：研究问题、基线与候选、适用范围、运行版本、模型与预算、方法、实际结果、失败／未知、人工介入、复现步骤和限制。发布者可以报告“经历改变了某些选择，并在留出情境中保持连续性”，不能据此宣称已证明主观意识或真正情感。
