# 从双人聊天记录导入人设

2026-11-19 纳入 PCAR 远期研发，工作包为 **LT-13**。用户将来自 DeepSeek App、QQ、微信等应用的一段双人对话保存为 `.md` 并导入 PCAR。PCAR 识别说话人，从对话中提炼两人的性格特征、语言风格和互动习惯，生成两份可编辑、可回查原话的人设草稿。用户可以选择一人或两人创建角色，并按需采用原话作为表达样例。

功能在桌面 G-AUTO 后作为独立工作包排期，承接现有人设创建和私有语料能力。工作台重构可先稳定通用的新建角色入口。本文记录产品目标、实现顺序与验收要求。

## 文件来源

PCAR 接收用户选定的本地 Markdown 文件。源应用提供其他格式时，允许在本地无损转换为 Markdown，保留消息顺序、说话人、原文和可取得的时间及引用信息。首期以一份 `.md` 独立完成导入为验收条件。

- **DeepSeek App。** 使用 DeepSeek 账户的历史对话导出。若当前客户端提供的是归档包或其他格式，从中选出目标会话并转换成 `.md`。有角色标记的复制文本也可整理成文件。根据实际样本确认 App 版本和导出结构。用户及助手保留各自身份与来源类型。只将选定会话的可见发言用于提炼，推理区、工具结果及粘贴的第三方引文单独标记。[DeepSeek 官方导出说明](https://cdn.deepseek.com/policies/zh-CN/deepseek-privacy-policy.html)
- **QQ。** 使用用户已有且有权处理的私聊导出。可把客户端可用的文本导出，或 QQChatExporter 产生的 TXT／JSON 转为 `.md`。按稳定账号或明确标记识别双方。导入入口仅读取文件，账号登录及 QQ 在线接入沿既有安排。[QQChatExporter 固定版本说明](https://github.com/shuakami/qq-chat-exporter/blob/07113d8ebb2be829db9b9c58865a43629cad1a57/README.md)
- **微信。** 接收 Moect v1.3.0 的 Markdown 私聊导出，后续可增加其他版本和工具的 Markdown 适配。既有研究验证了同批 JSON 与 Markdown 的交叉核对。LT-13 补齐单独读取 `.md`，保留正文、引用、转发和媒体占位的区别。[导出格式实现](https://github.com/mofan6/Moect/blob/7498e9f21ab283edb55a5d6a2e17c7ad696cf168/core/exporting.py) · [PCAR 私聊导入记录](../expression/E.L1-微信私聊导入与原文核对.md)
- **其他应用。** 接收保留明确说话人和逐条消息顺序的通用 `.md`，有日期、时间或回复关系时一并保留。用内容结构判定格式。有角色歧义时展示位置并让用户校正。缺失信息按缺失记录。

## 工作流

入口为「人物 → 新建角色 → 从聊天记录生成」。导入后自动识别并预览，用户确认分析范围后自动生成草稿。角色由用户确认保存。

1. **识别文件和说话人。** 在本机读取文件并保留原件。记录文件摘要、格式版本和消息位置，稳定区分两名说话人。可定位到原平台消息 ID 时使用原 ID，否则用文件及原文位置建立本地引用。按正文、引用、转发、通知和附件占位识别内容。缺少一方或无法确定归属时提示校正，以已确认的身份进入分析。
2. **整理可分析的片段。** 分别统计两人的常用词、标点、表情、消息长度和连发习惯。按时间和回复关系保留完整交流，覆盖不同日期和话题。保留引用的归属，排除引文和系统文字对目标人物口吻统计的干扰。合并重复导入来源时保留原会话中实际发生的重复发言。
3. **按人提炼并保留证据。** 同一份记录分别分析 A 和 B。对方发言用于理解语境，每条人物特征和表达样例的证据需指回对应说话人的原话。短记录直接分析，长记录分段提取并按说话人汇总，保留时间范围、跨段重复出现的观察和反例。孤立、矛盾或覆盖不足的观察可以留作待核，也可以保持字段为空。画像的适用范围标为这份记录覆盖的关系和情境。
4. **校验并预填两份草稿。** 通过官方 DeepSeek 的 JSON 输出取得候选字段，由 PCAR 检查字段类型、目标身份、消息 ID 和引文位置。证据验证通过的候选进入表单，每项显示可展开的原话、日期及归属。用户可逐项采用、修改或留空。用户选定并确认后调用现有创建流程，保存为独立角色。[DeepSeek JSON 输出](https://api-docs.deepseek.com/zh-cn/guides/json_mode/) · [现有人设创建入口](../../persona_runtime/service.py#L38)
5. **按需学习语言风格。** 将用户采纳的表达概述与代表性原句关联到所选角色。保留标点、连发和上下文位置，使用获准范围内的样例支持后续发言。新增记录可生成带来源和时间跨度的修订建议，用户保留既有设定的取舍权。撤回来源时停止它和依赖它的派生表达资料参与后续组装，并显示受影响的建议与样例。

原件和原话证据默认留在本机私有语料范围。用户选择可用于提炼及可在角色交流中使用的材料。开始云端分析前显示发送范围和用途，只向官方 DeepSeek 提交获准的必要脱敏片段。文件正文及其中的链接作为材料处理。提取模板及模型可见输入按项目总则审定，产品中的草稿采纳由导入用户决定。分析任务留存进度和回执，重复提交按导入、目标、输入与分析版本复用已有结果，结果未知时依现有规则核对。[脱敏与分区](../expression/E.L2-脱敏视图与交流分区.md) · [模型输入总则](../模型输入与提示词写作总则.md) · [供应商支持总则](../模型供应商支持总则.md)

## 现有人设字段

| 表单字段 | 草稿来源及保存条件 |
| --- | --- |
| 名称、介绍、初始背景 | 名称用用户确认的称呼。介绍和背景取有明确证据且经用户采用的信息。缺少的必填项交用户在现有表单补齐。 |
| 核心特征 | 提取跨片段反复出现的行为倾向，带支持消息和适用范围。 |
| 价值与边界 | 以目标人物明确表达的价值取向或边界为依据，留给用户核对。 |
| 表达习惯与样例 | 表达习惯保存语言和交流特征，样例引用用户选中的目标人物原话。 |
| 关系说明 | 用户明确选择自己与目标的对应关系后，可在表单核对并确认。导入原件保留来源身份和原会话归属。 |

保存复用 `PersonaSpec`、现有核心／表达版本与角色资料入口。原件保存在外部语料范围。新角色的会话历史从创建后的实际交流开始，共同记忆沿用现有录入和确认流程。风格学习通过可追溯的设定与表达资料生效，首期沿用现有模型权重。[核心字段](../../persona_runtime/models.py#L32) · [表达与关系字段](../../persona_runtime/desktop_profile.py#L77) · [角色资料与样例](../../persona_runtime/desktop_character.py#L117)

## 实施顺序与验收

| 阶段 | 可验收结果 |
| --- | --- |
| 本地导入 | 以一份微信私聊 `.md` 完成文件读取、双方身份确认、引用定位和样本预览，随后各用一份获准的 DeepSeek 和 QQ 实际导出完成对应格式验收。覆盖重名、缺少时间、多条连发、引用中含他人文字和重复导入。 |
| 自动预填 | 使用获审模板及数据完成一份 `.md` 生成两份草稿，逐项核对说话人、证据和字段。用户选任一人创建角色。证据不足、错误输出、中断及重复提交均有可解释结果。 |
| 表达学习 | 以留出的完整对话片段检查两人表达是否可辨、语境是否合适，并比较启用表达样例前后的回复。由熟悉样本的人审核，记录不匹配项。验证改稿、来源撤回及多次导入后的版本归属。 |

各来源按实测的导出格式与版本登记支持。开工时先冻结接口和验收材料，再根据真实记录跨度、提取成本与用户读感决定长记录取样和汇总策略。[远期工作包](README.md#5-研发工作包与依赖) · [复用记录要求](05-参考项目与复用决策.md#4-复用方式与记录要求)
