# M7.4 施工合同：自然表达、投递节奏与可省略余段取消

用户于2026-10-29批准实施。本计划取代[M7.4待定输入](M7.4-开工输入与待定事项.md)中的“未授权”状态；历史决定保留。开发基线 `main@791dd2a`，工作区开工时干净。目标0.7.4.dev1／主库14／导出11／桥接0.7.0；原基线0.7.3.dev1／13／10／0.6.0。M7.3的427项与真实调用不计为本期结果。

## 1. 范围和默认值

新增 `natural_structured`，与原三种模式共用版本化入口政策；现有及新建人格默认不变，分别按人格、入口手动开启。桌面完整显示生成结果，QQ使用语义组、传输片段和节奏。不开流式、运行中取消、自动重新生成、未知送达自动处理、无人值守宿主、Embedding、自动记忆、Director或演化；不改变控制台关闭停服。

受理冻结表达政策，自然批次首成员冻结；后续修改不影响旧请求。收集中切换须封存或取消后切换。显式重试采用当前政策及原引用绑定，旧尝试保留。缺少新快照的历史请求走原路径。

## 2. ReplyBatch v2 与回退

新模式对象只含 `schema_version:2`、`behavior_intent`、`messages`；每条只含 `content`、`content_kind`、`cancel_if_new_input`。意图为respond/clarify/support/explain/acknowledge，类别为chat/technical/code/quote。1–3条，单条≤8000字符，总正文≤12000字符。第一条及技术、代码、引用不可取消；必要答案不得藏在可取消尾段。意图不授予执行权限，不接受模型延迟字段。

严格拒绝重复键、未知字段、空白正文和超限。旧模式仍读写v1。原语义文本不被QQ展示转换覆盖。自然度靠提示及样例，不靠全局删标点；短句通常不加末尾句号，技术和引用保留必要标点。

校验不通过时，只可对完整解析的已知v1/v2容器回退：所有正文合法、完整、未超限，无重复键、未知字段、破损代码围栏；忽略不合格表达元数据，将全部正文按顺序合为一条不可取消消息，并再次检查单条上限。记录safe_text_fallback、原因和输出指纹。无法安全识别就失败并使用原服务提示，不正则修补JSON、不展示内部结构、不增加模型调用；实际用量仍入账。

## 3. 平台分块、等待和取消

新生成回复传输上限450字符，优先段落、换行和安全边界；代码按完整行，网址、数字、版本号和代码单行不可截断。不可分割内容超限时整批在任何发送前失败，不截断、不自动上传文件。拼接必须等于QQ展示文本，历史片段不重切。QQ装饰Markdown去除，但代码运算符、网址及原义保留。

仅新模式QQ组间等待：首条立即，后续 `min(1800,max(600,600+15×前条字符数))` 毫秒，从前组末片确认sent开始；组内不增延迟，三条计划等待最多3600毫秒。单调时钟判定，UTC仅诊断；重启对未开始下一组重新开始一次有界等待，sending转uncertain阻塞。等待在领取前，不持领取权睡眠；pending仍阻塞封存。不开放延迟参数。

仅成功持久受理的新聊天输入触发取消，作用域包含人格、本地用户、渠道、Bot、联系人、Session。重复、冲突、拒收、查询及草稿均不触发。受理事务记录触发Event；生成未完成时记录更新标记，生成落账再检查。只有可省略且所有片段均pending、零attempt的完整语义组可转skipped；一片已领取、发送、失败或不确定即保全全组。取消和claim共用事务/CAS，不取消LLM、不重算回复。

取消保存原因、触发Event和操作记录，界面标“新输入取消”，不能伪装sent。原回复事件不改。QQ上下文、引用、封存和整理仅使用sent实际文本；取消正文不能经摘要或缓存复活。其他failed/uncertain仍按原显式处置，M8.E政策不提前实施。

## 4. 存储、API、桥接和工作台

结构14增量：政策JSON表达参数、turn表达快照及更新标记、ReplyBatch v2与回退元数据、语义组类别/可取消性/等待、片段等待诊断/取消原因/触发来源、操作账本。旧CHECK表按事务重建，旧ID、原列、正文和FK保持，历史新字段空或兼容值，不补造证据。导出11保留旧内容并排除凭据。

管理员reply.current/update支持第四模式、预期版本和操作号；reply.preview预览给定输出或自有人格批次，零模型、零持久副作用；reply.cancel只取消完整可省略未开始组。parts/stream增加语义、等待和原因。claim需能力声明，未到期不领取、不新增attempt。健康声明reply_batch_v2和reply_rhythm_v1。旧插件不能领取v2批次或降级全文；新插件兼容旧服务，不持有第二计时权威。

工作台增加第四模式、正文/展示/分块/节奏预览、取消入口及等待/领取/发送/取消/不确定状态。切换人格、入口、目标拒绝迟到响应；失败保留草稿，不做UI重设计。
