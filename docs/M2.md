# 人格工作台（M2）

## 开始使用

1. 双击仓库根目录的 `启动人格工作台.bat`。六页窗口打开后不会自动登录、安装或调用模型。
2. 在首页点击“只启动人格服务”。在“人格与记忆”创建通用模板，选中并切换；也可导入自己的 UTF-8 人格 JSON。
3. 在“模型”填写接口基础地址、模型名和 API Key，点击保存。例如服务商要求 `/v1/chat/completions`，地址填到 `/v1`。本阶段只支持 Chat Completions 协议，不自动切换 Responses 或其他接口。
4. 点击“测试已保存配置”会明确发起一次真实请求，可能计费；不点击则不会测试。
5. 进入“聊天”，恢复或新建窗口会话后发送消息。用量由提供商返回，缺失时显示未知。

正式人格每次导入都是新身份，不自动继承旧人格数据；旧人格保留。窗口和 QQ 共用选中人格与长期记忆，但近期会话分开。
M1 命令行继续可用，显式记忆、来源与修订规则见 [原操作说明](usage.md)。

## QQ 本人好友私聊

本机独立依赖与 NapCat 程序文件已准备在 D 盘。以后需要重新准备或更新本项目插件时，先停止本项目全部组件，再点击“准备独立组件”或运行：

```powershell
.\scripts\dev.ps1 prepare
```

准备从 `D:\QQ_Bot_2\napcat-shell` 复制程序文件，不复制它的配置、数据库、日志、登录缓存或插件；原项目不被改动。
独立 AstrBot 为 4.29.1，使用锁定依赖和单独虚拟环境，不复用原 uv 工具环境。

1. 在“QQ 连接”填写 Bot QQ 和本人 QQ。两者必须不同；未填写本人 QQ 时不开放 QQ 私聊。
2. 确认旧 TRPG／其他 QQ 实例已从原入口正常退出。为避免 QQ 共用主进程，首版不自动并行启动另一套使用同一 QQ 安装的客户端。
3. 点击首页“启动服务”，依次启动人格服务、独立 AstrBot 和 NapCat。
4. 需要登录时点击“打开 QQ 登录页”，在本机页面自行完成扫码。工作台分别显示管理页就绪、账号已核对、OneBot 在线，互不替代。
5. 使用配置的本人账号向 Bot 发一条好友私聊。群聊、临时会话、其他联系人及含图片等非纯文本消息不会进入人格服务。

默认端口：人格服务 8765、NapCat 页面 6399、AstrBot 页面 6285、OneBot 6299，全都绑定 `127.0.0.1`。
账号或端口修改前，先在故障排查中“全部停止（含 QQ）”。端口冲突时不会静默改端口、接管程序或结束旧项目。
NapCat 登录页只在进程归属验证后打开，使用本项目运行配置中的管理令牌；链接可能包含该本机临时令牌，不要分享。

## 停止、恢复与失败处理

- “停止服务”先停止接收新请求，等待已接受请求及在途投递，然后关闭 AstrBot 和人格服务；默认保留 QQ。
- “全部停止（含 QQ）”另行向本项目验证过的 QQ 父窗口发送正常关闭请求。
- 首页与故障排查页新增“强制停止全部相关程序”：这是用户明确要求的紧急入口，不核对托管来源、宿主记录或实例令牌，不排空请求；结束所有 QQ（包括普通 QQ）、NapCat、相关人格/TRPG/AstrBot 服务、宿主和其他管理窗口。当前工作台保留。
- 强停有独立后台执行通道，不会被普通启停任务阻塞；会多轮扫描自动重启的残留进程。不会按名称批量结束所有 Python/Node，也不关闭无关浏览器、系统程序或控制程序的祖先进程。读取进程失败或仍有残留时明确报错，不假称成功。
- 关闭工作台保留后台服务，再次打开可继续管理。单项启动和停止位于故障排查页。
- 失败请求保留用户消息、错误类别和调用次数，不写入假回复，也不自动重试。
- 点击手动重试会沿用原用户事件、固定原人格和会话，使用当前保存的模型配置创建新尝试。旧尝试的配置密文快照仍保留。
- 重启发现进行中请求时标记中断，不自动继续调用。后续上下文只取成功轮次，失败和中断仍可在历史里查看。
- QQ 后台只投递已生成、明确尚未发送的回复。已经开始发送但结果不确定的消息不会自动补发；多段发送失败也视为不确定。
- 故障排查的“查看 QQ 待处理请求”可看详情并显式重试失败生成。待投递回复绑定原 Bot 和本人账号，更换配置不会把旧回复发送给新账号。

首版不保证 QQ 端恰好发送一次。平台发送完成后才记为已发送；发送与本地确认之间断电仍可能留下不确定状态。

强制停止可能中断尚未保存或正在执行的工作；下次启动由数据库恢复逻辑标记中断及不确定投递，不自动重试。停止报告仅含进程名、PID、范围和结果，保存在 D 盘 `logs/force-stop-*.json`。窗口不可用时可运行 `.\scripts\dev.ps1 force-stop`，该命令直接执行，不再询问确认。

## 模型与上下文限制

默认每条消息一次请求、总超时 60 秒、输出上限 1024 token、滚动一小时最多 30 次调用。测试和手动重试也计数，重启不清零。
配置或输入校验失败且尚未请求提供商时，不计为一次实际调用。首版不会把 token 用量换算成未经配置的金额。

近期上下文最多取 20 条成功对话事件；相关记忆最多 8 条，使用中文双字片段、英文词和短语匹配，不额外调用模型、不补入无关记忆。
总输入默认最多 24,000 字符，先移除较早对话，再移除低相关记忆；核心人格、关系和本轮消息仍超限则报错。字符上限不等于精确 token 上限。
同一人格串行生成，最多等待 10 条。切换人格不会修改已提交请求的归属。

## 数据与凭据位置

默认根目录始终为 `D:\Persona-Centric Agent Runtime`：

| 子目录 | 内容 |
| --- | --- |
| `config/workbench.json` | 非敏感配置、DPAPI 加密的模型密钥和两种本机 API 令牌 |
| `data/database/runtime.sqlite3` | 人格、会话、记忆、请求、尝试和投递状态 |
| `components/astrbot` | 独立 SDK 环境、配置及本项目桥接插件 |
| `components/napcat` | 独立 NapCat 程序和配置 |
| `runtime` | 实例锁、进程身份、健康状态 |
| `logs` / `backups` / `tmp` / `cache` | 元数据日志、备份、隔离测试与依赖缓存 |

模型密钥及人格 API 令牌以 DPAPI 密文保存，数据库中的模型快照也不保存明文密钥。加密内容绑定当前 Windows 用户，不能直接跨账号使用。
NapCat 与 AstrBot 的原生配置格式要求读取明文传输／管理令牌，因此仅在本项目运行目录生成，并将相关目录访问限制为当前用户和 SYSTEM；它们不是模型 API Key，也不复制旧项目令牌。整份组件配置和链接仍需当作凭据保管。
日志只保存级别、组件、操作、标识和错误类别，不保存消息、记忆、设定或完整异常正文。SDK 原始文件日志和消息日志不作为本项目诊断日志持久化，AstrBot metrics 已禁用。

数据库版本 3 兼容从 M1 版本 1 与早期 M2 版本 2 升级。升级前自动创建 `backups/before-m2-*.sqlite3`，迁移失败回滚，不清空旧数据。
数据库备份使用 SQLite 接口；配置备份保留 DPAPI 密文。恢复参见 M1 文档，需先停止相应组件，不要在服务运行时覆盖数据库。

## 接口与扩展

窗口页面由 `PAGE_REGISTRY` 注册，服务通过 `ServiceAdapter` 抽象启停、健康检查、排空和停止；不加载任意第三方桌面插件。
模型客户端接口独立于 Chat Completions 实现，后续可增加协议适配器。

本机接口均要求 Bearer 令牌，拒绝非回环请求及浏览器 Origin 请求，不开放 CORS：

- `GET /v1/health`：服务、实例、版本、排空及待处理数量。
- `POST /v1/chat`：`channel`、`request_id`、`text`、可选 `session_id`；QQ 桥接另附平台验证过的 `sender` 和 `bot`。
- `GET /v1/requests/{id}`、`POST /v1/requests/{id}/retry`：查询和显式重试；桥接令牌无重试权限。
- `POST /v1/manage`：`action` 与 `args` 调用白名单管理能力，未暴露任意 Python 调用。
- `GET/POST /v1/config`、`POST /v1/model-test`：脱敏配置与显式测试。
- `GET /v1/qq-pending`、`POST /v1/requests/{id}/delivery`：账号绑定的待投递读取、原子认领和确认。
- `POST /v1/control/drain|resume|stop`：管理令牌控制排空和正常停止。

管理令牌与 QQ 桥接令牌分离；桥接不能操作人格、记忆、配置或服务控制，也不能读取窗口请求。

## 验证与当前边界

### 扫码后显示未知用户，模型测试成功但私聊无回复

本项目已修复一次配置生成错误：NapCat 的 `timeout` 必须是包含 `baseTimeout`、`uploadSpeedKBps`、`downloadSpeedKBps`、`maxTimeout` 的对象，不能写成一个毫秒数字。错误会阻断 OneBot 初始化，即使页面报告核心在线，也可能没有账号信息和消息连接。

更新后的部署器生成正确结构，NapCat 宿主在启动前检查这一约束。已运行的旧实例需要修复配置并重启 NapCat 后生效，仅再次测试模型无效。
连接恢复的依据是账号信息可读取、OneBot 已连接、工作台核对账号成功；模型测试成功不替代这些检查。重启后刷新浏览器页面，再由本人 QQ 发送一条新私聊验收，旧的漏接消息不会自动补发。

### 自动验证

故障排查页的“打开管理页”独立核对本项目宿主及管理端口的监听进程，不要求 QQ 在线或桥接插件心跳正常。因此消息链路异常时仍能打开 AstrBot 管理页排查；未知进程占用端口则拒绝打开。默认浏览器未启动会显示提示。更新工作台后，关闭并重新双击打开窗口即可加载更新，不必停止后台服务。

```powershell
.\scripts\test.ps1
```

测试只使用 D 盘临时目录、回环模拟模型与模拟 QQ 事件。已准备独立 SDK 时，还运行真实 AstrBot 插件加载探针，阻止外部 DNS 访问、不登录 QQ、不调用真实模型。
包含真实人格服务子进程的身份核对、重复启动与正常停止，以及六页 Tk 在 100%、125%、150% 缩放和慢任务下的检查。
