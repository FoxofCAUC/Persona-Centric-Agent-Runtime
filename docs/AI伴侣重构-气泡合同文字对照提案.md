# 气泡合同文字对照提案

## 依据与假设

用户短聊倾向最简，参考线被偏好的原因是更有自己的观点和人物感。提示块调序在三组中1胜2负，本批不采用。参考线此前共同JSON条件下的三个输出没有被钩子直接改写，不能把偏好归为后处理润色。

当前共同气泡合同除结构说明外，还规定短句长度、表达目的、确认与追问分项、标点及示例。待检验的假设是：这些统一语言编排要求可能遮住人物已有表达。删除它们也可能没有收益，不能提前认定根因。

## 单一改动

对照使用原`bubble_prompt()`，变体只删去其中的语言编排条款，不增加新的表达要求。

| 删除范围 | 保留内容 |
| --- | --- |
| 通常8—35字、短回应及字数填充指导 | 同一JSON形状、字段、枚举及条数/字符边界 |
| 一项一个主要表达目的、确认/建议/追问如何分项 | 每项对应一个气泡、必要内容与取消语义 |
| 普通标点及段落安排的风格指导 | 技术、代码、网址、数字、引用与任务完整性 |
| 确认追问、条件结果、多项建议等语言示例 | 既有结构示例、JSON转义与严格校验 |
| 为凑数增加追问、结束语等话轮编排指导 | 完整理解整批用户输入；不增加“更有观点”等新指令 |

人物原文、已选材料、关系、前文、输入及来源ID、原块顺序、模型、供应商、采样与表达种子全部相同。先冻结同一请求再删指定文字，释放的空间不回填更多材料。

维持`natural_structured`、schema3、相同`response_format`及`reasoning_effort=low`，沿用现有无限输出/客户端时限合同。直接切到纯正文会同时改变现有Grok适配中的低推理设置，本提案不采用这种混杂的切法。

## 如选择继续验证

建议沿用三个开发场景，各生成两臂一次，共6个主回复位置；原生首次加最多3次重试逐次记账，不额外刷样本，不因质量差重生。不重放旧成功结果，不把新控制输出与旧轮跨批比较冒充同条件。

使用新获批可见资料副本及人工上下文，本地检索须实际就绪。前一轮私人数据清理完成后才能建立新轮副本；审阅后清除所有新副本、正文、匿名材料、数据库、缓存及备份。正式默认和QQ不启用。

用户匿名判断人物关注/立场是否具体、是否像该人物、接话是否自然；不以句长、问号、气泡数或规则数量判好坏。若无具体收益则保留原合同，不扩展删词清单来追求通过。
