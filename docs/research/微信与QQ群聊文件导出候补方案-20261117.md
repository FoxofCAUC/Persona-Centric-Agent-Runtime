# 微信与QQ群聊文件导出候补方案

2026-11-17。为真实语料学习保留独立于SnowCat的文件来源：从现有聊天记录导出TXT或Markdown供审阅，同时保存结构化副本，经过来源核对和脱敏后接入PCAR的表达学习流程。SnowCat是否通过账号观察，不再成为取得学习语料的唯一前提；QQ私聊研发仍按原条件分别推进。

文件进入PCAR后的工程与验收见[真实聊天语料表达学习施工规划](../expression/真实聊天语料与MaiBot表达学习施工规划.md)，当前为待审方案。

## 推荐路径

当前Windows环境优先考虑**微信官方客户端已有记录→Moect本地导出→文件语料导入**。已核实Moect v1.3.0提供Windows安装包，支持TXT、Markdown及JSONL；采用按需批量导出，无需持续挂着群聊采集器。[版本与下载](https://github.com/mofan6/Moect/releases/tag/v1.3.0)、[导出格式实现](https://github.com/mofan6/Moect/blob/v1.3.0/core/exporting.py)。

首次连接仍有账号相关边界：其密钥提取代码以查询和读取权限打开已登录的微信进程，并读取内存。由此只能判断它采用本地读取路径，不能推导账号无风控风险；本机微信版本的兼容性和实际账号影响需要另行观察。[密钥读取实现](https://github.com/mofan6/Moect/blob/v1.3.0/wx4/key.py)。

| 数据条件 | 候补方式 | 适用边界 |
| --- | --- | --- |
| Windows微信4.x已有目标群记录 | Moect导出TXT／MD，另导出JSONL | 首次读取微信进程取得凭据；版本适配需验证 |
| 有包含微信记录的iPhone本地备份 | WechatExporter读取备份副本并导出Text | 上游要求未加密备份；当前iOS／微信与备份格式需验证 |
| 已有QQ官方导出的TXT，或当前客户端实际提供文本导出 | 保留原始TXT，离线解析 | 不能假定当前所有QQNT版本都有该菜单；本轮未核实作者客户端 |
| 需要借QQ Chat Exporter重新登录取得记录 | 暂不选作规避第三方接入风险的首选 | 当前流程仍依赖NapCat并要求扫码登录 |

## Windows微信的操作流程

1. 确认目标群和允许处理的时间范围。原记录以官方客户端实际保存的内容为准，先保留现有备份。
2. 从Moect官方v1.3.0发行页取得安装包或便携包。使用已正常登录的Windows微信，打开Moect后手动连接微信；已有可读取的解密备份时，也可以从设置打开备份。
3. 选择目标群和连续时间段。首批使用便于与客户端逐条核对的小批记录，通过后再扩大；学习材料不按关键词只挑孤立句子。
4. 使用快速导出跳过头像及媒体资源，导出TXT或Markdown供审阅。使用相同范围另导出JSONL，作为后续解析的结构化副本。
5. 核对首尾时间、消息数量、同名发言者、连续多条发言及引用关系。保存工具版本、微信版本、范围、文件摘要和发现的缺失。
6. 导出完成后关闭工具，后续整理和PCAR导入仅处理文件；有新增记录时再批量导出。重复区间按来源身份去重，不能按正文相同就删除。

Moect使用指南说明了连接、备份、范围及快速导出操作，并指出当前不承诺适配所有微信4.x版本；维护者目前公告暂停常规更新至12月23日，因此候补采用前要先验证实际组合。[使用指南](https://github.com/mofan6/Moect/blob/v1.3.0/docs/usage.md)、[维护公告](https://github.com/mofan6/Moect/blob/v1.3.0/README.md)。

## iPhone备份的离线路径

有iPhone及相应记录时，可通过Apple设备App或iTunes制作本地备份。Apple官方说明了Windows上的备份步骤。[Apple备份说明](https://support.apple.com/zh-cn/108967)。

WechatExporter的项目说明支持从iTunes备份解析微信好友和群聊，并导出Text、HTML或PDF；已存在的Text输出模板包含发送者、时间和消息正文。其说明要求未加密备份，不能把现有加密备份直接当作受支持输入，也不应覆盖仅有的原始备份。[项目说明](https://github.com/BlueMatthew/WechatExporter/blob/main/README.md)、[Text模板](https://github.com/BlueMatthew/WechatExporter/blob/main/WechatExporter/res/templates_txt/msg.html)。

处理时复制备份到独立目录，在离线环境中读取副本、选择目标群并导出Text。保留TXT即可用于原文审阅；需要MD时只转换排版和来源信息，不改写聊天文字。这个解析步骤不要求在导出程序中重新登录微信。上游发行页有v1.9.5.13，但作者当前设备、微信及备份组合尚未实测；先验证能否完整列出目标群和导出文字，再把它登记为可用候补。[发行页](https://github.com/BlueMatthew/WechatExporter/releases/tag/v1.9.5.13)。

## QQ候补的选择

已有QQ官方TXT可以直接作为语料原件，MD仅作阅读副本。若当前官方客户端实际有消息管理与文本导出入口，按该客户端提供的范围导出；若没有入口，不为执行旧教程自行降级或覆盖当前数据库。

当前QQ Chat Exporter支持TXT、JSON等格式，但官方README中的Windows／Shell流程要求扫码登录，Docker流程也使用NapCat。因此它解决了导出操作问题，没有建立脱离第三方QQ接入的候补路径，本轮不把它标记为账号风险更低的方案。[当前安装与登录流程](https://github.com/shuakami/qq-chat-exporter/blob/master/README.md)。

WeFlow虽然列出TXT／Markdown导出，当前主线已移除内置读取、解密组件，要求用户自行配置第三方原生组件。它不能按旧教程直接当作下载即用的替代项。[组件要求](https://github.com/hicccc77/WeFlow/blob/main/docs/third-party-components.md)。

## 文件如何供PCAR学习

TXT／MD满足审阅需要，结构化副本帮助保留群、说话人、时间、消息身份、引用和转发关系。Moect的TXT／MD会把引用等内容排入可读文字；JSONL则逐条输出消息对象并保留一行导出元数据，但会清除部分内部字段。因此JSONL也是导出副本，不能替代底库备份，解析时必须区分本人正文、引用文字和导出工具添加的说明。[序列化与正文呈现](https://github.com/mofan6/Moect/blob/v1.3.0/core/exporting.py)。

后续适配沿用[真实语料研究中的数据分层](MaiBot真实语料学习与SnowCat静默采集研究-20261117.md)：

1. **保存原件。** 聊天文件进入私有语料目录，保留文件摘要、工具与客户端版本、时间范围和导出身份。原件不进入Git或人物记忆。
2. **恢复多人关系。** 保留稳定匿名说话人、时间、原消息ID及引用关系。缺少原ID时使用文件与记录位置作来源定位；只有昵称时标记身份不确定，不把重名合并成一个人。
3. **形成获准学习视图。** 按允许用途脱敏；排除系统通知、机器人、自身模型输出及工具演示数据。保留真人原句的标点、重复和分条习惯，不先让开发代理润色。
4. **按交流片段学习。** 围绕真实回复链和话题组织上下文，不把相邻两条群消息强行做成问答对，不补写理想回答。训练与留出审阅按完整片段划分，避免同一对话两头泄漏。
5. **生成可追溯提案。** 采用MaiBot的表达资产学习方向，保存原文依据与派生关系，由作者审阅后才允许对应角色使用。群友的身份、经历和观点不自动成为人物事实。

这里的首选“训练”是MaiBot式的表达提炼、资产积累和运行时使用；权重微调属于另一个研发任务。文件可先积累，后续通用文件导入、来源解析和学习适配仍需开发。导出、云端学习及资产使用分别按批准范围执行；现有[模型输入写作总则](../模型输入与提示词写作总则.md)继续生效，代理不创作新的学习prompt、模拟对话或角色例句。

## 后续最小验证

先由作者选定一种文件来源及允许处理范围，验证一小批真实导出能否还原消息顺序、发言者和引用，保留首次文件及缺失记录；文件导入工程验证通过后，再审阅具体学习模板和模型可见材料，开展有限学习试验。

当前状态为候补方案及公开源码核对：未安装或运行导出工具，未读取私人聊天、制作设备备份、登录账号、采集或调用模型，也未恢复QQ私聊。导出候补成立与SnowCat账号验证分别记录。
