## 2. 实际表达路径

```text
Planner的回复指导／真实会话
  → 按实际模型选择提示profile
  → 普通模型选择情境表达／组装角色和真实历史
  → Replyer生成
  → 可选的超级创意翻译
  → after_response改写钩子
  → 回复后处理与规则／LLM分句
  → 扩展转换／逐片发送
  → 已发送内容回流会话
```

普通路径并非“已有完整答案→统一人性化Gate”的现成插件。人性化相关能力分布在选材、生成、转换和呈现，PCAR需要抽取后重新组装。上游实验开关、可选路径和默认行为分别记录，不能把某个实验存在写成稳定路径已证明有效。

## 4. 不能整包照搬的实际行为

规则后处理可删除包含中文的括号内容，并在某些空文本、超长或分段溢出情况下使用默认替代回复；规则分段含随机分拆。见[规则准备与溢出处理](https://github.com/Mai-with-u/MaiBot/blob/478f671e64467121fd3e39205c8d3507b5ce0bd6/src/chat/utils/utils.py#L418)。这些行为可能丢失条件和有效答案，PCAR保留全文降级，不以长度或随机性制造自然感。

LLM分句比较忽略空白并归一部分标点，切片间空白可能丢失。普通聊天可借其切点还原，但代码、公式和精确引用必须采用更严格跨度／字节保护或整块呈现。这是本次局部检查确认的边界。

上游[模式说明](https://github.com/Mai-with-u/MaiBot/blob/478f671e64467121fd3e39205c8d3507b5ce0bd6/docs/replyer-prompt-profiles.md)明确区分普通创意、专用Mai Replier、默认关闭的超级创意与回复缓存。不能假定专用模型也使用普通表达选择，不能把缓存或跨语言开关当自然度保证。其Hook重试可重新执行生成与翻译，PCAR须改用独立表达阶段的恢复合同。

特别区分表达频率：每片携带`selected_expression_ids`是追踪元数据，已读发送路径并未据此证明每片都强化表达计数；明确的`Expression.count`增加位于[重复学习合并](https://github.com/Mai-with-u/MaiBot/blob/478f671e64467121fd3e39205c8d3507b5ce0bd6/src/learners/expression_learner.py#L864)。PCAR须分别记录学习出现、候选选中、表达采用和实际呈现，不能把三气泡当三次回忆。
