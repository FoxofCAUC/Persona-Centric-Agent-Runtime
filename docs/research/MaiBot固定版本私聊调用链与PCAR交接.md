## PCAR 各阶段怎么交接

候选在输入受理时绑定输出路线，绑定至少包含实例、会话、角色及版本、回合、执行版本、已收齐输入 ID 和获准接收方。每个发言阶段另外绑定决策版本、事实版本及派发回执。同回合的查前话和查后话分别建立发言决定。任何指向其他会话、过期执行版本或当前授权不成立的交接都在派发前拦截。

| 阶段和责任方 | 上一环交什么，本环交什么 |
| --- | --- |
| **1. PCAR 装配输入与候选信息** | `IngressService.accept` 持久化已受理输入，沿现有封包逻辑锁定本轮原话及选中引用。读取版本化人格、可见历史、相关记忆和已有资料，保留来源与访问范围。决策可以使用获准的候选信息，生成只会收到最后选中的部分。[工作台提交](../../persona_runtime/workbench_import.py#L152) · [受理与封包](../../persona_runtime/ingress.py#L389) |
| **2. PCAR Planner／Jev 决定动作** | 先决策是否回复、接哪条、是否用工具及本轮要完成的交流动作；对可回复阶段明确角色立场、语体、事实与限定、篇幅、是否收束。可增加独立 Jev 预设或事实选取模型，所有依赖合流后才冻结可发言决定。仅有 Planner 文本、缺字段、超时或决定冲突时停止正文派发，无旧 Pro 回退。首包的等待是等下一批用户消息，工具完成则经新决定发言。 |
| **3. PCAR 执行获准查询与证据选择** | 可复用已有公开底稿时直接进入证据选择。需要新查时必须有绑定的公开查询片段，查前如需说话，先按同一发言链取得可见回执，随后才派发查询。源文、来源 ID、日期和限制持久化，召回或独立选择器为查后决定给出足够回答的最少事实及必要限定。普通模式用一句短话答本题，完整资料在详情。旧实现中模型判定无效可落到 `need_web=True` 的策略回退，还会把预算内的整理底稿和来源片段附加给主模型；首包需将这两处替换为显式决策与有来源的证据投影。未查成时按真实结果另行决定可表达的内容，查前话既已显示，查后无需复述。[公开查询及旧回退](../../persona_runtime/knowledge_native.py#L348) · [来源落库](../../persona_runtime/knowledge_native.py#L419) · [既有正文材料附件](../../persona_runtime/knowledge_translation.py#L50) · [查后去重复](../../persona_runtime/knowledge_handoff.py#L9) |
| **4. MaiBot 私聊 Replyer 生成正文** | 接收已冻结并校验的阶段快照，包括真实目标、必要可见前文、已选角色资料、交流动作、明确的事实与立场、篇幅与收束。输出仅有角色正文，程序记录实际模型、输入版本、完成状态及正文摘要。模型无工具、路由、附加动作和发布权限。若正文模型的合约批准使用 Pro，Pro 也只能通过该入口措辞。现有 `ChatEngine._run_ready` 有自定义流水线、直接生成、场景及默认路径，旧 retry／resume 和表达回退也各有入口。对候选回合逐个封住，含查前预告；历史已确认内容照常读取。[现有生成分支](../../persona_runtime/chat.py#L745) · [主调用和多个出口](../../persona_runtime/chat.py#L882) · [旧续跑分流](../../persona_runtime/chat.py#L1106) · [表达回退](../../persona_runtime/expression_runtime.py#L210) |
| **5. PCAR 独立复核，MaiBot 输出链分段** | 独立复核只返回放行或阻断及可追溯原因，不改写正文。检查答到目标、事实有来源、无助手式邀约及无授权外动作。通过后由输出程序分段，按现行 Unicode 字符口径每个新气泡最多 75 字符，保持原文、顺序和可安全切分边界。不可安全切分的超限内容在发布前阻断。只有用户明确请求且 Jev 已判定的长文，才将全文送详情，聊天区只显示独立审核过的限长正文。程序保留全文和出处，既不截丢限定，也不把长答案切成一串短泡当作普通短答。[长度硬校验](../../persona_runtime/bubble_limits.py#L50) · [分段和输入节奏](../../persona_runtime/expression_protocol.py#L73) |
| **6. 工作台呈现，PCAR 写入可见历史** | 已审核的片段和详情划分一起持久化，工作台按序领取、呈现并回传片段标识、呈现者、正文哈希与回执 ID；沿现有接口对账。某段显示不明时暂停后续，原请求恢复应核对原回执。仅连续确认可见的前缀进入实际聊天历史，记忆仍有独立审核和来源规则。收束后等待新的用户输入。[领取和签收](../../persona_runtime/expression_utterance_publication.py#L132) · [连续可见前缀](../../persona_runtime/expression_utterance_publication.py#L239) · [工作台重连对账](../../persona_runtime/workbench_presentation.py#L86) |

| 中断点 | 恢复条件 |
| --- | --- |
| 决定未完成，或正文已证明未派发 | 从原回合和候选路线恢复，检查执行版本及授权，合格后继续缺失阶段。原输入、权限或模型绑定已变更时，旧决定失效。需要继续发言时先建立新执行版本并重新决策。 |
| 查询或生成已派发，结果身份不明 | 先对账原请求和外部回执。未知状态保留，不能当作未发重新调用。决策可以另记真实失败或待确认状态。 |
| 正文完成，复核或发布中断 | 继续同一持久化正文的复核或片段计划；不得降级播放原稿。关闭、唤回或冷启动共用同一状态生命期。 |
| 已领取片段，尚无显示回执 | 核对原领取记录。只续发能确认从未呈现的待发送段，保留已确认可见的连续前缀。 |

现有恢复合同检查实例、当前执行版本、模型尝试和在途工具，部分状态仅认识旧场景和主回复。因此首包要在状态表和恢复入口同时接入新阶段，不能只增加一次正常生成调用。[现有恢复合同](../../persona_runtime/desktop_recovery.py#L42) · [断线续跑判断](../../persona_runtime/desktop_recovery.py#L93)

## 首包施工与签收

1. 在隔离候选接通桌面批次、显式决策、单一 Replyer、独立审核和可见回执。用已有授权材料或纯结构测试验证跨会话、首包错误路线、无效决定、正文不确定及回执重启续跑。首包先跑普通私聊，核对复用组件没有依赖群配置。
2. 在同一入口接上查前、查后和明确长文。用晚间三轮分别回归无需查找、公开查询片段缺失和长答收束，用 A12 已保存的成功资料回归查后短答及保留限定。同时断言普通短答与每泡 75 字符是两项结果，回复正文、详情和出处逐一核对。
3. 作者审阅实际模型输入和用途后再做真实盲审。同角色、同回复模型、同批输入和匹配的前文进行比较，核对首答、完整可见私聊及证据。候选需优于现用方案、达到直接角色扮演的体验底线，且无助手式邀约、无授权外代办、无回复模型越权判断、无超限气泡。通过后从原 G-Auto 断点继续，沿用已经通过的回执。[晚间样本和验收口径](../expression/PCAR信息与决策层及MaiBot输出链路开发指导.md#现场回执与修复目标) · [A12 成功资料回执](../acceptance/G-AUTO-A12-查后作答专项.md#本批正式观察结果)
