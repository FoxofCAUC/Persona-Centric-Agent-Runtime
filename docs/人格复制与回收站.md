# 人格复制与回收站

2026-10-29。运行时0.7.5.dev4、数据库结构16、全量人格导出13；配置2、桥接0.7.0、PersonaSpec/CharacterSpec及原生角色包格式保持。

## 使用

打开“人格与记忆”，选中列表中的人格：

- “复制选中人格”：确认后建立独立ID，保留当前核心、表达、角色资料、设定书和表达样例。列表以“副本”和ID区分，不擅自修改文学姓名。当前使用人格不变。
- “删除到回收站”：先切换到另一个人格，再选中要删除的项并确认。它从正常人格列表和聊天选择中隐藏，历史原记录保留。
- 勾选“显示回收站中的人格”，选中已删除项，点击“恢复选中人格”。恢复原ID、资料和历史，不自动切换或重放任务。

删除为可恢复的逻辑删除，不是擦除磁盘内容。没有“清空历史”“彻底销毁”入口。存在收集中/中断输入、排队/生成、整理、额度预留或未决投递时拒绝删除，需要先用现有入口处置。恢复之前不能切换聊天或原地重试。

## 副本范围

普通副本不继承聊天、Session、记忆、摘要、主题、临时状态、模型调用记录或入口政策；使用原有新建人格默认政策，不复制运行中的关系状态。

2026-10-29用户修订默认规则：新建、原生导入和复制现在统一默认开启natural_batch、natural_structured、working_set和hybrid_llm，跨会话关闭。副本使用当前发布默认，不沿用源人格旧模式；提交后自动准备本地索引。见[默认开启要求](功能默认开启与人格初始化.md)。

正式私有人格不能直接删除。复制私有资料时，保留源文学设定和作者原始初始关系，继承隐私、云端供应商授权和禁止原体验收保护；不复制隐藏MD或真实经历。主运行目录中的私有副本仍不能直接用于验收，测试继续使用独立可删除运行目录。发布扫描从原始本机登记工作，不将私有正文、姓名、实际ID、账号或哈希写入Git。

## 接口与并发

仅管理员/v1/manage开放persona.inspect、persona.clone、persona.trash、persona.restore；persona.list可显式include_deleted。桥接令牌无权限。

写操作带operation_id及expected_selected。复制还携带inspect返回的核心/表达/角色版本；删除/恢复带expected_revision。同操作同内容返回原结果，载荷不同冲突；版本或当前人格变更拒绝覆盖。创建、指针和操作账本在同一事务中提交。界面迟到预检结果不能弹出其他选中人格的确认框；取消确认不写入。

## 存储、升级和恢复

结构16只新增persona_lifecycle和persona_operations；旧业务表原列、身份、事件和来源不重写。回收站状态、复制来源及隐私根保存在权威主库，备份包含这些记录；全量导出13新增本身份的管理元数据和操作记录，不导出密钥。

升级前核对实例，停写/持锁并备份结构15；升级自动生成before-persona-management备份。旧程序不能打开结构16，软件回退须恢复兼容结构15备份；恢复前先保全升级后新增的真实数据。不要通过删除本机私有登记解除保护。
