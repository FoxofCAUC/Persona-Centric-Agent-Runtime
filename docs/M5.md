# M5：人格与关系连续性

版本0.5.0，数据库结构6，2026-10-27。实现交付，真人待验收。M4仍为T01–T06真人通过、T07及后续待补，不因本阶段交付变为通过。

## 使用方式与默认项

双击工作台，新增“人格与关系”页；原“人格与记忆”及“记忆整理”保留。

| 操作 | 结果 |
| --- | --- |
| 编辑当前人格核心 | 编辑名称、自我介绍、核心特征、价值边界、初始背景；保留人格UUID、会话与记忆 |
| 编辑表达习惯 | 独立表达版本，不修改核心版本，不调用模型 |
| 编辑关系说明 | 独立关系版本；原人格与记忆页的同名操作也使用版本检查 |
| 设置/结束临时状态 | 用户显式文字，默认24小时、可填1分钟至168小时；结束后不再进入新调用 |
| 读取版本历史 | 选择核心、表达、关系或状态，查看内容、时间、修改来源及当前版本 |
| 比较/恢复版本 | 与当前比较字段；恢复产生新版本、保留旧历史，不清除聊天或复活无效记忆 |
| 从来源创建关系建议 | 选择用户发言或人工笔记，明确填写建议；不调用模型，不自动生效 |
| 编辑并确认关系建议 | 查看原文后确认；目标关系已变则拒绝旧候选确认，需重新核对、创建建议 |

本轮执行采用保守默认：核心、表达、关系分别版本；状态只手动设置；关系建议只手动创建并确认。没有自动关系提取、情绪推断、好感度条、主动问候或新后台模型用途，也不增加预算。每日记忆自动更新的权限不会扩展到这些设定。

关系是当前用户的显式说明，核心背景是人格设定；不把模型自述或虚构背景登记成与用户已发生的经历。关系类长期记忆仍是M4的数据对象，不自动改写本页显式关系。

## 版本、请求和纠错规则

- 新人格导入仍创建新UUID，格式1保持兼容；同身份编辑走独立版本接口，不通过重新导入实现。
- 新请求在受理时固定核心、表达和关系的版本；后续编辑、回退或切换人格不修改已受理请求。显式重试使用当前版本与当前模型，保留原消息及每次尝试记录；完成请求不重复调用。
- 状态在模型调用开始时检查有效期，排队时过期的状态不使用；已发出的调用不会因中途到期撤销。到期不删除版本，恢复过期状态会拒绝，需要重新明确设置期限。
- 记录的对话上下文包含人格/表达/关系版本、所用状态版本和期限。M4旧调用缺少这些信息时保留未知，不补造旧版身份记录。
- 关系建议只能引用同人格、同用户的用户事件或人工笔记，拒绝人格发言单独作证、已屏蔽来源及跨人格引用。
- 拒绝关系建议不会改动正式关系，也不会自动屏蔽整段聊天；这与M4拒绝记忆候选的保守屏蔽规则不同。
- 来源被M4修订/撤回策略屏蔽后，未审关系建议失效；已批准的关系版本保留并显示待复核，后续模型上下文不引用该旧关系文字。不会静默改写存储的关系或回退核心。用户可明确重写关系进行复核，或选择有效来源的新建议。
- 屏蔽来源的关系版本不能直接恢复；人格/关系回退始终遵守当前记忆、摘要与来源有效状态。
- 所有版本修改使用预期当前版本检查和稳定操作ID；冲突或保存失败保留编辑内容，不产生部分写入。原命令行关系设置保留接口、每次变化也留下版本，旧式命令行维持显式最后写入语义。

核心、表达、关系与状态单次JSON最多16000字符，非法或过大输入明确拒绝，不截断。核心及表达不能缺少原有必填项，关系可通过管理接口明确清空；窗口空内容编辑仍拒绝误保存。时间存UTC，窗口显示本机时间。

## 业务接口与存储

管理员 `/v1/manage` 新增：

- `profile.current / history / update / compare / restore`。
- `relationship.propose / proposals / proposal-show / review`。

这些操作都不调用模型，AstrBot桥接令牌无管理权限。QQ生成继续由同一个人格服务完成，插件0.3.0协议保持兼容。

结构6新增版本、当前指针、幂等操作和关系建议表，以及新请求的设定快照。升级前SQLite备份至D盘 `backups/before-m5-*.sqlite3`，事务迁移，失败回滚。旧人格和关系作为迁移初版，时间标记为迁移时间、来源标记migration；不伪造以前的修改史，不改原始行的名称、设定、关系时间或聊天记录。

人格导出格式3保留原字段并增加版本、指针和关系建议，不导出密钥或调用模型凭据。完整备份包含全部版本及日程。回退旧软件前必须停服务，另存结构6备份，再恢复匹配结构5备份和旧代码；不能让旧软件直接写结构6，旧备份后的新数据不会随回退自动合并。
