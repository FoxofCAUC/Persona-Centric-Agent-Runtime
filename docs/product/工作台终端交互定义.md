# PCAR 工作台终端交互定义

2026-11-19。本文定义 Windows 环境准备完成后，用户从首次打开工作台到日常聊天的目标体验，供后续原型、施工与验收使用。以 v0.2 已有的配置、人物和对话能力为起点。[v0.2 用户入门](../user/getting-started.md) · [工作台重构验收标准](../acceptance/工作台重构-产品目标与验收标准.md)

## 用户打开的是一个聊天窗口

**PCAR 工作台是以人物为联系人的即时通讯窗口。** 人物是用户来找的对象，会话是和这个人聊过的一段记录。进入聊天后，用户一眼能看出在和谁聊、刚聊到哪、现在可以做什么。完成基础准备后，日常入口直接回到对话。[PCAR 陪伴产品方向](../AI伴侣产品方向与大肥鱼参考线.md)

- **聊天是主界面。** 找人物、打开对话、看消息、输入和发送是常驻操作。对话顶部确认当前人物，时间线延续已有交流，输入区始终明确当前发送对象。
- **与人物有关的事从人物入口办。** 导入、切换、看人物资料、翻会话历史、确认自动记忆状态，都从对应人物进入。新建会话为显式操作，人物和会话各自有清楚的归属。
- **应用级操作容易找到。** 模型连接、使用帮助、收起到托盘与退出是基础入口。高级设置在应用菜单保留入口，技术详情按需查看。

- 左栏按人物找会话，支持在当前人物的记录里查找和打开历史。应用菜单提供使用帮助、高级设置、收起到托盘和退出。[Kelivo 会话侧栏](https://github.com/Chevey339/kelivo/blob/c2b48958de39c3a1715347d33fa8887bdef974ce/lib/features/home/widgets/side_drawer.dart)

- 使用 PCAR 的人物语义、界面文案与自绘图形。首启和日常共用一扇聊天窗口，工程选型随原型验证。[来源与许可登记](../REUSE.md#工作台设计参考)

## 首次打开与新手引导

首次打开时，先告诉用户 PCAR 可以与选定人物持续聊天，随后带他完成**准备一个人物、配通基础聊天、发出第一条消息**。引导按实际状态呈现缺项，已完成的步骤自动略过。人物和模型连接可以按用户现有材料的情况先后完成。

| 用户来到哪一步 | 这一步怎样带用户向前 |
| --- | --- |
| 第一次打开 | 说明接下来需要的人物与模型连接，并给出明确的开始操作。已有可用配置和上次对话时直接接续，确有缺项时从原界面引导补齐。 |
| 决定想和谁聊 | 从已有角色选择，或导入已有的人设、创建一个人物。确认前看到人物名称及可识别信息，选中后立即知道聊天对象是谁。对需要专门资料授权的人物，在相关用途首次生效前说明范围。 |
| 配好模型连接 | 引导填写基础聊天所需的官方 DeepSeek 连接信息，预填适用的地址和模型选项，本机安全输入密钥。遇到缺项、连接或认证错误时，说明下一步并保留已填内容。模型使用与可能收费的说明在首次实际发送前可见。 |
| 开始第一段聊天 | 两项准备就绪后直接进入选定人物的对话，显示人物与输入区，把发送交给用户。收到第一份实际回应后，说明如何回来继续聊，使用历史、自动记忆等功能时再提供相应提示。 |
| 中途离开或需要帮助 | 已保存的配置和人物可继续使用。用户可以收起引导，从当前缺项继续，也可以从“使用帮助”重新找到相关说明。联网、自动记忆等能力按相应配置和授权随用随开。 |

引导的完成标志是用户完成了一次真实对话，并知道下次在哪里继续。已准备好的老用户打开窗口时可以直接聊天。只有当前任务所需的配置或授权才在对应位置提示。[现行首次体验与可选能力](../user/getting-started.md#发送第一条消息)

## 每天打开会怎么用

| 用户自然会做的事 | 交互定义 |
| --- | --- |
| 回来继续昨天的话 | 默认回到上次打开的可用人物和对话，找到最近发生的交流。未发送草稿按原人物和会话保存、恢复，由用户决定是否发出。 |
| 换个人聊 | 从人物入口切换到对应对话。人物名、历史和输入目标一起切换，先前已受理的消息仍归原对话。 |
| 往上翻，找以前说过的话 | 按原顺序浏览与当前人物的记录，必要时按已有能力查找、复制或显式引用。翻看旧消息时保持当前位置，有新消息可从明确入口回到最新。 |
| 另开一段对话 | 用户主动开启新会话，既往会话仍可从同一人物下找到。封存会话可阅读，继续发送时进入明确选中的可写会话。 |
| 看看自动记忆有没有开 | 人物资料提供基础状态及开启或暂停入口，说明作用于当前人物。按现行条件完成配置和授权后，记忆整理随日常聊天推进。用户能区分已保存内容和仍待处理的内容。 |
| 暂时离开，或结束使用 | 最小化留在任务栏。明确收起到托盘时，工作台与已开启的后台任务继续运行，从托盘返回原对话。关闭窗口或选择退出时结束本实例运行，退出中的异常有简明反馈。 |

## 角色操作与设置入口

「人物」提供新建、导入与切换，「人物资料」提供编辑、补充、记忆和版本历史。模型连接与 API Key 从首次引导、应用菜单或连接故障处进入。旧页面的对应关系和高级设置的暂定范围见[工作台设置迁移与角色操作](工作台设置迁移与角色操作.md)。高级设置明细在无人值守收尾及 G-AUTO 后按证据细分。

## 发送、等待与中断

聊天时间线呈现真实发生的交流。常规等待只在对话附近显示简单状态，人物查找前亲自说出的话是一条正常消息。消息状态以实际受理及呈现记录为准，用语围绕用户的下一步操作。

| 情况 | 用户看到什么，能做什么 |
| --- | --- |
| 输入与发送 | 用户能连续输入、发送和补充消息。中文输入法选词和多行输入有明确行为。点击发送后很快看到受理状态，已接收的消息按顺序进入当前对话。 |
| 人物正在回应或查找 | 用户能理解这一轮仍在进行，可继续写下一条、补充内容或按当前状态停止。实际查前发言进入时间线，需可见确认的查找在该发言呈现后开始。 |
| 人物说了一部分，用户打断或换了对话 | 已确认显示的话留在原对话。打断发生在哪一条之后可辨，新输入按受理顺序接续。切换或重开按原对话记录核对已说到哪里。 |
| 明确失败 | 区分用户消息未受理和消息已受理但回复失败。保留原文字，给出与当前问题对应的操作，例如更正连接、编辑发送内容或发起一次允许的重试。 |
| 结果待核对 | 状态附在原消息或原对话上，从已有记录核对后续结果。恢复与重新打开沿已确认的进度接续。 |

呈现语义以已验收的 E.N6 约定为依据。自动记忆与桌面启停沿用各自的用户侧约定。[E.N6 呈现与恢复](../expression/E.N6-场景发言接入与回退.md#默认策略与发言合同) · [自动记忆正常操作](../acceptance/M8.D-自动记忆验收手册.md#正常操作) · [托盘与退出](../acceptance/M8.E-工作台绑定运行验收手册.md)

## 用真实流程检验界面

- **新用户第一次用。** 按引导选人物、配置连接并发出第一条消息。验证缺项和配置错误看得懂、途中关闭后能继续、完成后能独立进入同一个人物的聊天。
- **用户隔一段时间回来。** 打开后接上上次交流，翻看历史、切换人物并回到原对话，能看出每条消息和草稿属于哪里。
- **聊天发生例外。** 在回复等待和部分呈现时操作，遇到明确失败与待核对结果时找到相应处理方式。收起到托盘后能返回，正常退出后能再次打开历史。

上述路径作为实际窗口交互验收场景，和美术、工程质量一并验收。[阶段验收](../acceptance/工作台重构-产品目标与验收标准.md#阶段验收)
