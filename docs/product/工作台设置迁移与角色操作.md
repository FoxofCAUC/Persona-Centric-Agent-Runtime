# 工作台设置迁移与角色操作

2026-11-19。沿用已确定的 Kelivo 参考草图。左侧是人物和会话，主区是聊天，顶部「人物资料」进入当前人物，左下「应用菜单」进入应用级设置。本文件记录现有功能的承接方向，供重构原型与设置迁移使用。[终端交互定义](工作台终端交互定义.md)

## 从左侧人物入口创建角色

「首次引导 → 选择人物」和「人物 → 新建角色」进入同一套创建流程。用户可以从空白创建，也可以导入现有人设或 PCAR 角色包。导入先预览人物及内容范围，再确认建立新身份。带业务历史的导出包有独立导入入口，明确提示会带入哪些历史、哪些设置需要重新确认。

从空白创建时，把现有必填项按用户能理解的问题安排在同一份表单中：

| 用户要填写什么 | 承接的现有资料 |
| --- | --- |
| 这个人是谁 | 名称、人物介绍、初始背景 |
| 这个人有哪些特点 | 核心特征、价值取向和边界 |
| 这个人如何说话 | 表达习惯 |
| 你们怎样相处 | 用户明确设定的关系说明，随需要填写 |
| 还想补充什么 | 可展开年龄、外貌、兴趣、世界背景、设定条目和用户提供的表达样例 |

用已有校验指出具体缺项，保留已填写内容。保存前可预览将生效的设定和资料用途。说明哪些资料允许参与聊天、哪些资料仅作者可见，涉及外发的用途沿用各自的授权。保存后显示成功并提供「开始聊天」入口。模型连接尚缺时，可在原地进入配置并返回此人对话。[现有人物核心编辑](../../persona_runtime/desktop_profile.py) · [现有角色资料及角色包](../../persona_runtime/desktop_character.py)

新版工作台本期在「新建角色」接入「从聊天记录生成」。G 前通过手动创建和现有角色包导入验证共用的草稿预填、编辑、校验与保存流程。分析结果携带原文出处及待核对状态，仍由用户在同一表单里确认。[聊天记录导入与人设生成](../long-term/06-聊天记录导入与人设生成.md)

## 修改与追加从当前人物资料进入

| 用户想做什么 | 新版入口与作用 |
| --- | --- |
| 修改人物设定 | 「人物资料 → 编辑」读取当前角色的设定，沿用创建时的分组。保存按现有版本规则更新原角色，已受理的消息保留当时的设定。人物身份、会话与记忆继续关联原角色。 |
| 给人物追加资料 | 「人物资料 → 补充资料」为当前角色新增设定条目或用户提供的表达样例。保存时清楚显示新增内容、可见范围和实际生效状态。 |
| 添加或更正共同记忆 | 「人物资料 → 记忆」承接查看、录入、修订和撤回，并能看到来源。人物背景属于设定，用户与人物已经发生的交流和经确认的事实属于记忆。 |
| 查看或恢复以前的设定 | 「人物资料 → 版本历史」支持查看、比较、恢复。按现有合同记录恢复后的版本。 |
| 建一个独立角色 | 回到「新建角色／导入」，或在人物菜单选「复制为新角色」。独立身份和聊天、记忆的继承结果在确认前明确显示。回收站和恢复属于人物管理。 |

角色资料、表达习惯、关系、临时状态各自沿用现有生效范围。保存冲突时保留用户的修改，提示先核对当前版本。用户填写或导入的模型可见内容按现有来源和用途规则处理。[人格与关系版本规则](../M5.md#版本请求和纠错规则) · [模型输入与提示词写作总则](../模型输入与提示词写作总则.md)

## API Key 和常用设置

**模型连接属于基础设置。** 首次引导的「配置连接」、应用菜单的「模型连接」和聊天中的连接失败提示，都打开同一份配置。基础界面显示官方 DeepSeek 连接、当前支持的模型选项及 API Key 是否已设置。新填密钥以遮挡方式输入。更换或清除时说明影响哪些用途。正常保存配置本身不调用模型。用户选择真实测试时，先显示可能产生费用，测试结果就地反馈。

**资料、记忆和联网的使用范围属于人物操作。** 用户在人物资料或功能首次触发时，查看当前状态并决定启用、暂停或授权。某项可选能力需要单独凭据时，从该项的设置进入。例如 Jev 使用独立连接，随对应联网或场景功能说明。基础聊天引导只提示当前实际缺项。应用级和人物级入口读写现有权威配置和策略。[v0.2 配置合同](../../AGENT_INSTALL.md) · [模型供应商支持总则](../模型供应商支持总则.md)

## 现有页面的承接方向

| 现有工作台页面 | 新版可见入口 | 技术详情或维护能力的方向 |
| --- | --- | --- |
| 首页、聊天 | 首次引导、人物对话、当前消息的状态和可执行操作 | 实例健康详情和内部任务阶段按需展开 |
| 人格与记忆、人格与关系、角色资料 | 新建角色、人物资料、编辑、补充、记忆及版本历史 | 私有兼容检查、资料索引、命中预览等定位到维护入口 |
| 模型 | 基础模型连接、API Key、连接测试 | 内部用途配置、超时、长度和调用参数作为高级候选 |
| 记忆整理 | 当前人物的自动记忆开关、记忆记录和需要用户决定的事项 | 批次、覆盖、周期和摘要诊断作为高级候选 |
| 世界知识 | 当前人物的联网开关与资料使用授权，聊天中发起公开查询 | 原生检索与资料记录从详情进入 |
| 会话与主题、原始档案、档案检索 | 当前人物的会话列表、历史查找、引用和另开会话 | 原始记录、索引、主题和封存策略作为高级候选 |
| 输入与缓冲、回复投递、认知上下文 | 聊天中的等待、停止、失败反馈及结果核对 | 队列、投递、召回和上下文诊断作为高级候选 |
| 运行与约定提醒、故障排查 | 托盘、退出、使用帮助和可执行的故障提示 | 运行维护、日志、备份恢复、额度细则作为高级候选。约定提醒入口按其实际交付与启用范围安排 |
| QQ 连接 | 依现行暂停状态保留历史接续说明 | 渠道配置和平台维护按恢复阶段安排 |

以上覆盖当前工作台导航中的 17 个页面，具体字段随施工核对。[当前页面注册](../../persona_runtime/desktop.py)

## 高级设置定方向，自动化验收后再细分

依据是用户在当下是否需要知情、作决定或采取行动。首次就绪、日常交流、角色创作、个人资料授权以及故障的可执行处理放在对应用户入口。技术参数、维护、诊断、低频排障作为高级设置候选。若某项动作仍需人工才能继续，先保留从相关状态直接到达该动作的路径。

无人值守收尾和 G-AUTO 后，拿实际运行证据逐项判断，核对正常执行、异常恢复、退出和再次启动。能够稳定自动完成的工作，其运行参数与诊断可收进高级设置。仍需用户亲自授权、纠正或选择的事项留在发生处。高级设置的最终条目、默认值和迁移规则据此确定。[无人值守与 G-AUTO 验收矩阵](../acceptance/无人值守陪伴-阶段门与验收矩阵.md)
