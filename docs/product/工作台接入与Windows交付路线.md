# PCAR 工作台重构施工计划与 Windows 交付

2026-11-19。运行基线为 v0.2、业务库结构 33 及 E.N6 发言链路。以作者认可的首版 PCAR-工作台-Demo.html 为视觉与交互基准，沿用[终端交互定义](工作台终端交互定义.md)和[设置迁移与角色操作](工作台设置迁移与角色操作.md)。工作台重构后依次进行无人值守收尾和桌面 G-AUTO。

G 前交付 Windows 11 x64 候选 ZIP。在已准备 PCAR 环境的电脑上，双击「启动PCAR-新版.bat」即可使用真实工作台。新版承接日常操作和必要恢复。低频维护沿用旧工作台或现有工具。独立 EXE 目录包另行安排。高级设置的最终条目和默认值在 G-AUTO 后按运行证据确定。

## 施工顺序

| 工序 | 施工内容 | 通过条件 |
| --- | --- | --- |
| 桌面宿主与启动 | 用 pywebview 6.2.1 和 WebView2 加载已认可的本地 HTML、CSS 与交互脚本。接入现有数据目录定位、实例锁、后台运行、托盘和退出。新版 BAT 显式选用 WebView2 工作台。 | 在隔离实例验证双击开窗、重复启动唤回、收起与退出。缺少 WebView2 时显示修复入口。 |
| 真实聊天 | 先读已有角色、会话和历史，再接入新会话、翻找或引用历史、发送、停止与结果核对。收展侧栏保留对话状态，按人物和会话恢复草稿与阅读位置。 | 完成旧会话读入、发送、回复呈现、退出和重开。验证切换人物、部分呈现后打断、回执丢失和连续补充。 |
| 首启、人物与设置 | 先用已有配置判断缺项，再从同一「新建角色」表单选择空白创建或导入角色包。顶部「人物资料」承接编辑、追加、记忆和版本历史。模型连接从首启、应用菜单及故障提示进入。高级设置提供当前运行状态、待核对任务及排障入口。 | 用户能完成首次聊天，保存作用于预期角色或配置。导入建立新身份，表单校验失败或版本冲突可继续修改。 |
| 打包与演练 | 将新版静态资源、BAT、依赖锁和许可纳入桌面包清单并生成 SHA-256。用空实例及结构 33 的隔离副本验证。保留可运行的 Tk 路径。 | 在包含中文和空格的路径双击运行，核对旧版到新版、新版写入后退回旧版及再次升级。验证已有数据和新增业务都可读。 |

## 接入约定

- 启动脚本复用现有实例定位和环境检查，通过 `gui --frontend webview` 选择新版，旧入口以 Tk 为默认。工作台沿用实例锁、`ServiceController` 和 `AppRuntime`。收起到托盘继续运行，退出通过原结算流程释放所属组件。释放失败时保留状态与恢复入口。[启动脚本](../../scripts/Start-Workbench.ps1) · [现有桌面包生成](../../scripts/build_desktop_bundle.py) · [pywebview](https://pypi.org/project/pywebview/6.2.1/) · [WebView2 分发](https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution)
- 本地页面通过限定的桥接操作调用 PCAR。Python 用现有 `LocalClient`、管理接口及 `ConfigStore` 核对角色、会话、写入范围和版本。密钥按现有本机方式保存，页面读配置状态。草稿按实例、人物和会话加密保存。业务继续使用结构 33。[本机客户端](../../persona_runtime/desktop_client.py) · [界面与 Python 通信](https://pywebview.flowrl.com/guide/interdomain.html)
- 消息受理固定人物、会话和请求 ID。沿用现有可见呈现协议与回执。已呈现的气泡按原记录接续，结果未知时核对原请求。查前发言在当前聊天区实际呈现后，才放行相应联网环节。翻历史时用「回到最新」提示新内容。[E.N6 呈现与回退](../expression/E.N6-场景发言接入与回退.md)

## 给聊天记录人设导入留出接点

G 前把「新建角色」做成同一套草稿接收、预填、编辑、验证和确认保存流程。手动输入和现有角色包共用现有表单及字段校验。偏好、背景、表达和关系等字段在保存前可单独修改，界面能附带字段出处与待核对信息。用已有角色包验证预填可编辑，只有用户确认保存才创建角色。

本期由 LT-13 添加「从聊天记录生成」入口。双人 Markdown 的分析结果作为两份独立草稿接入这一表单，每个候选字段可回查原话。分析和预填先形成候选，用户选定要创建的人物后复用同一保存流程。[LT-13 工作包](../long-term/06-聊天记录导入与人设生成.md)

## 验收与交付

- **交互、美术。** 目标用户独立完成首次配置、创建和导入人物、首次聊天、编辑和追加、重开续聊。以已认可的 Demo 对照真实窗口，检查宽窗、窄窗抽屉、Windows 缩放、中文输入法、键盘焦点和长聊可读性，由作者确认视觉完成度。
- **工程。** 覆盖旧历史读取、版本冲突、密钥缺项或无效、角色切换、已显示内容防重、回执未知、托盘和退出。先用结构标识、既有回执和隔离数据验证，真实调用使用已确认材料和用途并逐笔记录。隐私边界与模型可见内容遵循[模型输入总则](../模型输入与提示词写作总则.md)。
- **交付。** 三项均通过后交付候选 ZIP、校验值、双击启动与回退说明、验收记录。旧工作台与新版按实例依次使用。交接注明 G-AUTO 可复用证据、待补验和仍需人工介入的事项。[产品验收标准](../acceptance/工作台重构-产品目标与验收标准.md) · [G-AUTO 验收矩阵](../acceptance/无人值守陪伴-阶段门与验收矩阵.md)

独立 EXE 另包时再验证封装后的服务运行环境、公开模型资源和 WebView2 依赖，目标是在未另装 Python 的 Windows x64 环境完成启动、退出与数据路径演练。
