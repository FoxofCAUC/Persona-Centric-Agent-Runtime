# README 维护与跨窗口交接指南

本指南适用于根目录 README、用户入门、产品路线、贡献入口和文档导航。当前展示约定更新于 2026-11-21。每次维护都应核对实际交付的版本和能力。

## 1. 接手时先确认什么

首页以 **Persona-Centric Agent Runtime（PCAR）** 为品牌，采用纯文字展示人格中心、人格版本化、长期记忆、聊天记录还原和远期愿景。

产品主线是人格的持续身份、自主生活、自我理解和经历驱动成长。聊天与长期记忆是当前基础。角色的经历既可以来自与用户相处，也可以在未来来自自己的活动；运行时同样可以承载其他人格。

**以仓库当前版本的 README 和配套文档为接续依据。** 早期交接包和页面预览保留各自的历史版本。接手时核对远端提交和本地差异，保护其他窗口的工作。

另一个窗口接手时：

1. 确认自己的源码根目录与本次交接目录；工作区外层可能是数据目录，并非 Git 根目录。
2. 读取本指南、根目录 `AGENTS.md`、`docs/STATUS.md`、`docs/HANDOFF.md` 和用户最新指令。
3. 查看 `git status --short`、当前分支、HEAD 与差异，识别本窗口和其他窗口的未提交工作。
4. 同一工作区直接接续现有文件；不同工作区先核对远端版本，必要时再按本机交接包清单比较并合入对应文件。README、配套文档和被引用素材一起交接，不用较早交接包覆盖更新的仓库内容。
5. 已有改动有冲突时，先保存本次负责文件的可恢复副本，再逐项整合。不要以旧 README、整目录复制或清理工作树覆盖其他窗口的工作。

临时接手其他开发窗口时，只同步用户可见事实；保留此版的定位、结构和视觉。涉及更大产品方向调整时，采用用户的新决定。

## 2. 保持的产品与设计约定

| 约定 | 维护要求 |
| --- | --- |
| 叙事中心 | 介绍人物如何维护设定、记住经历和接续聊天，并说明持续生活与成长的远期方向 |
| 模型条件 | 实际供应商支持以对应版本的规则为准 |
| 阅读体验 | 用用户能完成的事介绍功能，工程结项和检查记录进入详细文档 |
| 首页样式 | 纯文字和链接。旧角色形象、插画、概念图和工作台截图按历史素材保留 |
| 交付状态 | 公开能力、开发候选和远期规划均应标明适用范围 |
| 文字表达 | 应用 anti-defensive-writing：先说明事实和操作，保留影响理解的条件，删去重复限定与空泛赞美 |
| 平台排版 | 使用 GitHub 原生 Markdown 和必要的简单图片 HTML；不依赖自定义 CSS、网页脚本或装饰卡片 |

新版本带来使用方式变化时，更新对应段落及入口。体验优势须有相应验证。

首页先讲人格、版本和记忆，再说明聊天记录还原、远期愿景与入门。私聊建卡与历史接续以实际交付范围为准，分别链接到对应指南。

## 3. 哪些变化需要维护 README

| 触发事件 | 应采取的动作 |
| --- | --- |
| 普通修复、重构或内部测试完成 | 更新相应开发记录；用户体验、条件和入口未变时，README 可不改 |
| 候选版本新增能力或阶段状态改变 | 更新首页候选摘要、产品路线及需要接续该阶段的贡献说明；公开版下载保持实际发行 |
| 新公开桌面版本发布 | 核对真实附件、tag 手册和使用前提后，统一更新下载、入门、能力条件和状态 |
| 模型、开关、权限、费用、系统或渠道条件变化 | 核对适用版本，更新对应能力和入门说明，不把候选规则套到旧公开版 |
| 工作台重制完成并交付 | 更新已交付的操作路径和说明。目前首页采用纯文字 |
| 长期研究有新成果 | 更新产品路线与研究入口，区分方案、实验和实际交付，不把愿景整体改为“已实现” |
| 用户给出新的定位或审美纠正 | 写入本指南相应规则，再调整受影响页面；不要把模型自行提出的偏好当成用户决定 |

**代码推送不等于公开发行。** 标签、Release、桌面附件、功能启用和用户体验验证分别核对。若最新 Release 只有源码，不能把它当成已经可用的桌面包。

## 4. 先核事实，再更新页面

维护者在本机工作记录中保存一份简短事实摘要：核对时间、远端提交、公开桌面版本及附件、候选程序版本、功能是否启用、影响使用的条件、对应证据与待核项。不要把整份记录塞进首页。

| 要核对的事实 | 首选证据 |
| --- | --- |
| 用户的当前要求 | 当前会话及已明确采纳的决议 |
| 可公开下载的版本 | GitHub Releases 的实际附件、对应 tag 和包内手册 |
| 当前候选版本 | 对应源码的 `pyproject.toml`、STATUS、HANDOFF 和已交付记录 |
| 功能可否体验 | 最新实现与验收记录、实际入口、开关和授权条件 |
| 使用方式、模型及默认值 | 对应版本的安装手册、配置与当前实现 |
| 自然度、长期效果、成本与等待 | 对应场景的实际结果与审阅范围，不能用工程检查数量代替 |
| 远期顺序 | 最新已采纳方案与远期规划；后生效的记录优先 |

STATUS、HANDOFF 中有历史段落。按日期和后续明确结论判断，不单独摘取旧段落的“当前”“待审阅”或“已完成”。发生矛盾时记录具体矛盾并查后续证据，不能挑选更好宣传的一种说法。

首次交接的事实快照为：公开 v0.1、候选 0.2.0rc4、召回结项、表达 E0 完成、下一入口 E1。**这些值只用于理解本次交接，后续维护不能直接沿用。**

### 只有开发进度更新

更新 README 中受影响的能力与候选说明。路线或贡献入口有变化时同步对应文档。内部阶段编号留在研发记录。

### 有新公开桌面版本

1. 确认桌面包及校验附件确实存在，可获得，名称与平台正确。
2. 将首页下载与用户入门指向同一个版本；安装资料链接固定到该 tag 或包内手册。
3. 检查 docs/index 中所有固定版本操作链接，逐一确认目标存在且仍适用，再更新。
4. 核对模型、联网、自动记忆、后台行为、迁移和费用条件的变化。
5. 对照“下载 → 同版本手册 → 准备 → 启动 → 首次对话”检查文字与入口是否完整。

不要只全局替换版本字符串。旧截图、素材采集版本、历史许可和历史记录中的版本，继续保持各自真实时间范围。仅改文档时，不能把入口核对写成重新安装或实际对话验收。

### 新能力进入可体验阶段

用“用户在什么条件下能够完成什么”描述；把开关和限制写在使用位置。候选专属能力只放候选说明，进入公开版后再更新公开能力摘要。人格自主演化、自主生活、睡眠和云端常驻不能由现有记忆或恢复能力直接推出。

前版插画、概念图和工作台截图保存在 `assets/readme/`。来源、许可与停用状态见[素材署名](../../assets/readme/ATTRIBUTION.md)和[素材清单](../../assets/readme/provenance.json)。

现有发布保护的图片例外按固定路径与 SHA256 匹配，私人资料检查继续执行。首页改为纯文字不涉及发布保护规则的调整。

## 7. 验证、预览与发布

### 每次必做的局部检查

- 阅读完整差异，确认改动围绕本次事实变化，未把工程日志重新追加到首页。
- 检查相对链接、锚点、图片路径、alt、下载和同版本指南。
- 检查首页、路线图、入门、贡献入口的版本和阶段是否一致。
- 确认 README 只使用文字和链接，检查是否引用旧品牌、插画或截图。
- 执行 `git diff --check`；未跟踪文档也应检查内容、编码和实际引用。
- 重建预览。修改图片、布局、表格、标题或长文本后，查看桌面与手机、浅色与深色；普通小文本修改至少查看受影响区域。

纯文档维护不运行全量业务测试、QQ 实测或收费模型回放。本地 Markdown 渲染、代码验证、实际软件运行、用户试读和 GitHub 在线效果分别报告。

### 复用本机预览工具时

本机已有生成、浏览器检查和概念图导出脚本，具体绝对路径见随本指南交付的本机入口说明。这些是本机工具，不是仓库必备依赖。

生成脚本当前固定了源码目录、输出目录和 `renderer.COMMIT`。切换工作区或版本前先核对并更新这些值，输出到本次独立目录；新增本地文档页时同步页面映射。只更新 `COMMIT` 字符串不能证明素材或文案已经同步。

通用渲染器会把部分未本地渲染的资料链接到该提交，因此提交必须真实包含目标资料；新文档应加入本地页面映射或随预览一起交付，不能生成远端不存在的链接。

图片需完成解码与绘制再拍整页，回到页首，逐张打开截图确认无空框、缺字或错页。输出旧预览前先保存原结果。SVG 原稿修改后按当前导出方式处理，不只在浅色查看。

工具不在另一台机器时，使用该环境已有的 Markdown/GitHub 预览和浏览器工具，不擅自假定绝对路径存在；缺少视觉验证时明确记录未完成范围。Computer Use 按需调用，界面子任务完成后立即释放控制。

### 提交和推送

先完成可审阅差异与必要检查，再按当前会话授权提交和推送。已授权的文档提交不重复索取同项确认；本指南本身不授予 tag、Release、恢复 QQ 或后续功能开工权限。

提交范围包括所有新增的必要文档、被引用图片、许可与来源记录。临时预览、浏览器截图、私有数据、密钥和本机运行目录不进入源码提交。推送后核对远端提交与在线 README，记录实际结果；未推送时交付本地差异与预览即可。

## 8. 交回时给出什么

2026-11-16晚间接续已发布首页时，开发候选更新为rc7，后续入口改为[人物回复重构E.N0](../expression/E阶段重构-人物回复链路开发指导.md)。原四类产品叙事、三张首页图、公开v0.1下载与同版本入门保持；更新只涉及候选摘要、近期路线、贡献和导航。本机核对与预览记录在所选数据目录`tmp/e-stage-closeout-20261116`及`exports/readme-e-stage-closeout-20261116`，不随源码提交。后续继续按实际进度核对，不能把规划中的rc8或Pro新链写成当前公开能力。

简短报告即可：本次依据的版本或提交、哪些用户可见事实改变、修改文件、必要检查、预览入口、是否提交推送及其实际结果、仍待完成事项。

若 README 无需改动，说明理由，例如“本次为内部重构，公开能力、条件与入口未变，首页保持”。不要为了证明维护动作而增加段落。

### 可直接交给其他窗口的接续指令

跨窗口接续时先核对当前分支、远端和未提交文件，再按实际交付同步受影响的用户文档。检查链接、版本与相关渲染，汇报差异和提交结果。
