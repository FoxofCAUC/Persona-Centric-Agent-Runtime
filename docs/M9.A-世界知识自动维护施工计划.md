1. 来源登记与一次性授权，支持有限来源的定期发现、增量获取和按需获取。

基础资料固定为 Wikilite 中文 ANN 包，联网增量来源固定为中文 Wikipedia 和 Wikidata。其他来源通过清单逐项登记。使用公共页面标识、实体标识或明确登记主题进行外发查询，私人经历及作者资料仅参与本地权限判断。

### 3.1 来源与运行权限

每个来源登记地址、发布者、允许域名及路径、适用主题、内容保存方式、更新检查周期、新鲜度规则、请求限流和停用状态。来源条款、接口限制及实际可达性在 M9.A.0 查验；不能仅凭“公开可访问”推定允许镜像全文。

首批联网适配器为中文 Wikipedia 与 Wikidata，按页面/实体版本及内容哈希复用。数据集标注 GFDL，程序为 GPL-3.0，Qwen 原模型为 Apache-2.0，分别留存上游声明与对应版本。百科正文出处保留原条目链接，原始快照时间及作者清单缺口据实登记。

来源读取权限、知识处理模型权限、各角色使用范围分别记录。现有主回复或私人记忆整理授权不自动扩展为外部搜索授权。公共材料可复用存储，但角色能否读取仍检查知识集合与来源政策；私人聊天、作者隐藏资料、凭据和用户身份不进入公共库。

### 3.2 数据合同

新增实体保存在现有权威数据库，索引可放 `RuntimePaths.knowledge`；以下为拟定名称，实际迁移编号在开工时分配。

| 实体 | 必要信息 |
| --- | --- |
| `knowledge_sources` | 来源身份、地址/发布者、获取和保存许可、政策版本、范围、限流、刷新与有效状态 |
| `knowledge_documents` | 来源条目ID、规范URL、内容版本/哈希、原文或许可范围内证据、解析版本、ETag等更新标记 |
| `knowledge_claims` | subject/predicate/value、适用语境、事实或报道主张等类型、有效区间、当前状态、版本链和冲突组 |
| `knowledge_evidence` | 主张与文档版本的多对多关系、精确引文/位置、提取与复核任务、独立来源分组 |
| `knowledge_jobs` | 业务阶段、来源游标、覆盖结果、依赖、幂等键及对应受管任务ID；不另设模型派发权 |
| 基础包失效映射 | 基础包、文章/章节、影响范围、更正/撤回版本及当前有效性 |
| 检索投影 | 可重建词法索引、源版本、有效状态与索引版本；不承担正文权威 |

时间分别记录：发布时间 `published_at`、事件发生时间 `event_at`、实际获取时间 `fetched_at`，以及 `valid_from/to`、`fresh_until`。缺失时间记未知；不能把获取时间或网页修改时间填成事件时间。统一存储带时区时间，界面按本机时区显示。

主张类型至少区分“可核对事实、来源声称、评论、未核实信息”。模型自报置信度不作为发布依据；两个模型意见相同也不等于两份独立来源。转载通过原始链接、发布者和内容相似标记归组，不能累加成独立证据。

旧记忆分类 `world_knowledge` 保持原身份、来源与可见范围，新表不从旧分类无条件回填。若以后确需迁移，另列逐条可验证的来源转换，不在本次自动完成。

### 3.3 一条受管执行链

流程为：

`授权源发现 → 获取并保存证据 → 提取主张 → 独立复核 → 事务提交 → 更新索引 → 聊天读取`

默认继续使用现有 `OrganizationEngine` 及 M8.A 的任务、attempt、receipt、reservation、租约体系。为世界知识增加明确的 payload 来源域、任务种类和处理分支；获取阶段使用本地受管网络任务，模型阶段通过既有收费执行入口。新增业务表只负责阶段与覆盖记录。

世界知识任务固定受理时的角色/知识集合、来源政策和模型绑定，可没有聊天 Session；不伪造聊天事件、会话或用户发言来满足旧接口。M9.A.1 必须逐一检查原文 guard、Manifest、取消、恢复和导出中对 event/session 的假设。若现有结构无法安全承载，只提取必要共享执行原语，并证明旧任务ID和唯一领取权保持；不扩展成通用 Agent 平台。

- 发现幂等键绑定来源、条目与内容版本；模型幂等键再绑定阶段、流水线和相关事实版本。重触发及重启不创造新收费身份。
- 提取后，独立复核重新读取有效原文与已有事实，决定发布、新版本、隔离、忽略或等待新证据。无新证据的隔离项不反复收费复核。
- 发布前再次检查来源、权限、预期版本和有效区间；事实及证据依赖在同一事务提交。索引稍后完成也不能读到已失效事实。
- 已保存回执恢复解析/提交；已提交返回原结果；已发出但效果未知保留占位并隔离该任务，不重新派发。其他来源和前台聊天继续运行。
- 模型失败沿用已实现且适用于该任务的有限重试，不新增外层重试。GET获取可按单独有限政策重试，不能把它与可能收费的模型请求混为一谈。
- 工作台为生命周期权威，托盘继续工作；退出时停止新获取/派发，回收所属组件。重新打开后按游标和当前状态接续，不补放每个错过的轮询周期。

### 3.4 自动更新与撤回

同一来源内容改变先形成新文档版本，再提取和复核受影响主张。明确更正产生新事实版本；普通补充保留原事实；同对象不同有效时间可并存；无法裁定的矛盾进入冲突组，不由“更新更晚”自动决定真伪。

来源明确撤回或管理员停用后，读取路径立即过滤受影响证据，再清理或重建索引、摘要与缓存。提交前后的并发撤回、备份恢复和旧任务迟到都必须检查相同失效状态。多来源支持的事实重新计算剩余支持，不能因为删除一个链接就保留原来的“已核验”结论。

超时、429、单次404和明确撤回分开处理。获取失败记录来源不可达或待核实；不据此宣称事实为假。失去有效支持的内容退出当前确定事实视图；保留历史时显示原始时间和缺口。到期事实可以作为带日期的历史资料读取，不能继续回答成“当前最新”。

删除资料依现有删除政策处理正文、索引、缓存、导出和备份；最小审计不能包含可重建已删除内容的信息。恢复备份时必须应用现行撤回/删除约束；存在已清除私人内容的旧备份不得用于迁移回滚。

### 3.5 聊天使用

查询先区分角色设定、私人经历与公共知识。公共问题优先读取仍有效的本地知识；需要最新信息、明确来源或本地缺失时，才进入授权来源检索与获取。查询只携带必要公共主题；从私人对话自动生成的查询必须经过本地范围与敏感内容检查，无法安全缩减时不外发。

普通聊天不等待后台扫描整个来源库。明确查询可在冻结的等待窗口内等待所需知识任务完成；超时就说明本次未取得足够新证据，后台在原任务上继续，不再额外生成第二条主动回复。后续追问复用完成的知识。现有主回复、消息缓冲和投递链继续负责实际回复。

知识上下文只加入相关有效条目及必要时间、来源信息，保持一次主回复。Manifest记录主张ID、版本、文档证据、使用范围、筛选和裁剪原因；调用前重新检查来源，生成期间撤回则在交付前拦截受影响结果，保留调用账目而不自动重生成。

用户问出处或最新事实时提供可用来源；普通陪伴聊天保持 v8 表达，不强制每句报URL、置信度和审计状态。未命中知识时不凭模型记忆声称“刚查到”；无关输入的 v8 装配应保持原行为。

知识引用随回复进入聊天档案后，自动记忆仍须保留其外部来源身份；不能经“机器人说过—聊天摘要—共同经历”循环变成私人事实，也不能把用户对外部消息的转述自动提升为独立公共证据。

### 3.6 额度与公平调度

默认设计为知识提取/复核与自动记忆共用既有后台额度和执行租约，按任务种类分别展示用量，不再复制一套60/240。当前自动整理为60次/小时、240次/滚动24小时；原总额0仍为不限，不重复乘十。正式启用时以届时有效配置为准。

用户主回复及明确手动操作沿用人工次数免额规则并照实记账；定期更新、聊天附带的自动学习及后续新来源仍计自动额度。手动刷新只豁免受理时冻结的范围，不能给整个来源永久免额。网络请求另计频率和流量；如果未来加入付费搜索，其账目与限额单列。

后台模型并发沿用1。来源扫描每次只受理有界批量，前台优先；记忆新证据、知识需求与历史积压采用轮转及等待提升，避免知识抓取占满队列。无变化版本零提取调用，有效本地命中零外部搜索。

初始新鲜度为 24 小时，每日一次协调扫描，优先处理按需查询及明确更正，每批最多 5 份文档，每日复核最近使用的最多 100 个页面。启动只补一次到期检查，内容未变按哈希复用。普通百科解释可使用带快照标识的本地资料，明确要求最新时检查上游版本。时政和热梗的专门时效指标交接 M9.B。
