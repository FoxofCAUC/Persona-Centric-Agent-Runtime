# PCAR 认知与召回优先级开发指导

修订日期为2026年11月11日。本文承接用户对DeepSeek项目评价的讨论、上一轮项目评审，以及本轮明确提出的自然时间衰减与回忆强化方案。用途为后续开发指导，状态为方向与实施约束已整理、功能待实施。同日后续许可证更正已完成，PCAR当前采用AGPL-3.0-only。

本文作为[产品方向](AI伴侣产品方向与大肥鱼参考线.md)的专项修订依据。当前实施事实只读[STATUS](STATUS.md)，下一施工入口只读[HANDOFF](HANDOFF.md)。涉及本轮新决定时以本文为准，既有阶段成绩、失败记录和历史授权按原时点保留。

## 1. 项目定位与本轮决定

PCAR以持续存在的人格身份为中心，长期保存真实经历、关系理解、已接受的知识及其来源。模型承担可替换的理解、推理、检索规划和表达能力。评价开发成果时，首先检查它是否改善长期相处、记忆连续性和实际任务完成。

用户本轮明确的方向如下。

| 决定 | 后续开发含义 |
| --- | --- |
| 以召回优先级实现遗忘 | 优先级随自然时间下降，影响主动注意与默认召回，不通过丢失原始资料实现遗忘 |
| 每次有效回忆增强优先级 | 用户重新提起、模型有依据地回忆等独立事件形成强化记录，同一事件的重试和恢复不重复计数 |
| 覆盖多种进入PCAR的数据 | 对话经历、正式记忆、网页获取的知识及其他合法导入材料采用统一原则，按数据性质设置不同政策 |
| 为后续认知能力提供基础 | 情绪、主动行为、自我认识和反思通过明确接口使用优先级与回忆记录，后续分阶段开放 |
| 允许复用MaiBot代码，项目采用AGPL-3.0-only | 用户已确认相关开发者及A_Memorix作者A_Dawn对PCAR的复用授权；随后明确将PCAR许可证更正为AGPL-3.0-only。具体移植仍核对文件许可与署名 |

开发指导交付时未修改业务代码、数据库、运行配置或许可证。随后同日按用户指令完成许可证及相关声明更正，业务实现与运行数据不变。真实模型调用、QQ接入、正式数据迁移及提交推送不由本次文档和许可更正自动启动。

## 2. 从项目评价中采纳的方向与校准

采纳百科检索、当前语境和个人记忆应分工的判断；采纳按真实交流失败改进触发、等待和选材；采纳优先改善记忆选择与不确定性表达；采纳供应商接口解耦及一次验证一个认知机制。

完成度百分比不作为排期依据。当前20轮观察中6/12个知识轮实际注入证据，8/8个闲聊轮没有新检索，说明该批语境与注入链存在缺口。该结果不等同于全系统能力只有50%。固定集18/20也不等同于自然对话完成验收。不同阶段的P95分别保留，成功率与事实质量优先的政策继续有效。

当前代码已有来源、冲突、有效期、更正和不确定信息处理。新增工作应改进这些信息的实际消费，复用现有记录。记忆排序仍主要依赖词语匹配与更新时间，适合接入独立的注意与优先级机制。参考实现为[记忆装配](../persona_runtime/context_m4.py)及[上下文检索](../persona_runtime/context_builders.py)。

人格核心稳定、经历增长和情境反应变化可以并存。作者确认的身份与核心设定继续受保护，经验形成的理解有独立来源与版本。情绪、反思和演化仍遵循G-AUTO后的阶段安排。

“本地持久化”“关闭外部知识获取”和“完全离线推理”分别定义。当前云端主模型并未因使用本地百科而成为离线模型。大型百科包去留继续按现行A/B方案决定，个人记忆与知识版本的本地权威地位保持。

## 3. 认知职责与数据分层

以下分层用于明确职责，不要求增加同等数量的模型、进程或数据库。

| 层次 | 保存或处理的内容 | 当前与后续安排 |
| --- | --- | --- |
| 人格权威状态 | 身份、作者核心设定、明确关系与权限 | 沿用版本管理；普通遗忘与回忆强化无权更改 |
| 原始经历与资料 | 原始事件、完整对话、网页正文、来源版本 | 在现行留存政策内保真保存；低优先级不触发删除 |
| 长期理解 | 有来源的事实、事件概括、共同经历及可修订模式 | 复用正式记忆、主张与证据结构，推断和事实分别表示 |
| 召回优先级 | 时间衰减、有效回忆、可用性分层及选择记录 | 本轮新增方向，程序确定性管理，可解释、可恢复 |
| 当前工作上下文 | 当前话题、指代对象、明确意图、未完成任务、选中的记忆与知识 | 按本轮需要装配，保留必要近期消息，不把完整历史持续加入提示 |
| 认知活动 | 语境理解、知识处理、反思、情绪评价及行为建议 | 复用受管执行；先实现当前任务所需部分，后续能力按阶段开放 |

日常语言理解和通用推理由模型能力与场景验证承担。当前语境负责区分个人时间叙述和最新资料要求，解析代词及追问。公共知识负责可核对事实。暂不因“常识层”这一名称新增万级图谱，遇到稳定、可归纳的实际缺口后再决定是否增加规则或小型知识材料。

建议的处理闭环为输入与情境观察、形成本轮需求、选择记忆与知识、组织回答、确认实际消费、提交回忆事件。后台再按现有政策整理新经历与来源。每个环节使用同一任务与证据身份，避免出现多套写入权威。

## 4. 遗忘的语义与适用范围

### 4.1 保存、可用与容易想起分别管理

原始数据保留回答“过去发生过什么”。来源与权限回答“现在是否允许使用”。召回优先级回答“当前有多容易被注意到”。优先级下降不得把真实事件改成未发生，也不得使错误知识变成正确知识。

有效性、更正、撤回、来源政策和角色权限始终先于优先级。高频使用的过时知识仍须按时效政策处理。撤回或无权限资料不能通过强化、冷层检索、备份恢复重新进入正常回答。

本轮“无损遗忘”不覆盖用户明确删除、永久清除或禁止保留的指令；已删除私人原稿及派生内容不恢复。授权到期、来源使用限制等仍按既有政策执行。

### 4.2 召回单元与域隔离

优先级绑定稳定的知识或记忆单元，并保留其具体证据版本。个人领域可采用有来源的事件片段、事实或事件集合，公共领域可采用文档章节、主张或已学习的概念材料。一个主题的使用不能自动强化整份文档、整个会话或所有相邻关系。

同一事件的多个切片、摘要和事实之间保留lineage，按实际使用范围去重。默认不沿来源图递归传播强化。发生更正时，当前版本与旧版的优先级继承规则必须显式确定，旧版有效性不因继承改变。

原始事件、助手自述、用户陈述、公开资料与模型推断分别保留来源类型。未经复核的陈述可以是可回忆的经历，但不能仅因重复提及成为已核对事实。

优先级至少按人格与既有访问范围隔离。公共正文可以按许可共享存储，不共享某个私人角色的使用热度与经历。渠道是否共享召回状态沿用当前角色和会话政策，不通过本功能扩大跨会话或跨入口可见性。

### 4.3 所有材料进入统一生命周期，使用不同参数

对话经历、网页正文、事实版本和导入资料登记进入PCAR的时间及其原始发生时间，两者不混用。每类材料有明确的初始化及衰减政策，半衰期、强化系数和阈值在实际实施包中冻结，不凭名称预设同一种速度。

大型只读百科包使用独立的稀疏优先级覆盖层。未逐条写入覆盖层的条目可按包登记时间和默认政策惰性计算，实际选中后再建立条目状态；不为全部向量逐轮写分数，也不修改封存基础库。包的本地登记时间不冒充原始资料快照时间。

相同内容的重复抓取、导入、定时扫描不重置衰减锚点，不制造新的回忆。真正的新版本按来源版本处理；资料新鲜度更新与注意力强化分开登记。

身份设定、权限、明确约定和当前任务等具有专门的必需装配规则。它们的有效性及履约不能因普通召回降权被绕过。明确置顶是独立、可查看的政策，模型不能自行将任意材料永久置顶。

## 5. 首版优先级计算建议

本节为拟采用的最小算法形态，具体数值与实现细节待工作包冻结。它是工程上的注意力近似，不宣称复现完整人类遗忘规律。

设单元在锚点时刻的优先级为 `p_anchor`，类别半衰期为 `H`。读取时按有效时间计算。

```text
elapsed = max(0, effective_now - anchor_at)
p_before = p_anchor × 2^(-elapsed / H)
p_after = p_before + alpha_event × (1 - p_before)
```

`H`为有限正数，优先级范围为0至1。每次独立有效回忆使用正的强化系数，提升幅度随接近上界而减小。达到数值上界时不承诺继续增长。事件类别可以采用不同系数，系数不能由模型任意填写。

每次更新先计算自然衰减，再应用该事件强化，最后提交新锚点。读取或定时维护本身不强化、不重置锚点。后台无需持续逐条扣分，可采用惰性计算和下一次分层变更时间索引。

自然时间包含停机期间。时间采用持久化UTC时间及版本化政策，界面按用户时区展示。校时回拨不得增加优先级或使已提交事件时间倒退；异常前跳应记录并校准，避免一次错误时钟使全库休眠。恢复后不补造“软件关闭期间曾经思考或回忆”的事件。

重要度、优先级、当前相关性、事实可信度与资料新鲜度分别表示。初版重要度优先来自用户明确标记和已经成立的任务关系，暂不把模型猜测的情绪强度作为永久事实。未来情绪可以提供有界的选择偏置，不得修改证据正确性。

## 6. 什么算一次有效回忆

### 6.1 事件口径

| 情况 | 是否强化及计数方式 |
| --- | --- |
| 用户重新提起一个已存在事件或事实 | 明确解析到合法单元后形成一次用户回忆事件；当轮回复失败不撤销已经真实发生的用户提及 |
| 模型调用回忆工具并实际消费结果 | 结果通过权限与版本检查，进入已完成认知任务的采用记录后强化；普通对话以成功回答对应的最终上下文采用记录作为首版可观察依据 |
| 主模型主动联想到已有经历 | 须能绑定已存在且有效的来源，并有成功消费记录；只有模型自述“我想起”不计 |
| 新一轮通过缓存复用有效资料 | 这是新的逻辑回忆，可以强化；缓存命中不替代有效性复核 |
| 用户明确深入查找冷层旧事 | 找到并确认使用的单元形成回忆，可重新进入活跃范围 |
| 检索产生候选、重排、预热、预览、管理页查看、备份与索引维护 | 不构成认知消费，不强化 |
| 同一任务重试、轮询、恢复、重复消息、同一证据的多片投递 | 使用原逻辑事件幂等去重，不重复强化 |
| 请求失败、取消、效果未知，仅知道材料曾准备发送 | 单独保留状态，不推定模型已消费，不凭未知回执强化 |

最终上下文包含某材料，只能作为“已提供给成功任务使用”的可观察代理，不能证明模型内部实际依赖了它。记录区分用户显式提及、上下文采用与输出有证据支撑的回忆，验收分别统计。

用户提及与主回复使用同一单元时，按同一根交互合并，只采用一次已确定的强化贡献；事件级别升级时只结算差额。检索翻译与主模型先后使用同一来源，也不在同一个根任务中连乘强化。事件是否幂等由程序判定。

### 6.2 防止自我强化与热门垄断

每个真正独立的有效回忆仍登记强化。对短时间内、同一话题链上的重复使用，可采用较小但为正的贡献；这与同一事件重复执行的零贡献严格区分。半衰期和饱和强化共同限制无限累积。

后台自主回忆必须有获准的任务触发、明确目的和可追溯来源，不能因“该记忆优先级高”不断自行创建下一次回忆任务。摘要整理、来源复核、质量检查等维护读取本身不作为自主回忆。

模型过去生成的推断和反思不能作为新的独立事实来源。后续反思确有必要复用某段经历时，最多按一次合法认知任务登记使用，不能将派生摘要逐层当成新经历强化原事件。回忆次数也不增加事实可信度或来源独立性。

## 7. 检索与注意力选择

### 7.1 分层缩小默认候选范围

| 范围 | 默认行为 | 恢复方式 |
| --- | --- | --- |
| 活跃范围 | 优先参与普通相关检索 | 按时间可降入休眠范围 |
| 休眠范围 | 保留轻量索引与原始定位，不全部装入每轮候选 | 明确历史追问、强实体/时间线索或活跃范围证据不足时进入深入检索 |
| 原始档案 | 保存原文及合法历史版本，支持检查与重建 | 精确引用、审阅和受管重建；受当前权限与删除政策约束 |

活跃/休眠是注意力分层，来源撤回、事实过期、权限拒绝是另一组状态。不得复用同一个“失效”标记混淆它们。

仅在全库结果返回后增加一个排序分数，不能解决所有历史始终参与默认检索的问题。首版须验证候选生成阶段的分层确实生效，保留冷层查询入口，使用预算、实体/时间索引及分页控制规模。索引可以按使用层次重建，原始内容保持可恢复。

### 7.2 本轮选择顺序

1. 解析当前意图、话题、指代及必要时间范围，检查是否有显式引用或未完成任务。
2. 按当前角色、渠道、来源、版本及事实状态限定可用集合，并在结果采用前复查。
3. 从相关的活跃范围取得候选；显式旧事查询可直接进入休眠范围。
4. 优先保证问题相关性，再在相关候选中结合召回优先级、明确重要度、时间适用性和内容多样性选材。
5. 证据不足时按同一任务逐步扩大合法检索范围；需要外部知识时进入当前知识路由。不能仅因优先级低而把可找到的必要证据判为不存在。
6. 只将实际所需材料进入工作上下文与Manifest，完成使用后提交一次回忆结算。

高优先级不能让无关旧事挤掉用户本轮明确问题。深入检索也不等于每轮无差别扫描全库。相关性阈值、深搜触发、候选预算和分层阈值应通过开发集及未参与调参的新场景检验，避免所有旧资料永久沉底。

当前语境优先级只对本轮有效，不自动写成长期重要度。低优先级事件经明确追问仍应可找回；冷层无结果、未搜索冷层、权限不允许和来源已撤回必须有不同结果状态。

## 8. 与现有运行时的接入要求

优先扩展现有SQLite领域结构、受管任务、operation_id、Manifest和来源校验，不建立并行记忆数据库或第二个后台调度器。以下为逻辑字段，具体表名与迁移版本在实施时确定。

| 记录 | 最小内容 |
| --- | --- |
| 单元关联 | 单元身份、来源域、人格/可见范围、证据版本、来源lineage、原始与登记时间 |
| 优先级状态 | 锚点分值、锚点时间、政策版本、活跃层次、最后有效回忆、状态修订号 |
| 回忆事件 | 根任务/交互、唯一事件ID、单元与证据版本、事件类别、消费状态、有效时间、前后分值 |
| 检索解释 | 本轮相关性、优先级快照、候选范围、深搜原因、采用与排除理由 |

同一逻辑事件只提交一次，事件记录和优先级更新须原子完成。并发使用修订检查；异步返回按稳定顺序归并或重放，不能让较晚到达的旧事件覆盖更新状态。事件重复、迟到及乱序均有明确处理。

缓存键或使用复核涵盖政策与优先级状态变化，避免强化后继续使用失效候选排序。资料的权限、版本与撤回仍在采用和投递前重新检查。旧请求可以保留当时的优先级解释，不能绕过当前来源限制。

备份恢复同时保留政策、状态与幂等身份，继续应用当前权限、删除与失效记录。时间衰减只从合法锚点计算一次，不因多次恢复重复扣减或增加。导出不包含私人密钥；跨人格导入不得继承其他人格的私人回忆热度。

首次迁移不能把所有历史回合补造为已使用事件，也不能因年代久远立即让全部旧资料不可检索。采用明确的历史初始化政策并观察分层分布；未知使用历史保持未知。优先级索引可以重建，原始事实及历史验收记录不回写。

新计算使用本地确定性代码。仅为计算衰减和强化不增加LLM调用。语境理解、目标生成、知识翻译和今后反思分别使用已有受管调用与费用记录。

## 9. 与情绪、主动行为、自我认识及反思的接口

| 后续能力 | 可读取或提出的内容 | 不可自动改变的内容 |
| --- | --- | --- |
| 情绪与心境 | 来源事件、当前关注、短期选择偏置，必要时提出重要性建议 | 事实真伪、来源可信度、作者核心、权限及既有用户边界 |
| 主动行为 | 从相关经历和未完成约定中提出话题或行动候选 | 静默时段、发送频率、授权范围；高优先级本身不触发外部消息 |
| 自我认识 | 对自身经历、行为倾向、能力与不确定性的版本化概括 | 将模型自述伪装成真实经历，擅自变更身份正典 |
| 独立反思 | 有来源的模式、反例、待验证解释或NO_CHANGE，关联原始证据 | 用旧反思反复证明自己，直接把重复回忆变成新事实 |
| 受控人格演化 | 将长期、独立证据支持的变化形成可审阅提案 | 仅凭热度改写核心人格、显式关系和治理权限 |

先交付可观察的选择机制，再验证新增认知活动对交流的作用。情绪、独立反思和Director仍在G-AUTO之后按既有路线推进；当前只保留兼容接口，不提前执行这些模型任务。

## 12. 验证与验收原则

纯函数和时间边界先用可控时钟验证，长期自然时间观察另行记录；模拟经过30天不能写成实际运行30天。先固定开发案例与预期，再用未参与调参的新问法检验。既有成功与未知收费位置不重放，新验证使用新位置。

| 维度 | 必测场景与判据 |
| --- | --- |
| 原始数据保真 | 降权、休眠、强化前后，原始文本及来源绑定不因遗忘变化；明确删除另按政策执行 |
| 自然时间 | 同时刻重算一致，经过半衰期按政策变化，停机时间计入，回拨/前跳和恢复有记录 |
| 强化正确性 | 用户提起、独立模型回忆、新轮缓存复用能强化；同根多阶段、重试、轮询和多片只结算一次 |
| 反自激 | 候选扫描、预热、管理查询、摘要维护不强化；无新合法触发不能递归自建回忆任务 |
| 选择质量 | 高频无关旧事不压倒相关新资料；低优先级旧事在明确实体/时间追问中可找回 |
| 有效性 | 高优先级错误版本仍被更正；过期、撤回、隔离和跨角色数据不越过原有约束 |
| 分层收益 | 同等问题成功与质量下，实际候选规模和无关注入下降；仅改变最终排序不算分层完成 |
| 恢复与迁移 | 领取前、回执后、结算前和未知状态中断；重启/导入/恢复不重复强化、不复活已撤回内容 |
| 认知接口 | 情绪偏置不改事实，反思不创造独立来源，主动发送仍由原政策控制 |
| 陪伴体验 | 少问已经明确的重要信息，适时接续旧事，不无故反复提及热点记忆，不把知识回答都变成长篇讲解 |

报告分别列出材料取得、实际注入/复用、关键事实支持和用户体验。回忆事件数、命中率、测试数量或注入比例不能单独证明体验改善。优先级强化只证明注意状态发生变化，不能用于宣称模型已经拥有意识或人类式记忆。

首版参数、案例规模及调用位置在召回配套0冻结。当前指导不虚构半衰期、准确率、费用或完成工期，不以新增固定等待时限保护指标。观察延迟、CPU、内存、磁盘、后台写入和实际调用成本，在同等成功与质量下优化。
