# M6.0 角色系统实施计划

2026-10-27；依据用户明确批准的实施计划。基线 `5eb82d1`，原0.5.0/结构6；目标0.6.0.dev1/结构7，桥接0.3.0。

## 范围和决定

落实[总施工任务](施工总计划/09-M6施工任务单与决策登记.md) T00–T02：结构化人设、版本、简易设定书、动态设定读取、角色请求快照、原生角色包、结构化工作台。用户已选择表单与设定书，日常不编辑JSON。

不做输入合并、ReplyBatch、向量、Session/Thread、联网、自主情绪或人格演化。M4 O01–O03和M5 P09继续待验；整个M6不能因M6.0完成标为完成。

## 字段和存储

- persona_id保持；core继续管理姓名、介绍、性格、价值边界、初始背景；expression管理基础文风；关系和临时状态不复制。
- CharacterSpec v1保存identity/age/appearance/biography/interests/social/world/lorebook/examples；全部扩展字段可未设定，不从旧背景猜测提取。
- 年龄支持unspecified/fixed/calendar，calendar按上海日期计算周岁，非闰年2月29日按2月末；生日月日不直接推年龄。固定年龄不同时设置完整出生日期。
- 新表character_versions/heads/operations，版本间复合归属外键；每次存完整快照，条目有稳定ID。保存expected_version+operation_id，版本冲突拒绝且草稿保留；相同内容无新版本，显式恢复总建新版本。
- 扩展128KiB UTF-8；设定书≤100条/正文≤2000字符；样例≤50条/示例≤500字符。校验字段、类型、有限正数、日期、依赖、可见性和容量；不截断保存。

## 动态上下文

精确字段优先；当前消息大小写归一后按字面关键词激活，不执行正则/脚本。优先级降序、ID升序，最多4条设定，依赖最多两层；循环/缺依赖/公开依赖私密条目拒绝保存。依赖组装不下则整组跳过。creator_only永不注入。

最多2条人工表达样例。角色总预算3000字符（含标题）：锚点800、事实/设定1600、样例600；总预算不足先裁可选角色内容，保留必要事实和完整用户输入，无法容纳时明确失败。没有额外理解/审查调用。

新turn在受理事务中固定character_snapshot；显式重试固定当前版本，旧context_uses不覆盖；旧turn空快照保持未使用角色资料。state仍在调用开始检查到期。使用记录只记录版本、路径、条目/样例ID、预算和缺口，普通日志不存资料正文。

## 接口和界面

管理员/v1/manage新增character.current/update/history/show/compare/restore/fact/preview/export/import。显式persona_id；变更时当前选择不匹配报character_selection_conflict。桥接令牌无管理权限。fact区分unknown path/unset/value；preview零调用、零事件。

工作台角色资料页：基本资料、设定书、表达样例、版本与预览。编辑角色资料打开表单与条目编辑器；扩展独立保存，姓名/核心/表达显示只读并链接既有编辑功能。保存失败保留草稿；保存中锁定输入；页面/人格切换和关闭前处理未保存草稿；过期读取不覆盖新选择。

pcar_character_v1原生包只有PersonaSpec和当前角色扩展，无聊天/关系/状态/记忆/凭据。导入创建新身份，不自动切换当前身份，不支持外部角色卡/PNG/CHARX/宏/脚本。全量人格导出格式4包含角色版本和指针，PersonaSpec保持v1。

## 施工与验收

1. 数据合同与迁移/版本服务。
2. 创建人格与全量导出兼容。
3. 请求快照、确定性激活、预算及使用记录。
4. 管理API、表单、条目编辑、版本及包操作。
5. 专项/受影响回归、一次必要全量，正式副本迁移/恢复演练。
6. 按既有授权执行真实模型与工作台验收；扫码/掉线/连续失败按既有停止约定。

旧库每个人格建立migration空扩展，不改旧原列/旧快照；升级备份、持锁、事务，旧程序不能读结构7。回退需恢复结构6备份并处理升级后新增数据。

硬门：旧身份/历史不变、版本和并发正确、来源域分离、隐私过滤、快照正确、无额外模型调用、表单可用、迁移可恢复。测试与实际结果见[M6.0说明](M6.0.md)和[操作手册](acceptance/M6.0-角色系统验收手册.md)，不以本计划存在推断已验收。
