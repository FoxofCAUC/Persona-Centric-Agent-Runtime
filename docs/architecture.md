# 架构与实施基线

## 已确认的产品方向

1. 人格是持续存在的主体，模型是可替换的能力提供者。
2. 首先建立与用户长期相处的 AI 朋友；群聊是接触外界的渠道。
3. 对话、记忆整理、检索和上下文管理可由不同模型承担。
4. 个人经历、关系和世界知识持久化，不依赖单个窗口上下文。
5. 新知识可经搜索补充，带来源和时间；人格演化应可追溯、可回退。
6. 项目生成的数据优先存储于 D 盘同名目录。

## 建议架构（尚未实现）

消息渠道 → 适配与会话管理 → 人格运行时 → 模型调度 → 回复

人格运行时负责核心人格、当前状态、记忆召回、世界知识、上下文组装；后台任务负责事件整理与候选更新。
QQ / AstrBot 接入层与核心逻辑分离。保留原始事件，摘要和索引可重建。私聊与群聊明确记忆可见范围。

## 实施顺序

- M0：项目骨架、独立开发环境、D 盘路径规则（本次初始化）。
- M1：定义人格、事件、会话、记忆的数据结构；建立本地持久化与重启恢复。
- M2：接入一个模型，完成私聊输入、记忆召回、回复和事件写入闭环。
- M3：接入现有机器人渠道，处理群聊身份、权限和记忆可见范围。
- M4：搜索补充知识、后台整理、人格更新版本与回退。

以上是初步实施顺序，不代表数据库方案、模型提供商、向量检索或 Agent 框架已经冻结。
