# M6.3 片段可靠投递实施计划

[阶段说明](M6.3.md) · [验收手册](acceptance/M6.3-片段可靠投递验收手册.md) · [路线图](施工总计划/02-总施工路线图.md) · [架构](architecture.md)

## 目标与边界

在 M6.2 ReplyBatch/语义段之上，持久化实际平台传输片段、领取权、发送尝试、平台消息 ID 与失败处置。M6.3 不调用模型、不重算回复、不改变 M6.2 的 `legacy_full` 默认，也不实现 Session/Thread、向量、联网、自动情绪或演化。

基线为 M6.2 `0.6.2.dev1` / 结构 9 / 导出 6 / AstrBot 0.4.0。目标为运行时 `0.6.3.dev1`、结构 10、导出 7、AstrBot 0.5.0。M6.3 数据只由迁移建立空表；历史 turn 不伪造逐片状态、平台 ID 或发送尝试。

## 实现合同

- 回复成功事务同时写完整回复事件、ReplyBatch、语义段、QQ 投递 stream 和传输片段。片段默认按 450 字切分，片段正文及 SHA-256 指纹都持久化。
- stream 以人格、用户、渠道和固定原始目标身份隔离；同一目标的不同回复共享有序 stream。
- 事务内按预期修订号领取一个片段，生成 claim token 并增加 attempt。发送结果必须携带该 token 和片段修订号；迟到或重复的旧结果不能覆盖新状态。
- `pending -> sending -> sent|failed|uncertain`。重启将 `sending` 转 `uncertain`；`uncertain` 与 `failed` 阻塞余段及同目标后续自动投递，不自动重发。
- 管理员可将单片核对为已处理、跳过当前批次剩余片段、暂停 stream、释放管理员暂停，或显式重发单片。显式重发创建下一次 attempt，并明确提示可能重复。所有动作携带 `operation_id` 和预期修订号并幂等记录。
- 旧 turn 级 `/v1` 投递仅用于没有新账本的历史记录；发现新账本时明确拒绝旧领取路径。新桥接通过 `reply_delivery_parts_v1` 能力标记走 v2；后台轮询器直接使用平台 API 并记录返回的 message ID。
- 桥接只可读写配置中当前 QQ Bot/本人目标的数据。管理员处置只对所选人格开放。全量导出包含账本和操作审计，移除活动 claim token，不包含模型凭据。

## 文件与施工结果

1. `schema_m63.py` 将迁移事务从结构 9 升至 10，建立 stream、part、操作审计表及作用域约束。
2. `delivery.py` 提供事务领取、CAS 结果、重启恢复、显式核对/跳过/重试/释放和导出视图。
3. `chat.py` 在生成完成事务中创建 QQ 投递账本；旧 `/v1` delivery 对有账本的 turn 拒绝领取。
4. `server.py` 提供 `/v2/replies/{reply_batch_id}/parts`、claim/result/resolve 与 stream 查询，健康接口声明能力。
5. AstrBot 插件升级为 0.5.0，只由单一后台投递器逐片发送并登记平台消息 ID；旧客户端不得以全文路径拿取新账本。
6. 桌面新增“回复投递”页面，可按人格核对片段和处置阻塞。
7. 导出格式升为 7，保留旧导出包含的资料并新增投递账本。
