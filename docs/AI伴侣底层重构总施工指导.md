## 底层职责

主链：正常受理 → 共同材料 → 表达输入编译 → 主生成 → 内容/格式处理 → 展示及投递。

| 职责 | 实现要求 |
| --- | --- |
| 受理与权威 | 复用入口政策与快照，冻结人物、关系、来源、模型与运行版本；不另建平行聊天权威 |
| 材料收集 | 复用现有可见人物、关系、状态、前文、记忆、本轮成员及引用读取，保留说话者和来源生命周期 |
| 表达编译 | 独立组织必要材料，不把工程诊断、未知清单和策略说明变成角色台词任务；纯装配器继续复用 |
| 人物表达 | 体现具体关注、立场与反应，不强制客服步骤、固定动作或回应顺序；作者原文不自动改写 |
| 生成 | 一个客户端职责管理流式、终态、取消、usage与物理账本；不复制每协议/每恢复批次的重试层 |
| 展示 | 原答、处理后正文、最终气泡可区分；代码、数字、引用及完整任务不被后处理损坏 |
| 连续陪伴 | 自然取用相关关系与记忆，更正有效，想象不升级成权威事实；本轮不重建自动记忆发布 |

优先复用内部结构；表达编译返回模型消息及实际材料摘要，生成返回正文/终态/已知用量/供应商标识，不为每层新增表。运行方案版本写入既有政策与受理快照，旧请求保持旧语义。可选公共参数仅在现有政策管理入口增加，不另建第二套聊天API。

新生成合同显式支持省略上限与无客户端时限，旧整型参数仍可读。上游不支持省略时报告拒绝，不能暗补额度、超时或更换供应商。运行中取消必须终结本地回合、释放占用、阻止迟到投递；上游最终用量未知保留未知。

## 阶段3：有效机制与底座选择

按成本由低到高：同一原答离线开关后处理/分泡 → 单项提示/人物材料组织 → 同初始材料历史/记忆取用 → 格式/推理分别比较 → 确有瓶颈才提一个模型候选 → 仅有重复重要失败才考虑额外辅助或改写。

每项说明具体改善、生效入口、接入/维护代价、调用与等待、许可和PCAR内复验，结论用直接复用/适配复用/仅借鉴/不采用。区分代码猜测、系统偏好、部件作用、移植后收益；同请求的随机输出差异不算组件收益。

部件足够时保留独立PCAR。若大量重造现成功能，提交独立PCAR与AstrBot宿主两种具体方案，列唯一权威、资产、迁移、许可、维护和回退，用户选定后实施；未选择不暗改底座。没有用户愿使用的方向就暂停扩建，不以沉没成本推进整合。

## 阶段4：胜出链路正式工程整合

本阶段按已确认范围拆为4-A与4-B：4-A先用人工资料、模拟生成把现有伴侣候选接入正常工作台，完成启用、恢复、取消、版本保存及请求核查；4-B再重新整理表达修改，交用户审阅，批准后用现有版本管理保存正式人物版本。旧私人改稿和副本已按约删除，不恢复正文，不把4-A工程通过写成真实体验通过。4-A验收入口见[正常工作台接入手册](acceptance/AI伴侣重构-正常工作台接入验收手册.md)，实际进度仍只在STATUS维护。

一个正常编排入口分开材料、编译、生成、内容处理、投递；从有效链路去掉固定证据目录、人工标注和模拟附件依赖，旧工具保留历史。默认直回，只留已证实有效辅助。人物原意与作者版本不变，事实/样例/互动记录分工明确。

记忆相关时自然带回，不强制“我记得”；更正不重复旧值，助手猜测/自然补白不成为用户事实。纯文本若胜出可转现有ReplyBatch，不为格式重写投递库。后处理有开关和定位，不以无差别删词掩盖人机感。

统一流式、终态、取消和重试；辅助成功不因主失败重放。工作台显示实际方案和易懂状态，细节留诊断；健康版本从统一源读取。先收敛在用接线，再分批去无用重复代码，不全仓重造。

旧快照照旧，新默认经政策正常受理。需要迁移才增加版本，先隔离验证备份/升级/导出/恢复/旧记录。退出依据：无实验外壳也能跑、可维护、输入输出可核对，用户认可的效果仍存在。

## 阶段6：后台自动百轮记忆与稳定性验收

2026-11-07用户明确取消3—7天、至少3个交流日的人工长时间试用，改为新的后台插件全自动执行。使用完全人工编写的虚拟人格和用户消息，通过PCAR正常工作台API调用已配置DeepSeek官方模型，真实计费；不使用私人角色，不依赖Computer Use或持续占用桌面。

## 验收与停止

主要判断：愿意持续相处、人物感、不客服/不人机、跨轮自然、更正/拒绝有效、任务与展示完整、等待可接受、实际权限/投递正确。自然补白/普通礼貌拟稿允许，不用短句率、问号、禁词、气泡数或逐句来源代替阅读。

质量差但合法不重生；协议/传输最多原生3重试，耗尽停止批次；用户取消/来源/权限/隔离/账目异常停止相关执行。未知不造0，成功不重放。每次运行事前列目的与逻辑位置，不新增总额度，也不刷到通过。一个机制无益就删/归档/换假设，扩大实验必须有新依据；连接恢复单列稳定性。

旧R4-A/B/C等以人机味改善为目的的历史整改项已按v8最终采用决定冻结，不再要求补旧证据或修旧实现稿。后续阶段按自身范围检查实际前文、更正、任务与投递功能，保持真实执行状态，不沿旧表达失败自动重启整改。旧路由/合同按已采用或退出的事实记录。M4 O01—O03可用恰好发生的真实观察补证，否则交M8.A/D；M5 P09按新模型实际范围，不泛化关闭；M6.1不重放旧收费组，新恢复交M8.A。
