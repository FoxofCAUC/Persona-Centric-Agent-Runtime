## 执行权威与合同

原organization_tasks继续维护业务状态，OrganizationEngine仍为唯一执行入口。managed_organization是它的领取、授权、预算与恢复适配层，不是第二个调度服务。手动、每日、空闲增量、封存及人工模型探测统一注册和领取；不开放模型创建任务或任意认知任务API。

结构22新增organization_contracts、organization_submissions、organization_policies、organization_reservations及单行organization_execution。操作身份校验完整提交内容；工作身份包含角色、用户、渠道/账号、有效事件版本、相关记忆版本、整理目的及明确重建身份。普通触发器不能制造重建批次。相同工作复用原任务，重叠来源串行后重新预览、裁剪已覆盖部分；旧业务记录不改写。

任务政策绑定角色、触发类型、渠道/账号及供应商指纹，以版本化更新和预期当前角色保护写入。派发前和结果发布前均复核政策、角色状态、来源与模型。私人资料要求当前角色独立的organization授权；main授权、祖先角色授权及私人验收副本策略均不能替代它。角色复制和导入不携带本机可执行授权。

一次事务持久化领取代次、60秒租约、Manifest及该物理调用的额度预留，再派发。每15秒续约；活进程的租约过期不能证明远端停止，不让另一worker重叠派发。迟到回执可以保存，失去领取代次的持有者不能发布结果。

## 额度、恢复与调度

QuotaService和原物理调用账本继续作为唯一额度权威。整理预留不伪造聊天回合，主聊天与整理共同计入项目额度；整理另受后台小时/日额度约束。每个重试单独预留和记账，首次加最多3次确定安全的重试，退避1/2/4秒，跨重启累计。确定未发送或明确429允许安全重试；超时、丢失响应等不确定效果阻塞。格式/语义不合格保留原回执，不重新生成。

| 恢复边界 | 产品处理 |
| --- | --- |
| 受理但确定未派发 | 复核授权、来源、额度后续接 |
| 完整回执已保存 | 校验原回执，幂等提交，不再调用 |
| 结果已经提交 | 返回原任务与结果 |
| 派发后结果不明 | blocked_unknown，保留用量未知，禁止重发 |
| 旧任务缺少必要证据 | 显式待核查，旧失败和中断不自动排队 |

前台收集、排队、生成时不开始新后台调用；已经派发的后台请求不因前台到来被强杀，也不持有阻止前台受理的锁。后台并发1、等待队列最多10。手动任务优先，自动任务等待10分钟后同级FIFO，仍让位前台。额度等待按时间窗口自然恢复；控制时钟测试不代表真实跨日观察。

取消排队任务不调用模型；运行中取消保留调用账目、不发布结果、不自动重试。政策暂停停止新派发及后续重试；恢复原任务仍须重新核对版本。未知调用的执行槽释放不代表收费未知已解决。

回退先暂停后台政策及自动触发，主聊天保留；不回放未知模型调用或投递。主机仍随工作台受管启停，关闭工作台后服务停止。
