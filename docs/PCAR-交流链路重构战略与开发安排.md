**一　已经确认的战略调整**

产品目标仍是单人私聊陪伴：角色能理解正在发生的交流，形成符合人物的关注与取舍，并自然地参与其中。情境、人格决策和表达接口确定重构；诊断用于选择实现方式、控制复杂度与安排先后，不再用来反复讨论是否需要重构。

| 决策 | 本轮已确认内容 | 对开发的约束 |
|---|---|---|
| 产品范围 | 单人陪伴，先解决交流链路 | 不并行推进无人值守工程；群聊不进入本轮 |
| 重构力度 | 情境、决策、表达接口一起纳入重构范围 | 实现分批推进，不等于一次重写全部基础设施 |
| 表达自由 | 活泼性优先于逐句可溯源 | 生活细节、心情和自然联想不因缺少出处自动判错 |
| 新验收 | 独立协议，旧成绩保持 | 新路线不机械继承旧 R4 的“至少减两条、至少四组同后端”门槛；新数值在实测前确认 |
| 评价分工 | 机器全量分析，用户审核少量匿名关键对照 | 不增加必须找到第二位独立评审人的关口；不称为多人盲评 |
| 模型路线 | 先用当前网关，确有瓶颈再提候选模型 | 不先换供应商、底模或训练模型 |
| 调用结构 | 普通轮次一次主回复；复杂情况最多一次联合辅助；第一版无付费改写器 | 云端选例、情境理解与决策不能各自再开一轮，却仍宣称只有一次辅助 |
| 私人验证 | 私人角色副本纳入验证体系，验收结束后清除验证副本数据 | 正式原件保持；副本及其派生数据不提交、不进入公共证据包 |
| 即时通讯表达 | 额外评价“不客服式”“不人机式”，越接近真实人类在相同语境下的即时通讯语言风格，评分越高 | 两项独立报告，并保留整体即时通讯自然度判断；不以禁词、短句率或刻意口癖代替 |

**三　重构后的职责划分**

建议按下列逻辑接口落地，字段名称可在合同阶段调整。逻辑层不等于独立模型或服务。保留现有 Python、存储、渠道和受理权威，不先迁移基础架构。

`受理快照 → 共同可见材料 → 情境解释 → 人格取舍与交流规格 → 主回复 → 校验及实际投递`

**共同可见材料。** 从已有档案和来源规则读取本轮全部输入、合法引用、相关前文、有效状态及必要记忆，形成不可变的来源快照。来源版本、范围与最新更正统一，各消费者可以按职责选用其中材料，但必须能说明自己实际看见了什么。共同视野不等于复制全部历史，也不等于扩大跨入口或跨人格权限。

**情境解释。** 区分明确请求、当前意愿、局部/整体进度、未闭合问题、必要缺项、候选解释与未知。原文和推断分开，确定性材料收集不冒充通用语义理解。前期用人工正确情境验证字段价值；自动版本再与它比较。自然想象不自动写成用户档案或共同经历，也不因未成为事实而禁止在回复中出现。

**人格投影。** 身份事实、条件性取舍、表达材料和真实互动经历分工管理。新投影能表示适用条件、优先关系、例外及反例，继承现有作者批准流程。倾向可以指导同一动作里的不同关注点；不强迫计算题、代码结果产生人物差异。报告的 8–12 条只是试验建议，不设为人格最低配置数量。隐藏作者原文仍不能进入云端；可见行为投影需单独审核，不能通过解释原因泄漏隐藏背景。

**交流规格。** 至少区分三类内容：明确请求带来的必做内容、符合人物的可选关注或立场、不得违背的明确条件。可以包含 focus、stance、obligations、optional_moves、missing_slots、disposition_refs 等；不是每轮必须填满，也不规定正文按字段顺序展开。日常分享允许没有额外任务义务。不能要求每条补白附证据，或强迫每次先确认、再共情、再建议。

**表达实现。** 接收必要事实、当前输入、交流规格及少量适用样例，生成一次正常回复。长篇技术回答按任务完成度评价；闲聊允许短接话、异议、轻微玩笑和联想。不让内部计划、schema、错误码或审计说明进入角色正文。若最终采用直接生成，也保留统一输入与结果合同，不保留没有收益的独立规划调用。

**投递与观测。** 沿用 ReplyBatch 和发送记录，分别保存计划、生成正文、展示文本及实际已发送片段的关联。语义义务最终看用户实际收到的内容。原有可选诊断继续限大小、不包含正文；详细人工实验正文放在独立实验包，不能把全部规划内容塞入 Manifest。

三个接口的重构是确定范围；增加长期情绪、Director、人格自主演化、每轮反思或后台主动行为均不属于本轮。

| 角色召回与选择 | 接入情境，后续按证据改元数据 | 先保留候选算法与预算作对照，不同时更换 embedding、候选数量和策略 |
| `prompt_assembly.py` | 保持纯装配职责 | 只拼接、记录最终实际块；不承担判断、重写或反思 |
| 重试、调用账本、ReplyBatch、渠道 | 保留 | 新辅助调用接入同一计量、取消和终态规则，不叠加第二层重试 |
| 工作台上下文页 | 在集成阶段扩展 | 显示请求模式/实际模式、情境/规格版本、回退原因和输入指纹；历史不由当前预览替代 |

新派生对象至少绑定请求执行修订、角色与投影版本、来源指纹、策略及表达配置。来源撤回、引用失效或更新输入出现后，旧情境与规格一起失效，不能只重建主提示而沿用旧计划。第一次实现先以纯数据合同和隔离适配完成；是否新增持久化结构，在确有恢复与审计需要时设计迁移，不预先造一套数据库。

**六　下一最小施工包 CR0 的具体范围**

CR0 建议命名为“交流链路合同与共享情境骨架”，零真实模型、零 QQ、不启动正式服务、不迁移正式库。新规划需要用户另行要求实施后才执行。

1. 核对当前提交和未提交改动，记录新报告与已确认决议。将当前入口单独列明，避免在 AGENTS、STATUS、HANDOFF 和指导书中继续堆叠互相覆盖的“下一步”。旧记录归档引用，不删除、不改分。
2. 复用既有七批问题卡和来源索引，按情境遗漏、意图错位、取舍不足、表达未落实、样例误用、历史影响、评审分歧、投递改变八类整理诊断地图。旧样本只供理解失效模式，不改造为新独立验收。
3. 为一条新人工请求输出“受理快照—普通前文—选择器—观察器—决策—主回复—投递”的材料清单，分别标正式基线、旧隔离 Assist、R4 表达实验与新接口模拟。配置名称存在不能当作实际生效。
4. 建立共同可见材料、DialogueFrame、CommunicativeSpec 的最小不可变合同及人工适配器。显式区分事实、解释、未知、必做内容和可选表达；字段携带来源是为了状态治理，不要求最终句子逐句可溯源。
5. 编写六个独立人工用例：局部完成；明确停止建议；相同措辞不同交流意图；前文已回答缺项；后续更正覆盖旧引用；完整技术任务。另用小变体检查来源撤回、同动作不同人物取舍、以及客观任务不强求人物分化。
6. 验证字段被消费、被删除/更正时对应输入改变；验证失效、范围、空规格、取消与旧路径回退。旧路径用 R0 冻结场景及受影响渲染等价检查，新增分支只允许有解释的变化。
7. 交付 CR1 诊断方案草稿，包括条件、材料、人工正确输入的审核方法、调用工作量、评价和停止条件，列出实测前需要用户确认的数值。将“不客服式”“不人机式”和整体即时通讯自然度纳入阅读规则；同时定义后续私人副本验证的隔离、审阅、不提交和清理流程，以人工替身验证流程，不在 CR0读取私人正文。

CR0 的完成是可审计接口和可用隔离入口，不是几份未接线的 DTO，也不是自然度通过。它不实现通用语义算法、不换主提示、不增加付费评分、不启动训练，也不把模拟“正确回复”当效果证据。

**七　诊断实验如何帮助选择实现**

首先冻结当前有效条件，明确“正式 v2/Shadow 基线”与“旧 Assist 机制对照”是不同条件。不能拿没有胶囊的基线推断旧胶囊的优劣，也不能将实验中的词法选例描述成日常云选择入口。

| 条件 | 保持与改变 | 回答的问题 |
|---|---|---|
| B0 旧有效链路 | 复现当前版本和实际模式，保存各层所见 | 当前问题在新材料上怎样出现 |
| B1 人工正确情境 | 参与理解/选择/表达的消费者获得一致、正确的情境；其他变量尽量固定 | 信息缺失或状态表示影响多大 |
| B2 人工正确规格 | 在 B1 上加入具体且经审核的取舍与交流内容 | 计划到表达的接口是否有增益 |
| B3 人工适用样例 | 在固定情境/规格下只改变表达材料 | 风格材料质量是否为主要限制 |
| B6 直接生成 | 同等人物、事实、历史和样例，取消独立计划生成或注入 | 简单路径能否达到相当效果 |
| B5 自动链路 | 用自动情境/规格替代人工内容，其他条件固定 | 自动理解与决策损失在哪里 |
| B4 候选表达器 | 只有已证实表达瓶颈后另提模型 | 是否值得更换表达模型 |

执行前必须检查 B1 与 B6 是否实际上相同。在 Shadow 基线无旧规划输入的情况下，它们可能就是同一请求；相同请求合并为同一条件，不为补齐表格重复收费，也不当作两项独立证据。B2 与旧动作胶囊的比较需另外固定旧 Assist 条件。对统一事实的表达比较固定已选材料；对完整系统比较允许独立选择，但选择差异和辅助费用要单列，不能混成纯表达效果。

建议先建立 24 个诊断场景，两个人工角色；每类既有失败机会也有成功控制，人物身份和知识尽量相同，以取舍和表达材料区分。六个合同用例不能直接充当最终独立持出集。首轮可以从中事前选定 12 个场景、两人物、B0/B1/B2、两次独立采样，即 144 个主回复位置；若 B6 不等价，再预先冻结相应复杂度对照。该规模是工作量建议，不是本轮执行授权、硬费用上限或统计充分性保证，正式数值在 CR1 开始前确认。

重复采样必须事前拥有独立位置、种子及顺序，并保留所有结果；不能把已成功但不好看的输出重新生成，称为“复测”。按场景、时间块交错执行，保持模型路由和公开参数可核查。辅助、主回复、重试、协议失败分别入账，无用量回执记未知。

人工正确情境与规格用于判断是否还需要更好的表达条件；人工正确输入的收益也不保证自动提取容易实现。按 CR1 事前确认的停止与转向规则，充分对照仍无实用收益时，应归档该实现假设，改用另一实现，不继续增加同类软提示。报告的“连续两轮”作为待确认建议，不在本次直接设成硬门。失败结论不是战略重构取消，也不是追加下一版提示的自动触发器。

**八　新验收协议的口径**

工程有效、组件改善、整套体验、正式发布分别结算。旧 R4 原成绩与协议保持；新协议只用于新路线，标明规则版本及适用批次，不将旧失败追改为通过。

| 维度 | 观察单位和判断方式 | 不采用的替代指标 |
|---|---|---|
| 情境正确 | 具体对象、进度、更正、已知缺项、有效引用是否一致；未知保持未知 | 只有字段非空或来源数量多 |
| 交流内容完成 | 该回复的必要内容是否全部完成，支持满足/部分/未满足/无法判断 | 动作名称相同即兑现，或某一句满足即整条通过 |
| 人物取舍 | 在预标注需要取舍的场景有合理差别；同人物随意愿变化合理调整 | 所有题必须不同，靠名字和口癖区分 |
| 自然度与活泼性 | 是否在参与眼前交流、回应合适、有观点或反应；匿名胜/平/负及文本依据 | 短句率、问号数、禁词、礼貌或分点本身 |
| 不客服式 | 是否以交流参与者的身份接话；无必要时不把分享变成咨询、不套用安抚—建议—追问流程；贴合意图、关系和人物的回应得分更高 | 遇到礼貌、共情、建议或提问就扣分；故意粗鲁或拒绝帮忙来显得像人 |
| 不人机式 | 是否避免机械改写输入、策略报幕、固定句式循环和生硬样例套用；能自然承接省略、玩笑、更正与转折的回应得分更高 | 禁词命中、句长、标点或字词重合直接决定分数 |
| 真实即时通讯语言风格 | 同一语境和人物下，越接近真人聊天的措辞、长短变化、承接、语气与分条组织，整体评分越高；兼看连续多轮是否重复套路 | 强塞网络用语、表情、错别字、碎片短句或强烈人设标记；只统计发送速度与气泡数量 |
| 补白与边界 | 允许自然想象；检查是否违背明确更正/拒绝、任务、关系或实际行动 | 一切无来源细节均算幻觉 |
| 样例使用 | 自然借鉴、贴切复用、生硬套用、与当前条件冲突分别判断 | 只看字词重合，或选得更多即改善 |
| 任务 | 候选的明确任务控制全部通过，相对对照不得新增任务/明确边界错误 | 用旧对照的错误否决已正确完成的候选 |
| 投递与恢复 | 实际发送语义、取消、终态、成功不重放、来源撤回 | 只看模型初稿或本地模拟成功 |
| 延迟与成本 | 从最后有效输入到首条实际有效回复，分快慢路径报告 P50/P95及调用构成 | 用240秒恢复时限当体验目标，或先发无意义占位消息 |

机器对全部结果逐项分析并给片段依据，用户审核少量事前约定的匿名关键对照；抽核同时包含有利、不利、平局、争议和任务边界案例，不能只展示最好看的例子。用户审核用于校准偏好和裁定争议，不要求另找评审者，不将模型评分包装为独立人类盲评。

新增两项是明确的验收指标，不能仅放在结论中的形容词。评分必须同时给出具体语境、回复片段和判断理由：低分锚点为明显客服流程或机械生成感；中间状态为内容合适但仍有模板痕迹；高分锚点为像一个有具体反应的人在自然接话。两项分别记录，整体即时通讯风格另给综合判断，不把重叠缺陷简单重复扣分。数字量表、权重和通过阈值在 CR1 实测前随新协议确认，本次不擅自固定。

这些判断以当前交流目的为准。用户认真请求解释时，完整、清楚的长回答也可以很像真人；克制或正式的人物不必变成热闹口吻。自然补白和联想继续允许，不因为没有出处扣分；任务错误或违背明确拒绝则另外记录，不用“很像真人”抵消。旧批次不追改原评分，新路线开发、持出、多轮和私人副本验证统一采用新增指标。

私人副本的片段依据与匿名对照只在本地临时验证区域供必要审阅；隐藏姓名不等于可以公开。人工实验包可按原规则封存，私人验证包采用验收后清理规则，不将私人正文嵌入人工案例、训练材料、普通日志、公共报告或Git历史。

归因分两层报告：固定且可辨认后端条件下的组件差异，以及当前实际服务路由下的整体平均表现。后端缺失或变化不再自动使所有产品观察无效，但必须记录，不据此声称固定权重的因果效果；不同组系统性落到不同后端时仍存在混杂。采样以场景或会话为簇，两个角色和重复生成不能全算成互相独立样本。

报告中的“义务90%作为继续信号、发布95%且下界90%、P95不增20%”都是建议值，尚未采用。CR1 实测前需确认主要比较、最小有意义改善、任务和关键边界、允许的延迟退化、用户审阅数量；持出样本量依据问题频率与所需区间确定，不先承诺很小样本就能发布。

多轮验收先做固定历史回放，再做闭环使用；前者适合比较组件，后者用于实际体验。先覆盖6–12轮的更正、状态和意愿迁移，再扩到30–50轮及隔天接续，是否需要百轮测试依发现的漂移决定。用户模拟器、被测角色和评分不得由同一模型自演后直接宣布成功。

**十　快慢路径、回退和实施约束**

新快路径使用本地可确认的材料与状态、已有批准投影、适用样例及一次主回复。新内容不能被旧摘要覆盖；不能可靠判断的状态保持未知或进入复杂路径。不能仅因某关键词命中就宣称已具备通用语义路由能力，需用开发材料检查路由错分与遗漏。

复杂路径最多一个联合辅助位置，可在同一输出中提供情境解释、人格取舍及必要选例，分别校验。现有观察/云选择若仍被调用，就必须合并或替换，不能在外层再加规划形成三个辅助。第一版不增加生成后的收费修复，不以自然度差触发重生成。旧路径的原有调用行为保持可复现，新路径的结构变化另作系统级成本对照。

回退只适用于合同明确列出的情形，例如辅助合法返回“不确定”或空规格，且当前有效原始材料足以走经核查的无规格路径。重试耗尽、取消、权限/必要来源失效、账目异常等继续按现有规则中止，不能借降级发出另一请求。来源变化引起的重建也必须同步使旧情境和规格失效；不能重建不完整仍放行。不得把内部计划作为回复。允许降级与必须中止的情况在 CR0/CR1 合同中逐项列清。

模型参数、历史窗口、样例预算、候选召回、输出协议都是独立变量。先固定，只有对应诊断支持时才另开比较，不与三接口变化打包后强作单因归因。报告的6–12个完整回合、top12–20、0–3样例等不直接设成默认值。

新实验工具应复用一套准备、模拟、执行、报告、验证入口和协议版本，旧批次工具及封存保持只读。一次阶段基线、按变更保存执行源码和请求指纹、逐次账本即可追溯；避免每次细微修订又复制整套历史、重跑全量、增加一套近似执行器。涉及共享上下文或权限公共合同时，仍须按实际风险安排必要集成/迁移验证，不能用精简流程省掉关键检查。
