## 1. 目标、基线与边界

施工起点为已推送的`main@46871ef`，工作区另含用户新增总规划和指导接入文档。当前源码0.7.0.dev1、主库结构11、导出8、桥接0.6.0；MIT许可。M7.0规定范围验收已完成，M4 O01–O03、M5 P09、M6.1旧付费续跑条件继续携带。当前源码及副本迁移证据不等于本阶段新结果，本轮未复测正式运行环境。

本阶段实现后应能：

1. 管理员在工作台按中文词、英文标识、明确时间查找同一入口范围的成功经历。
2. 命中任一输入成员或实际回复片段后，查看完整回合，保留命中目标、原顺序、时间来源与覆盖缺口。
3. 在全范围或最近50个成功逻辑回合内检索，预览只读工作集及其引用预算。
4. 来源撤回后，旧缓存、详情及工作集预览均不能重新带回失效回合。
5. 删除派生缓存后从权威档案重建；索引故障不能冒充“没有这段历史”。

工作集初版属于管理查询与预览，不自动注入聊天，不持久绑定引用，不增加模型调用。M7.2再接入任务级CognitiveContext及聊天召回；新M7.3为Session/Thread，新M7.4为表达硬化。向量是候选实验，不占用本阶段必交范围。

本阶段不实现Session生命周期、TopicSegment、后台反思任务、自动情绪、Director、演化、主动消息、联网、分段取消或表达模式切换。复用现有精确引用和可靠投递，不重做M6.4付费对照。

## 3. 权威接入合同

### 3.1 范围与资格

完整Scope为`persona_id/user_id/channel/bot/peer`。用户固定为本机身份；桌面bot/peer为空，QQ必须显式提供档案所属Bot及本人联系人，按已有记录核对归属，不从当前配置补旧身份。可在同入口跨session查询；显式session过滤须属于该Scope。未知QQ归属不由当前配置补造。

普通来源须满足M7.0资格：turn完成，全部成员有效，目标与入口归属一致；撤回任一成员使整轮及逻辑回复退出。失败、取消、收集中、排队中、缺完整turn的旧Event不进入普通检索。管理员仍可按明确ID使用既有审计读取，但该结果不能成为工作集或聊天引用。

搜索和预览始终由管理员鉴权；桥接令牌没有全文枚举、工作集或重建权限。跨范围目标与同范围未知目标采用一致的不可访问外观，不返回他人格数量或存在性。

### 3.2 实际DTO及内部投影

现有实现依据：[archive.py](../persona_runtime/archive.py)、[turn_input.py](../persona_runtime/turn_input.py)、[references.py](../persona_runtime/references.py)、[Store事务](../persona_runtime/storage.py)。

- 普通完整回合返回`members/replies/delivery/raw_metadata/coverage`等字段；成员是`id/role/text/created_at`，顺序由数组表达，不存在统一的member_order/source_kind/time_axis DTO。
- 内部新增SearchDocument适配结构：`document_id、scope_key、turn_id、session_id、target、source_kind、text、source_hash、times、coverage`。这些是拟议内部字段，不改变M7.0公共响应。
- 文档类型为用户输入Event、桌面生成回复Event、QQ确认sent的实际片段。普通QQ不以原语义回复替代实际发送文本；uncertain正文不入索引，用户已读继续unknown。
- 命中目标须可回到稳定的event或part ID；详情调用权威层恢复完整回合。同回合多个命中只占一个结果组，但`matched_targets[]`全部保留。
- 不使用只返回最近一页的archive.list充当全库枚举。内部在同一核心读事务枚举本Scope的turn并逐组复用资格判定；通过批量加载减少N+1，不能复制出第二套权限规则。
- 生成投影前不把原文变为摘要；检索片段只是展示，不能作为完整成员或受理引用正文。

### 3.3 时间映射

| 轴 | 文档取值 | 无对应值时 |
| --- | --- | --- |
| recorded | 输入/桌面回复的Event.created_at；QQ片段自身created_at | 标缺口，不能统一套turn.created_at |
| received | 输入RawEvent.received_at | 回复片段通常无该值，不回退到recorded |
| platform | 输入RawEvent.platform_time，按已有语义解析 | 缺失/非法时未知，不自动取平台历史 |
| sent | QQ片段sent_at | 输入及桌面生成记录不具备发送证明 |

过滤按命中文档的时间执行，随后展开完整回合；其他成员即使不在时间区间也须完整显示，并标明“因同回合展开”。回合创建时间、用户报告的事件发生时间分别展示，不冒充平台时间或已证实生活事实。

## 4. 查询与排序合同

### 4.1 QuerySpec v1

所有字段白名单，未知字段拒绝。以下为拟议接口合同：

| 字段 | 首版规则 |
| --- | --- |
| persona_id/channel/bot/peer | 按第3节校验；user_id不由客户端任意指定 |
| session_id | 可空；非空须同Scope；不跨入口 |
| query | 原始字符串≤256字符，拒绝NUL，不静默截断；空白等同空查询 |
| match_mode | all_terms默认，或phrase；不接受任意FTS/正则/脚本 |
| time_axis | recorded默认，或received/platform/sent |
| start/end | 带时区ISO时间；UTC半开区间[start,end)，start<end |
| local_date | Asia/Shanghai的YYYY-MM-DD，转换为UTC半开区间；与start/end互斥 |
| window | all默认，或recent_50；不得把结果limit当窗口大小 |
| limit | 默认5组，1–20；不提供连续分页或有效cursor |

空查询仅在提供时间条件时允许；不以空查询默认枚举历史。最近50回合预览用独立管理动作。日期快捷按钮可以计算昨天，但不从任意自然语言猜日期。原始输入保留给界面；规范化用于比较，不改写原文。

### 4.2 匹配与编译

确定性规范化采用NFKC与casefold，不压缩内部空白；版本及实际路径写入结果。保留原文，规范化坐标不能直接用于原文高亮。

G02比较四路：完整规范化子串、同语料规则投影、中文bigram+FTS5、trigram+短词回退。最终tokenizer与版本在验收集运行前冻结；仅用独立开发集选型。

首选候选编译合同：连续汉字生成相邻bigram；英文/数字/下划线按完整词项；去重后最多32词项。仅编码后的ASCII类型前缀和UTF-8十六进制进入MATCH，原始OR、引号、冒号等不得成为操作符。FTS与SQL参数绑定，内部表名固定。

all_terms要求编译词项均出现，允许分散在同一文档；不把两个不同成员各有一半词项拼成单文档命中。phrase须对同一规范化文档再次做连续子串确认。标点可作词边界；纯标点、单字或不能完整支持的字符查询走受限子串路径，不静默丢弃不能编译的字符。具体Unicode覆盖范围在G02记录；300与三百、同义词、繁简、拼音不自动等价。

FTS不可用时可对同一授权快照进行完整的有界子串扫描，响应明确degraded及匹配语义。若不能完整扫描，返回预算/能力限制，不能把部分扫描当完整no_matches。

### 4.3 排序及结果预算

Scope、session、窗口、时间及资格约束先于候选截取。排序只依赖本次授权文档：完整规范化查询连续命中优先、匹配的不同查询词项数降序、所选时间降序（缺值排后）、source_kind/document_id升序；不使用全库BM25或他Scope文档频率。G02可比较本Scope专属评分，但采用前须明确公式并固定对照，不暗改排序。

同turn按其最佳命中文档排序，合并全部实际命中目标；完整成员和实际回复按权威顺序展开。默认最多200个文档候选，截取时带`candidate_limit`和剩余覆盖未知标识，不称已完整遍历。

响应预览片段每命中≤240字符；完整组正文序列化后合计≤12000字符。装不下的整组不展开，返回ID、原因及详情入口，不截断某一成员冒充完整组。若合法命中存在但全部无法装入，返回query_budget_exceeded，不返回no_matches。

### 4.4 结果和状态

SearchResult至少含：`status、query_id、effective_scope、effective_query、window_manifest、time_filter、cache_schema、tokenizer_version、cache_instance_id、generation、source_digest、read_at、freshness、degraded、groups、coverage、budget`。

组包含`turn_id、matched_targets[]、members、replies、delivery、raw_metadata、coverage`。搜索片段、完整原文、生成记录、实际发送与已读状态明确区分。只暴露当前Scope的统计和诊断。

- ok：至少一组可用结果；限制/缺口单独返回。
- no_matches：完整处理了所声明范围且确实无命中。
- invalid_query：字段、时间、复杂度非法；不产生聊天事件。
- unavailable：权限、存储或必需能力不可用；错误外观不泄漏其他身份。
- coverage_gap：所选轴没有可用时间等覆盖问题；不能伪装成历史不存在。
- index_stale：来源在构建/查询期间变化，不能证明当前结果完整。
- query_budget_exceeded：来源枚举、扫描、字符或时间预算不足。
- cache_busy/cache_generation_changed：派生维护冲突，保留草稿，允许用户显式再试。

状态与coverage、degraded分别表达；成功查询不能因部分记录缺时间就丢弃已满足条件的合法结果。普通日志只记录诊断ID、计数、耗时、路径和错误类型，不记录query、正文或账号凭据。

## 5. 最近50回合与只读工作集

window=recent_50先在完整Scope及可选session中选出最近50个普通可用逻辑turn，再应用query和时间过滤。近期按现有turn创建顺序（核心rowid倒序、稳定ID消歧），不是用户陈述的生活发生时间；一个三成员批次只算一轮。不足50轮返回实际数量，不用失败、审计或他入口记录凑满。

工作集清单记录：窗口规则、稳定turn ID及顺序、来源digest、计入/排除原因、候选/选中/未展开组、字符预算和覆盖缺口。它是一次只读选择的Manifest，不新增长期记忆或Session，也不是被永久授权的证据缓存。

`archive.working-set-preview`接受Scope、可选session和window（all或recent_50），以及最多20个明确的event/turn/part目标；目标按权威层再读、校验窗口资格并按turn去重，仍保留所选目标映射。该action默认window=recent_50；未提供targets时仅预览recent_50的窗口清单，window=all必须带非空targets，不返回无限全库正文。

预览以当前有效正文计算引用块大小，显示12000字符引用预算、整组装入情况及`total_input_checked=false、creates_request=false、usage=retrieval_preview`。无未来输入时仅使用明确标注的36字符占位输入ID估算，不能声称实际max_input_chars已检查。真实发送仍由已有ingress受理并固定目标、当时发送快照和引用选择。

同回合多目标可合并展示，但旧input_references中的各成员选择与发送快照不得改写；后来新增sent片段不能加入旧绑定。点击“选择引用”只进入既有单目标引用条，用户显式发送前不创建请求；跨桌面/QQ限制不因搜索结果来自管理员而放宽。

## 6. 派生缓存及一致性基线

### 6.1 存储

拟使用`${PERSONA_RUNTIME_HOME}/cache/archive-search/v1/index.sqlite3`，默认位于D盘。派生库有自身cache_schema=1，不能写入主库user_version。表建议为meta、scope_generations、documents、fts_documents、maintenance_operations；含Scope键、分区键、稳定目标、hash、规范化文本、时间和代次。Scope键为完整规范化Scope的哈希；分区键另包含可选session与window规则，不包含query或时间过滤。读取时校验实际Scope及分区，哈希不是授权。

单一派生库不使用跨Scope排名统计；SQL约束与返回前权威校验共同实施隔离。缓存可能含私人文本，按项目数据保护约定保存，不进Git/日志或人格导出。权威事件、记忆、角色资料及已确认投递账本不迁入缓存。

### 6.2 逐次查询算法

1. 校验管理员及QuerySpec，领取运行时派生维护锁；锁忙返回cache_busy，不启动后台常驻器。
2. 使用Store.connection的显式读事务，在本Scope和session内按window规则构建完整可用分区投影A；recent_50只展开选中的50轮，但选择过程同样受预算限制。枚举边界、成员、回复/投递状态、资格、时间和覆盖都进入确定性source_digest；不能仅比较max(Event.seq)。预算不足则关闭读事务并失败，禁止发布半份语料。
3. 关闭核心读事务。若缓存Scope/分区、schema/tokenizer及digest匹配则复用；否则在派生库单一写事务替换该分区快照及generation。失败回滚，原缓存不能冒充新快照；无需向核心写change-log。
4. 在派生读事务中确认目标代次、按Scope和过滤查询、排序及组去重。缓存变更与读取均受代次约束，不读取不完整代次。
5. 释放维护锁，在新的核心读事务B重新构建同Scope/分区资格、窗口清单及摘要指纹，并恢复所选完整回合。A与B一致时，以B作为返回读取边界；变化则index_stale，拒绝用旧结果宣称完整，尤其不能返回no_matches。不自动循环重试。
6. 以后打开详情、工作集预览或实际聊天再次复核。响应发出后才发生的撤回不可能追溯改变旧响应，但旧响应不是后续使用授权。

指纹覆盖查询会展示的来源、正文、时间、成员顺序和发送状态；失效回合退出语料也改变digest。完整分区两次投影及窗口选择成本须进入G02性能报告，不能只计FTS的MATCH耗时。核心快照内不做分词/FTS写入或慢UI操作，不更改主库journal_mode来掩盖锁问题。

该基线按需整分区重建，不承诺增量消费。若规模证据表明需要增量/变更日志，先形成最小事务写入口矩阵、导出/迁移和回退设计，再修订计划；原I02/I03/I09改测一致性行为，不预设新表。

### 6.3 重建、失败与幂等

显式重建同步执行有界操作，沿用同一派生事务；不交付独立作业进程、定时器或自动续建。开始前校验Scope/分区及`cache_instance_id、expected_generation、operation_id`，参数相同返回既有完成结果，内容不同冲突。幂等结果与新generation同派生事务提交。

崩溃/磁盘满时事务回滚，已提交代次可读但必须重新与来源核验；未提交代次永不发布。重开后管理员显式重建，不自动模型调用。损坏时安全隔离/重建派生库，创建新的cache_instance_id；旧代次/旧操作来自其他实例时明确冲突，不能把清空后的0冒充原代次。

首版通过代次行和事务发布，不替换Windows读者仍持有的SQLite文件。删除缓存只处理已核对位于本项目cache目录的明确路径，关闭句柄后操作，不顺带删除权威数据。无缓存备份可正常恢复人格，之后重建。

### 6.4 资源保护与G02冻结

设计初始保护值：query≤256字符、≤32词项、候选≤200、结果≤20组、正文≤12000字符、源投影≤10000文档且正文≤200万字符、单次总工作预算≤5000毫秒。它们是服务保护上限，不是已测性能承诺；全部转为版本化内部常量，本阶段不开放调参页面。

计时包括锁等待、两次来源投影、同步、FTS/扫描和完整组恢复；使用单调时钟与SQLite进度中断，按批次检查。触及上限明确失败，不取前10000份伪装完整查询。cache_busy可提前返回，不能拖住聊天投递。

G02须在功能集及1000/10000份人工文档上测冷/热p50/p95、构建、两次投影、空间/内存及并行前台写入延迟。热查询目标p95≤1000毫秒，整个请求不得越过冻结总预算；若达不到，记录并修订方案/保护值及理由后再冻结，不在验收集上调参或偷偷提高预算。额外报告单库与分Scope文件的小规模对照；只有证据显示必要时才改组织。

## 7. 管理接口与工作台

下表为v2冻结合同；四个action现已实现，具体使用及错误见阶段说明：

| action | 请求及行为 |
| --- | --- |
| archive.search | QuerySpec，返回SearchResult；可维护派生缓存，零权威业务写入 |
| archive.search-status | 明确Scope及可选session/window分区，返回缓存实例/代次/版本/诊断；未核源时freshness=unknown，不只凭时间称fresh |
| archive.search-rebuild | 明确Scope及可选session/window分区、cache_instance_id、expected_generation、operation_id；有界重建，不创建聊天事件 |
| archive.working-set-preview | 第5节只读目标/窗口预览，零模型与持久引用写入 |

沿用[server.py](../persona_runtime/server.py)中的管理员/v1/manage及既有错误外观。服务端核对必填Scope，不依赖界面当前人格推断。search-status不得跨Scope泄漏统计。既有archive.get/resolve/preview/list和QQ引用语义保持，桥接不升版。

工作台扩展工程档案页或新增档案检索子页，包含人格/入口/QQ账号、query、匹配模式、四种时间轴、时间范围、全范围/最近50、查询/状态/重建/工作集预览及详情。控件以实际实现更新操作手册，本计划不声称按钮已存在。

显示命中目标、完整组、实际发送状态、时间轴、窗口限制、缺口、degraded及预算原因。没有连续分页，不显示误导的下一页；结果过大可以按ID打开详情。普通结果进入既有引用条前检查入口，不把QQ历史默认附到桌面消息。

异步响应携带完整Scope、view_epoch和query_generation；只有三者匹配才显示。切人格/入口/账号/会话或修改查询条件即使旧结果失去当前资格；保留查询及聊天草稿，清除不适用的引用选择。UI后台线程调用有界服务，失败保留输入，不因刷新触发收费。新查询不自动重发旧操作，不取消既有聊天/投递。
