## 3. 查询合同：首版固定为可解释词法检索

### 3.1 QuerySpec v1

| 字段 | 规则 |
| --- | --- |
| persona_id、channel | 必填，服务端核对，不靠界面当前选择推断 |
| bot、peer | QQ必填且精确匹配；桌面不接受伪QQ目标；user由当前本机身份确定 |
| session_id | 可空；填写时须属于上述范围；空表示该入口内跨session搜索，不跨渠道 |
| query | 原始字符串最多256字符，不静默截断；保留表单原稿 |
| match_mode | `all_terms`默认；`phrase`为规范化后连续子串；不支持任意FTS/正则/脚本表达式 |
| time_axis | `recorded`默认，可选`received`/`platform`，必须随结果回传 |
| start、end | 带时区ISO时间，UTC比较，半开区间；start必须小于end；无边界表示开放区间 |
| local_date | 界面便捷输入YYYY-MM-DD，固定Asia/Shanghai转UTC[start,end)；与显式start/end二选一 |
| limit | 1–20，默认5个证据组；每组不是一条被截断的成员 |
| cursor | 首版保留为null；本阶段不交付连续翻页，避免对可变索引伪装稳定分页 |

空query仅在有日期/起止时间条件时允许，按时间返回；空query且无时间条件返回invalid_query，不默认枚举全部历史。`昨天`只作为界面日期快捷按钮计算，不在任意自然语言中自动抽取日期。无对应时间的记录不满足该轴过滤；全范围缺该时间时显示coverage_gap，不伪造零条历史。

服务先做权限与字段/长度校验，再查索引；日志仅记录耗时、计数、模式、错误码等工程信息，不记录query、原文或凭据。单次查询生成一个诊断ID，不建Event/Receipt/turn/attempt，也不调用理解/评分模型。

### 3.2 分词与匹配

首选候选为**预分词bigram+FTS5 unicode61**；trigram和精确子串是比较路径。已有探针证明默认unicode61不能直接解决中文片段，trigram漏两字词；因此不直接把默认FTS上线。

确定性规范化v1：NFKC、casefold；保留原文不变。中文首版使用与当前terms兼容的U+3400–U+9FFF连续字串相邻bigram，英文/数字/下划线按词分组。索引词编码为仅含ASCII字母数字的类型前缀+UTF-8十六进制，避免标点、引号、下划线改变FTS语法。查询使用同一编码，去重，最多32词项；超限明确query_too_complex，不悄悄删后半段。

`all_terms`：所有编译词项都命中，但bigram可分散在同一文档中；界面说明它是“包含全部词项”，不是连续原句或语义同义。`phrase`：候选命中后再次对规范化原文做连续子串确认。否定、数字同义（300/三百）、拼音、繁简和同义改写不自动等价；不确定含义不猜测。

单个汉字、不能生成bigram的字符、标点查询，以及FTS不可用的环境使用受限规范化子串扫描。单/两字覆盖须单列测试；扩展汉字等不支持分词的输入可走子串，不静默丢字符。FTS MATCH只接受程序生成词项；用户的OR、冒号、引号、括号不得作为操作符。SQL值均绑定，动态对象名只来自固定内部版本/可信生成标识。

### 3.3 排名和截取

仅在已授权scope中处理候选，时间和当前有效性约束在候选截取前生效；不使用全库top-k再过滤。首版物理按完整scope隔离索引文件，避免跨人格文档频率参与BM25及结果解释。

单路最多200个文档候选，FTS路径按BM25升序、所选时间轴降序（无过滤时缺时间排末）、source_kind/source_id升序稳定排序；子串路径按精确连续命中、时间及稳定ID排序。不把不同路径的分数直接相加；采用哪个主路径由G02冻结，子串回退不是向量融合。

原文验证后映射为EvidenceGroup，以turn为主要去重键；同一用户事件不得因原语义段和多个part重复占名额。无turn的独立历史Event单独成组。命中某个成员须指出该成员，但来源展开读取全部有序成员；组内有效性不满足整轮规则则整个排除。200候选已用尽仍不足limit时返回candidate_limit标识，不能假装检索了所有正文。

## 4. 结果、状态与权限

Result v1至少返回：status、query_id、effective_scope、time_axis/UTC区间、index_schema/tokenizer版本、generation、实际路径、freshness、groups、coverage与budget说明。groups含稳定来源ID、命中成员/part ID、来源类别、原文片段、turn/batch、可见时间和缺口；详情按ID走Canonical层读取，不信任索引缓存的正文。

状态固定：`ok`、`no_matches`、`invalid_query`、`unavailable`、`coverage_gap`、`index_stale`、`query_budget_exceeded`。降级是单独字段，不能把“索引坏了”返回成no_matches；有真实候选但时间轴覆盖不全可返回ok并附coverage警告。越权和别人的未知ID统一不可访问外观，不返回其记录数量。

初始限制：最多5组默认/20组上限；单次结果正文总量最多12000字符、预览最多240字符/命中，完整正文通过详情读取，不丢档案。超限整组跳过并说明原因，明确剩余组未展开；禁止截断成员后标记完整。UI使用纯文本展示，规范化坐标不能直接用于切原文高亮；首版可不做字内高亮，保留命中成员标识即可。

若有合法候选但所有组均超过正文预算，返回query_budget_exceeded而非no_matches，提示按来源ID打开详情或缩小范围；不能把“未展开”解释为“没有历史”。

首版只通过管理员`/v1/manage`增加以下**拟议**action：

| action | 行为与权限 |
| --- | --- |
| archive.search | QuerySpec查询，读取/维护派生索引，不改原档案；管理员 |
| archive.search-status | 当前scope索引状态、版本、覆盖及健康；管理员 |
| archive.search-rebuild | 当前scope显式重建，expected_revision+operation_id；管理员 |
| archive.search-job | 查询派生重建任务状态；管理员 |

名称须与M7.0最终action核对后冻结；当前代码没有这些接口。桥接令牌不能调用管理action，本阶段不新增桥接全文搜索API。旧/v1/chat、/v2/ingress及已有QQ引用读取语义不变。

## 5. 可重建索引与一致性

### 5.1 两类持久化，不能混为权威正文

核心库只增加确实缺少的scope_revision与变更登记；若M7.0已有等价能力则复用。拟议日志字段：scope_key、scope_revision、source_kind/source_id、change_kind、created_at；revision在核心写事务内递增。登记新增、完成状态、发送确认/不确定、屏蔽/恢复（如支持）及明确删除。不要给同一含义建两套revision。

D盘`cache/archive-search/v1/<scope-hash>/`保存派生SQLite文件。scope-hash为完整规范化scope的SHA-256，不把账号写进文件名；文件内保留scope并打开时复核。派生表建议：meta、documents、fts_documents；documents保存稳定来源键、group键、时间、hash和索引文本，FTS保存编码词项。meta含index_schema=1、tokenizer版本、generation、来源revision和build状态。原始事件、角色设定、已确认记忆不混入同一档案索引。

结构化documents即使FTS模块不可用也可建立，创建FTS失败不得使主数据库迁移失败。缓存文件不纳入人格权威导出，只导出必要版本/重建说明；核心新日志如承担恢复依据，需按最终导出版本保留。缓存含私人文本，权限沿用本项目D盘当前用户/SYSTEM政策，不进Git或普通日志。

### 5.2 增量、查询和失效顺序

1. 查询读取当前scope修订R及权限；索引与R一致才是fresh。索引落后时消费该scope变更，不从全库max seq推断无变化。
2. 每次最多同步500条变更，按revision处理，source_id更新/删除幂等；同scope串行维护，其他scope互不接管文件。
3. 同步完成后重新读取修订；未追平、变更日志出现断档或来源快照不一致时标stale并重建/显式降级，不返回“完整最新”。
4. 候选查询后，在新的核心只读快照内复核权限、来源hash、整轮有效性及scope revision；结果以该快照作为读取线性化点。不能承诺响应发出后发生的撤回也被过去的响应覆盖。
5. 后续打开详情或M7.2使用证据时再次复核，禁止把旧查询响应当永久授权。没有M7.2集成时不偷偷往context_m4注入结果。

不要跨SQLite文件宣称原子提交。核心变更先提交，缓存随后幂等同步；缓存写失败允许档案受理成功，查询显示不可用/降级。核心变更登记写失败则同核心业务事务回滚，遵守既有受理成功语义。

### 5.3 重建、恢复与预算

显式重建创建唯一job/generation，在同scope维护锁下向新文件构建，不覆盖活动文件。固定来源修订和完整稳定source_id列表，短事务分批读取，补齐构建期间变更；只有追平、完整性/hash/范围检查通过，才发布新generation。采用关闭SQLite连接后更新manifest指针的方式，不依赖Windows替换正在打开的数据库文件。

进程重启后未发布的generation标interrupted，不对外读取；管理员显式继续或重建。operation_id相同且参数一致返回原job，参数不同冲突。已发布旧generation在新索引完成前保留，但源revision不匹配时不能冒称fresh；旧文件清理须先验证在本scope缓存目录、无打开读者，再删除。

单次查询总维护/扫描预算初值1000毫秒，使用单调时钟和SQLite中断/进度检查；单字/无FTS扫描最多10000份可见文档，超过要求缩小日期/会话范围。不能扫描前10000条后把结果当完整无命中。超预算返回query_budget_exceeded且不交付伪完整结果。以上是工程保护初值，G02在独立开发集校准后冻结，不是性能通过声明。

重建不在HTTP事件循环中长时间同步执行，工作线程短批处理；不增加付费后台队列，不因索引损坏触发模型整理。锁忙、磁盘满、损坏、FTS不支持分别给出状态；主服务受理/投递不因索引构建长时间持锁。

## 6. 中文方案选型与固定真值

G01先建立人工档案集v1与64查询：[M7总计划](M7-原始档案与检索实施计划.md)的E01–E16精确、C01–C16中文、T01–T08日期、B01–B08成员、N01–N08负例/权限、R01–R08撤回。另建12条开发查询调参；验收集不得用于试错调参。M7.0精确路径用E组做回归，不把它改走全文。

C组固定覆盖：C01–04中文专名/连续片段；C05–08单字、两字及混合标识；C09–12词项分散、重复词、同字不同项目与无关干扰；C13–16表达变体，标注哪些有词法支持、哪些应明确无法语义找回。不为提高分数在索引中暗加测试答案或同义词。

每条qrel包含query/spec、fixture_revision、expected_group_ids、required_member_ids、forbidden_ids、expected_status、answerable、time_axis。每条可回答查询最多5个相关组，否则另列大相关集测试，不制造Recall@5理论不可达。度量以组ID为主、成员完整性为硬门，不能文档切块后改变分母。

比较四路：同档案子串、同档案terms规则投影、bigram FTS、trigram+短词回退；现有memory.search和聊天记忆召回单独列背景，不与不同语料的档案分数混比。各路使用相同范围/时间/有效性和同一qrels。选择先过权限/撤回/完整性门，再看Recall@5/MRR@5、耗时和空间；bigram是首选候选，未通过不得强行采用。

验收门：E组16/16正确；全部forbidden_ids返回0；负例不假引；可回答C组逐查询Recall@5均值≥0.90且不低于规则投影基线，同时报告Hit@5/MRR@5及C13–16未命中限制。N组不进入可回答召回率分母。任一门未过，记录失败并修复，不改真值稀释失败。

性能单列小功能集、1000条和10000条人工档案，冷/热查询分别记录p50/p95、构建/增量耗时、数据库大小、内存峰值、前台写入延迟。先跑基线后在G02冻结目标，不能现在承诺某毫秒值。计时重复查询不调用模型；数据扩增不是用户真实使用质量证据。

## 7. 工作台与验收体验

增加“档案检索”工程页：人格/入口/账号、query、all_terms/phrase、时间轴、日期/时间范围、查询按钮、索引状态/路径/新鲜度、重建入口。结果按组显示命中成员、时间、覆盖、发送状态与完整成员展开；旧历史缺平台字段必须可见。

切换人格或入口时取消旧页面显示资格，不自动保存/发送；异步响应携带scope和页面generation，仅匹配当前页面才渲染。保留未提交查询草稿；后台刷新不覆盖输入。关闭页面不取消已存在聊天或投递任务。分页本期不做，明确“最多显示N组/可缩小查询”，不要显示误导的下一页按钮。

预览和查询零主要调用，点击重建只处理派生数据，不改变原人格、关系、记忆、事件及模式。界面按钮以实际实现更新验收手册，当前文档不证明这些按钮已存在。
