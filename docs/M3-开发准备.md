# M3 开发准备：群聊与多参与者边界

日期：2026-10-26。状态：M2 已由用户确认真人全流程通过；**M3 尚未实现，本文件不是已批准的最终实现计划。**

## 1. 阶段目标

让已经与你相处的人格能够接触获准加入的群聊，识别不同参与者，并在私聊与群聊之间保持同一人格及明确的信息边界。

群聊不是为每个群复制一个新人格，也不是让所有参与者共享主人的私人记忆。身份连续性与信息可见性应分别设计。

建议首版只扩展指定 QQ 群、成员身份和受控回复；其他联系人私聊、主动插话、多模态、自动记忆、搜索和人格演化不默认并入。最终范围在 M3 计划讨论时确认。

## 2. 当前代码中必须先解决的限制

| 当前实现 | M3 必要变化 |
| --- | --- |
| 业务服务大量依赖固定 `LOCAL_USER_ID` | 引入平台参与者身份映射；主人身份与普通参与者身份区分，不能继续将所有人写成本地用户 |
| 会话 scope 仅允许 private | 表达本人私聊、群会话和参与者来源；按真实平台、Bot、会话类型与会话 ID 归属 |
| 当前会话映射主键只有人格与入口 | 同为 QQ 的不同群不能再复用同一条映射，也不能混入本人私聊 |
| QQ 入口仅允许本人好友纯文本 | 增加显式群授权与成员检查；保留本人私聊原路由，未授权范围继续拒绝 |
| 记忆主要按人格和用户过滤 | 增加可见范围及来源检查，检索、详情、导出与上下文组装使用一致规则 |
| 投递来源只有本人账号与 Bot 绑定 | 绑定目标会话类型、群/用户和 Bot；发送前再次验证授权及目标 |
| 同人格串行与项目级调用额度 | 为群消息增加明确的触发、节流和排队策略，避免群消息淹没主人私聊 |
| 工作台仅配置 Bot/本人账号 | 增加群授权、响应策略、会话与可见范围管理页面或区块 |

这些限制是代码核对结果。不能只放开 `allowed_message` 的本人判断，就把群聊视为已支持。

## 3. 应延续的工程原则

- 复用当前人格、独立数据目录、模型客户端和工作台，不把 TRPG 规则或旧项目配置重新引入。
- 默认不开放新群，权限由主人显式配置；昵称、消息正文中的自称不授予主人或管理权限。
- 私人资料不进入群请求的检索结果或模型上下文，不能仅靠“请不要透露”的提示词防止泄漏。
- 共享人格设定中的自我介绍与私人经历也要分清，不能默认把完整私人档案放进每个群的系统提示。
- 迁移前备份，保留 M2 人格、本人会话、记忆与请求历史；不能将旧私人记忆默认迁移为群可见。
- 请求提交时固定身份、会话、人格和权限依据；投递时验证目标，避免切换配置、撤销授权或延迟回复后误投。
- 保留失败分类、调用额度、去重、投递不确定状态及正常启停；紧急强停不作为常规迁移或测试步骤。

## 4. 实现前需要确认的产品选择

以下是讨论起点，不是用户已经批准的配置。

| 决策 | 建议的首版起点 | 需要确认的取舍 |
| --- | --- | --- |
| 群内何时响应 | 先支持 @Bot 或明确触发 | 是否首版就需要自然择机发言；后者需要独立的发言决策与费用约束 |
| 谁可以在获准群里交流 | 群授权后允许普通成员进行普通对话，管理仍仅主人 | 是否还要逐成员名单，是否排除部分账号 |
| 哪些内容可跨范围使用 | 私聊资料保持私有；群信息先按群隔离，跨范围共享需显式授权 | 群公开信息是否允许进入主人私聊；同一成员跨群的关系资料如何共享 |
| 群的近期上下文 | 各群独立保留，成员来源明确 | 只记录触发消息，还是也接收未触发的背景聊天；两者的存储与上下文影响不同 |
| 人格连续性 | 默认同一人格进入获准群 | 是否需要每群绑定既有人格，以及切换的生效时机 |
| 私聊与群聊的响应分配 | 私聊不被群消息长期阻塞，群请求有节流 | 是否接受同人格继续完全串行，或允许按会话并发并定义共享状态一致性 |

上述高影响选择确认后再形成决策完整的 M3 实现计划。其他联系人私聊不应因群成员身份建立而被自动开放。

## 5. 建议的开发顺序

1. **身份与可见范围合同**：明确主人、参与者、群授权、人格和会话的关系，以及读写/召回/投递规则。
2. **存储与迁移**：升级身份、会话归属、记忆范围、请求及目标字段；验证现有 M2 数据完整保留。
3. **业务服务与上下文**：先通过群间隔离和私有资料不入群上下文测试，再接入平台入口。
4. **QQ 桥接与投递**：按选定触发策略接收消息，保留去重，落实授权变化及正确目标投递。
5. **工作台扩展**：群授权、策略、会话及范围展示；所有保存弹窗沿用已修复的操作栏和成功确认逻辑。
6. **回归与真人手册**：完整保留 M2 回归，新增 M3 自动测试，并按实际界面提供可照做的 `.md` 真人验收手册后再进行真人测试。

## 6. 最低验证清单

- 同一发送者在不同群、本人私聊与窗口的身份映射正确，会话上下文不串入。
- 主人私人记忆、关系或背景不出现在群请求的上下文、详情或输出路径中；其他群的信息也不越权召回。
- 未授权群、正文伪造身份、冒充主人以及未触发消息均按约定处理，不触发额外模型。
- Bot、群、发送者和平台消息 ID 正确参与去重；两个群中相同消息文本不被错误合并。
- 授权撤回、配置切换、重启及发送结果不确定时，不向错误群、成员或 Bot 投递，不自动重复调用。
- 群请求的排队与费用限制符合确认的策略，不能让主人私聊长期饥饿。
- 迁移前后 M2 人格、会话、记忆、窗口聊天与本人 QQ 私聊继续通过回归。
- 新页面和弹窗覆盖高缩放、最小尺寸、慢任务、失败保留输入和正常重开窗口。
- 真人验收手册同时覆盖允许范围的正常对话与不允许范围的拒绝行为，结果和截图保存在 D 盘。

本次仅准备文档与交接，不更改数据库结构、权限、运行配置或服务状态，也不自动加入群、发送消息或触发模型。

## 7. 开工门槛与交付清单

M3 进入实现前，先把第 4 节的选择整理为用户确认的实现计划；“准备 M3”本身不等于批准其中的建议。计划应给出允许/拒绝矩阵，至少覆盖本人私聊、获准群、未授权群、同一成员跨群、其他联系人私聊，以及授权撤回后的在途回复。

按以下顺序形成可审查交付：

| 顺序 | 交付 | 进入下一步的条件 |
| --- | --- | --- |
| 1 | 已确认的身份、会话及可见范围合同 | 高影响待定项有明确答案，不以实现者猜测代替产品选择 |
| 2 | 存储迁移与旧数据兼容测试 | M2 数据保留；原私人记忆不被默认公开；失败可回滚 |
| 3 | 群业务、上下文与投递自动测试 | 允许范围可用，拒绝范围在进入模型前就被阻断，撤权后的回复不误投 |
| 4 | 工作台与桥接集成 | 在独立模拟环境验证，不自动操作真实群或触发收费请求 |
| 5 | M3 真人验收手册与版本交接 | 按实际按钮编写 `.md` 手册，区分自动证据与待执行的真人步骤，再交由用户测试 |

保留现有全部回归用例；新增测试重点覆盖隔离和拒绝行为，不能只增加群聊成功回复的正向用例。真实群号、成员资料、聊天记录和真人验收结果仍保存在 D 盘，不加入源码或示例配置。
