# 模型输入与提示词写作总则

2026-11-17起，依据作者明确禁令执行。适用于PCAR所有开发代理、子代理、自动化任务及后续开发阶段；与此前规划、开工指令、测试预算或素材准备安排冲突时，以本总则及作者后续明确指令为准。

## 1. 未明确授权，不得写作模型输入

**开发代理不得自行创作、改写、扩写、润色或优化任何拟发给上游驱动LLM的提示内容。** 此禁令同时覆盖拟用候选和实际使用内容，不因标为静态模拟、测试数据、示例、离线夹具或研究材料而豁免。

范围包括system／user提示、人格与口语设定、表达习惯和例句、模拟用户消息与聊天历史、理想回复、理解笔记、参考资料的代理转述，以及写在代码模板、配置、检索资产或上下文装配中的自然语言。这些内容只要可能影响后续LLM的判断或表达，就须按同一规则处理，不能通过改名绕过。

“开始施工”“继续开发”“做测试”“改进活人感”、已有调用预算、过去的素材计划和源码复用许可，均不自动构成本轮提示写作授权。授权须指向具体写作事项及范围。

## 2. 写作授权与使用批准分开

**即便作者明确授权代理写作，未经作者审阅通过，该版本也不得发给上游LLM。** 草稿必须留在待审阅区，不能提前做真实调用、接入默认配置、登记为可用表达资产，或作为另一批测试的隐藏输入。

作者审阅应能看到完整内容、来源、将如何装配、面向什么模型及用途。批准绑定所审阅版本和适用范围。代理不得在审阅之后再自行增删措辞、追加“保险”规则、改写例句或加入未展示的上下文；内容性变更重新交作者审阅。纯编码、传输与存储工作不得暗中改变可见文字。

测试通过、文案看起来更顺、模型生成成功或代理自行打分，都不能代替作者批准。已被否决或撤回的版本不能通过旧导出意见、改文件名、改任务ID或换实验目录恢复使用。

## 3. 开发代理在“去人机味”中的位置

默认职责是源码和机制研究、可核对的原文摘录与来源说明、输入装配审计、工程实现、回执／用量记录及故障验证。具体角色口吻和语言审美由作者决定；代理不是默认的角色文案作者、真人语料提供者或自然度裁判。

可以逐字读取、定位和比较已存在的上游提示或作者材料，保留来源与版本；不得借研究之名改写为新候选，或把未经审阅的新上游模板直接激活。需要语言材料才能继续时，先指出具体缺口，继续不依赖该材料的工程工作；不得自行补造一批话术填空。

anti-defensive-writing等写作规范服务开发文档和与作者的沟通，不能自动变成人物的语言风格。不得把开发代理自己的短句、套话、修辞或提示偏好灌入人格、表达库或测试集。

## 4. 场景判断与最小必要输入

不同场合使用不同说法，由运行模型结合人物和真实交流判断。工程实现只提供与当前交流相关、来源明确的必要材料，不为覆盖所有假想场景将逐项操作规则堆进同一人物prompt，也不将行为要求写成人物自述或固定台词。

角色、会话、来源、权限、资料状态、协议与恢复的工程合同继续保留。能在后台实现的校验留在后台，不能以“工程严谨”为由自行扩大人物可见指令。新的自然语言说明仍须满足前述写作授权和使用批准。

## 5. 评测材料与结论

测试材料同样会影响模型表现。开发代理不得自行生成拟发送给LLM的模拟用户对话、参考答案、理解笔记或所谓真人表达样本；来源、选材与使用范围先由作者明确指定或批准。获准原文保持原文，按既有资料权限处理，不擅取正式私人聊天。

工程测试可以使用不进入上游模型的标识、摘要、状态、接口替身和已保存回执验证边界。不得以离线测试为入口创建新的自然语言模型输入；不得重新装配已否决候选来声称它“只是测试”。

代理自己创作素材、示范回答，再据此判断自然度，不能构成独立体验证据。既有真实调用仍是实际发生的调用，其自然度结论须连同输入来源和可能的诱导一起解释，不改写首次结果，也不将输入影响的怀疑冒充已经完成的因果验证。

## 6. 本次E.N0处置

作者已否决本轮E.N0的开发代理静态语言候选。四份口语设定、48条情境表达、16组话语片段、三份提示、模拟场景和理解笔记，以及其装配预览，全部退出可用候选，仅作历史证据保留。不得用于E.N1、表达学习、后续prompt种子或替代真人材料。

本轮曾实际完成的仅是静态创作与页面／输入结构检查，真实模型调用为0。截图中的“先把分析搁下→先不分析”由开发代理同时写入设定与示范；该问题已成立，但不能将这份静态稿记为上游LLM已发生的泄漏。此前“研发标记未混入”的检查只验证字段和特定字符串，不能证明文风、行为指令或样本诱导没有污染表达。

撤销本轮旧的“全部勾选即可进入E.N1”推进路径。下一步须由作者明确材料来源或授权具体写作事项，完成独立的使用审阅后，才讨论新的有限实验。64次预算没有执行，也不能替代上述授权。

## 7. 既有运行与记录

本禁令约束开发代理的输入创作、修改及新材料使用。已经获准的运行版本仍可在原范围按冻结合同处理真实用户消息、获准检索资料和运行时理解结果；此次不自行停用正式实例或修改其现有提示。

总则放在根AGENTS入口，并同步开发验证原则和当前阶段指导。每次新任务先核对该边界。保留作者指令、候选版本、审阅和撤回记录；不宣称一份文档能技术性阻止所有未来违规，工程入口对当前已否决候选另作明确阻断。
