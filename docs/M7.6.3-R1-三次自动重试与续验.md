# M7.6.3-R1 三次自动重试与续验

2026-11-01，用户在Grok批次阻断后追加授权：请求失败最多自动重试3次，并明确同时加入日常聊天运行时。候选更新为`0.7.6.dev8`，数据库结构20、导出17、配置2、桥接0.7.2保持。旧dev7阻断与全部原始证据保留，不删除停测文件，不覆盖成功输出。

## 重试行为

日常聊天的主回复与角色选择共用`generation-retry-v1`：首次调用失败后最多再尝试3次，最多4次物理调用；第三次重试仍失败，返回`provider_retries_exhausted`并中止该请求。选择器耗尽重试后中止本轮，不再以词法回退继续发起主回复。

连接/读取超时、网络错误、空白、无效响应、截断、结构不合规、选择器返回非法候选，以及HTTP 408/429/5xx可重试。密钥/权限/请求参数错误、内容过滤、来源变化、额度不足、账目失败和用户取消直接停止。完整但质量差的回答不会因此被重新生成。

每次重试保持原请求正文、模型、格式、采样和输出额度；角色资料、引用、临时状态和权限在发出前复核。复核导致实际消息变化时停止，不把新上下文伪装成旧请求的重试。单次选择期限仍60秒，主回复仍180秒；间隔为1、2、4秒。主动取消与服务退出不触发自动重试；取消未能完成清理时停止，避免同一请求叠加本地在途任务。

运行时负责重试，实验执行器只记录每次物理调用，两层不会各重试3次。后台整理、胶囊编译与情境观察沿用原生成流程；共享额度统计已包含聊天重试消耗。

## 记录与兼容

复用既有attempt记录和usage_json，不新增表或配置。`usage_json.generation_retry.attempts`逐次保存独立ID、序号、时间、请求指纹、完成/失败/取消状态、已知用量及无正文诊断。未知用量保持未知；失败正文仅留指纹，密钥与思考正文不进入此记录。外层用量汇总所有已知尝试，推理子项不重复相加。

原attempt表示逻辑请求，新增数组表示物理调用；额度按照后者逐次计算，包括跨小时/日期边界的重试。旧记录没有此字段仍计一次。额度界面的主回复和选择计数同步更新，编译与观察使用的共享额度也不会漏掉选择器重试。

每次发出请求前先持久化预留。取消路径单独捕获`CancelledError`，写终态再传递取消；普通异常不会吞掉它。第三次重试失败会保留最后的具体原因及结构校验诊断，界面恢复说明明确已耗尽自动重试。
