# PCAR M9R DeepSeek 原生能力接入与后续开发手册

规划日期：2026-11-15。基线：`v0.1`，程序 `0.1.0`，数据库结构 `27`，提交 `29dc3d04a2a9671a25573c3523a9158bade06ba6`。

本次方向调整是：人格、经历、关系和长期知识继续由 PCAR 持有；后续云端生成与应用能力集中支持 DeepSeek 官方 API，Jev 保留独立联网判断。通过官方能力减少检索编排、重复推理和转接损耗，把研发投入转向持续陪伴、记忆消费和自然交流。

按作者本次命名意见，新增阶段采用 **M9R（M9 修订）**，子包为 M9R.0—M9R.5。已有 M9 的验收结果保持有效；原 M10 导演与演化、M11 高阶主动行为、M12 多模态编号保留。作者已要求将本轮讨论纳入开发手册并提交推送，本手册的方向、阶段顺序和职责边界据此成为后续研发依据；具体真实验证预算、样本规模和发行版本在对应工作包确定。规划采纳不代表功能已经实现或通过验收。

## 0 开工顺序与交付约定

1. 开发前依次阅读根目录 [AGENTS.md](../AGENTS.md)、[STATUS](STATUS.md)、[HANDOFF](HANDOFF.md)和本手册。新供应商范围、M9R 顺序及原生能力边界以本手册和供应商总则为准；实现状态、历史验收和当次操作授权分别核对，不相互替代。
2. 下一次功能实施从 M9R.0 开始，再按 M9R.1—M9R.5 推进。先验证原生接口，再替换编排；两段式先形成可用闭环，单段式须经比较才能成为默认。
3. 每包开工明确输入、输出、受影响文件、验证材料、真实调用预算和停止条件；复用当前会话已经给出的授权，不为同一已授权操作重复请求确认。需要新增资料范围或副作用时，再明确该项边界。
4. 每包收尾更新状态和交接，记录代码与协议版本、完成项、失败及未知状态、费用、当前默认路径和下一最小入口。只验证受影响行为，不把计划、模拟和真实用户体验合并成一个通过结论。
5. M9R 联网、召回配套、M12 前置小包和安装交付分别结算。M9R 不占用 M10 编号，不自动恢复 QQ，不跳过 G-AUTO 提前接入 Director 或人格演化。SnowCat公开进展持续跟踪，QQ接入待作者明确批准，见第9.6节。
6. 本次交付限于手册及相关文档的提交推送。程序保持 v0.1／0.1.0、数据库结构 27；真实原生接口验证、业务迁移及下一功能发行在后续实施任务中执行，不把此次文档发布记为原生能力上线。

### 1.2 现有 M9 已经使用 DeepSeek 搜索

源码中的 `knowledge_web_transport.py` 已直接访问 DeepSeek 官方 `/v1/tools/search` 和 `/v1/tools/fetch`。因此，这次调整的主要收益来自 **把应用侧检索编排交给 DeepSeek 服务端**，而不是第一次更换搜索服务商。

目前一次新增联网资料的典型链路为：

```text
Jev 是否联网
  → DeepSeek High 生成计划
  → PCAR 循环调用 Search／Fetch、挑选和裁剪结果
  → DeepSeek High 整理底稿
  → DeepSeek 按 v8 人物上下文回应
```

应用侧通常包含三次 DeepSeek 语言生成，另有 Jev 和若干工具请求。原生能力有机会合并规划、查找和整理，减少中间文本损耗与维护点；服务端内部仍可能多次推理和调用工具，不能把一次 HTTP 请求当成一次推理或更低账单的证明。

M9 留下的主要资产是人物体验基线、Jev 职责、来源和笔记、追问复用、调用恢复、费用记录及部署能力。应替换已被官方覆盖的编排，保留这些仍然有用的资产。继续扩充旧搜索循环、复杂排序或多轮整理模板，优先级低于验证新接口。

## 2 修订后的核心原则

### 2.1 人格持久化与供应商支持分别定义

**人格独立性**：人物身份、核心设定、关系、原始经历、有效记忆、知识版本和权限由 PCAR 保存。清空一次模型上下文、重开会话、更新 DeepSeek 型号或迁移电脑，不得抹掉这些状态。

**供应商范围**：后续只对 DeepSeek 官方生成和应用 API 提供产品适配，Jev 为明确例外。停止以支持任意兼容网关为目标设计新功能；存量第三方配置保留可读和导出能力，切换时给出明确的配置迁移路径，不静默改密钥或转发资料。

**型号演进**：DeepSeek 内部不同型号与版本仍需区分。首个原生联网基线选择官方当前支持的 `deepseek-flash`；不能因为同属 DeepSeek，就默认其他型号具有相同工具能力。[官方发布说明](https://api-docs.deepseek.com/zh-cn/news/news261113/)

**本地组件**：本地 Embedding、SQLite、档案检索和角色选材继续服务 PCAR。“只支持 DeepSeek”约束云端模型及应用服务，不构成删除本地 BGE 或本地记忆系统的理由。

“不依赖模型上下文窗口”在工程上的含义，是人格和长期历史不以某个窗口为唯一载体；每次推理仍需要 PCAR 装配有界上下文。无限塞入历史或依赖云端会话自动记住一切，均不满足原始目标。

### 2.2 职责边界

| 职责 | 负责方 |
| --- | --- |
| 人格、关系和经历的权威状态 | PCAR |
| 记忆选取、有效性、更正、撤回和跨机迁移 | PCAR |
| 是否需要新增联网资料 | Jev；沿用现有异常降级政策 |
| 获准联网后的搜索、阅读、资料综合 | DeepSeek 原生工具 |
| 人物的语言表达和本轮推理 | DeepSeek，使用 PCAR 提供的人物及情境 |
| 来源归属、任务结束状态、费用记录和副作用权限 | PCAR |
| 日后本地工具和 MCP 的执行权限 | PCAR；不能转交给联网模型自行决定 |

保留人物自己的倾向、观点和普通错误修正空间。来源用于查阅和追溯，不恢复已删除的权威来源门、逐数字裁决、严格日期审核或独立审核后才能回复的旧链路。

## 3 官方能力与本项目的对应关系

| 官方能力 | PCAR 中的用途 | 开发安排 |
| --- | --- | --- |
| 内置联网与深度思考搜索 | 替代手写规划、搜索循环和同步底稿整理 | M9R 核心 |
| 内置阅读链接 | 用户发来文章后直接讨论 | M9R 核心 |
| 独立 Search／Fetch | 精确取回指定网页、必要的正文留存、原生工具的有限补缺 | 保留为底层能力，退出默认长编排 |
| 图片与文件解析、OCR | 看截图、阅读用户主动提供的资料 | M12 的首批可前置子包 |
| ASR／TTS | 语音消息输入和人物回复朗读 | M12 后续独立子包 |
| 深度思考 | 按任务需求深入分析 | 配置能力，不等同于人格反思或成长 |
| 内容安全返回 | 正确处理上游拒答和结束状态 | 接口合同的一部分 |

发布说明覆盖联网、文件、语音及相关基础接口，没有据此证明可以替代任意 MCP 服务、日历、桌面操作或本地执行系统。原生搜索可以减少“为了搜索而接 MCP”的必要性；真正需要外部工具时，再按具体任务实现最小连接。[发布说明](https://api-docs.deepseek.com/zh-cn/news/news261113/)、[构建 Chatbot](https://api-docs.deepseek.com/zh-cn/guides/build_a_chatbot/)

### 3.1 影响架构的接口边界

以下为截至规划日期核对的合同要点，实际接入先做针对性探针：

| 事实 | 规划中的处理 |
| --- | --- |
| 启用内置工具时，JSON 输出模式不适用；部分采样参数会被忽略 | 独立建立原生联网请求合同；不把旧计划和整理的 JSON 参数直接搬过去 |
| 工具用量与模型用量同时存在 | 扩展用量账目，分别计数，不把工具开销记为零 |
| 内置工具不能被 `tool_choice` 强制调用 | 分别记录“Jev 要求联网”和“实际取得资料”，不能声称必然搜索 |
| 搜索素材与读链接的后续可用方式不同 | PCAR 保存自己的可读资料与来源；不把回传包当长期记忆 |
| 联网生成可能在 HTTP 200 后失败 | 依据最终结束状态结算成功、已知失败或未知，保留实际用量 |

上述接口边界见[联网工具指南](https://api-docs.deepseek.com/zh-cn/guides/web_tools/)。开启应用功能后，`max_tokens` 限制的是各步输出，不能作为整轮总费用的硬上限；不要依靠被忽略的采样或工具次数参数控制原生链路。[Chatbot 参数说明](https://api-docs.deepseek.com/zh-cn/guides/build_a_chatbot/)

Chat Completions 的扩展包括 `server_tool_calls`、引用注解及工具进度事件；它们需要单独解析与保存。当前只抽取 `message.content` 的实现无法完整承接这些能力。[Chat Completions 参考](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)

**首版沿用 Chat Completions。** 当前正式路径、费用和恢复已经建立在这一协议上；官方原生能力也覆盖它。首轮同时更换协议、重写人物提示和删除转译，会让退化难以定位。只有实测发现不可解决的缺口，才另立 Responses 迁移任务。

## 4 采用的迁移架构与人物自然度验证

### 4.1 第一交付采用两段式

```text
用户消息 → PCAR 读取人格、当前情境和有效记忆
                    ↓
             原联网权限与 Jev 判断
             ├─ none → v8 人物回复，可用已有资料
             └─ web  → DeepSeek 原生联网任务
                         ↓
                    可用结果、来源和协议回执
                         ↓
                    v8 人物回复
                         ↓
                 PCAR 保存经历与资料
                 按既有政策异步整理记忆
```

原生联网任务只接收完成公开资料任务所需的信息，不携带完整人物原件、隐藏设定、整库记忆或无关私聊。它的结果是工作资料，v8 仍决定如何接话、说多少、是否表达自己的判断。初期普通联网与深入调查采用不同请求配置；复杂检索可用 High，普通对话不因此全部开启高强度思考。

这一形态把旧“High 计划＋工具循环＋High 整理”收敛为一个原生联网任务；在典型联网轮次中，应用层 DeepSeek 生成由三次减少为两次。它保留已认可的人物输出层，也降低搜索阶段接触私有上下文的范围。

所谓公开任务最小化必须落实到输入字段和数据来源，不能只靠一句“不要泄露隐私”的提示词。服务器自主形成查询时，客户端无法逐条提前审批；涉及私有资料且无法形成合适公开任务的情况，应使用已有资料或明确授权范围内的受控查询，不把全量上下文交给原生搜索来碰运气。

### 4.2 然后验证单段式

候选链为“PCAR 上下文＋Jev → 带原生工具的 DeepSeek 人物回复”。它有机会将应用层 DeepSeek 生成进一步减少到一次，并避免底稿再转述。

但单段式会让人物推理、搜索策略和表达处于同一请求；原生功能对采样的处理也可能改变 v8 的读感。是否更自然、是否更便宜，都必须通过比较决定。

采用规则：

1. 先完成两段式的工具、状态和持久化接入，再比较单段式；不维护三套长期生产编排。
2. 比较使用同一人物、同一获准材料与必要前文；保留无法对齐的服务端参数差异。
3. 优先看人物连续性、接话、观点、信息完整性与追问，再看费用和等待。
4. 单段式只有在隐私输入边界合格且读感无明显退化时才成为默认；否则两段式即可完成 M9R。
5. 不为让单段式胜出追加“文风修复模型”或循环改写。若需要常驻修复链，先承认该合并没有达到目标。

### 4.3 保留 Jev 的唯一决定权

| 状态 | 行为 |
| --- | --- |
| 全局联网关闭 | 不调 Jev，不声明联网工具，不执行独立 Search／Fetch |
| Jev 为 none | 不新增外部资料；已有本地来源及底稿可用 |
| Jev 为 web | 执行原生联网任务，实际工具回执决定本次资料取得状态 |
| Jev 异常 | 沿用已有 `policy_fallback`，在原权限内优先联网，独立记录 |

Jev 不负责选择来源、规划查询、检查数字或决定观点。原生模型没有调用工具时，记作本次联网任务未取得资料，不能把它解释成第二个模型推翻了 Jev。

对用户明确要求“请查最新资料／读这个链接”的任务，先检查真实工具结果；若已明确完成但未执行工具，可按预先定义的政策，使用一条最小的独立 Search 或指定 URL 的 Fetch 补缺。补缺是独立记账的新动作，不是重放已成功或结果未知的请求。无法可靠构造公开查询时，不自动再加一个规划 LLM。

## 5 上下文之外的人格与知识

### 5.1 保留三种不同的数据

| 数据 | 用途 | 存储与迁移策略 |
| --- | --- | --- |
| 人格与经历 | 身份、版本、关系、用户事实、真实对话及有效长期记忆 | PCAR 本地权威；按现有迁移政策保留身份和来源 |
| 可读资料 | URL、标题、取得时间、可获得的摘要或正文、模型归纳、适用范围 | 本地持久化；原文、摘要和模型推断明确区分 |
| 原生协议回放包 | 工具调用字段、签名、必要回传内容和协议版本 | 按角色／入口／会话隔离；视为可失效的协议资料，不视为人格权威 |

内置联网未必提供完整网页正文；独立 Fetch 提供可读页面内容。因此，需要长期保存原文、精确引用或脱离当前协议包复用时，才按需取正文；不对所有搜索结果再抓取一次，否则会重新引入重复成本。[Search／Fetch 指南](https://api-docs.deepseek.com/zh-cn/guides/search/)

仅有模型总结时标为模型归纳，不伪装成网页逐字证据。公共知识不能写成用户亲身经历或角色正典；网页内容也不能修改权限和系统指令。来源可追溯是数据职责，不在每条人物回复前增加内容裁判。

### 5.2 当前对话的回传与长期记忆分开

当前原生会话保留官方要求的回传字段，避免框架丢字段后“请求成功、实际上忘掉网页”。协议回放包与普通审计正文分离；思考内容不作为人物自述、不展示给用户、不抽取为长期记忆。确需协议回传的部分按合同保留，不能把普通聊天的丢弃规则直接套用。[Chat Completions 参考](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)

上下文预算不足时，以完整因果单元裁剪用户消息与其原生回复，先形成 PCAR 可读的工作摘要。超出保留窗口或重开会话后，由本地档案、记忆和资料重建一次新请求；不声称仍处于服务端原会话，也不要求把全部历史无限回传。

必须覆盖的恢复场景：立即追问、关闭工作台后追问、新会话谈旧事、上下文裁剪后的追问、跨机迁移、供应商协议包失效。前四者不能靠反复搜索掩盖本地记忆失效；缺少原始网页细节时可以明确重新查阅，但必须据实计费。

### 5.3 跨机与升级规则

M9R 首先增加兼容数据，不重写旧 M9 来源、底稿和账目。正式数据迁移前在隔离库验证。旧请求继续按旧快照解释，未完成请求不自动切到新协议重发。

协议包的本地保存与可携带不代表跨账号、跨型号永远有效；迁移后应能丢弃失效包，凭本地可读资料继续工作。若换用新 API 账号，外部文件标识也不能假设有效。迁移失败的恢复仍遵循现有业务保留与凭据重配规则。

## 7 验收安排

### 7.1 工程与体验分别验证

先用离线固定响应验证状态、字段、账目和恢复，再做最小真实协议验证，最后用原始人物回复进行一次集中审阅。无需重跑全部历史付费批次，也不重新设置长期私人试用门。

建议真实语料由 **12 个场景族**组成，具体数量在 M9R.0 按预算固定：

| 场景 | 必须观察的结果 |
| --- | --- |
| 1 闲聊、情绪分享、玩笑 | Jev none，无新工具；人物正常接话，不主动变成知识解说 |
| 2 明确查询最新消息 | 有实际联网凭据；能回答本轮需求，不只复述泛泛常识 |
| 3 游戏攻略与社区经验 | 能参考社区内容并表达判断，不恢复“只有官方能说”的路线 |
| 4 饮食、出行等日常任务 | 普通任务不用复杂调查；需要条件时保留条件，详略合适 |
| 5 简答后要求完整步骤 | 继续展开所需细节；已有材料足够时不重复联网 |
| 6 发来新链接与后续追问 | 首次真的读取；下一轮能接续链接内容；无法读取时据实处理 |
| 7 需要多来源比较的深入问题 | 资料足够完成任务；保留不同经验与人物判断，避免固定报告腔 |
| 8 同主题跨会话与重启 | PCAR 找回有效知识和经历；不能依赖仍未清空的窗口 |
| 9 更正、撤回、错误信息和外部指令 | 更正实际生效，旧错误不复活；外部内容不变成人格或权限指令 |
| 10 取消、断流、拒答、工具失败 | 各状态可区分，保存费用；成功和未知物理调用不重放 |
| 11 关闭联网、Jev 异常、资料不足 | 原权限和降级政策可观察；不谎称已经搜索或读过网页 |
| 12 升级与跨机迁移 | 人格及历史身份保留；旧笔记可用；新协议包失效也不清空人物 |

两种新架构需要同题比较时，使用新的、预先登记的调用位置并交错运行。历史批准样本只作参考；模型版本或搜索结果随时间变化时，不把跨日期对比当作严格因果实验。保存首次结果，不为让某个方案好看而重生成。

工程定向回归覆盖现有 `test_general_retrieval`、用量汇总、截止／恢复、解耦迁移及受影响的原生聊天测试；新增测试集中在真实新增的工具字段、流式结束、知识持久化与协议包隔离，不按模块数量机械增加测试。

### 7.2 通过与停止条件

**硬条件**：无串人格或串会话数据；无隐藏资料外发；无成功／未知物理调用重放；无重复投递；无把失败写成完成；升级不损失原始经历；Jev 和联网总开关有效。这些条件不能用平均体验分抵消。

**产品条件**：人物感、接话和追问达到已接受基线；常见联网任务有效完成；正文保持 v8 的自然表达；额外机制确实减少维护或改善体验。信息覆盖和普通事实问题可作为样例检查，但不恢复逐数字全量审核后才允许说话。

**比较条件**：记录用户偏好、首次可见正文、整轮完成时间、应用层模型请求、服务端工具用量和费用。小样本以逐例结果及描述统计为主，不用小批 P95 或精确百分比推断长期表现；不将思考或状态事件算作可见正文。

**失败处理**：合同不成立先停止相关真实探针并修复；单段式读感退步则保留两段式，不拖住整个 M9R；原生任务结果未知时不自动换旧链路重跑；已明确未发出的配置错误可以在修复后建立新调用。

## 8 成本与等待的实际控制

### 8.1 先减少重复工作

优先顺序为：复用已取得资料；取消重复的规划与整理；普通和深入请求分开；只有确有长期用途时补取网页；最后再调整模型参数。已有 M8 自动记忆的额度和手动调用规则继续有效，不借本次规划静默改为新的全局限额。

保留两个账目层次：用户可读的本轮总成本，以及内部逐物理调用、服务端计费工具次数和失败用量。遇到供应商未返回的值明确记为未知。

截至 2026-11-15，官方人民币价表列出：搜索和抓取各 5 元／千次，文件解析及 OCR 1.5 元／千页；语音存在限时折扣。它们与 token 费叠加。当前代码的 USD 单次工具估算应改为带币种、价格版本及估算标识的计价记录；历史账目保留原口径，不回写成按新价实付。[官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

```text
一次对话的费用估算
  = Jev 费用
  + 所有 DeepSeek 步骤的输入、缓存输入和输出费用
  + 计费搜索／抓取／图片搜索费用
  + 本轮实际发生的文件或语音费用
```

三次应用层生成变两次，不等于费用必然下降三分之一。深度搜索可能比旧的有限查询更充分，也更贵；报告同时比较任务完成质量和实际总成本。

### 8.2 不把进度展示当费用硬上限

原生请求内部已经发生的推理与工具行为无法由 PCAR 事后撤销。前端取消、断开连接或停止展示，不足以证明服务端立即停止计费。实现时记录取消时点与最后已知用量；对于需要严格逐步费用控制的任务，使用独立工具的受控路径，或在超出可接受暴露前拒绝启动深度任务。

正常聊天不设置为了漂亮延迟指标而截断有效任务的固定等待门。桌面显示简短的实际状态，例如正在查找、正在读网页、正在组织回复；不用每个阶段都让人物发一条机械进度消息。先完成后台流式接收和可靠结束，再决定是否把正文实时呈现；不强制重写已经验收的气泡和投递节奏。

### 9.2 第一优先级仍是持续陪伴

M9R 稳定后，先检查真实交流中的记忆消费：能否少问已经说过的重要信息，能否接续隔天话题，更正是否有效，旧知识是否被无意义重复注入。

既有自然时间衰减、有效回忆强化和分层找回方向保留，落实为一个最小配套包：先做作用域、来源有效性和一次有效消费的去重，再做默认候选缩小与冷资料找回。重复整理、重复摘要和后台扫描不应制造新的经历或强化。它不是恢复已删除的旧高级召回或审核链，也不把大型百科库重新设为前置。

建议在 M9R 保存资料时预留稳定来源和实际消费记录，算法另包实施，避免同一次对照同时改变联网和记忆排序。依据：[认知与召回优先级指导](PCAR-认知与召回优先级开发指导.md)。

G-AUTO 的现有矩阵包含历史 QQ 条目。开工前应按当前“工作台为主要入口、QQ 暂停”的政策重订适用范围，使用明确的桌面范围结论；暂停项不记为通过，不为满足旧表格擅自恢复 QQ。无人值守在当前范围内指工作台／托盘运行期间无需日常管理介入，正常退出停止所属组件，不新增系统服务或自启。[当前状态](STATUS.md)、[原联合矩阵](acceptance/无人值守陪伴-阶段门与验收矩阵.md)

### 9.3 M12 的最小能力可前置

**先做图片和文件。** 从用户主动发来的截图、照片或文档开始，保持同一人物、同一对话和同一记忆来源体系。文件内容首先是这次交流的材料，经过既有政策才成为长期认识；不能因上传一份人设文档就覆盖人物核心。

普通文字文档与图文混排文档分别选择解析方式。官方文档指出上传原件及解析结果不可下载，因此 PCAR 需先保留获准保存的本地原件与必要可读结果，不把 `file_id` 当成本地原件的替代。[文件解析](https://api-docs.deepseek.com/zh-cn/guides/document_parsing/)

建立本地媒体身份到云端文件的映射，记录账号范围、用途和有效期。Files API 可以设置过期时间，未设置时为永久有效；建议 PCAR 明确设置适用期限，并让用户能清除本项目上传的文件。迁移到不同账号后不得继续假设旧 `file_id` 可用。[Files API](https://api-docs.deepseek.com/zh-cn/guides/files_api/)

**再做语音输入，最后做语音输出。** 第一版采用录音后转写、允许用户检查或直接发送的语音消息交互。当前 ASR 是整段识别，上限 120 秒且不支持流式，不能据此安排连续实时语音通话已经可用。[ASR 指南](https://api-docs.deepseek.com/zh-cn/guides/asr/)

TTS 先朗读已经确定的回复，再考虑分段合成和打断。当前文档列出两种预置音色；若这两种声音无法满足角色辨识，先保持文本或让语音可选，不将“能朗读”等同于人物声音目标完成，也不默默接入另一个云端供应商。[TTS 指南](https://api-docs.deepseek.com/zh-cn/guides/tts/)

### 9.4 M10 保留为人格与关系演进

按[社会科学指导](social-science/README.md)区分三类变化：对用户的理解更新、双方关系的适应、角色稳定倾向的演化。前两类可以由实际互动形成有来源的候选，第三类不能由一次联网总结、一次模型自述或一句“我成长了”直接生效。

G-AUTO 之后再做 M8.B／M8.C 的影子观察与独立反思，随后进入原 M10.A／M10.B。Director 是低频变化审查角色，不插入每一句回复；它也使用 DeepSeek，但权限由 PCAR 决定。先验证可观察的行为收益，再开放有限变化和观察期。人物核心、作者设定、显式关系与权限维持现有分层管理。

长远差异化集中在：经历如何改变理解、关系如何影响交流、记忆怎样被恰当地想起、观点怎样有据修正。官方 API 提供基础能力，PCAR 负责把这些能力组织成同一个持续存在的人物。

### 9.5 MCP 与安装体验

外部搜索已由官方工具覆盖时，不再为搜索另搭通用 MCP 系统。未来若出现真实需求，例如读取本地日程或管理用户指定文件，再实现一个明确任务的最小工具连接；先做只读能力，再定义写入、副作用和恢复。原生联网和自定义工具能否共用同一请求，需要单独验证，不能预设兼容。

安装工作先简化现有 Agent 部署，再考虑带运行时的一键安装和可回退更新。M9R 的包继续携带清晰的启用、数据保留、升级和诊断说明；界面可以将云端配置收敛为 DeepSeek 主连接与 Jev 独立连接，后台子用途复用配置但分别计费，不向普通用户暴露一长列内部模型角色。

### 9.6 SnowCat 跟踪与经批准恢复 QQ

## 10 收尾原则与下一次开工入口

当前 v0.1 是已验收的稳定交付；M9R 的开发、验证和候选打包使用隔离实例。正式切换前核对原人物、历史、记忆、来源和调用记录。

M9R.5 通过后，删除失去生产用途的旧计划生成、搜索循环和同步整理逻辑，以及对应陈旧开关和测试；保留解释历史数据所需的兼容读取。已删除的冻结实现不恢复、不重新打包；既有 v0.1 发行作为历史基线，无需再复制源码快照。

回退不等于用旧程序直接打开不兼容的新数据库。候选方案必须明确采用兼容增量结构、版本检查或迁移前的受保护业务备份，并说明回退后怎样处理候选期间新增业务。任何运行时回退都不自动重放成功或未知调用。

**下一次实施从 M9R.0 开始**：固定请求／响应与记忆边界，完成少量真实原生探针，再进入 M9R.1。先交付一个确实可用、可接续、保持人物感的原生联网闭环；其后依据结果决定链路合并和多模态前置的力度。

本规划依据公开官方文档和当前仓库状态完成；尚无 PCAR 原生全家桶接入的真实验收结果。工程工作量减少是架构目标，费用下降、等待改善和自然度提升保留为待验证结论。
