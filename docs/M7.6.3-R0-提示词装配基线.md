# M7.6.3-R0 提示词装配基线

2026-11-01。基线提交 `19bca9ee6407927117ded3bd43d9605716afce40`，候选从 `0.7.6.dev4` 升为 `0.7.6.dev5`。数据库结构 20、导出 17、配置 2、桥接 0.7.2 不变。

本阶段建立可核验的提示词装配起点。没有改写、缩短、去重任何提示词，没有修正词法分类、角色选择、表达采样、气泡协议或发布门。验证对象是模型请求等价，不是模型回复一致，更不是自然度改善。

## 实现范围

| 位置 | 职责 |
|---|---|
| `persona_runtime/prompt_assembly.py` | `PromptBlock` 不可变输入；`assemble()` 只拼接已经渲染的块、历史和当前输入，返回消息及不含正文的分块诊断；负责诊断大小限制 |
| `persona_runtime/context_m4.py` | 保留原选择、裁减、回退顺序和异常；将主回复与供应商测试入口交给纯装配器 |
| `persona_runtime/cognitive.py` | 在原 Manifest 中加入可选 `prompt_assembly`；最终来源复核重建时重新计算；在最终复核和持久化后检查可选字段大小 |
| `persona_runtime/chat.py` | 原 `context_uses` 继续保存原详情；新诊断只进入受大小限制的 Manifest，避免在旧上下文记录里重复保存未裁减诊断 |
| `persona_runtime/desktop_context.py` | 复用原预览、历史入口，新增只读摘要、历史记录选择和可滚动分块表；原始 JSON 保留 |

装配顺序仍是人格与表达、关系、有效临时状态、弱行为提示、展示合同、角色资料、记忆与摘要、明确引用、回复协议、胶囊、历史、当前输入。空块可在诊断中标记“未进入”，不向消息插入内容。原实现不生成的临时状态块也不会被补写。

选择器、情境观察器和记忆整理器只登记职责及原版本清单，没有改造生成链路。辅助登记不是本次请求实际执行这些模块的声明。`existing-organization-render-r0` 只是对原无独立版本号渲染器的登记名称。

## Manifest 合同

`prompt_assembly` 包含装配器版本、请求的表达/格式/胶囊模式、实际表达与格式渲染分支、原输出合同、胶囊是否应用和原因、块顺序/责任模块/渲染版本/消息位置/字符偏移/字符数/指纹，以及已有来源引用和裁减原因。

- 全部字符数使用 Python `len(str)`，即 Unicode 字符数，不是 token。
- 内容指纹与最终消息指纹沿用 `archive.fingerprint` 的规范 JSON 哈希。最终指纹与原 `input_snapshot_hash`、模拟客户端实际收到的消息一致。
- 新字段不包含提示词、输入、历史、设定或记忆正文，也不包含密钥。完整消息仅在运行中的装配/调用路径及明确人工测试快照中存在。
- 新字段最多 16 KiB，以 UTF-8 编码后的 JSON 字节计算；超出时移除块明细、来源引用、裁减列表，保留汇总和 `details_omitted` / `omission_reason`。
- 加上新字段会超过原 Manifest 128 KiB 限制时，删除该可选字段。最终复核与持久化时再次检查；持久化检查位于 Shadow 信息写入之后。原清单本身超限仍保留原错误 `context_manifest_too_large`。
- 原 Manifest 各字段含义不变，无新表、迁移、请求配置、管理接口或策略开关。

表达与格式分开解释。例如 v2 表达可与旧 `context_structured` 格式共存；供应商测试请求即使带 v2 快照，实际也可能只是测试提示。界面分别显示请求表达、实际表达、实际提示格式、输出合同表达版本、胶囊模式及应用结果，不声称“新版全部生效”。装配器版本不是表达政策。

## 界面证据语义

“预览任务上下文”显示“按当前可用来源重建，未发起模型调用”。它仍沿用原受理快照与当前来源复核，不能替代调用时证据。

“查看调用清单历史”只读数据库保存的 Manifest。下拉框切换保存记录，原始 JSON 保留整个响应。旧记录缺字段显示“该历史记录未采集分块信息”，不重建或推测；因大小限制完全省略字段的历史记录同样无法补推明细。

原目标保护仍有效。除人格/入口/请求变化外，同一请求先点预览后点历史时，较迟完成的前次读取也不会覆盖新结果。新摘要没有执行模型、切换新版或修改政策的按钮。

## 对照与验证

装配源码修改前，固定人工输入、ID、时间及请求快照，保存 34 个原实现场景的完整消息、供应商参数、材料选择/裁减/胶囊结果、异常类型和错误码。样例在 `tests/fixtures/prompt-baseline-r0.json`，没有私人设定或冻结独立评测内容。冻结工具拒绝覆盖已有基准，并核对原提交与原运行时代码。

`check_prompt_baseline.py` 逐场景比较上述对象。测试同时比较序列化 UTF-8 字节，防止只比较对象而忽略正文、换行或顺序。额外的集成验证加载施工前保存并校验哈希的原 `context_m4.py`，对同一人工数据库、已选材料和请求执行前后对照；不会修改冻结基准来适配新代码。

覆盖四种回复模式、表达格式 v1/v2/v3、两类供应商的普通/结构化测试入口、无 v2/v2/消融/非法快照、baseline/Shadow/隔离 Assist、胶囊生效与不适用及预算回退、样例/历史/记忆/摘要裁减、必要输入超限、来源撤回/关系屏蔽/状态到期/引用失效、连续更正输入、模拟 QQ 已发送片段、新旧清单、诊断省略及迟到界面响应。

受影响回归包含上下文、v2、胶囊、协议及桌面；没有运行全仓库测试。首次检查暴露历史测试对结构 19/导出 16 的旧断言：当前受影响的两处测试改为基线已存在的结构 20/导出 17；未改变产品结构。另两条由 unittest 自动加载外部导入夹具而带入的人格管理旧断言保留，执行入口收窄为明确的气泡默认类。首次失败证据保留，不计为通过。
