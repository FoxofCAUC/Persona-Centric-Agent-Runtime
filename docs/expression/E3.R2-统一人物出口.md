# E3.R2：统一人物出口

候选`0.2.0rc7／结构32`将人物发言登记为独立单元。同一轮的查前发言与主回复各有唯一发布权，源回执只登记一次；结构31的主回复、发布计划与原始回执继续按原合同读取。

## 运行链路

主回复保存完整源稿后登记`main`单元，继续复用已验证的结构31表达、呈现和回执状态机。查前发言在源请求前冻结口吻、策略和来源证明，原始组织回执持久化后才派发独立表达请求。所有网络调用及呈现等待都在数据库事务之外。

新模型仍只接收两条消息：专责指令与精简`core_traits/style`，以及完整源稿。人物、来源、权限、执行版本、关系及召回证明留在后台。既有提示、历史、当前用户原话和检索资料没有加入新转译输入。

查前发言转译稿完成全部呈现回执后，才允许现有编排启动搜索；该阶段气泡等待为0。实际呈现正文回流为本轮预告，主回复接续同一正文；内部源稿只留作证据。部分呈现后取消，只保留已确认的连续前缀，后续搜索不启动。

标点指导在启用v2的主回复和查前发言上均由转译器负责；原v8对照、未启用转译及旧版请求保持原职责。

## 接口与恢复

管理接口`expression.v2.list/status/plan/offer/ack/visible/pending_receipts/cancel`使用`utterance_id`定位单元，`ack`另外携带`fragment_id`。`plan/status`不返回隐藏正文，只有首次片段租约交付正文；重启核对返回原租约身份。旧的`turn_id`主回复接口保留。

源稿、冻结口吻及来源、HTTP原文、版本化计划、实际发言和呈现回执分别留证。失败、未知或取消不自动重放；迟到回执只补证据，不能替换已确定的发布稿。完整正文有效而分段不符时整块呈现；代码等保护片段丢失时拒绝转译，尚未呈现且来源有效时保留完整源稿降级。开始呈现后不从另一份整稿重新发送。

来源撤回、角色资料变化、取消及提供商许可校验仍在派发和呈现时执行。预告和主回复沿同一根交互结算召回，气泡不重复强化；实验不启用表达学习。系统界面提示、日志和内部协议数据不进入人物出口。

## 迁移与后续接入

结构32增量增加8张表，不替换31的表或协议。31→32先备份；兼容副本支持退到31，暂停新发言权限，保留完整与未知回执，原库不被替换。整库迁移同样暂停表达并只投影已确认的前缀。

未来人物功能必须复用`CharacterOutlet`的持久来源、口吻冻结、单次转译、呈现回执及实际历史合同，并补齐对应来源和载体适配。当前候选只开放桌面主回复与查前发言；启用v2的角色不能静默绕到尚未适配的QQ或主动输出。QQ和主动运行仍暂停，本轮没有恢复外发。

## 验证与推进

175项不同关联检查通过，包括最小输入、原v8职责、旧主回复、查前顺序、取消竞态、未知及迟到、来源撤回、部分呈现、管理权限、召回和配额。实际旧rc6程序读取31兼容副本并追加业务后，再升级32，主稿、表达HTTP回执及发言源稿保真；另已验证整库导出／导入与未知前缀暂停。

本阶段没有新真实模型请求。界面回执使用隔离模拟端，不代表E4真实桌面呈现或E5连续体验通过。正式实例仍保持结构27与原策略，默认表达仍关闭。下一阶段R3完成8组、每条链48轮的独立会话对照；作者明确审阅通过之前不进入E4或统一正式接管。
