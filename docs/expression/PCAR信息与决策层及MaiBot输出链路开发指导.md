## 项目分工

| 模块 | 职责 |
| --- | --- |
| PCAR 信息与工具层 | 受理消息与多条输入，管理版本化人格、会话、长期记忆、上下文检索和召回，从聊天记录还原人设。负责资料预处理、工具权限与实际调用、查找结果落库和来源核验。远期保留自主生活、情绪及状态演化，把获准产生的内容作为信息提供给同一输出链。 |
| PCAR 决策层 | 在发言前确定是否回复、接话目标、交流动作、人物要表明的立场、联网、已选事实及限定、篇幅和收束。需要时可增加独立模型处理证据冲突和事实取舍。专项候选的发布前语义复核由独立阶段完成。Jev 预设按实际场景和误判样本扩展，首批区分闲聊、分享、求助、查后短答、明确长文和收尾。 |
| 去群聊化后的 MaiBot 输出链 | 采用 MaiBot 普通私聊的目标交接、上下文装配、Replyer、分段、发送节奏与发布流程，接收 PCAR 已准备好的当轮材料。Replyer 仅生成角色正文。输出程序负责气泡、长文详情、实际呈现和发送回执，并把回执交还 PCAR 用于历史和记忆。 |

停止扩展 PCAR 自有正文生成和发布编排。新候选只开放去群聊化的 MaiBot 输出入口，逐项断开旧直出、场景卡直接生成、异常兜底、重试和重启中的旧发言入口。范围覆盖查前与查后发言。工作台可以承担呈现和回执采集，PCAR 保存已确认可见的正文，作为之后的会话历史。旧运行效果和原有测试留下作对照。[现行路径与 MaiBot 对照](../research/PCAR与MaiBot发言链路差距复核-20261118.md)

## 去群聊化与当轮交接

- 以已核对的 MaiBot 固定提交 `478f671e64467121fd3e39205c8d3507b5ce0bd6` 为复用基线。优先沿用私聊触发、真实发言目标、Replyer 上下文装配、普通分段和发送后等待。适配时移除群聊频率门控、群聊发言配额、多人参与判定、群成员排序、群内提及和群聊专用材料。PCAR 决策层接管查找、场景、参与时机和篇幅等选择。复用表按上游文件注明保留和替换的接口。[私聊调度](https://github.com/Mai-with-u/MaiBot/blob/478f671e64467121fd3e39205c8d3507b5ce0bd6/src/maisaka/scenes/private/scheduling.py) · [回复与发送](https://github.com/Mai-with-u/MaiBot/blob/478f671e64467121fd3e39205c8d3507b5ce0bd6/src/maisaka/builtin_tool/reply.py) · [上下文装配](https://github.com/Mai-with-u/MaiBot/blob/478f671e64467121fd3e39205c8d3507b5ce0bd6/src/chat/replyer/retro_prompt.py)
- PCAR 的全部相关资源都可供预处理和决策阶段使用。进入 Replyer 的是本轮已获授权、已选定的材料。交接记录绑定回合、会话、人物版本、执行版本和阶段，给出接话目标、交流动作、事实及出处、要保留的限定、表达范围、篇幅与收束方式。联网预告与查后发言各自经过交接。工具失败、权限不足或决策不齐时，由程序按真实状态处理。
- Replyer 仅把交接内容写成角色发言。事实取舍、语气或动作选择、是否追问、是否代办、工具调用、继续或结束都由独立决策阶段完成。发送前核验输入和决策的绑定，有效交接才允许发起正文调用。撤权、版本改变、无效决定或超时停止派发。生成后的事实或行为复核另用独立阶段完成。
- 继续执行角色气泡最多 75 字符的硬上限。普通查后回复用一句短话答到所问，完整底稿和出处留在资料详情。明确请求且 Jev 判定为长文的回合，由输出链在详情视图呈现正文。聊天区仍用限长气泡。已有原稿、真实可见回执和历史显示记录按原边界读取。

## 电力恢复后的细化与实施顺序

1. **细查上游与冻结对照。** 已核对固定提交的普通私聊调度、Planner、`reply`、Replyer 和发送链，列出 PCAR 接入点及必须切断的控制路径。进入施工前，沿现场回执绑定用于盲审的 Windows 程序、角色、实际模型和已获准输入。[组件清单与阶段合同](../research/MaiBot固定版本私聊调用链与PCAR交接.md#复用与剥离)
2. **先修调用链。** 在隔离候选中接入去群聊化输出，打通已定决策与正文之间的唯一交接。复验合法决策才能派发、失效或超时拦截、权限与回执、重启恢复和气泡边界。补齐查后将资料落库、选择证据后短答，以及明确长文的详情呈现。更改模型可见输入时，按既有规则审阅完整装配、用途和接收方。[模型输入与提示词写作总则](../模型输入与提示词写作总则.md)
3. **再盲审正式候选。** 使用同一角色、同一回复模型、相同采样条件、同一批获准输入及相同起始前文。对照现用方案和新方案的实际首答与完整可见私聊，固定位置和连续多轮都覆盖。每条链接续自己的已呈现历史。联网对照用同一保存资料或等价获准证据，避免资料差异替代对发言链的评价。同模型直接角色扮演继续作为体验底线，MaiBot 原私聊作为机制参考。

## 通过条件与 G-Auto 续验

作者盲审确认新方案整体真人感优于现用方案，且达到直接角色扮演的体验底线，才登记专项通过。助手式邀约、无请求的代办承诺、答非所问、回复模型越权判断、气泡超限均按原零容忍标准判定。程序核对阶段职责、首答、实际显示、耗时与每笔调用。允许因增加决策模型带来的延时，用实测记录衡量。

专项通过后恢复 G-Auto，从私有状态的 `reply_quality_pause` 定位原断点和待验项，直接沿用已通过的回执。盲审结论与候选、实际输入、原稿和可见回执一同登记。[原验收断点](../acceptance/G-AUTO-自然跨夜观察.md)
