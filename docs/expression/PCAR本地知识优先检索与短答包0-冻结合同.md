## 2 篇幅合同

字段由程序根据既定阶段与模式填入。J6 选择模式，Replyer 读出准确的可见范围，程序与 J7 都按同一份合同评价原稿。

| 阶段与模式 | 可见气泡 | 字符及句数 | 输出字段 |
| --- | --- | --- | --- |
| 普通私聊 | 按原文分泡 | 每泡最多 75 个 Unicode 字符 | 原角色正文 |
| 查前提示 | 一泡 | 最多 75 个字符，可含自然短句 | 原角色正文 |
| `main + short_answer`，含本地查得和联网后重查 | 一泡 | 单句，最多 75 个字符 | 原角色正文，随句保留会改变含义的限定 |
| `main + long_detail` | 聊天仅一泡 | `body` 单句且最多 75 个字符 | `body` 是引句，`detail` 是用户请求的完整详情 |

装配需显式给出 `phase`、`mode`、`max_bubble_chars`、`max_bubbles`、`sentences_per_bubble` 和 `output_fields`。`body` 用于标记可见正文。普通私聊、查前和短答继续使用纯文本，独立长文采用 `body` 和 `detail` 两个字段。字符口径包括标点和空白。正文原稿合格后按本机显示计划完整呈现。格式失败回执记录超出的约束和实际计数，复核回执单独保存目标、事实等语义判断。一轮延续现行一次修复上限。返工复用仍有效的事实和搜索收据，补足明确的失败细类。已提交的有效资料可以从原回合详情读取。工程实现入口为[正文交接及检查](../../persona_runtime/ordinary_reply.py)、[出站装配](../../persona_runtime/ordinary_providers.py)和[显示边界](../../persona_runtime/bubble_limits.py)。

## 3 本地检索、联网许可和事实版本

1. **管住各自职责。** J1 确定接话对象。J4 使用 `retrieve / none` 判定是否需要检索。程序独立判断本地资料能否回答及本轮是否具备联网许可。J5 选已验证的事实及其必要限定，Replyer 负责写出选定内容。
2. **保证命中适用。** 本地命中同时满足当前作用域、实体和条件、适用时点、覆盖关键事实和可追溯来源。联网权限关闭时继续允许读取本地获准资料。存储暂不可用进入恢复状态。资料不足、过期，或本轮明确要求新链接或当下联网核实而已有证据达不到时，进入原授权流程。
3. **联网先有显示回执。** 用获准查询和本轮授权绑定查前提示。提示实际显示后才能外发。原始回执进入暂存，专职整理输出事实、来源引用和适用范围，由程序校验。事实修订和索引在同一 SQLite 事务提交，使用原查询重新读取已提交事实，再交给 J5。当前会话和已获准的公共增量资料按对应权限读取。
4. **保留生效依据。** 事实键绑定归属、规范实体、属性和适用范围。版本记录包含发布渠道、地区、条件和生效区间。分别保存来源发布、事实生效、抓取与最近核验时间。同事实追加证据，新值生成新修订。传闻、公告、实际版本、争议、更正及撤回各自有状态和来源。问现在使用当前适用证据，问历史按所问的时点取用。
5. **按原回执恢复。** 每次搜索、整理和提交绑定原任务身份。确认已完成的动作沿回执核对。结果未知的尝试沿原身份对账。提交已完成后，重新查库和正文失败的恢复点独立记录。标准授权和已授予会话全流程授权继续由现有接收方及修订机制管理。新增整理用途的材料和实际接收方随对应包审阅。历史已经完成的回合沿其原协议读取。

以上合同在包 2 至包 4 实装。实现时用真实证据指纹、受理号、显示回执和可复核的索引事务对账。[当前检索入口](../../persona_runtime/private_lookup.py) · [已有知识存储](../../persona_runtime/schema_m9a3.py) · [会话授权](../../persona_runtime/session_privacy.py)
