# PCAR E阶段重构：人物回复链路开发指导

2026-11-16采纳。本文是后续E阶段开发的主入口，依据作者本轮决策及[MaiBot机制深读](../research/MaiBot-活人感机制深读-20261116.md)形成。旧E0—E3和E3.R系列保留其真实进度、首次结果及失败记录；与本文冲突的后续安排，以本文为准。

**本次交付为规划落档和既有成果提交。当前源码仍为0.2.0rc7／结构32，正式实例保持结构27与原策略。E.N0—E.N6尚未实施，今晚不启动新阶段或追加真实模型调用。** 后续获得开工指令后从E.N0开始，依次通过素材、研究价值、完整对照与正式接入门。

## 一、目标、已定决策与保留成果

目标是以MaiBot普通Replyer方案为主要参考，把现有v8正文生成与后置转译合并重构为“理解局面→人物直接发言”，让PCAR形成自然、具有角色特点的持续聊天体验。

作者已确认以下决策：

| 决策 | 本路线采用的方案 |
| --- | --- |
| 正文分工 | 前级理解局面、整理信息，Replyer直接形成这次人物发言，不再改写完整主稿 |
| 输入范围 | 开放必要的人物设定、实际交流、关系与记忆、资料状态及表达习惯 |
| 内容取舍 | Replyer可选择回应点、形成观点与建议，尊重用户明确边界与必要信息 |
| 表达学习 | 先精选素材；获准聊天形成提案，作者确认后生效，支持撤回 |
| 本轮互动范围 | 人物回复、连续聊天与发送节奏；自主发起、沉默调度和无人值守留在后续 |
| 模型 | 官方DeepSeek Flash理解，官方DeepSeek Pro发言，Pro关闭思考 |
| 对照 | v8 Flash、v8 Pro、Flash理解＋Pro Replyer三条独立会话 |
| 正式推进门 | 新链正文和整体交流明确优于同Pro的v8，额外等待与费用可接受 |
| 人物材料 | 先提交四种人物口语设定与精选表达，作者审阅后再真实生成 |
| 首批研究 | 四种角色各4个场景位置，共16个位置，最多64次请求 |

旧E阶段以下成果继续使用：E0来源与呈现合同、E2表达资产及版本／撤回／受控学习能力、E3完整回执和恢复、结构32通用发言单元、唯一发布权、已确认正文回流、气泡原文映射与保护跨度。旧正文方案作为未获完整体验优越性认可的候选留档，不改写为已通过。

新路线编号为**E.N0—E.N6**。主线为：人物与素材审阅→小规模生成研究→统一链路重构→完整三链对照→桌面呈现→连续体验与受控学习→正式接入→工作台重构→无人值守收尾→G-AUTO。

允许为本目标解封v8上下文装配、正文生成和表达接点。人格权威、召回资产、来源权限、Jev联网判断及原生深度搜索职责继续由PCAR管理。旧“两项材料、1,200字符口吻卡、完整主稿逐项保留”的限制不再约束新候选；旧版本仍按原合同读取。

## 二、生成链路与职责

### 2.1 普通回复

受理与选材→Flash理解→保存理解回执→装配人物交流语境→Pro生成完整正文→保存正文→本地气泡计划→呈现→实际发言回流。

Flash输出简短的对话局面、相关事实、用户明确条件与资料状态。它不生成完整人物主稿，不指定必须复述的观点清单，不替Replyer设计台词。

Pro结合人物和交流直接形成回复，可以选择切入点、适度联想、表达态度、提出建议或简短收尾。前级材料用于理解与合理取用，不要求全部说出。

新链仍承接这些有实际意义的边界：尊重用户更正、拒绝与操作条件；准确理解资料已取得、未取得及尚未确认的状态；区分参考材料的他人经历和人物与用户的共同经历；保留明确要求原样的文字、代码及命令。不增加逐轮语义审核模型，不恢复逐数字裁决或完整要点复述门。

工程侧通过来源、材料组织、权限、持久回执和验收保障可靠性。人物提示围绕人物和当前交流组织，避免把后台证明、账目与长篇检查清单写进角色发言任务。

### 2.2 Replyer输入与模型参数

借鉴MaiBot普通创意路径，首版固定两条消息组织：

- system：人物身份、性格、具体说话习惯和少量必要聊天要求。
- user：真实交流、当前输入、相关关系与记忆、Flash整理的局面与事实、资料状态和适用表达习惯。

从PCAR已有完整人格及角色资料投影，不建立第二套人格权威。真实发言和内部参考分开，工具日志、内部规划、用量和来源账目不伪装成历史聊天。当前消息、明确引用和必要条件优先；历史沿既有预算选择，可选表达素材先让位，旧消息优先缩减。

解除1,200字符口吻卡限制；每次请求沿用60,000字符容量保护。必要材料超限时留证，不静默截断人格断言，也不额外调用摘要模型。角色例句和情境表达可以使用，不要求逐轮套用。研发目标、台词与句数自由度等元说明只留开发文档。

首版模型配置：

| 用途 | 模型 | 思考 | 温度 |
| --- | --- | --- | --- |
| 理解 | 官方`deepseek-flash` | 关闭 | 0.3 |
| 人物发言 | 官方`deepseek-v4-pro` | 关闭 | 1.0 |

模型、参数与输入随本轮冻结，不随机切换。工具由既有工具链调用，Replyer不直接启用工具。三链实验中的v8 Pro使用同一Pro思考设置；各自首次请求与实际返回模型身份留证。

### 2.3 联网前后

Jev判断→Pro查前发言→确认呈现→原生深度搜索→Flash理解结果→Pro正式回复。

查前发言直接使用人物、必要交流和“搜索尚未开始”的真实状态，不先生成v8源稿再转译，也不额外增加理解调用。查前气泡不叠加模拟打字等待。搜索后接续实际已呈现的查前正文；追问是否重新联网仍由Jev判断，本地资料沿原召回规则复用。

原生联网保持深度思考＋联网搜索。系统界面提示、工具数据、后台知识整理和协议JSON不进入人物出口。

### 2.4 正文与气泡

Pro只返回人物正文，不输出`body＋segments`、候选ID或运输JSON。正文只生成一次，后面不再挂旧转译层。

本地气泡层复用原文跨度、保护片段、完整正文降级、节奏和回执，按段落／自然句界作确定性切分。代码、公式及需整块阅读的引用保持完整；不增删文字，切分失败呈现完整正文。标点用法由人物表达决定，分段器不润色正文、不随机拆字、不制造错字、不新增收费分句模型。

## 三、人物素材、资产和工程兼容

### 3.1 人物与表达资产

首批仍使用青禾、夏栀、宁舟、林川，保留原有差异。每个角色准备一份具体口语设定、12条情境表达、4组供审阅的话语片段，全部标明人工材料；四人合计48条情境表达。

口语设定描述措辞、句式、反应、幽默、认真场景及收尾习惯，沿已有表达资料版本和E2资产管理。作者确认后冻结。三链采用同一份确认后的初始人格与表达设定，v8保持原装配逻辑；新链另外使用场景表达资产，报告明确记录这一差异。

首版沿E2本地检索与多样性选择提供0—5条适用表达，不增加选择LLM，允许没有合适候选。复用MaiBot“情境—说法”的学习和注入方式，暂不引入全库随机抽样、注意力漂移、跨语言生成或随机风格切换。

只收集获准范围的真人消息；自己的回复、内部材料和评测输出不作为真人样本。学习形成提案，作者确认后发布，保留来源、角色范围、版本和撤回。三链对照期间关闭学习，避免实验中途改变人物。

### 3.2 版本、接口与账本

实际工程接入时升级至候选**0.2.0rc8／结构33**，本次规划落档不提前修改程序版本或正式实例。

- 增量保存理解回执与直接Replyer回执，分别记录冻结输入、模型、原始响应、用量和状态。
- 发言单元可引用理解回执或查前状态快照，不再要求必须存在完整源稿；父交互、发言阶段及唯一发布权保持。
- 现有`expression.v2.*`呈现接口和旧`turn_id`主回复接口兼容；新增`dialogue.generation.*`配置、状态和恢复接口管理两阶段生成。
- 普通状态不暴露内部理解材料；调试审阅可查看完整证据。
- 两模型独立配置和冻结，凭据通过受管引用使用；角色许可分别核对Flash理解和Pro发言，不能继续强制表达模型与主模型同名。
- 结构31／32及旧提示版本按冻结合同读取；历史回显、恢复及未来语音消费已确定正文，不重新生成。

### 3.3 失败与恢复

理解材料是内部材料，不能作为人物回复的降级正文。理解或Replyer不可用时保存已取得结果，显示最小失败状态；恢复只补尚未完成且允许派发的阶段。成功或未知的物理调用不自动重放，旧v8不作为隐藏的额外收费调用自动补位。

开始呈现后保留已发边界，迟到结果只补证据。来源撤回、角色切换、取消、迁移暂停和权限变化在派发／呈现边界生效。多阶段与多气泡按同一根交互结算召回，不重复强化。

兼容副本暂停新链，保存内部回执与未知状态，旧程序只消费已确认人物发言。验证旧rc7／结构32新增业务后再升级33，原实例不被替换。

## 五、验收与正式默认策略

### 5.1 体验

作者审阅人物自己的关注、态度和自然反应，以及轻松／认真场景是否贴合角色。四种角色必须保持差异，克制角色不统一改成活泼吐槽型；回复能够取舍，不机械铺满解释、建议或追问。用户更正、边界、必要条件与资料状态须正确承接，正文收益和气泡收益分别评价。

完整三链审阅提供同排版正文、整段气泡会话、内部理解材料展开项、失败、耗时及费用。甲乙丙组内固定、组间随机；相同内容折叠，前文可展开。

正式推进以作者明确认定新链优于v8 Pro为门，不用改字率、句长、问号、气泡数或检查数量代填体验。若单独升级v8 Pro已达到相同或更好体验，保留该结论，新架构不因已有投入自动通过。

### 5.2 工程

检查实际请求与冻结模板一致；人物输入没有内部日志、运输字段或旧完整主稿残留；正文只生成一次；理解、Replyer、Jev、搜索、学习分别记账。验证查前确认后搜索、实际发言回流，以及取消、未知、迟到、部分呈现、角色变化、授权撤回和重启不重复发布。

验证学习确认／撤回、评测不自学习，32→33升级、旧32追加业务回退再升级、正式27业务迁移与未知回执保真。界面验收按需调用Computer Use，屏幕子任务完成立即释放。

### 5.3 正式接入及工作台

E.N6之前保持正式实例原配置。通过后，旧v8和旧转译保留为历史对照与显式版本回退，后续人物自然语言功能须接统一出口；QQ与主动运行仍须遵守对应阶段启用边界。

E.N6后的工作台重构继续落实：默认聊天区呈现人物交流，常规系统状态、阶段、费用和诊断隐藏；高级设置可开启显示。最小失败入口和未知状态核对保留，不诱导重复生成。人物自己说出的查前发言属于正常聊天，不受系统提示显示开关影响。随后完成无人值守闭环并进入G-AUTO。
