# PCAR 即时通讯决策层开发总则

2026-11-21 起，决策层作为 PCAR 的核心模块持续维护。它研究的是收到消息之后怎样理解并参与一次交谈。人会判断对方此刻在做什么、这句话接的是哪一段、自己知道什么、有没有必要查证，以及该怎么接着说或适时停下。PCAR 将其中一部分可以检验的过程落实为程序和独立决策。

同一句话可以是在求助，也可以是在分享、试探或结束话题。先理解这句话在双方交谈中起什么作用，再决定是否推进任务。对话的节奏也取决于对方是否愿意继续、是否给了足够线索。PCAR 让这些可能性进入决策，并保留让人继续说明、改口或停下的空间。

## 原型截断

当前形态是一次有限的原型截断。有限候选覆盖的是我们理解并已经体现在程序中的场景。真实对话含有含蓄表达、双方经历、临时转意和未说出口的信息。相同字句放进不同关系与上下文，会产生不同而合理的回应。模型选项和概率只记录一次具体判断，不能把它们当成人类心理状态的测量结果。

决策层负责在可见信息有限的条件下选下一步。要给等待、澄清、适时停下和按实际证据继续保留空间。后续交流中的新事实、用户纠正和撤回会改变下一轮判断。允许错误被发现和纠正，避免错误进入长期记忆或变成后续决策的默认前提。

## 模块职责

| 层级 | 决定的内容 |
| --- | --- |
| 消息受理与接话 | 从实际收到的输入和引用中确定当前接话目标，判断是否该回应。 |
| 交流动作与语境 | 结合对话和版本化人格，判断当前适合接话、回应情绪、解答、澄清、换题或收束，并选必要的历史与记忆。 |
| 取材和外部动作 | 先判断是否需要查资料，优先使用本地授权来源；有必要且获授权时才联网。事实、出处和适用条件在生成前进入交接。 |
| 表达边界 | 决定回答范围、篇幅和收束。主回复模型用交接和人物口吻完成发言，保留自然表达的自由。 |
| 工作台交付 | 程序核对角色与会话归属、证据和授权有效性、原稿与显示回执一致性，并保存可恢复的进度。 |

当前生产私聊装配保留 J1 至 J6 的六组、十二个决策项。J7 已退出生成后语义复核。现行向量召回由本地原文取材，J5 的结构化选择及前提关系保留在相应分支。现行常见回复有十次 Jev 决策，联网主链由查前和查后各执行八项发言规划，合计十八次。J7 在先前常用路径原已跳过，因此移除不等于这两条路径再减少一次调用。

## 优化与维护原则

1. 从真实对话里的差异提出改动。先找到哪个决定、候选项或交接导致了可见问题。比较改变它前后的行为，至少覆盖同一请求的改述、不同关系或不同话题。只有截获的输出与作者的体验能说明交谈是否改善。
2. 给每个决定写清职责、触发条件、信息来源、输出、消费者和失败时的处理。遇到已有节点可以表达的问题，优先改语境和交接。新增节点需要说明它改变哪一个有意义的行为。长期只有单选、没有消费者、或与其他节点重复的决定应合并、复用或撤掉。
3. 分别检验决策质量、调用开销和表达结果。用同一流程记录等待、实际回答、查前与查后、取材、纠错以及无须外部动作的情况。并发和复用优先受会话归属和授权约束，未确认的物理请求沿原回执核对。
4. 优先研究查前阶段的规划成本。短预告的事实和任务已由前置阶段定下，已审简短预告只消费少量参数。后续用回执核对哪些决定文本阶段实际读取，先验证去掉冗余决定对对话的影响，再迁入当前配置。
5. 对已确认的失败保留证据。下一版重新校验职责和行为，不按单个题目添加关键词、逐项核对或通用拒答门。角色聊天质量仍由作者在真实窗口评阅，提示和决策预设的新文字沿项目审阅规则使用。
