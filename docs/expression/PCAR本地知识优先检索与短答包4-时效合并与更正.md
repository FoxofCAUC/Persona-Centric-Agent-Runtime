# 包 4 · 知识时效、合并和更正

2026-11-20。候选读取协议为 `local-first-v3`。本包在结构 36 的不可变文档和事实记录上构建版本查询。整理预设沿用已审原文，核验台账存入现有业务数据库。新版装配会在源程序支持相应协议时启用，旧装配和已冻结的旧回合继续按原合同读取。

## 同一个问题怎样随时间得到不同答案

- 本地查询先核对作用域、会话授权、来源可用性、主体、属性、单位及条件，再核对适用版本和时点。查询当前实装时取该版本的观察记录。明确问爆料或公告时保留对应证据状态。明确给出历史日期时按生效起点和排他终点查询，爆料和公告还需在该时点已有可确认出处。
- 数字版本按各段数值比较，支持「1.10版」「版本：1.10」「v1.10」等写法。原文有明确的单一版本而整理结果漏了该限定时，程序可从引文补记。地区、平台、渠道和计量单位属于事实身份的一部分。相同条件下仍有不同值时进入待核实；最新可用版本已过期时，触发沿原有授权补查。
- 同源同内容复核只保留一份文档正文，分别记录取得回执、核验时间和那次来源的标题与发布日期。不同来源支持相同事实且适用区间和证据状态一致时，合为一条作答候选。资料详情可查看各来源原句、链接和位置，台账以编号回指每次核验。相同内容指纹标记同文，额外来源不自动认定为独立验证。
- 同一主题拥有稳定的事实编号。值、版本、状态或生效区间变化形成对应修订。写入在同一次 SQLite 事务中建立有依据的接续关系，包括已生效的新版本、爆料得到公告或实测确认、同页有较新发布日期的改值，以及操作员显式指向的前序修订。晚到的旧页面按原始日期归位。
- 当前候选的主引文在派发前与显示前重新核对。新增佐证可以出现在资料详情；主引文已撤回或修订失效时阻止旧稿发布。详情中的证据列表按当前可读来源生成。多个来源的完整台账留在本地，发送到模型的是选中的文字与出处。

## 整理模型

专职整理固定使用官方 DeepSeek 端点的 `deepseek-flash`。每次派发从主模型配置取凭据，并核对与该次已授权的端点和账户一致。主 Key 完成轮换及相应接收方授权后，后续整理请求使用新 Key。隔离验证在实际 HTTP 客户端提交之前截取了两次请求，覆盖主模型名与整理模型名不同、临时测试 Key 轮换以及 JSON 输出。核对记录只保存模型、端点和比对结果。

## 更正、撤回和恢复

现有本地工具 `scripts/pcar_local_knowledge.py` 的 `admit-public` 和 `admit-turn` 支持版本化准入。经授权的结构化更正可指定同一归属和主题的 `previous_id`。查询使用 `query`，撤回单条证据使用 `withdraw`，撤回一个文档内容版本及其相同归属的副本使用 `withdraw-document`。工作台已有的来源更正立即使原来源绑定失效。在有效的会话全流程授权下，后续整理可以使用用户更正的来源原文，并留下独立引证。

自动备份恢复先验证原快照，再在独立恢复副本与当前实例对账。已授权且来源可重验的修订可接续，已撤回、授权失效或无法证明仍可使用的旧材料退出投影。快照缺少后续私聊来源回执时，相关旧事实停止复用，下次提问沿原流程补查。当前实例不可读时，恢复副本暂停使用其中的旧本地证据。恢复回执分别记录快照指纹、交付数据库指纹和对账计数。
