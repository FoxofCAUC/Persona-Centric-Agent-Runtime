# E3 表达收益复核与提示词职责诊断

本页为修订前诊断时点。作者随后已明确实施[最小输入新路线](E3R-成稿转译修订路线.md)，当前[R0及首批16位研究](E3.R0-R1-冻结与首批转译研究.md)已交付，等待首批价值确认；以下暂停和旧结果保持历史记录。

2026-11-16，作者要求暂停开发，并明确：气泡组织已有成效，正文表达未见明显改善。表达层的目标是把主模型的最终输出改写为更贴合角色、自然且适合即时通讯的话语；消息内容和回应策略由主模型确定。

**当前结论：气泡组织的收益保留；本版正文再制未通过体验审阅。优先复核提示词职责重叠，开发和E4继续暂停。** 本轮只读取已有请求、回执与结果，新增模型调用0，运行代码和提示词未修改。

## 1. 作者反馈与实际作用

12轮正文差异中，G08-1、G13-2无明显差别，其余10轮主观上更偏向已保存主稿；没有一轮表达稿获得优先选择。其余36轮正文逐字相同，未纳入这次逐项主观评分。

表达层确实执行了48次独立模型请求。48个发布计划都来自表达响应，正文也与首次响应逐字一致，未发生统一回退主稿或显示错版本的问题。36轮相同正文是表达模型原样返回的结果。

气泡方面，48轮中41轮形成多个气泡；36轮正文相同的结果中，30轮有多个气泡。这个作用与作者肯定的气泡收益相符。实际桌面节奏仍属于尚未实施的E4验收范围。

## 2. 实际提示词存在职责重叠

两套提示词字面不同，核心职责都要求模型以人物身份参与当前交流。48组主回复和表达使用同一驱动模型`deepseek-flash`。

| 位置 | 实际发送的关键指令 | 当前职责 |
| --- | --- | --- |
| 主模型 | “你就是下面这个人物，正在和对方私聊。用自己的口吻参与眼前的交流。” | 根据当前消息、人物和上下文生成回复 |
| 主模型 | “随口说此刻真正想回应的内容……意思到了就收住。” | 已经承担自然私聊表达 |
| 表达层 | “你是青禾。人物资料……” | 再次建立人物回复者身份 |
| 表达层 | “读之前的聊天记录，把握当前话题，在JSON的body字段中写出日常且口语化的人物发言。” | 仍以当前话题生成人物发言 |
| 表达层 | “把主稿里要说的内容接到眼前的私聊里，用人物此刻的语气表达。” | 指向再表达，但未把成稿改写确立为唯一主体任务 |

表达层末条输入同时携带`当前消息、本轮已经说过、主稿、保护片段`，前面还有人物投影和真实聊天历史。它增加了主稿和表达候选，但仍保留Replyer的回复生成任务形状。

模板来源可以定位到`expression_protocol.py`的`REPLYER_TEMPLATE`和`build_messages`；`expression_realizer.py`将运输职责限定到JSON的body字段，仍保留“把握话题、写出人物发言”的生成指令。它适配了上游普通Replyer的装配方式，后置编辑职责没有充分分开。

这已经证实提示词的职责重叠。它是否是原样返回的主要原因，尚未进行独立替换对照；当前最合理的优先验证方向是职责分离。同一驱动模型仍可执行不同任务，关键是第二次请求是否提供了清楚、不同的操作目标。

## 3. 实际改动也没有体现充分的表达重构

12轮有差异的正文中，5轮只改变标点、空白或引号。其余改动也多为局部增补或小范围替换。例如：

- G02-2新增“不一定要出门，坐窗边发会儿呆也行。”，增加了一条原稿没有的具体建议。
- G09-2新增“别郑重其事地道歉。可以说”，继续给回复策略和编辑指导。
- G13-2把“之前”换成“刚”，作者判断无明显差别。

这些差异支持“改写任务不够明确、部分结果继续增补回应内容”的诊断。它们不构成对人机感的系统改善证据。

本轮40次表达输入获得候选，22次响应自报参考过候选，其中17次正文仍与主稿相同。自报参考只是追踪信息，不能当作风格收益。试验资产为每个隔离人物的4条人工通用风格模板，学习任务为0，尚未形成丰富的角色表达习惯材料。当前结果评估的是这一套PCAR适配组合。

## 4. 按作者目标重新界定职责

| 内容 | 职责归属 |
| --- | --- |
| 事实、观点、建议、回答范围、必要条件、是否追问及承诺 | 主模型确定，形成最终主稿 |
| 用词、句式、口语化、省略、语气、人物习惯和私聊节奏 | 表达层改写已确定主稿 |
| 当前消息与必要前文 | 帮助选择称呼、承接、熟悉程度和语气，作为改写参照 |
| 人设 | 约束同一内容应呈现的声线与表达习惯 |
| 气泡组织 | 保留现有有效成果，与正文收益分别验收 |

表达任务应围绕“把这段已确定的话，改成这个人物此刻会在聊天里发出的说法”组织。允许重构句式、合并机械重复、自然省略和改变信息展开方式，同时保持主稿实质意思、必要条件、否定、承诺、不确定状态及代码／逐字片段。

“更活泼”结合角色、关系距离和当前话题确定。轻松聊天可以更有即时互动感，认真任务保持该人物清楚利落的表达；不把所有人物统一成同一种口癖或热闹程度。

当前工程顺序中没有在表达后再次检索知识、重做Jev路由或重跑主模型。需要优先纠正的是给表达模型的工作任务，避免它再次面对当前消息决定如何作答。

## 5. 额外代价与后续验证边界

48次表达调用使用46,797已知tokens，按试验时官方峰值价格保守估算CNY0.159084，实际金额未知。单次表达调用中位耗时约2.12秒，平均约2.55秒；这是调用耗时，尚非实际桌面首泡等待测量。

恢复开发前，应先确认成稿改写职责。后续验证若获授权，应使用同一批已保存主稿，对比主稿、现有已保存表达稿与职责分离后的新候选，保持模型和必要语境一致，以作者读感、角色一致性及内容保持判断收益。现有成功或未知调用不重放，气泡收益单独保留。

当前仅形成诊断和职责约定，没有修改提示词或运行新对照。E4不启动，原有输入、Jev、搜索与主回复链保持。
