场景发言已纳入 v0.2 的 Windows 桌面包。默认按角色关闭，配置需要自备相应获审材料和授权。[v0.2 部署手册](../../AGENT_INSTALL.md)

## 验收基线

作者已通过 D4。两段各 15 轮的桌面正文与补验一起归档。独立查找出现在 1-11 和 2-05，分别在查前发言可见后启动。1-12 和 2-06 均直接复用同段资料。作者确认自然度、等待、费用和整体体验可接受。完整记录见本机 D4 审阅包。

E.N6 候选为 **0.2.0rc9／结构 33**。桌面角色启用的是 D4 已审的 Jev 判别说明与五份场景提示。确认版本的提示正文、判别依据、Jev 1.14 的响应计时方式与短气泡规则随同冻结。正式业务人格材料在本机私有目录交付，使用已核对的原人物身份与人物资料版本。

## 默认策略与发言合同

普通桌面消息受理时冻结人物、会话和场景材料版本。启用的角色由 `jev-1.14` 对本轮全部气泡、最近两轮及显式引用进行单选。判别范围不携带角色提示正文。单选不确定、超出预算、会话内请求失败或线上的等待到期时采用独立兜底。迟到回执只记账。当轮查前发言与主回复共用这一份提示。查前发言取得桌面可见回执后，才放行原生深度搜索。查找发送使用既有公开问题授权。

主回复一次生成。原始回执、显示计划和可见前缀分别保留，只有可见前缀进入历史、召回和后续上下文。重开使用本地回执。部分呈现时被取消或被新消息中断，保留已有发言和已发生的调用。未知呈现保留原身份，仍停在已经确认的边界。回退后新回合使用原 v8 Pro，历史仍按实际呈现内容读取。

新安装与迁移副本默认关闭场景路线。每位人物须绑定单独获审的材料、人物版本和提供商授权。本次提供一位已审人物的本机材料。QQ 和主动运行的入口继续遵循各自启用状态。

## 安装与回退核对

1. 核对候选包清单与 SHA-256。解压至新的程序目录，保留原程序和原业务实例。先在隔离副本运行升级和回退，核对旧会话、原回执和已确认正文。
2. 导入业务迁移包后，恢复目标机器的模型配置并完成迁移核对。将目标人物的聊天方案设为 v8 原生私聊。主回复使用官方 DeepSeek Pro，Jev 使用获审连接的 `jev-1.14`。只有拟启用的角色需要安装本机私有场景材料。
3. 停止候选实例的桌面和服务后执行以下命令。路径、人物 ID 和两个校验值以随附私有交接记录为准。启用校验核对人物材料、模型地址和许可。启动后通过普通桌面使用。
4. 回退时先停止目标实例，再用 `disable` 冻结尚未完成的场景项目。已确认部分留在历史，未确认部分保留回执。先在结构 33 上检查 v8 回退，旧版检查使用独立兼容副本。随后在副本用旧读取器新增一轮，重新打开候选并核对新旧业务都可读。

```powershell
python scripts/pcar_scene_voice.py --home $Instance --persona $Persona status
python scripts/pcar_scene_voice.py --home $Instance --persona $Persona enable --approved-material $Material --catalog-sha256 $CatalogHash --approval-sha256 $ApprovalHash
python scripts/pcar_scene_voice.py --home $Instance --persona $Persona disable
```

代码候选包可独立安装。私有材料随目标人物在本机核对，授权记录与源稿保存在业务证据目录。实际部署和正式范围验收由作者确认，之后进入工作台重构。
