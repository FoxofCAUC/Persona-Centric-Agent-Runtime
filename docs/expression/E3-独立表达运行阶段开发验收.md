## 1. 主稿、表达与实际发言

主调用完整返回后，在供应商子任务内先保存主稿正文、原始模型文本、物理调用身份、校验结果、上下文来源和用量，再允许独立表达请求。完整响应与取消竞态中，已收到的主稿也能留存；本地保存或后处理失败不触发第二次主模型请求。

表达任务消费已保存主稿、获准的人物表达投影、真实可见历史、已说查找前发言和E2候选快照。沿用作者选定的`expression-json-scoped-v3`，角色发言在`body`，片段映射回该正文原文。代码及结构明确的逐字片段保持。分段失效而表达正文有效时，使用完整表达正文；运输或整个表达结果不可用时，降级到已保存且来源仍有效的主稿。

普通聊天状态和呈现计划只暴露主稿身份／摘要、表达状态和片段元数据。正文通过逐片段授权发给呈现端。每个根交互只有一个发布权，表达稿与降级主稿互斥。

呈现端确认后，片段追加到实际发言表。全部结算或明确结束时，只将确认呈现的正文合并为一个既有聊天事件。隐藏主稿、尚未呈现的尾段和呈现状态未知的正文不会成为后续对话历史。该角色／会话的下一主调用等待上一发布计划结束，已受理输入继续保存在队列中。

`turn.status=completed`表示生成已完成；实际呈现以`expression.publication.state`和回执为准。E4接入时应据此区分生成完成与显示完成。

## 2. 故障归宿

| 情况 | 保存和后续行为 |
| --- | --- |
| 主调用没有完整结果 | 沿用已有失败／未知账目与重放保护，不派发表达 |
| 完整主稿之后进程或本地处理失败 | 保留主稿；显式继续表达阶段，不重跑主模型 |
| 表达派发前权限或资产变化 | 重新核对已用来源；可用时降级主稿，否则停止 |
| 表达请求已发送、结果未知 | 保留一次物理请求和未知用量；默认降级主稿，不重发该表达请求 |
| 完整表达响应后本地处理失败 | 从保存的首次HTTP响应恢复解析，不新增调用 |
| 降级发布之后迟到表达结果到达 | 保存原响应和用量，只作迟到证据，维持原发布权 |
| 首次片段授权之前表达来源失效或表达关闭 | 原计划作废，使用新版本的已保存主稿计划 |
| 主稿已用记忆、引用、人格或云许可失效 | 主稿与表达稿一并阻止；已确认说出口的内容继续保留 |
| 已授权／部分呈现之后发生变化或用户停止 | 取消剩余待发内容；已授权但未确认项保留未知，不从整稿重启 |
| 重复回执 | 相同身份与内容幂等；冲突回执拒绝，不重复写聊天事件 |
| 呈现端重启 | 原租约可按呈现端身份只读核对，不重新交付正文，再按已知结果补原回执 |
| 切换角色或会话错配 | 阻止正文授权；原呈现端仍可结算自己已取得的租约 |

表达请求的供应商原始响应与已派发请求合同不可改写；主稿回执、计划版本、实际发言和回执历史为追加记录。运行时不在线循环重写、不增加付费选择器或付费分句器。

## 3. 权限、召回和账目

表达用途使用独立的角色／提供商许可`expression`，受限学习另用`expression_learning`。私人角色已有主回复许可不会自动扩大到这两个用途。已用记忆、摘要、历史、显式引用、已说预告和知识来源在派发及呈现前复核；E2候选继续使用来源、范围、版本和撤回规则。

本轮只在主调用完成处增加持久回执接点，并在后置表达与实际呈现处扩展，具体范围见[核心扩展清单](E3-核心扩展清单.json)。Jev判联网、人物查找前发言、原生深度搜索和v8原提示／编排保持。

主回复用量保留在原逻辑attempt与主稿回执，表达请求在`expression_runs`按独立attempt保存用量与原始响应。普通状态可分别读取主回复`usage`及`expression.run.usage_json`；未知保持空值。学习仍按E2作独立任务计账。

实际发言结束时，仅向原主调用根提交一次召回反馈。表达请求和多个气泡不另计消费；预告与主稿沿既有同根规则合并强化。来源已撤回的反馈按已有校验拒绝。

## 4. 呈现与维护接口

以下动作沿用已认证的本机`/v1/manage`，使用`{"action":"…","args":{…}}`。桥接凭据无权调用。

| 动作 | 关键参数／结果 |
| --- | --- |
| `expression.policy.current` | `persona_id`；默认关闭 |
| `expression.policy.update` | `persona_id, changes, expected_revision, operation_id`；版本检查、操作幂等 |
| `expression.status` | `turn_id`；主稿身份／摘要、表达状态／用量、发布状态 |
| `expression.presentation.plan` | `persona_id, session_id, turn_id`；计划ID／版本及片段元数据，不含正文 |
| `expression.presentation.offer` | 上述范围及`publication_id, revision, ordinal, presenter_id`；首次授权一个正文与`lease_id, body_hash` |
| `expression.presentation.ack` | 范围及`utterance_id, lease_id, presenter_id, receipt_id, body_hash, state`；状态为`presented/not_presented/unknown` |
| `expression.presentation.pending_receipts` | 范围及`presenter_id`；重启后核对原租约，只返回身份／状态 |
| `expression.presentation.visible` | 范围；只读已确认的片段 |
| `expression.fallback` | `turn_id, reason`；使用保存主稿，不调用模型，已授权后禁止整稿替换 |
| `expression.cancel` | `turn_id`；关闭后续发布权并保留已呈现／未知项 |
| `expression.resume` | `turn_id`；受管继续表达阶段，已成功／未知请求不重放 |

`chat.cancel`同时取消本进程持有的运行任务。`expression.cancel`关闭发布权，供呈现侧控制使用。回执证明应用报告已呈现，不代表用户已读；无法确认的呈现项需保留未知并结算原租约。

E4呈现端须持久保存自己的身份、原租约和显示结果，再提交回执；网络断开后先核对原租约，不能以重新请求正文代替恢复。新输入到来时的可省略补充取消、实际等待和逐条显示在E4实施。

维护入口为`scripts.pcar_expression_runtime`，显式指定`--home`与请求文件，提供策略、状态、计划、已呈现内容、降级、取消及结构30兼容副本；该工具不派发模型。运行中恢复使用上述管理接口。
