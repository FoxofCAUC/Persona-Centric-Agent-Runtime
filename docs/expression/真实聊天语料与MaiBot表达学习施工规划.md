## 1 目标与开发顺序

目标是让PCAR从获准的真实交流中积累表达方式，结合既有人格和当前对话，由人物回复模型直接说话。学习需要保留原话为何在那个场合出现、由谁对谁说、哪些部分是引用；最终收益由作者对人物发言的审阅确认。

本施工主线采用MaiBot已实现的**真实语料提炼→表达资产积累→按语境选取→人物直接发言**。这是一条可持续的应用层学习链。SFT／LoRA等权重训练另列于第13节；当前聊天API调用、资产入库及向量检索均不记作模型权重已经更新。

整体顺序调整为：

**来源与输入审阅 → 文件导入及可选静默采集 → 真实语料整理 → 小批表达学习 → 有无表达库对照 → 新回复链工程接入 → 完整三链审阅 → 桌面与连续体验 → 正式迁移封口 → 工作台重构 → 无人值守收尾 → G-AUTO。**

沿用E.N0—E.N6，不新增M阶段。本文以E.L0—E.L6标识其中的语料学习工作包，便于单独交付和验收。SnowCat试点作为E.L1-Q分支，文件路径可以独立完成学习主线。

| 本规划提出的决策 | 实施含义 |
| --- | --- |
| 语料先行 | 先取得可追溯的真人原文，不再用代理自拟样本填满测试数量 |
| 两类来源接同一入口 | 文件导出和SnowCat事件都进入独立语料库，人物业务历史不直接接收群聊 |
| 小批学习后确认 | 模型生成表达提案，作者决定具体角色能否使用；批次可统一审阅 |
| 同模型检验学习收益 | 新Replyer在其他输入相同的条件下比较有／无表达库，再与v8 Pro比较 |
| 沿用人格权威 | 表达学习不自动改写身份、经历、关系、事实记忆或长期价值观 |
| 来源权限贯穿全链 | 撤回后停止新派发、发布和选用，已发生调用及实际发言如实留证 |
| 体验决定是否推进 | 气泡、资产数量、改字率和工程检查不能替代正文自然度判断 |

## 5 数据来源与采集施工

### 5.1 文件路径优先完成

先支持用户交付文件，按实际来源选择解析器。首个适配器以取得的真实文件为准，不为等待全部格式耽误先完成一条路径。

| 输入 | 首版处理 |
| --- | --- |
| Moect v1.3.0 JSON／JSONL | 识别导出元数据、消息对象、说话人、时间、消息ID、引用及转发；与同批TXT／MD核对 |
| Moect TXT／MD、WechatExporter Text、QQ官方TXT | 各自固定版本和格式识别；保留文件内记录位置、时间和原句 |
| 其他TXT／MD | 先显示解析预览及未识别区；没有可靠边界时只存原件，不猜发言者或自动拼成训练对话 |

TXT／MD用于作者阅读，结构化副本用于程序处理。工具标题、导出说明、Markdown排版、引用标记及媒体占位须识别为包装或类型信息，不作为聊天口吻学习。多行正文不能按每一行误判为一个人发言。

首次连接微信、读取密钥、备份设备属于实际平台操作；使用版本、账号和目录落实后再执行。Moect读取进程的路径与WechatExporter解析已有备份的路径分别记录。QQ Chat Exporter当前仍依赖NapCat登录，不作为脱离第三方接入风险的证明。具体操作见[文件导出候补](../research/微信与QQ群聊文件导出候补方案-20261117.md)。

## 6 独立语料库与数据合同

### 6.1 保存布局

原始群聊存放在作者选定数据目录的私有corpora区域，使用独立SQLite索引和原文件；不默认写进Git、公开附件或人物聊天库。对外导出采用JSONL＋manifest，TXT／MD作为阅读副本。

| 对象 | 主要记录 | 用途 |
| --- | --- | --- |
| 数据集与导入批次 | 来源类型、工具／版本、账号范围、导出范围、文件摘要、格式／时区、解析器版本 | 重现一次导入并识别缺口 |
| 原消息 | 本地ID、平台ID、群、说话人、时间、原始位置、顶层文字、消息类型及原始摘要 | 保留真实语言与定位依据 |
| 交流关系 | 回复目标、引用来源、转发关系、撤回状态、时间邻近候选及关系可靠性 | 恢复多人交流，区分正文与引用 |
| 身份与用途 | human／self／known_bot／unknown、许可范围与版本、有效期、撤回记录 | 决定采集、处理、上传及表达使用范围 |
| 可学习视图 | 稳定匿名身份、脱敏后的原文、原文跨度映射、排除项与原因 | 冻结模型允许看到的材料 |
| 交流片段 | 有序消息集合、目标发言、上下文、关系与缺失标记 | 构成学习和审阅单元 |
| 版本与分区 | 数据集版本、片段清单、去重组、学习／开发审阅／最终留出分区 | 防止评测材料被先学到 |
| 派生依赖 | 片段、学习任务、提案、资产、候选快照及人物使用记录 | 追溯和撤回 |

首版字段需包含`dataset_id`、`batch_id`、`message_id`、`speaker_id`、`source_locator`、`text_hash`、`permission_revision`、`view_hash`、`fragment_id`和`split`；模型材料只按获准装配投影，不把这张后台字段表全部塞给人物。

### 6.2 解析与身份

保留原文件字节并记录编码，解析出的字符串另存；统一传输编码不改写标点、表情、重复字、换行和连续气泡。导出程序添加的标记与原句中的相同字符按格式上下文区分，不能全局替换删除。

平台身份用稳定匿名标识表示，原身份映射独立保存；低熵QQ号不以无盐哈希冒充匿名化。昵称可变或重名时不合并身份；没有稳定身份的文件保留“不确定”，由作者核对后决定能否用于目标发言。

同一次消息从多个文件重复取得时保留全部来源定位，再归为同一消息。没有可靠平台ID时，只做有证据的重叠匹配；不能因两条正文相同就吞掉真实的重复发言。冲突记录并存，后续选择依据可追溯。

### 6.3 多人交流组织

明确回复边优先，时间邻近只用于补充上下文。同一时刻不同话题不强行拼成一问一答。学习目标为获准的真人顶层发言，引用和转发保留自己的作者及关系，不归给转发者。

目标发言和上下文分别标注。所有实际上传文字都需要对应用途许可；仅作为上下文也不豁免。未知来源、机器人或PCAR输出不作为真人学习目标，群内真实人类转贴的AI文本依已知来源排除，不能用“像不像AI”自动推断身份。

不足以解释目标发言的片段可留作原件，不能由代理补写前文或理想后续。图片、表情包、语音和文件首版只保留类型及缺失状态；依赖媒体才能理解的片段暂不进入文字学习目标。

### 6.4 脱敏、分区与保留

预先确定允许处理的群、发言者、时间、提供商用途和保留期。脱敏记录具体替换位置，尽量保持句法；改变意思或受话对象的片段退出当批，不调用另一个模型重写“匿名版本”。小范围试点由作者核对脱敏结果。

先按完整回复链、时间段、群及近重复组划分，再选学习目标。建议首个足够规模的数据集按约70%学习、15%开发审阅、15%最终留出，比例为容量安排，完整片段优先；少量材料按预先登记的片段清单分区。最终留出不用于选提示、调检索或补充表达库，发现跨区重复须先修订分区。

范围撤回、用途撤回、到期清除分别执行。默认先禁用来源与所有下游使用，再处理原件、派生视图、请求负载、资产、索引、导出和备份。已外发请求不能宣称自动从提供商处收回。删除方案必须注明仍保留的哈希／状态、实际清除的内容和待到期备份。

## 7 表达学习流程

### 7.1 首批材料与模板审阅

先用一个已批准来源的小批原文验证全链，建议首次导入不超过2,000条消息，便于核对解析及范围；这个数是试点工作量，不是自然度门槛。来源通过后再扩充群、时间和风格覆盖，不追求尽快填满表达库。

作者审阅的材料包包含：原文与上下文、脱敏差异、学习／留出分区、拟使用的上游模板原文、PCAR现有适配差异、完整请求预览、具体模型及最大预算。原E2首尾追加指令和模板替换均在预览中可见，不能漏审。

新学习任务采用独立协议版本，例如`corpus-expression-learning-v1`。名字只是工程版本；自然语言内容须来自作者批准的材料。群聊中的请求、命令和其他发言作为数据；数据与任务指令的运输边界，以及是否具有工具能力，由装配和运行权限控制。

### 7.2 任务准备与派发

1. 对数据集、人物、用途、目标发言及全部上下文重新校验，剔除未获准材料；出现缺失时整批回到准备状态，不能静默变更已批准请求。
2. 固定目标来源列表、上下文列表、精确可见文字、模板及装配器摘要、模型配置和数据版本，生成请求预览及唯一任务身份。
3. 先持久保存准备结果和派发身份，再在数据库事务之外进行一次模型调用。跨文件路径的来源和计费记录均能定位回该任务。
4. 保存首次完整HTTP回执及用量，随后本地解析；成功、未知和无效输出位置不自动补跑，修复解析器可重读原回执。
5. 派发后来源撤回时，保留调用事实并阻止提案生效。未派发的过期任务终止，旧任务不能靠更换operation_id重新扣费。

首版研究每批最多10个目标来源，完整请求沿用12,000字符保护；上下文与模板也计入总量。必要上下文放不下时按完整片段减少目标，不截断原句或额外调用摘要模型。目标数量与上下文数量在新协议中分开记账，旧E2的来源列表仍按旧合同读取。

### 7.3 输出与人工发布

复用情境、说法和来源编号的提案形式。程序从冻结原文取证据，不相信模型自行复述的“原话”。来源必须指向本批允许学习的目标发言；只存在于上下文、编号越界、原文摘要不符或引用关系不清的候选不发布。

保留完整模型返回，同时登记本地接受和拒绝原因。表达内容可以包含真实口语及有代表性的措辞；结构检查不把口语统一修成书面语，也不以短句、问号数量或词表判断是否有人情味。

作者审阅情境是否成立、说法是否自然、是否含私人身份或群内特定经历、适合哪些角色及使用范围。提案分为待审、接受、拒绝、来源失效；拒绝后不能进入候选集合。作者修改自然语言时生成新版本，再按该版本发布。

发布沿用E2角色隔离、来源版本、禁用和回退。相同表达可合并多个有效支持来源，但调用次数、出现频次、发出气泡数和用户满意度分别记账；不把高频自动当成更好。

### 7.4 连续学习

首次试点按**2批→作者判断提案价值→最多追加6批**推进，共最多8次学习请求。首批没有形成可用表达时停止当前候选，记录问题位于语料、提炼还是选择环节；不循环换措辞、换种子直到出现满意输出。

研究期显式启动有限批次，不安装常驻学习服务。后续E.N5才验证在已批准范围内增量收集、提案、人工发布和撤回；正式对话与后台学习各有预算，工作台退出即停止新任务。评测产生的人物输出永远不会自动回灌为真人材料。

## 8 资产进入新人物回复链

普通回复采用：**真实输入与获准上下文→Flash理解→冻结理解结果→本地选择表达→Pro直接发言→保存正文→气泡呈现→实际发言回流**。不再接旧完整主稿转译。

检索使用当前交流及实际生成的理解结果，选择已发布且来源有效的资产。初版继续0—5条和3,000字符上限，无合适候选则为空；容量不足先移除可选表达，不挤掉当前消息或必要背景。检索分数、资产ID、审阅状态和来源账目保留后台。

首版实际使用“情境—说法”资产，原文证据供审阅和追溯，不把整段群聊逐轮注入人物。若之后确需加入真人例句，属于新的材料投影和对照变量，先审阅具体例句与装配，不由代理改写补充。

当前E2的Embedding只重排已有词项候选。若实际留出材料显示同义情境漏召回，先保留失败查询和正确资产，由作者核对；经该证据再增加版本化本地语义召回并校准阈值。首版不直接套用MaiBot全库随机抽样，也不为提高命中率强制填满5条。

查前发言仍先于搜索呈现：Jev判断→Pro查前人物发言及本地表达选择→确认呈现→原生深度搜索→Flash理解→Pro正式回复。查前阶段不额外叠加Flash理解或模拟打字等待；后续回复接续实际已说正文。

即时聊天的标点和表达节奏由最终Pro人物发言承担，Flash理解不重复承担口吻加工。气泡层只按既有原文跨度和保护片段切分，完整正文保持；切分失败退回完整正文，不用符号替换或随机删标点制造口语感。

资产体现的表达方式不能替代PCAR人格事实。不同角色可批准不同资产；群友的恋爱关系、生活经历、身份和承诺不会因语料学习变成人物自身经历。对严肃内容、拒绝和边界的适应由人物结合真实语境处理，工程侧不追加场景大全prompt。

## 10 真实对照与验收设计

### 10.1 先确认数据和提案

导入核对至少覆盖批次首尾、多行文字、同名用户、重复导出、连续消息、引用／转发、系统消息、缺失媒体和撤回。样本来自实际文件中存在的类型，缺失类型用不进模型的接口／状态测试验证，不能补造对话。

首批提案审阅同时展示原文、必要上下文、脱敏差异、模型概括、适用角色和本地拒绝原因。原话自然而提炼结果变成泛泛指令时，记录为提炼损失；不让代理先改得顺口后再交审阅。

### 10.2 E.N1加入有无表达库对照

保留四种角色各4个位置，共16个位置的研究容量。角色核心以作者已认可版本为准，旧被否决口吻不复用；材料从开发审阅分区或作者亲自提供并划入该分区的真实对话中选择，最终留出集不在这一步使用。

群聊语料可用于表达学习，但不能把多人讨论直接冒充人物与用户私聊。私聊评测使用有明确受话对象的真实输入；从群聊挑出的单条话若缺少角色关系或前文，不自动转成测试用户消息。材料不足时报告缺口，不由代理补齐。

| 条件 | 配置 | 回答的问题 |
| --- | --- | --- |
| A | 原v8 Flash | 相对当前基础的表现 |
| B | 原v8 Pro | 同一Pro主模型是否已经足够 |
| C | Flash理解＋Pro直接发言，表达库关闭 | 新职责分工本身的表现 |
| D | 与C相同，启用冻结真实语料资产 | 学到的表达是否实际带来收益 |

每个位置使用同一份批准的人格、初始上下文、真实输入及冻结资料。C与D复用该位置一次真实Flash理解回执，只改变获准表达材料；两次Pro各自只发送一次。A、B保留原v8装配，B与C／D的Pro设置一致，不削弱基线。

本阶段不派发Jev或新搜索，资料情境使用同一份获准冻结材料。配置、输入和每个位置的首次结果在运行前后可核对，调用顺序交错安排；不能把相同参数误称为模型输出必然相同。

这是固定上下文位置研究，不能称为完整多轮会话结论。无资产选中或结果相同的位置如实计入；作者分别评价自然度、角色感、语境适应、意思承接和不恰当借用，自动统计只辅助定位。

先判断D对C的增益，再判断D对B的价值。D若不优于C，学习作用尚未成立；C若有独立价值可单独记载。若v8 Pro同样或更好，保留结论，停止宣称新链优越，不因工程投入继续扩大调用。

### 10.3 E.N3完整三链对照

通过小规模门后，使用v8 Flash、v8 Pro、新链＋冻结资产三条链。四种角色各两组新会话，每组6轮，共8组、每链48轮。三链初始人格、设置及用户输入脚本相同，之后各自维护实际发言历史。材料使用预先冻结的最终留出部分；依据本轮结论修改候选后，不能再把同一部分称为未见过的最终评测集。

用户输入来自作者提供或批准的真实材料；代理不得写作测试脚本。计划覆盖轻松交流、情绪与边界、偏好更正、认真任务、追加条件、引用／代码、追问和资料状态，场景名称只用于覆盖登记，不形成模型话术。

两组资料场景复用同一份冻结公开资料及未完整取得资料状态，在隔离范围分别登记，明确标为受控资料；真实联网联合验证放到E.N5。比较期间关闭增量学习，资产包、模板和检索策略固定。

审阅提供同排版正文、完整气泡会话、选择资产及理解材料展开项、耗时费用和所有失败。身份在组内固定、组间随机；可折叠相同结果，完整前文始终可查。首次结果保存，不能补跑后只展示更好的一次。

### 10.4 E.N5连续体验

两段各15轮桌面对话，由作者真实输入或使用其明确批准原文。覆盖新话题、情绪变化、认真任务、联网、资料追问和收尾。记录模型等待与呈现等待，验证查前发言先显示、历史只回流实际说出内容。

第一段使用冻结资产包；段间以最多2次获准增量学习形成提案，作者确认后发布第二版，第二段记录新增资产的实际选择。两段输入不同，不能据此单独宣称资产更新的因果收益；收益依据仍来自第10.2节对照。

撤回测试覆盖尚未派发、已派发未返回、提案待审、资产已发布及正文部分呈现。停止后续使用并保留已发生边界，不能在同一发言中途换另一份整稿重发。

## 11 版本兼容与代码施工清单

### 11.1 版本策略

独立语料库从`corpus_schema=1`开始，研究阶段不随导入升级人物主库。正式集成仍沿原新E规划使用候选**0.2.0rc8／主库结构33**，新增语料来源接点与直接Replyer账本一并纳入迁移清单；本次文档不提前修改版本。

结构30的来源CHECK和支持证据外键不能靠传入一个新字符串扩展。E.L5采用版本化来源解析器及新增来源／支持绑定表，让外部语料引用携带数据集、消息、视图、权限版本与摘要；旧来源／回执按旧版本读取。统一资产管理复用E2的角色、修订、禁用和候选生命周期，不另建第二套人物权威。

新学习任务合同区分目标来源和可见上下文，记录模板及完整输入批准；旧`learning_messages`及历史请求不得被新模板重新解释。新表、索引及解析器在隔离库实现后再加入结构33迁移，不能只改Python白名单而遗漏SQL约束或兼容程序。

语料库和人物库的来源变更采用持久事件及幂等投影。撤回先在权威语料库生效；派发、提案发布和候选使用都复核当前权限与来源版本，投影中断可恢复。数据集不可访问或版本不一致时，不使用依赖该来源的资产；不能把跨库操作假装成单库事务。

撤回与派发授权在同一受控入口排序，记录已获得授权的不可逆调用边界。网络等待不持有数据库事务；已经发送后才到达的撤回阻止后续发布，记录在途请求的真实状态。

| 本地维护 | 新`scripts/pcar_corpus.py`及已有资产维护工具 | 导入预览、版本导出、提案审阅、撤回和来源核对；调用动作显式区分 |
| 静默采集 | 独立工具目录内的SnowCat事件接收器 | 只接收与落盘，含版本、账号观察与缺口证据 |

首版拟提供`corpus.import.preview/commit`、`corpus.inspect/export`、`corpus.dataset.freeze`、`corpus.source.revoke`及学习准备／执行／解析／发布操作。预览、检查、导出和冻结不调用LLM；执行入口单独校验用途、批准版本与预算。

### 11.3 必须关闭的工程问题

| 验收组 | 必查内容 |
| --- | --- |
| 导入保真 | 编码、多行正文、同名发言者、乱序、重复文件、部分导出、格式变化；不改写标点或丢失段落 |
| 来源与范围 | 跨群／跨账号／跨角色不可混用；私有群不冒充公开；未知发言者不自动标真人 |
| 模型输入 | 实发请求与已批准版本逐项一致；未获准原文、工具包装、代理素材及导出说明未混入 |
| 学习状态 | 幂等派发、完整回执、无效／未知、取消、重启、迟到、来源撤回；已发生位置不重放 |
| 发布和选材 | 拒绝不生效；来源撤回使提案、资产和快照不可用；回退内容不能恢复旧权限 |
| 新回复链 | 正文只生成一次；无隐藏旧转译；查前呈现早于搜索；实际发言回流及根交互召回不重复结算 |
| 留出隔离 | 同一回复链与近重复组不跨区；评测输入不进入学习批次；人物结果不作为人类样本 |
| 跨库与清除 | 中断投影可恢复；缺失语料库暂停依赖资产；原件、派生负载、资产、索引与导出保留范围可核对 |
| 迁移回退 | 32→33、旧rc7副本新增对话后再升级、正式27迁移、整库和选择性语料携带；完整／未知回执保真 |

来源撤回用现有失效合同；物理清除另做受控维护，不能直接关闭追加保存触发器后随意删表。新数据的敏感负载及副本清单在E.L1定稿，必要的重建清除在隔离库验证；直到清除实证通过才标记已删除。旧回执的留存或清除依对应批准范围，不把清除后的不可读取状态伪装成从未发生调用。

迁移包将人物资产与原始语料分层：可只带获准发布投影，但必须携带足以校验的来源状态和权限记录；完整私有语料仅在所选范围内复制。没有来源有效性证据的资产随迁移暂停，新机重新核对数据范围和模型用途后启用。

## 12 调用预算与停止条件

本节是待审预算上限，不是本轮派发指令。沿既有模型配置规划，实际派发前核对官方模型身份、参数、价格和用途许可，不根据历史金额推算本轮已扣费用。

| 阶段 | 新客户端请求上限 | 组成 |
| --- | --- | --- |
| E.L0—E.L2 | 0 | 导入、解析、视图、审阅准备均本地完成 |
| E.L3首批学习 | 2 | 两个预先登记批次各一次 |
| E.L3后续覆盖 | 6 | 首批价值确认后，最多六个新批次 |
| E.L4／E.N1 | 80 | v8 Flash 16＋v8 Pro 16＋共享Flash理解16＋Pro无库16＋Pro有库16 |
| E.L5／E.N3 | 234 | 三链144份正式回复＋新链理解48＋Jev36＋查前6；受控资料回执不计作真实搜索调用 |
| E.L6／E.N5 | 96 | 理解30＋正式回复30＋Jev30＋查前2＋真实原生搜索2＋增量学习2 |
| 合计 | **418** | 学习共10次、其余对话与工具请求408次；原生工具内部用量另记 |

相对原E.N规划的394次，本版新增首轮语料学习8次和有／无库对照16次，增加24次。旧预算被本节对应阶段替代，不能把两份额度相加；此前已执行的历史E研究也不占用为新实验可重放的名额。

每阶段分别批准并设置调用次数、输入／输出容量和金额上限。沿用已有小时／日限制；若有限研究需要不同速度，在该研究配置中显式确定，不绕过现有限额。准备、调试、格式转换、来源检查和学习素材筛选不隐含额外模型。

学习、理解、人物回复、Jev、原生搜索分别记录实际模型、开始／结束、首次回执、tokens、已知费用、估算与未知项。资料未取得、输出无效或被作者拒绝仍计入已发生调用；未知费用保留未知。

连续3次提供商异常停止后续新派发，输入越界、权限变化、错误账号或非预期发送立即停止相关任务。作者判定当前语言候选无价值时停止扩大，复核首次证据；新候选先审阅修改及有限预算，再开新版本，不覆盖失败记录。

## 13 权重训练的后续条件

若本文所称“深度学习”后续进一步指向训练模型参数，需要独立立项：确认获准模型权重或官方训练接口、训练与部署资源、数据用途、目标说话人映射和可回退版本。当前PCAR没有这条实现，不能把给DeepSeek聊天接口发送语料称作SFT。

本次保留消息身份、上下文、目标发言、来源权限和完整留出分区，使后续可在原件基础上制作训练集。届时训练目标必须是真实获准发言，不能把群聊相邻两句自动变成user／assistant对，也不能用代理补写答案。

权重训练须分别比较基础模型、仅表达资产、仅权重训练及二者结合，并验证人物可控性和数据撤回的处理能力。若训练或部署需要改变现有官方提供商原则，先由作者决定该变化。它不阻塞本轮MaiBot式表达学习的价值验证。

## 14 审阅包与提交范围

本轮交付主规划、前置研究、来源候补及项目导航衔接，均标记待审。本规划获批表示采纳施工路线；具体语料、模型可见文字、账号操作和正式迁移仍使用各自的已确认范围，不以规划批准代替材料审阅。

请作者重点审阅以下决策：

1. 以真实语料表达学习为近期主线，保留未来权重训练分支。
