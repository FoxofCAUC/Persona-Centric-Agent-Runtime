## 桌面消息怎样运行

- 接收一轮桌面消息时冻结本轮人物、范围、材料及策略版本。已开启候选的人物使用受审的 v8 上下文装配。普通发言先由 Flash 理解，再用获准的语义选择器选择适用表达，最后由 Pro 直接写出人物正文。选择结果可以为空；没有可选库时省去选择请求。
- Jev 判定需要新查资料时，复用已审的查前发言装配，由 Pro 直接生成。桌面确认这句话已完整呈现后才启动检索。随后生成的主回复接续实际呈现的查前发言。查前气泡零附加等待。
- 模型原始回执、最终呈现文字和气泡计划分别保存。按既有规则识别保护片段并从正文连续切片。中断后只把连续确认过的文字写入会话；接下来的回复读取这份历史。
- 理解、选材、主回复和查前发言各自留存模型、请求、依赖、响应和用量。常规状态只显示阶段、状态和账目。首次成功或发送结果未知的位置不会自动补发。恢复按原发言和物理回执继续，已发出的气泡沿原呈现凭证核对。

## 配置和恢复入口

| 入口 | 用途 |
| --- | --- |
| `python -m scripts.pcar_dialogue_sources --help` | 本机预览材料、登记已审用途、复核来源与撤回。研究回放绑定仅供离线比较 |
| `dialogue.generation.policy.current/update` | 查看或设置单个人物的候选版本。开启须绑定当前人物有效的材料 |
| `dialogue.generation.authorize` | 分别核对私有人物的理解、选材、发言三种云端用途 |
| `dialogue.generation.status/resume/cancel` | 核对本轮各阶段独立回执，恢复尚可继续的位置或停止本轮 |
| `expression.v2.*` | 列出查前与主回复，逐片呈现、确认、核对未知、取消。原按轮访问的主回复入口复用同一发布记录 |
| `python -m scripts.pcar_recall_rollback --help` | 从候选生成旧结构兼容副本。结构32目标使用 `--target-schema 32` |

候选按人物、桌面会话和本机材料授权生效。来源绑定保留数据集、消息、学习提案、版本、授权及校验值。撤回或缺库会阻止依赖材料的后续派发和呈现。迁移默认不带独立聊天语料，导出时可以用 `--include-corpus` 明确选择独立语料库。新机先核对来源、实例和云端用途，再启用候选。

## 本机验证

| 检查 | 结果 |
| --- | --- |
| 已审材料与新装配逐项比较 | 从已存的34轮分别重建理解、选材、正文请求，共102份与旧请求一致。34份显示正文也一致 |
| 既有提供商回执兼容 | 只读重解析上轮192份HTTP响应，正文、返回模型、结束状态和用量均与原记录一致 |
| 普通桌面入口与连续气泡 | 使用已审材料、33条来源资产和本地提供商替身，走通查前发言、呈现回执、检索、主回复，再从同一会话输入两个气泡并取得下一条回复 |
| 撤回与中断 | Pro派发后撤回语料时保存首次响应，人物事件和发布计划均为0。预告生成成功、组织回执尚未提交时中断，可复用同一次Pro响应恢复。呈现途中重启保留原租约，取消后仅已确认前缀进入历史 |
| 旧版与迁移 | 从固定版本的结构27及32实例实际写入私聊后升级；兼容副本暂停来源和新链权限。结构31回执、未知结果、默认导出及明确选择携带语料均有回归覆盖 |

最终候选的30项定向测试全部通过。扩大回归共运行155项，其中3项跳过，已执行项通过；需要私有材料的入口随后以本机授权材料单独验证。运行 `python -m scripts.pcar_dialogue_generation_preflight --repo .` 可复核468个核心文件及49个证据工具和测试文件。[结构33扩展清单](E.L5-结构33候选扩展清单.json)

另行抽查结构13旧版迁移时，M7.4用例 `test_migration_atomic_and_preserves_original_columns` 的共享初始化发生 `companion_policy_conflict`。固定的rc7在相同初始化处也出现该错误。单独执行原结构13升级与故障回滚断言通过，此用例的整套共享初始化仍有冲突。

离线等价证据由私有状态 `el5_equivalence` 定位。现场测试的提供商返回标记文本，本轮新增计费请求为0。原始微信文本、具体人物材料和模型原始响应保存在本机私有目录。
