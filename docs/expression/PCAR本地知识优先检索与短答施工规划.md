## 2 第一条施工线 把字数要求送到生成端

### 2.1 给每一种发言绑定明确的篇幅合同

| 发言 | 模型在生成前知道的合同 | 本机校验与呈现 |
| --- | --- | --- |
| 普通私聊 | 按已选交流动作和收束方式回应。给出短句或分段目标。 | 每泡至多 75 个 Unicode 字符。沿原文完整分泡，保留必要语义、数字、引用和受保护片段。 |
| 联网前提示 | 说明当前要做的查找，轻短地说完。上限是一泡、75 字符。 | 同样按一泡验收，允许自然的短句组合。J7 通过且提示可见后派发联网。 |
| 有资料的短答，含本地命中和查后作答 | 一句、一泡、最多 75 字符。给出此轮选定的结论和会改变结论的限制。当前版本、地区、日期或传闻状态有影响时随答案保留。 | 按交接时声明的句数与字数检查最终气泡原文。有效稿按原文发布。 |
| 明确请求长文 | `body` 为一句、最多 75 字符的引句，`detail` 为完整详情。事实和表达范围由前级决定。 | 保留两个现有字段。聊天只显示引句，详情中展开正文。 |

字数计入标点、空格和实际可见字符，沿现有 Unicode 计数口径。显示分泡沿现有程序执行。发言原稿、分泡和实际可见文本逐项对账。请求的 token 复用现有输出预算和计量，字符和句数由正文原文核验。若使用结构化输出，也由程序校验非空、字段、长度和内容条件。[DeepSeek Chat Completions 合同](https://api-docs.deepseek.com/api/create-chat-completion/)

### 2.2 接入点与返工方式

1. **生成前冻结合同。** 在 `ordinary_reply.py` 汇总交流动作、事实范围、篇幅和收束时，将每个模式的气泡数、句数和字符上限绑成可核对的格式字段。J6 继续决定模式，程序按模式填数。`ordinary_providers.py` 使用对应的待审系统段和明确字段组装出站请求。长文详情沿两个字段合同。实际装配版本、用途和接收方随回执登记。
2. **优先处理机械校验。** 适用的字数、句数、字段和受保护片段可在调用 J7 前检查。机械检查失败时记录观测值及失败细类，如字符超限或句数超限。机械检查通过后，J7 仍独立核对目标、事实、限定、人设和收束。日志保存两类结果或明确记录某项尚未运行。由此可还原本次第二稿同时长和答偏的情形。
3. **给一次重写提供可执行原因。** 返工请求携带同一篇幅规则、错误细类和仍有效的选定事实。机械长度失败沿用原目标、已核定证据和语体。若一泡容不下多个必要事实，由已有 J5／J6 先决定核心结论和必需限定，再让 Replyer 重写。查前与查后共享现行一次修复边界。搜索回执、资料版本和已显示的查前发言继续沿原身份引用。
4. **保留失败回合的可用资料。** 两稿均无法发布时，由工作台给出真实进度或停止状态。已经通过校验并入库的资料，在原回合详情可查。作者发起续问或已授权重试时可沿波次重读现有事实，从正文失败点接续。新正文仍走原复核和显示回执。
5. **对照验收。** 先把现场 63 字两句、76 字两句的结构作为离线故障基线，再检查成功短答、查前多短句、一泡边界、长文、嵌套引号、URL、版本号和组合字符。截获实际出站输入核对合同存在。正式出站的提示文字按模型输入总则逐版审阅。另记录首稿合格率、重写次数及用户实际看到的样子。

原先的一泡 75 字限制得到上游原生配合。通过程序检查的稿件仍保持原意和自然的表达。见[写作与外发审阅规则](../模型输入与提示词写作总则.md)、[单句检查](../../persona_runtime/private_lookup.py)、[泡长校验与切分](../../persona_runtime/bubble_limits.py)。

## 3 第二条施工线 先查本地，缺失或过期再联网

### 3.2 逐阶段职责和判定

| 部位 | 改造内容 |
| --- | --- |
| **受理和 Jev J4** | 先有 J1 接话目标。J4 选择是否须查资料，建议使用 `retrieve/none` 的新版本合同。知识型提问、时效核实和已指明公开资料的任务进入本地检索。闲聊、倾诉、道别等沿现行私聊。J4 选择查资料时尚未决定联网。由程序从已绑定的消息、引用和时间上下文形成检索条件。 |
| **本地检索** | 在角色与会话有权读取的资料中，使用本机模型编码整段提问，按向量相关性取回带有出处、日期与适用范围的材料。 |
| **本地命中** | 本地模型返回与当前提问语义相关的授权来源，进入回复上下文。一个来源可以有不同表述，召回按向量排序。普通本地命中轮无需联网。 |
| **需要更新** | 没有可用的相关资料，或用户明确要求联网核实时，沿现有授权与查前说明进入补查。本地模型或数据库不可用有单独状态。 |
| **授权与查前说明** | 先确认可用查询和联网许可，再生成查前短提示。提示由角色结合本轮说，参数和原始查询继续在程序端。标准模式沿用公开片段确认、调整和跳过。明确仅使用已有资料时沿本地结果答复或如实说明资料不足。查前提示完整显示后，工具才取得派发资格。 |
| **联网结果暂存** | 留存原回执、原始资料、来源和查找时间，绑定回合与授权。保留原生 Search／Fetch 手段与有限补缺逻辑。原生联网结果里的合成摘要、带来源的摘录和实际网页正文按各自类型登记。工具长文本作为入库材料和只读详情来源。 |
| **整理和提交** | 获准来源以连续片段保存，保留来源身份与时效。已有通用整理合同可提供索引描述。逐字抽取和拆题预设退出新回合。 |
| **重新读取和作答** | 入库后的资料沿相同向量路径召回。有限数量的相关来源交给既有表达链，追问可结合当前会话继续检索。 |

**命中条件需要同时满足题意、版本时效、来源及权限。** 对方问旧公告当时怎样说，历史版本就是有效结果。对方问现在怎样，则使用当前有效的证据。回忆阶段是本地 I/O。现有 Jev 和正文模型仍使用各自已授予的上游连接。

### 3.3 整理模型的边界

- **独立用途。** 设知识整理为专职处理用途，由已有任务、回执和计量机制管理。首版建议用已有获准的 DeepSeek 模型服务做单次结构化提取。按真实材料抽样评估有效事实覆盖、来源回指和耗时，再确定是否需要换模型或增加复核。密钥、端点和模板在施工时按该用途核对。
- **最小整理输入。** 可选的专职整理沿已审合同读取授权查询和来源。索引可以使用其描述，保存和召回来源不要求整理模型逐字重写材料。
- **保留证据等级。** 官方公告、可核对的现场资料、社区实测、未证实传闻、工具摘录和合成文本各自标注。只有标题或合成底稿时标记证据不足或按明确限定保存。关键时间和实装结论需要对应的可引用证据。若需要阅读明确页面，继续在既有只读补缺范围内执行。
- **来源权限。** 独立可证实的公开事实可进入获准的公共层。含有个性化内容、隐私查询或会话专属资料的条目以原作用域保存。已有全流程授权覆盖已列明的实际接收方和当前会话，沿用该用户选择。新增不同接收方时沿现有接收方变更流程登记。发布、撤回和复用继续核对实际作用域。

前后台工程基础见[任务执行和回执](../../persona_runtime/managed_organization.py)、[原生来源提取](../../persona_runtime/knowledge_native.py)、[会话授权](../../persona_runtime/session_privacy.py)及[历史增量维护中的证据经验](../M9.A-B方案持续维护衔接实施记录.md)。已冻结的旧整理类型提供结构参考，实际运行使用版本化的新用途。

## 4 本地知识载体、时效与合并

### 4.1 建议数据布局

沿用业务 SQLite 及其迁移、备份和迁移包入口。新增使用明确命名的增量记录，在同一库建立新读取投影。实现时优先沿用兼容的来源解析、文档指纹和回执。旧知识表继续保留原义，符合新证据和授权合同的条目可经版本化方式加入候选池。迁移先从结构 34 候选副本验证，正式结构 33 的升级另用独立兼容样本检查。恢复旧库时仍核对当前撤回与授权版本。

| 层 | 最小记录 |
| --- | --- |
| 原始回执与文档版 | 来源标识、规范化 URL、内容指纹、原始回执 ID、取得时间、来源发布时间或修订、原始资料及来源类型。能查到原证据的句段和位置。 |
| 事实 | 规范实体与属性、值及单位、适用版本／渠道／地区／条件、证据状态和授权域。每条可关联多份独立或同源证据。 |
| 生效与历史 | 事实修订、有效起止、最近核验时间、替代关系和冲突关系。保留传闻、公告、观察实装、已更正或已撤回的历史。 |
| 查询与回合收据 | 查询指纹、命中或需要更新的理由、所选事实与来源修订、整理任务、入库提交号和显示回执。后续回复和详情能查到当时用的是哪版。 |

SQLite 写事务负责合并、索引更新和提交回执，同一批写入成功后才会对外读取。远程等待发生在事务之外。重新检索开启新读事务，读到提交后的版本。若索引须重建，可从已确认的事实修订恢复。[SQLite 事务隔离](https://www.sqlite.org/isolation.html)

入库的最小交接字段包括文档修订 ID、稳定的事实候选键、规范值、版本与条件、证据偏移、证据类型及建议有效时间。程序复核内容指纹与证据偏移后再更新当前版本。查回结果携带事实修订号和生效依据，绑定到本轮的 Replyer 与显示合同。迁移验收以独立副本对账，回退时保留新版已产生的业务库和新增资料快照。

### 4.2 识别过期和适用时间

至少记录三类时间。**来源何时发布或更新、事情何时生效、PCAR 何时抓取及核验。** 来源没提供时间时保留缺失状态。有效期按事实类型和版本边界判断。稳定概念以来源修订和人工更正为主，版本、活动和时效问题以适用区间和用户指定时点为主。已知存在新版本时，针对「现在」的回答先核验新版本记录。用户明确问旧版本时查旧适用区间。主动更新首版由实际查询触发。

### 4.3 合并与更新规则

先以「归属域、规范实体、属性、适用条件」定位同一主题，再比较具体适用版本、有效期、事实值和证据状态。映射不明确的别名继续保留独立记录，等证据证明是同一实体再归并。整理模型可提出同义事实的合并候选，程序按实体、单位、限定和有效区间确认，索引随实际变化增量更新。

| 新资料情况 | 合并处理 |
| --- | --- |
| 同页同内容再次返回 | 使用规范链接和内容指纹去重，追加本次核验记录。内容只存一份。 |
| 不同来源重复同一事实 | 事实值合并到同一个当前适用条目。追加证据关联，标注转载或同源。 |
| 同一属性在新版本里沿用原值 | 在该事实下更新适用版本和核验回执。保留原始来源及版本归属。 |
| 爆料后来得到公告或实装证据 | 将明确确认的部分链接为新证据和新生效版本。变更部分生成新值，旧爆料留作历史。公告与实测按各自状态登记。 |
| 新旧值冲突，或不同地区、渠道、平台分别实装 | 按实际条件分别保留。面向本轮时点选择有依据的版本。若同条件仍冲突，标为待核实或报告已知分歧。 |
| 来源更正、撤回或权限变化 | 更新有效投影和索引，停止该证据进入新回答。历史回复保留原样，新详情和续问按实际权限与现行修订读回。 |

以用户举的版本更新场景为例，版本前读取的爆料明确留在暂定状态。新版正式资料进入库后，同一实体的相同部分沿用事实及追加来源，改动项才出现新的事实修订。「现在是什么」优先读符合版本、渠道和时间的实装证据。「原来爆料怎么说」仍能查到当时版本。这种合并减少重复内容，也保留更正的依据。

## 5 续跑、隐私和用户看到的结果

- **给各阶段留原身份。** 持久保存回合、外发许可、查前可见回执、工具调用和整理任务的绑定。同一工具结果与整理版本形成幂等键。搜索已回而整理未提交时从整理继续。提交完成而正文失败时重新读库。已经完成的物理调用沿原回执核对。已有明确未发出的步骤可自动恢复。效果未知的尝试沿现有对账原则处理。[候选派发与停靠](../../persona_runtime/private_transport_recovery.py)
- **边界变动触发复核。** 入库前、重新读取时以及显示前核对原作用域、证据状态和修订版本。撤回后停止新外发和新复用。跨角色或实例复用公开事实需满足本机已配置的授权。日常会话的自动记忆仍接收实际可见发言，世界知识使用独立的事实来源类型。
- **把进度说清楚。** 本地命中直接进入答复。开始联网以一泡查前提示建立预期。查找、整理、失败和有资料可读由工作台显示实际状态。保持角色正式气泡有内容才出现，详情供按需展开。窗口隐藏、断网、浏览切换以及完全退出后，沿原回合和确认可见前缀恢复。
- **测量分段时长和成本。** 记录受理、J4、本地查库、查前可见、网络开始与完整回执、整理返回、事务提交、重新查库、最终出稿和逐泡显示。区分实际收费请求、服务端工具次数与估算费用，沿现行额度设置和临时放行。用户原计时口径继续按普通 120 秒、托盘唤回 150 秒核对完整可见，另列真实主体等候与故障阶段。验收覆盖事件组合和实际聊感，延迟分段用于定位瓶颈。

### 定向验收矩阵

| 场景 | 必须核对的事实 |
| --- | --- |
| 普通闲聊、情绪交流、自然收尾 | J4 跳过知识检索。联网和整理调用数为零。实际用语由作者体验。 |
| 本地已有新鲜事实，换一种问法或相邻追问 | 授权和版本匹配。无查前提示，联网和整理调用数为零。能在详情找到真正在本轮使用的来源。 |
| 冷问题，资料查到且证据充分 | 查前可见时间早于物理查询。原始回执、整理、入库提交和重查的因果顺序可核对。有效短答完整可见。 |
| 查后首稿 63 字两句、76 字两句及 75 字边界 | 生成请求含准确合同。无效稿留档并按具体原因处理。只有通过最终检查的正文可显示。 |
| 网络返回但只有未核验摘要，或整理失败 | 回执完整保留。事实可用性与实际证据相符。详情和界面状态准确。 |
| 爆料、公告、实装三次查询，另有重复转载 | 已有效事实不重复堆积。历史查询与当前查询选择各自资料。相互矛盾的值保留适用条件和来源。 |
| 标准模式、全流程已同意、撤回或更换接收方 | 对照每阶段实际外发、命中范围与授权版本。记录本地私人条目的可见边界。 |
| 断网、托盘、完全退出和次日重开 | 分别在查前、已发未回、有回执未整理、已提交未回复、已见首泡处复验。同一回合沿原证据恢复。 |
| 并发同题、纠正一条事实后续问、旧备份恢复 | 重复确认和提交幂等。重新查库只读当前有效版本。以撤回和更正后的有效投影供新回答。 |

本轮产出为施工规划。真模型输入的写作与使用仍按具体版本审阅后推进，原盲测结果和正式 G-Auto 断点作为后续验收的基线证据。
