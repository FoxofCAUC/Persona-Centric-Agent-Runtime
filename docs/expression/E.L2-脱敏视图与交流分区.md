## 脱敏如何处理

本版只在明确匹配的原文跨度内替换账号、电话、邮箱、链接、长标识及可明确匹配的人物别名。实际共27条消息发生28处变更：链接20处、电话6处、邮箱2处。占位标识使用本地密钥HMAC生成，同一值在本数据集内保持对应关系，不以低熵号码的裸哈希作为匿名身份。

每处变更保存原文位置、派生位置、替代标识及核对依据。规则之外的标点、空格、换行、表情和重复说法保持原样；没有纠错润色、语气加工、模型摘要或补写。原文和映射只在私有目录核对。

单字符昵称只在独立字词命中时标为待核对，避免把普通词内字母当人名。自由文本中的其他姓名、地址及未符合规则的标识尚未完成人工核对；当前版本不标记为已经全面匿名或可直接外发。首批预览只选择没有规则变更、没有已知问题标记的完整片段，仍供作者检查具体内容。

## 交流片段与重复内容

以连续30分钟没有新消息作为基础边界，形成1,723个时间片段。这里没有推断话题或情绪；双方消息按实际顺序保留，不拉平成交替的user／assistant问答，也不替缺失语境写解释。

明确引用跨越时间片段时，相关片段绑定为同一分区组。实际记录了193条跨片段引用绑定；同片段引用继续沿原关系保存。6条无法定位的引用保留缺口标记。

去重仅用于分区与独立参考资格，不改写或删掉原文：

- 片段文字结构完全相同，绑定在同组；实际产生34条绑定。
- 具辨识度的较长目标正文完全相同，绑定在同组；实际产生3条绑定。
- 对较长片段及目标用5字符片段、64项bottom-k指纹形成候选，再做Jaccard不低于0.9的重合筛查。本批未产生额外近重复绑定；这不是语义相似度模型，也不声称识别所有改述。
- 短句在不同上下文重复是正常交流。跨区共有短句保留上下文，在后一区取消其独立参考目标资格，避免把学习区原句再次作为未见答案。

Unicode、空白和大小写归一只用于重复索引，不回写展示文字。引用绑定、已检测重复组、默认参考目标和完整片段归属均有本地校验。

| fragments-*.html | 学习和开发片段，保留A／B及消息顺序；最终留出记录不出现在这些页面 |
| learn.fragments.jsonl | 学习区的结构化派生材料 |

| final_holdout.fragments.jsonl | 单独封存的最终留出材料，不用于本阶段挑提示或表达 |
| audit-*.private.jsonl | 来源、跨度、分组和关系证据，仅作私有工程核对 |
| manifest.json | 视图、规则、内容摘要及导出文件校验 |
| learning-preview/index.html | 既有学习模板原文与两批真实输入的只读预览 |

JSONL是数据工程文件，不等同于可以整包直接发送的LLM提示。分区文件不带原文哈希和脱敏映射等审计字段；原文对照页及audit文件包含私有核对材料，不能冒充匿名训练输入。页面正文均转义，不执行聊天中的脚本或命令，不加载远程头像。

最终留出只在独立文件中保存，默认审阅页面仅展示其统计。后续完整对照使用前，仍须按实验冻结版本及实际输入确认；不能看过结果再把同一部分当成新的未见评测。

## 现有学习模板与首批输入预览

为完成施工规划中的输入审阅材料，本轮只读复用原有`expression_learning.learning_messages`，未创作或改写模板。页面同时展示MaiBot原始模板、PCAR既有适配后的完整3条消息和请求序列化结果；序列化保持消息文字不变，不加载凭据、不派发。

两批按时间顺序取学习区中最先满足以下条件的完整片段：双方都有原话、2—10条消息、全部可作文字目标、没有规则脱敏和问题标记、没有片段外引用、总请求不超过既有12,000字符保护。实际分别7条和5条原话。筛选没有按“像不像真人”打分，也没有自拟用户台词或参考回答。

现有E2协议发送有序id／text数组，没有新增说话人或独立历史字段；后台保留说话人和引用关系，作者可据完整预览判断该接口是否适合首批研究。原模板中的可选来源编号、PCAR现有的必需来源适配及JSON首尾指令均完整可见，没有借“上游复用”隐藏差异。

预览绑定当前数据版本、模板／装配器摘要、两批文件摘要与计划模型参数。**它不是已获准或已接线的学习任务**。E.L3仍需把私有语料来源接到持久学习账目，核对具体模板和最终输入的使用批准、提供商用途及有限预算后派发；不把原件授权变成新prompt写作授权。
