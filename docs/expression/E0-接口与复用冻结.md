## 1. 封口基线与扩展接点

[核心清单](E0-core-baseline.json)固定401份运行、模板、维护脚本及依赖文件，包含原始Git内容摘要和跨Windows检出的文本摘要。源码比较仅将CRLF换成LF，其余字节保持；模型正文、材料及上游快照始终逐字节校验。[预检](../../scripts/pcar_expression_preflight.py)检查已有文件及未登记的运行扩展，不需要Git或正式实例配置。

E0允许新增`expression_contract.py`和只读预检脚本。已有核心运行文件保持。后续扩展按下表独立落地，变更清单记录接点、理由、新摘要及定向验证；E0清单始终保留为最初基线，不用覆盖旧摘要掩盖后续改动。

| 接点 | 当前实现与后续改造 |

## 2. 数据合同v1

可执行定义为[expression_contract.py](../../persona_runtime/expression_contract.py)，版本`pcar-expression-v1`。它提供不可变数据对象及纯校验，不执行网络、数据库写入或显示。所有身份均引用原业务记录；新增ID仅标识表达派生物和呈现记录，不另建人物或记忆主键体系。

```text
MainDraftReceipt → ExpressionContext → ExpressionArtifact
                                          ↓
                       PresentationPlan → PresentationReceipt → UtteranceEvent
```

| 对象 | 固定字段及语义 |
| --- | --- |
| `InteractionRef` | `root_id/persona_id/session_id/scope_id/policy_version`，继承受理时快照；表达上下文和产物完整匹配 |
| `CallReceipt` | 独立`attempt_id`、`stage`、官方提供商、实际模型、完成／失败／未知／取消状态；输入／输出tokens、实际金额与估算金额分开，未知为`None`；估算必须带价格版本 |
| `MainDraftReceipt` | `draft_id/body/body_sha256/storage_receipt_id/call/protected`；只接受完成且完整保存的主稿，缺失正文或仅有指纹不足以继续 |
| `DialogueLine` | 原事件身份、说话者、正文、受理或呈现回执、普通回复／查找前发言阶段；历史可引用旧根交互，但人物、会话和范围一致 |
| `ScopedText` | 来源ID／版本、角色／范围、授权ID、正文摘要和有效状态；用于角色表达投影与表达候选，撤回内容不可派发 |
| `ExpressionContext` | 主稿ID／摘要、投影授权及版本、当前用户消息、必要真实历史、当轮已说内容、角色表达投影、少量候选；`context_hash`冻结全部输入 |
| `ExpressionArtifact` | 独立`artifact_id`、主稿及上下文追踪、完整正文及摘要、独立调用及落盘回执、保护片段映射、实际采用的合法候选ID；可以与主稿相同 |
| `PresentationPlan` | 原稿或表达稿的`producer_id`、正文摘要、单一发布权ID、节奏政策版本、有序气泡区间 |
| `BubbleRange` | 稳定`utterance_id`、`start/end`、正文类型、是否必要、建议等待毫秒；区间连续覆盖完整正文，空格和尾段保留 |
| `PresentationReceipt` | 计划／发言／回执ID、正文摘要、已呈现／取消／未知、观察时点及取消原因。已呈现证明应用显示，不表示用户已读 |
| `UtteranceEvent` | 从已呈现片段取得原文、顺序、来源产物及呈现回执；保存主稿或生成完成均不自动产生实际发言 |

字符区间为Python字符串的Unicode码点半开区间`[start,end)`，不是UTF-8字节或JavaScript UTF-16下标。后续前端适配需显式换算，包含表情符号的测试不可省略。代码、命令、公式、引用及指定原样文本各有稳定保护ID、种类和原稿区间；表达稿必须保留每个对应片段，呈现不能从其内部切开。局部校验不替代任务语义审阅，条件、否定、承诺及资料状态在固定样本中单列检查。

`visible_utterances`仅投影已呈现记录；待发或未知片段不进入历史。已确认取消的可省略片段可跳过，必要答案不得因新输入取消；来源／权限撤回及会话关闭可以终止剩余呈现。缺失／未知的前序回执会阻止后序被误记为已顺序呈现。调用方先完成产物／来源校验，再以事务保存实际事件；纯合同中的ID不能代替实际数据库授权或发布权检查。

## 3. 模型运输合同与降级

E1拟采用一次官方DeepSeek表达请求，返回一个JSON对象。模型只填写下表内容，根交互、任务及调用身份、账目、发布权和实际呈现回执由PCAR填写。

| 模型字段 | 形状 |
| --- | --- |
| `body` | 完整表达正文，非空字符串 |
| `segments` | 有序对象数组；每项`start/end/kind/required/delay_ms`，采用相同字符坐标 |
| `protected_ranges` | 对象数组；每项`span_id/start/end/kind`，指向正文中的原样保护片段 |
| `selected_expression_ids` | 本次提供候选中的唯一ID数组，可为空 |

结构及词法要求用于运输，具体提示装配在E1冻结。场景标签、研发排期、预算、验收要点和表达自由度元说明不下发给人物模型。再制可接收获准角色表达、必要真实语境及已说内容；不开放联网、动作执行、记忆写入或核心设定修改。

处理顺序：先解析整个JSON并独立确认完整正文，再核对保护片段和表达产物，最后检查分段。空返回或整个运输对象不可解析时，保存首次结果及错误，候选记不可用；运行接入时采用已保存主稿。完整表达产物有效而分段失败时，以表达正文单块呈现。原始JSON、内部字段和推理内容不显示给用户，不用正则从坏包体抽出一段冒充完整正文。

一旦已有表达内容呈现，不能切换另一份整稿从头发布。表达结果未知先停止自动重发；若运行政策选择降级主稿，先封存当轮回复的发布权，迟到表达只保存证据。Jev判web后的原有人物接话继续先于搜索，表达主稿接收该原文；默认不为这句发言新增收费再制。

| 组件 | 排期及抽取方式 |
| --- | --- |

| 分段数据、整稿回退和打字估时 | E1/E4复用纯计算及失败设计，按现桌面就绪时点和回执适配 |
| 发送结果、表达采用与历史回调 | E3/E4借用责任划分，平台发送回执改为桌面呈现证据 |
| 学习来源ID／SELF过滤和去重 | E2抽取；自己的输出不循环学习，学习合并频次不冒充已发强化 |
| 大型向量索引／压缩效果记录 | 小库先接已有本地检索及SQLite；按规模再抽取，原依赖和理由已登记 |

该固定提交的上游根`LICENSE`是GPLv3文本，PCAR当前为AGPL-3.0-only；A_Memorix既有AGPL复用记录单独保留。作者已授权直接复用。实际移植时记录文件来源、固定链接、原声明及本地改动，并携带相应许可全文；新增依赖逐项核对。E0新增合同和预检使用Python标准库，未引入上游服务、ORM、模型客户端或向量后台。

不采用上游默认的随机兜底、括号内容删除、固定超限截尾、成功主调用重生成、全局群聊Planner或默认跨角色分享。专用Mai Replier模型和跨语言往返留作后续独立候选，当前生成仍用官方DeepSeek。

## 5. 数据迁移与回退设计

E0不增加表或升级结构。E3采用加法迁移，实际迁移编号待接入时按当时结构分配，逻辑数据如下：

| 逻辑记录 | 主要约束 |
| --- | --- |
| 主稿回执 | 唯一关联主物理调用及根交互；保存完整合法正文、摘要、来源及用量引用 |
| 表达任务／尝试 | 每位置单独身份、冻结输入及授权版本；prepared→dispatched→completed／failed／unknown／cancelled；成功／未知不自动重发 |
| 表达产物 | 与主稿、上下文、资产版本及物理尝试关联，完整正文先落盘，再生成呈现计划 |
| 当轮回复发布权 | 对`(root_id, reply阶段)`唯一；原稿降级和表达稿争用同一权利，已呈现后不替换生产者。查找前已说事件保留自己的原阶段 |
| 气泡及呈现回执 | 按稳定发言ID去重，逐条确认／取消／未知；事件与实际呈现引用事务关联 |

E3须在`audited_complete`收到合法完整主结果后、把该物理尝试作为可恢复完成结果交给后段前，事务保存主稿及完成账目。只在`ChatEngine._run`开始Gate前加一行保存，会留下“尝试成功已记、正文尚未记”的崩溃窗口。适配应提供受管的完成回执接点，其本地落盘失败不得被当作可重试的传输失败；保持已派发证据、停止Gate及自动重发。外部返回与首次落盘之间发生硬中断时按原尝试未知处理。

旧完整人物事件作为旧版历史保留，不能反推成从未保存的完整主稿，也不能补造桌面分片回执。启用表达前已受理的任务继续遵循旧快照；旧成功／未知只读解释，不自动换号再制。新开关仅作用于之后受理的任务，当前开关默认关闭。撤回来源在表达派发及呈现前复核，降级同样受当前权限约束。

回退分两层：

1. **功能回退**：停止接收新表达任务，暂停未派发位置；已派发未知保持，已呈现片段保留。旧链处理之后的新根交互，历史接续实际发言；不把已成功主调用再跑一遍。
2. **程序回退**：导出兼容0.2.0rc4／结构29的离线副本。主稿／产物／回执保留在独立受保护备份，旧程序只接收已经呈现并按原事件身份登记的历史；未决任务不得被旧程序误当可重试主请求。实际旧版读写新增业务后再升级验证通过，才能交付E3迁移候选。

原正式库、配置、人物原件和密钥随完整实例备份管理。现有召回rc3兼容快照只证明29↔28的已验收范围，不冒称已覆盖未来表达结构。表达备份和导出按现有私人数据边界处理，正文及业务包不进入公开源码。

主模型与表达层对同一资料的使用合并到原根交互；召回仍按最强已证明贡献结算一次，气泡数和派生产物不增加记忆强度。表达候选的使用记录与人格演化分开，C/C0实验不向正式记忆或表达库回流。

## 6. 固定材料与有限调用计划

[材料目录](../../experiments/expression_e0/README.md)包含24个开发场景：16份公开人工角色的已审阅真实首次主稿，以及8份明确标记的人工边界稿。真实首次正文、所需的最近真实交流与已说原文放在所选证据目录`tmp/expression-e0-20261116/materials`。原16份结果仍在召回证据中，逐一摘要核对；输入材料另存，原首次回执保持。

真实历史在本实验中来自作者已读的原文审阅档案，不伪造现工作台逐条呈现回执。人工边界稿是隔离实验输入，不伪装成官方模型调用或生产`MainDraftReceipt`；E1实验适配须保留此来源区别。两类结果分别汇总。

A保存原稿，B仅本地分段／节奏计划，C一次再制并建议分段。另8个C0位置移除表达候选，保留基础人物设定和必要语境，检验表达资产的贡献。所有位置在[材料清单](../../experiments/expression_e0/materials_manifest.json)固定；人工候选有角色范围和来源。对照全文匿名展示，允许无区别或都不好，作者评价不预填。

[调用计划](../../experiments/expression_e0/call_plan.json)固定：官方`deepseek-flash`、思考关闭、JSON输出、无工具、单次输出容量8192tokens；24个C＋8个C0，物理调用最多32次，自动重试0。没有新增主回复、收费选择器或独立分句器。首次成功但格式或读感不佳的结果保留，不增加同位置抽样；未知立即暂停，连续两次明确请求失败停止整批。已知tokens达到800,000或保守估算达到CNY5时停止下一次派发，未知用量／估算也暂停。它是请求间停止规则，实际账单硬上限为`null`。

2026-11-16核对的[官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)：每百万tokens，Flash峰值输入未命中CNY2、命中CNY0.04、输出CNY8，闲时分别CNY1、0.02、4。实验统一按峰值及未命中输入保守估算，实际金额独立留空等待账单；模型、价格变化时先更新冻结。官方[JSON文档](https://api-docs.deepseek.com/zh-cn/guides/json_mode/)要求显式JSON格式和足够输出容量，也说明空白返回的情况；本实验保留首次空返回并按失败规则处理。

E1测新增表达等待和首个可用产物时间；A的历史等待不冒充本轮同步测量。B只是呈现计划，逐条显示、打断及恢复体验由E4/E5验证。E5的12个新场景及两段各15轮连续体验尚未创建或消耗。
