## 目标与边界

PCAR 管理消息受理、角色与记忆、信息检索、工具执行和决定。去群聊化的 MaiBot 普通私聊链只生成已决定的角色正文、分段并交付。工作台核对实际呈现，再把连续确认可见的内容回写 PCAR 历史。每个新角色气泡最多 75 个 Unicode 字符，计入标点、数字与空白。Pro 如获准承担 Replyer，仅做正文生成。

既有能力从当前源码入口接续。复用真实目标、已呈现对话、普通私聊上下文、分片映射与发完等待。候选链移除群聊频率、配额、抢话、群内提及、跨会话 Focus、被动 Replyer、自由文本触发、插件改稿及继承 Planner 工具定义的回复缓存。真实发送时只开放一个角色正文入口。原有直出、场景卡直出及故障兜底不进入候选路径。

## 运行设计

### 会话级隐私授权

工作台新会话给出「使用标准模式」与「同意并开启本会话全流程授权」。默认标准模式。已有会话从标题栏菜单查看、开启或关闭。协议列出配置的实际模型服务商、Jev 网关及联网检索服务，并在界面说明其生效范围。

> 开启后，PCAR 可把本会话已有及以后新增的全部内容，包括私人对话、人物资料、引用、已导入本会话的记录、相关记忆和文件内容，发送给所列服务，用于理解对话、回复、查找、复核、修复和后台整理。联网查询也可能包含私人信息。开启后无需逐条确认。你可以随时在本会话菜单关闭授权，关闭后的新外发按标准模式处理。

- **一次同意。** 授权按实例、用户、角色和会话绑定。全流程模式用一次许可覆盖所有相关模型用途、Jev 和实际联网服务。前后台停用逐条隐私判断、脱敏、重复审批与公开片段确认。各阶段按任务取材，资料随真实任务派发。
- **修订与接收方。** 结构 34 增加授权协议、接收方和授权修订、操作 ID、生效时间。工作台操作为读取、开启、关闭。重复操作按 ID 去重，多窗口按预期修订提交。同一服务内换模型和增设预设沿用。用户主动更换服务商、账号或网关，在配置保存页展示新接收方，保存后同步更新已授权会话。外部漂移与未完成的配置保存不得静默新增接收方。
- **切换与撤回。** 已等待隐私确认的原回合可在同意后继续。关闭后新外发按标准模式重新检查。已提交的物理请求按原身份对账。同实例退出、重启和升级恢复当前授权。新实例独立选择，同机恢复旧备份核对最新撤回修订。不同会话的查询、底稿、召回及派生记忆按来源归属。
- **派发核对。** 模式为全流程时，只核对实例、会话归属、授权状态与接收方。相关旧隐私门控由会话授权统一满足。来源撤回、数据删除、任务取消、回合版本变化、用户明确要求本轮不查继续按实际状态处理。用户主动开启全流程授权仅影响本会话。

### 受理、决策与正文

即时、定时、无限三种缓冲共用受理。先落库原话、引用、顺序和请求编号，重复确认只封成一个回合，无限模式确认前模型调用为零。封包固定输入成员、候选路线、人物版本与执行版本。新输入进入下一批。PCAR 按来源取出已确认可见前文、人物资料、有效记忆、已导入历史、公开资料及角色状态。接话目标锁定后，明确引用取原事件。

| 节点 | 责任与交接 |
| --- | --- |
| J1 接话与目标 | 判断回复或等待，从真实事件、引用或整批表达选择接话目标。等待结束该次发言。 |
| J2 交流动作与立场 | 判断分享、回应情绪、求助、澄清、换题或收束，并确定立场、语体及任务状态。开放式候选由独立且获准的规划模型组织，再作选择。 |
| J3 历史与记忆取材 | 候选目录含过去原话、导入资料、已发布记忆和已有资料。确定使用范围，由 PCAR 读取并给出来源。 |
| J4 是否新增联网 | Jev 唯一给出 `web / none`。只有 `web` 进入搜索。标准会话缺明确公开范围时在原消息旁确认、调整或跳过。全流程会话直接按当前目标形成已授权查询，可包含私人信息。 |
| J5 事实与限定 | 本地召回或本轮工具结果落库后选定事实与出处、有效时间或必要的保留条件。无新增证据需求的闲聊可跳过。 |
| J6 篇幅与收束 | 每次发言前冻结要答到哪里、是否必要追问及收束。分别处理查前、查后短答、普通私聊和明确长文。 |
| J7 独立终审 | 用本轮决定、证据和实际原稿核对答非所问、主动邀约、擅加事实或代办。输出放行或退稿原因。 |

沿现有 Jev 原生 `Choice` 单题传输。独立判断并行，依赖新事实的阶段等落库。Planner 汇合决定，记录用途、预设版本、请求指纹、实际模型、选项、耗时和物理回执。无有效或存在冲突的发言决定时停止正文派发。Replyer 接到绑定对象、阶段、执行版本、事实、限制和篇幅的冻结决定，工具列表为空。

### 联网、修复与续跑

1. **联网。** 查前发言显示并获得回执后派发查询。结果先落库，再通过绑定原工具回执的当轮召回入口进入 J5。普通查后一句一泡，保留结论与必要限定。完整底稿、出处和角色明确长文分别从适当详情打开，详情入口由真实可读的记录决定。
2. **发言修复。** 终审确定稿件违规且尚未呈现时，回到对应决策节点，建立新一笔生成和复核任务。每个用户回合最多修复一次，独立保留首稿、修复稿与费用。再次退稿显示真实状态，用户可继续聊天。查前已经说过的内容沿原回执保留。
3. **恢复。** 可证明未派发的阶段按最新有效回合和授权自动恢复。已发出但结果未知按原身份对账。已生成的正文沿原稿完成终审或呈现。气泡已领取但未确认时，先核对原回执，只续发确定未显示的片段。用实际可见前缀写回历史和记忆。
4. **验收计时。** 以原提交到末泡实际可见计时，托盘唤回观察窗 150 秒，其他工况按原 120 秒口径。无限缓冲从确认发送计时。记录首泡、末泡及唤回到完整可见的间隔，按事件验收。调用额度默认关闭，用户主动设限后的临时放行须能恢复原回合全部阶段。

隔离服务通过 `ChatEngine(..., private_reply_transport=本地替身)` 登记该实例的候选出口。已有旧回合沿受理时的路线处理。新桌面输入在受理时冻结候选标记，定时或手动封包时转到回合记录。兼容提交、调度、重试及重启复核同一记录。供后续 Planner 调用的 `contract` 返回作用域指纹与真实输入目标，`accept_decision` 绑定目标、动作、立场、语体、事实、篇幅、收束和有效期。决定入库后可由调度器领取。派发前再次校验人物、输入、配置与授权。在同一事务登记物理尝试并占用派发位置。收到的正文保存在独立回执，等阶段 2 的终审与发布。结果未知的尝试停止重发。[唯一正文入口](../../persona_runtime/private_reply_entry.py) · [定向回归](../../tests/test_private_reply_stage1.py)

工程验证使用三个冻结结构 33 实例的数据库副本。空白、旧历史、导入历史三组分别有 0、9、150,013 条对账范围内的既有业务记录。升级后逐行指纹一致，旧回合无新增调用，SQLite 完整性与外键检查通过，并留有结构 33 升级前备份。在隔离 Windows WebView2 中走通同意、接收账号变更确认、关闭授权，取得第 1、2、3 版授权记录。本阶段验证使用本地替身，真实模型调用 0。正式会话与 G-Auto 继续使用阶段 0 的冻结断点。
