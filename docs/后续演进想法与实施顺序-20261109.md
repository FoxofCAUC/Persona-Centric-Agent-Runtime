# PCAR 后续演进与远期目标规划

记录日期：2026年11月9日　状态：后续与远期规划目标，待各阶段细化实施

这轮规划的目标，是让 PCAR 更容易迁到其他电脑，也让没有技术背景的用户能够完成基本配置、导入人设并开始使用。先保留想法和实施顺序，本轮只整理文档；具体功能开发、部署和验收另行安排。

## 一 实施顺序

| 方向 | 安排时间 | 希望达到的结果 |
| --- | --- | --- |
| 本机环境解耦 | G-AUTO 之前 | 另一台依赖完备的 Windows 电脑能够从 GitHub 克隆并部署 |
| 工作台简化 | 无人值守联合验收通过后 | 基础配置一眼能懂，复杂页面统一收进高级设置 |
| 对话式人设创作 | 在新版工作台基础上 | 自然语言沟通设定，生成合规文件并一键导入 |
| MCP 能力扩展 | 后续按具体用途分批规划 | 为人设增加经过授权的工具能力 |
| 低门槛安装包 | 远期 | 提供 .exe 安装或 .zip 解压即用等部署方式 |

工作台简化以 PCAR 已具备无需 Agent 介入、无需日常人工管理辅助的持续服务能力为前提，拟以 G-AUTO 联合验收通过作为实施节点。环境解耦可结合 M9 的施工安排推进，但必须在 G-AUTO 前完成。以上为顺序安排，不预设各项工期。

## 二 在 G-AUTO 前完成本机环境解耦

目标是在另一台依赖项已经完备的 Windows 设备上，直接克隆 GitHub 仓库，按照手册完成安装和使用；也可以把仓库链接交给该设备上的 Codex、DeepSeek Harness 等 Agent，由其依据仓库说明协助部署。

后续施工重点：

- 明确并核验所需依赖、支持的版本和首次启动步骤，让手册能判断“缺了什么、下一步做什么”。
- 提供源码目录、运行数据目录及组件路径的设置方式。允许选择盘符和路径，支持空格、中文路径，不依赖原电脑的用户名、固定盘符或其他项目目录。
- 将程序与数据的职责分清：配置、数据库、日志、缓存、模型、QQ 资料和备份都有可定位的位置；首次部署与迁移已有资料分别说明。
- 在仓库提供面向用户及 Agent 的安装、验证、升级和退出说明。个人密钥、私人设定与本机账号资料由用户在新设备自行配置或明确迁移。
- 延续工作台绑定运行：收起到托盘可继续运行，退出软件后整体结束，不为部署便利引入系统常驻服务或开机自启。

完成标志：在另一台符合依赖要求的 Windows 设备上，从克隆仓库到首次运行、基本使用和完整退出能够按文档完成，过程不需要临时修改源码中的本机路径。完整安装器和免依赖分发包留在远期。

## 三 简化工作台的日常使用

当前工作台页面和参数较多，后续要让普通用户只接触启动、使用 PCAR 所必需的设置，同时保留现有调试能力。

新版主界面优先展示：API Key、接口 URL、模型选择，人设导入与选择，聊天入口，自动记忆开关及少量有清楚解释的基础参数，以及启动、运行状态、收起到托盘和退出。路径设置可放在首次配置或基础设置中，不要求用户理解内部目录结构。

其余复杂页面和参数通过统一的“高级设置”按钮进入，继续用于故障排查、日志检查、精细配置和开发调试。迁移页面时保持现有功能与配置可达，基础界面和高级界面使用同一份设置，避免出现两套互不一致的配置。

先梳理任务流程、页面层级、默认值、按钮名称和错误提示，再逐步改善视觉样式和交互细节。界面需要直接告诉用户现在能否使用、遇到了什么问题、需要做什么。

完成标志：不熟悉项目的用户能完成模型配置、导入人设、启动聊天、开启基础自动记忆及正常退出；日常使用无需进入高级设置，排障时仍能找到现有页面。

## 四 集成对话式人设创作助手

在人设导入页面增加 LLM 辅助创作窗口，并将“人设导入”保留在高级设置之外。用户配置模型后，可以自然语言描述人物、补充设定并反复修改，满意后再生成符合 PCAR 要求的人设 JSON。

基本流程：打开人设导入 → 选择文件导入或辅助创作 → 对话完善设定 → 查看并确认成稿 → 生成结构化文件 → 现有校验函数检查 → 一键导入。

后续需明确以下规则：

- 保留现有 JSON 文件导入，辅助创作成为新的入口；内部格式和校验规则继续统一。
- 对话草稿与已经生效的人设分开。未经用户确认的模型补充不直接写入正式人设；校验通过后也应先展示导入结果预览。
- 校验失败时明确指出缺少或不符合要求的内容，允许在同一创作流程中修正；不静默丢弃设定或导入半成品。
- 保留用户设定的可见范围，区分可用于聊天的内容与作者私有内容。创作窗口只使用用户为此次创作提供的资料。
- 创作模型可考虑复用已保存的配置或提供独立配置，开工时确定；实际调用提示与用量记录接入既有机制，避免无限自动修正和收费。

完成标志：用户从自然语言开始，无需亲自编写 JSON，就能得到可预览、可保存、校验通过并可导入的人设；已有角色不会被误覆盖。

## 五 逐步接入 MCP 能力

后期按具体需求接入 MCP，让人设可以使用更多工具。首批服务器和实际功能暂不确定，届时按使用价值、接入成本与维护负担选择，先做少量可验证的能力。

后续设计应说明每项工具可以访问什么、能执行什么、何时需要用户确认，以及失败、超时和取消后的处理方式。工具权限按人设及用途配置，不能因为某项工具可连接就默认全部开放；调用、费用和外部操作结果应可追踪。

MCP 接入后仍受工作台生命周期管理。PCAR 启动的工具子进程随软件退出；连接外部服务时仅管理本项目连接，不影响其他应用。首批具体范围确定后，再编写独立施工与验收计划。

## 六 后续开工时再确定的事项

当前先确定方向，不提前扩成完整实现方案。开工时分别补齐：环境解耦的依赖清单与迁移方式；新版首页和基础参数范围；创作助手的模型配置与长设定处理；首批 MCP 的用途和权限；安装包的分发方式与升级机制。

项目接续时先读取本规划，再结合当时的实际进度安排施工。现有 M8.E 长时待验项继续按实际情况记录，本文不替代验收，也不授权现在启动这些功能。
