## 3. 故障与修复记录

1. 角色预览新增下拉框最初使用pack，与现有按钮栏grid混用，导致窗口构造失败。改为遵循同一按钮栏的grid，7项实际隔离Tk控件检查复验通过。旧失败输出保留。
2. 审查发现已ready准备任务的显式重试会被过度去重，无法在缓存失效后重建。修复为只合并queued/running，ready允许显式retry；添加专项。队列满诊断同样可由状态接口查看。
3. HTTP政策切换需要在原事件循环调度封存后的请求；其短事务仍在原调用线程，耗时Embedding及缓存准备单独后台执行。专项确认准备被阻塞时健康、入站和投递接口可响应，封存切换只发起一次模拟主要调用。
4. 最初真实本地集成使用临时改写的阅读样例，候选未达到冻结阈值，链路正确拒识但“必然激活”的探针断言失败。未改模型、阈值或32例开发标签；改用已知D01的单个输入/来源作为集成夹具，并保留一个前置成员验证非首成员命中。此举仅确认接线，不证明泛化质量，也不抵消原样例的拒识记录。

## 4. 真实本地链路边界

`scripts/probe_m753.py`使用独立运行根目录/数据库，复用已下载模型。封锁DNS、socket连接和create_connection；未重装依赖或下载模型。启用hybrid后自动预热和构建，第二条输入触发语义候选，完成最终渲染、Manifest落盘及模拟主模型调用；预览后权威库逐条导出一致。

通过批次：自动准备1313毫秒，角色准备31毫秒，最终角色块207字符；候选reading为语义独有，命中成员序号1。实际模型指纹仍为`9604d8e7728c59a3396c7afc1e363f29ec775ed4ca59cb329bafa11831ae4be3`。Manifest输入哈希等于模拟模型实际收到的messages哈希。

两次探针累计：**3次本地查询、2次模拟主要调用、0次付费调用、0次QQ发送**。第一个批次在拒识断言处停止，第二个批次含一次聊天和一次只读预览。性能是本次接入观测，不是完整100条角色或并发压力结果。

本地模型只在服务进程内复用；超时只放弃等待，不声称强制杀死ONNX。停服时等待队列被清空，执行中的本地线程最多等1秒，不能在进程外继续常驻。已验证的准备结果在finalize只复核来源与完整性，不重新扫描缓存或执行Embedding。

## 5. 最小操作说明（仅供后续隔离/正式验收）

1. 在认知上下文页选择人格与入口，读取政策，选择“语义增强”并保存；有收集中批次先封存或取消。原“自动工作集召回”和回复模式是独立配置。
2. 在角色资料页选择入口及当前/历史版本，查看“索引状态”。准备中或失败时允许聊天继续词法；修复本地依赖/模型条件后点“重新准备”，不会下载模型。
3. 输入预览文字，选择“按入口政策”或显式模式。“requested_mode”表示选择，“effective_mode”表示实际使用，degrade_reason说明降级。预览只读且不调用主要模型。
4. 在上下文检查中查看持久角色诊断和最终来源；选择新政策不会改写旧记录。保存失败保留草稿，切换人格/入口/目标后旧异步结果不显示。
