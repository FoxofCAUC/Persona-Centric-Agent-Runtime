## 工作台导航

左侧入口使用独立Canvas视口和竖直滚动条。鼠标位于导航按钮或其间空隙时，滚轮只移动左侧导航；位于右侧时仍按原规则滚动当前页面。支持小幅滚轮输入、窗口缩放及未来新增入口，不需要全屏才能访问故障排查。

修改在下一次打开工作台时加载。不要为加载界面修订强制关闭有未决工作的正式控制台。

## 真实 QQ 测试的新边界

用户已指定独立测试QQ，日常QQ仅用于非测试。此规则适用于通用人格和私有副本，覆盖全部后续阶段；过去使用日常账号的证据保留历史事实，不能据此沿用旧流程。

实际账号只保存在运行目录的private/qq-testing.json，不写入公开文档、测试夹具或Git。该文件不是角色正典或第二套会话权威，只管理本机测试账号选择及恢复信息。日常owner_qq和当前正式人格在本轮保持原值。

### 进入与恢复

从源码目录、D盘虚拟环境执行，显式指定本项目PERSONA_RUNTIME_HOME。以下均为维护命令，不调用模型，也不会启动服务：

```powershell
python -B -m persona_runtime.qq_testing status
python -B -m persona_runtime.qq_testing enter --persona-id TEST_PERSONA_ID
python -B -m persona_runtime.qq_testing restore
```

1. 创建独立通用测试人格，记录其ID。私有角色必须使用可删除独立副本，禁止选正式受保护身份。
2. 先排空、停止全部服务并退出工作台；有收集中批次、排队/生成、未决片段时拒绝切换。
3. enter固定恢复记录，切换已有owner_qq到专用测试账号并选中指定测试人格，不修改Bot账号、不搬迁历史会话、不启动服务。
4. 再打开工作台启动服务。检查实际Bot、测试联系人和OneBot在线；机器监听准备好后才请求测试账号发送自然消息。不能把“已加好友”当作实际入站通过。
5. 收尾排空并停服、退出工作台，执行restore；恢复原额度、日常账号及原选人格，不覆盖测试账本或日常历史。

进入中断保留entering恢复信息；同一人格可续接。恢复中断保持restoring，QQ发送被阻止，显式restore完成后才回日常。不能删除恢复文件来规避检查。

### 运行时保护

- 测试模式或临时验收额度启用时，QQ桥接和v1/v2受理均校验已就绪测试账号。日常账号或其他联系人不能进入测试事件/模型调用。
- 桥接在禁止目标下不落接收日志、不发送失败提示、不领取回复；投递入口同样检查，避免意外测试发送。
- 开始真实QQ监听的工具必须先require_ready。窗口测试可以独立执行；未配置QQ测试入口时不会因此允许使用日常账号。
- 关闭额度覆盖不等于退出QQ测试模式；须按恢复步骤结束。测试模式内仍禁止向正式私有人格写入验收内容。
- 这不是多联系人开放或群聊功能；归属、引用和投递Scope继续使用既有Bot/peer规则。
