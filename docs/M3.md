# M3 私聊体验与稳定性

版本 0.3.0，2026-10-26。开发和离线验证完成，真人验收待执行。M2 已有的真人通过结论保留，不代表 M3 新用例已通过。

## 已落实的行为

- 连续消息按用户确认的方式逐条有序回复，不合并。同一人格串行生成，仍最多等待 10 条。QQ 同一账号目标的回复串行领取发送权，长回复分段不会与后一条交错。
- 聊天每 500 毫秒独立查询会话变化，不等待慢速进程身份扫描；未变化时不重复传输正文。受理后继续编辑下一条消息，前一条确认不会清掉新草稿；切页、查看记录和状态仍可操作。
- 请求详情显示阶段、队列顺位、尝试历史和实测耗时。完整响应模式没有首段输出数据，显示为空；旧记录也不补造耗时。模型远端速度没有被承诺提速。
- 本机提交意图先在 D 盘 DPAPI 加密保存，稳定请求标识用于找回回执。相同标识、不同正文或归属会被拒绝。网络结果未知时先查原请求，已受理不再生成；未受理只能显式提交。
- QQ 接收意图同样加密保存。后台仅查回执，不自动重放未受理输入。故障排查可查看未确认记录；明确提交时使用原消息标识、核对原 Bot/本人，并提示按当前人格受理及可能计费。
- 失败、重启中断、投递未知有不同恢复说明。模型失败不自动重试；生成已完成的待发送回复沿原投递流程恢复，不重新生成；不确定投递不自动补发。
- 排队取消、QQ 等待提示为可选设置，默认均关闭。前者只取消尚未调用模型的消息；后者达到阈值后每请求最多领取一次提示，不调用模型。失败服务提示与人格回复分开，不进入对话上下文。

## 使用入口

双击仓库中的 `启动人格工作台.bat`。已有窗口须关闭重开才能加载新版界面，关闭窗口保留后台服务。

| 页面 | 操作 |
| --- | --- |
| 聊天 | 找回未确认消息；请求队列与详情；原有重试最后失败请求 |
| 请求队列与详情弹窗 | 查看详情；取消选中排队消息（先在模型页开启） |
| 模型 | 私聊交互设置，保存不调用模型；等待阈值 5–120 秒，默认 15 秒 |
| 故障排查 | QQ 未确认接收；查看 QQ 待处理请求及失败生成重试；原有备份和分项启停 |

完整回复沿用 M2。未实施流式输出、运行中取消、自动重试、合并、自动记忆或群聊。用户只确认了逐条回复；其他新增交互没有代用户开启。

## 升级与回退

SQLite 版本 3 升至 4，新增阶段活动、服务提示领取记录和取消时间。旧人格、关系、事件、记忆、调用尝试和投递状态保留。初始化先用 SQLite 备份 API 创建 `backups/before-m3-*.sqlite3`，再事务迁移；失败回滚，不跳过错误继续运行。

升级应先正常排空并停止本项目消息服务和人格服务，再更新插件，启动人格服务执行迁移，随后恢复消息服务。不要让旧版服务继续使用已升级数据库；不要运行整套组件准备覆盖正在运行的 NapCat。外部端口占用不接管。

需要回退时，先正常停止本项目人格服务与消息服务，保留当前版本 4 数据库的独立备份，恢复迁移前备份至原数据库位置，使用匹配的旧源码和桥接插件后再启动。版本 3 程序不能直接打开版本 4 数据库。恢复旧备份会丢失备份之后的数据，正式执行前应另行核对，不是日常失败请求的处理办法。

## 验证

全量离线回归覆盖 M1/M2、SDK 装载、界面缩放和 M3 状态机。新增测试覆盖连续消息、取消边界、重复标识、回执丢失、加密草稿重开、多写入者、QQ 查询不重放、提示领取一次、HTTP 权限、版本 3 事务升级与失败回滚。全部使用隔离数据和模拟模型/QQ。

`scripts/benchmark_m3.py` 可用 D 盘项目 Python 运行，仅生成本地模拟报告至 `exports/acceptance`。本轮 6 条消息、模拟模型等待 40 毫秒：受理 p50/p95 为 0.0100/0.0115 秒，排队 0.1763/0.3027 秒，模型阶段 0.0534/0.0591 秒，总计 0.2306/0.3629 秒。该样本是流程基线，不是前后速度提升对照，也不含真实模型、窗口可见延迟或 QQ 网络。

真人步骤见 [M3 验收手册](acceptance/M3-真人私聊验收手册.md)。真人费用、QQ 收发、实际延迟、长时间运行和人工观察必须另行记录；未执行项目不能由自动测试推断通过。
