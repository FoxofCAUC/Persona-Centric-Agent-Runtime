## 0. 本阶段的两项已明确决策（Codex 不得自行变更）

1. **M7.5 首次实施即必须包含真正可运行的轻量本地 Embedding。** 不接受只建立接口、假向量、关键词伪装语义、把向量模型推迟至 M8/M9，或每轮调用云端 Embedding API 来冒充本地实现。默认候选：**FastEmbed（ONNX Runtime/CPU）+ `BAAI/bge-small-zh-v1.5`（512 维）**；该候选须经实际 Windows/Python 环境探针验证后冻结具体包版本、模型修订和文件哈希。如有兼容性阻断，可提交简短 ADR 比较本地 ONNX 替代实现，但仍须在 M7.5.1 实现实际 Embedding，不能降格成纯词法方案。
2. **M7.5.1、M7.5.2、M7.5.3 分别施工，但不分别进行正式阶段验收。** 这三个工作包允许必要的快速静态检查、定向单元测试、一次真实本地模型冒烟测试和缺陷定位；**禁止每包都跑一次项目全量回归、真实付费模型整套质量对照、真实 QQ 联合验收、正式库迁移或出具“阶段验收通过”结论。** 在 **M7.5.4** 统一进行一次有记录的**联合功能、检索质量、兼容性、迁移恢复及必要真实场景验收**。如果最终失败，先对失败影响范围补验，只有涉及基础合同的广泛变更才决定是否追加全量；应记录额外运行理由与次数。

**解释：** “前三包不验收”不是“不写测试”或“带着已知致命故障堆功能”，而是取消三个中间正式验收门，将成本高、涉及平台的验收集中到最后一次。禁止把 .1/.2/.3 的局部测试写成整个 M7.5 已验收。

## 1. 项目目标、现有基础与范围

### 1.1 想解决的实际问题

现有 M6.0 `character_context.select_context()` 依靠明确字段路径、别名、`lorebook.keywords` 和 `examples.keywords/scenario` 进行激活。例如“你老家在哪儿”可能命中 `biography.hometown`，但“你小时候最熟悉的地方”“你曾经长大的那座城市”等间接问法无法稳定找到相同角色资料。**M7.5 让角色理解语义相近的提问，主动选择与本轮相关的创作者设定，而不是把完整人设书每轮塞给模型。**

预期提升：

- 对同义改写、隐喻式问法、实体别称、关联人物/地点/事件，能找到正确的 Character Bible / Lorebook / 相关表达样例。
- 保留**明确事实优先**（已设置的身高、生日等不被向量相似度覆盖）、**未设置保持未知**、**创作者正典不被模型写回**。
- 在不扩大 Scope 和 `creator_only` 权限的前提下，把检索结果以带来源的 `CharacterContext` 注入现有 `DialogueContext`，并纳入 M7.2 的 Context Manifest。
- 本地模型下载/准备完成以后，**普通对话的 Embedding、查找和排序不联网、无需新增付费 LLM 请求**；语义服务异常时安全退回现有的词法路径。

### 1.2 已有代码与必须复用的合同

| 现有能力 | 代码/来源 | M7.5 的接入原则 |
| --- | --- | --- |

**硬边界：** M7.5 不开发情绪引擎（M8.B）、独立人格反思（M8.C）、Director/人格演化（M10）、世界知识与热梗更新（M9）、主动消息、群聊、语音/多模态，也不更改 Persona Core、正式 Relationship/Expression 政策和 AstrBot 桥接权限。

### 1.3 本阶段不允许使用的捷径

- 不能每轮将 100 个 Lorebook 条目全量交给主模型，让主模型“自己挑”。
- 不能只调用 LLM 做 query rewrite 就宣称已完成 Embedding。
- 不能以关键词命中率高为理由删除本次明确要求的本地 Embedding 工作包。
- 不能使用“语义相似”覆盖精确引用、时间有效性、角色版本或可见性检查。
- 不能为了兼容向量检索迁移到新的大型服务、常驻独立数据库服务或云模型，除非基于真实基准另行批准。

## 2. 轻量 Embedding 选型及运行合同

### 2.1 首选候选与选型冻结

- **模型候选**：`BAAI/bge-small-zh-v1.5`，中文优先、512 维、约 24M 参数、公开权重约 95.8 MB，模型页标示 MIT 许可。适用于主要中文、夹杂少量英文术语的 QQ 私聊。对日语、英语或高度专业语料的覆盖不做无证据承诺。
- **推理库候选**：`fastembed` 的 Python `TextEmbedding`，采用 ONNX CPU 推理；它的受支持模型清单包含该模型，提供 `cache_dir`、`local_files_only` 和本地模型目录参数。**固定依赖版本和模型快照时以实施环境测试为准**，不要在本文提前写一个未经验证的版本号。
- **候选向量维度**：512；向量前后必须采用**相同的归一化与编码策略**，评分采用 cosine 或归一化后内积；不得混用不同模型的向量空间。
- **运行形态**：常规请求只做轻量 query embedding（模型按需加载、复用），Lorebook/样例的文档向量在编辑/导入/回滚后的后台或预处理阶段生成；小数据集优先采用 NumPy 内存余弦相似度或等价方案，**不强制 `sqlite-vec`**。如实测大规模卡片检索有瓶颈，再提交向量索引 ADR，不能先为最多 100 个 Lorebook 建复杂服务。
- **M7.5.1 必需探针**：在项目实际 **Windows + Python 3.12 + D 盘 `.venv`** 中完成安装/导入、固定两对中文语义样例、向量维度/有限数/归一化、离线重启加载、缓存路径、冷/热时延和内存占用测试。没有这个真实模型探针，不算完成 .1 的开发交付。

参考：

- https://huggingface.co/BAAI/bge-small-zh-v1.5
- https://qdrant.github.io/fastembed/examples/Supported_Models/
- https://qdrant.github.io/fastembed/Getting%20Started/
- https://github.com/qdrant/fastembed/blob/main/fastembed/text/text_embedding.py

### 2.2 离线、文件路径与许可

按照仓库 `AGENTS.md` 规则，数据根使用 `PERSONA_RUNTIME_HOME`，通常为 `D:\Persona-Centric Agent Runtime`；以下子路径**仅为建议，具体名称由开工合同冻结**：

```text
$PERSONA_RUNTIME_HOME/
  .venv/
  models/character-embedding/       # 安装/导入时明确取得的模型权重
  cache/character-semantic/v1/      # 可丢弃、可重建的向量及索引投影
  cache/fastembed/                 # 工具缓存（或统一指向 models 下）
  acceptance/M7.5/                 # 本地验收证据与小规模评测结果
```

- **只在明确的“安装/模型准备”操作中允许下载。** 普通对话、冷启动、索引失效、异常恢复、后台任务不得静默联网下载模型；运行时使用 `local_files_only=True` 或等价离线模式，找不到本地模型必须明确标 `embedding_unavailable`，走词法回退。不能误将下载失败包装成检索命中。
- 依赖缓存、Hugging Face 缓存、模型文件、运行时临时文件及测试输出均指向 D 盘数据根；不能因第三方库默认设置落到 C 盘或系统临时目录。
- 权重、缓存、个人角色卡、聊天原文、运行库、日志与凭据都不提交 Git；遵守项目许可证与第三方模型/代码的原许可登记。
- 不把私密角色设定送往第三方 Embedding API；`creator_only` 条目**不进入面向普通对话的 Embedding 候选库**。
- 缓存路径需做归属、符号链接/重解析点、意外指向权威数据库等检查；沿用 `ArchiveIndex.safe_path()` 的设计原则，但不要复用聊天档案索引文件。

### 2.3 索引一致性与生命周期

向量缓存是**派生投影，不是事实来源**。每条索引记录至少绑定：

```text
persona_id
character_version_id（请求受理时冻结的版本）
item_kind / item_id / field_path（稳定源定位）
source_content_sha256 / index_text_version
embedding_model_id / pinned_revision / model_file_hash
embedding_dimension / normalize_policy / index_schema_version
visibility / enabled（仅用于二次核验，不能取代权威读取）
```

- 使用当前**已受理请求的角色版本**读取源数据。角色编辑、导入、恢复都必须确保**新版本重新索引**；旧版本若仍被已受理请求引用，可按版本保留其索引，或从对应不可变角色快照安全重建。绝不让旧向量对应新正文。
- 模型升级、量化策略变更、文本拼装模板变化、归一化变化、索引格式更新，均要改变缓存指纹并触发重建；不允许新旧模型向量混排。
- 在选中候选和主要模型调用前，重新按权威快照核对 item、来源、可见性和版本；删改失效条目不能因为向量缓存未更新而继续被使用。
- 索引损坏、生成中断、超时、缺模型时可以重建或词法回退；不得阻塞输入保存、真实 QQ 投递、原始档案查询与已有健康检查。
- 模型对象按进程复用但并发有界；避免每条消息反复加载权重，也禁止在主库写事务中执行 CPU 推理或下载。

## 3. 查询、候选、权限与上下文合同

### 3.1 推荐检索顺序

```text
当前 InputBatch 的完整原文 + 已授权情境信号 + 冻结 CharacterVersion
    ↓
确定性 Scope / visibility / enabled / version 过滤
    ↓
精确字段路径与已知别名（强匹配，作为“硬事实”）
    ↓
本地词法候选（M6 关键词、标题/实体别名、必要时字符/FTS）
           ＋ 本地 query Embedding → 同版本的 Lorebook/示例候选
    ↓
候选去重与融合、阈值/拒识策略、稳定排序
    ↓
Lorebook 依赖完整展开、权限再次校验、预算裁剪
    ↓
CharacterContext → DialogueContext / ContextManifest → 主模型
```

**硬约束：** 精确身高/生日/血型等必须走现有 `read_fact()`/别名合同，语义相似只是补充候选，不可覆盖准确值或把 None 补成“推测值”；低分、无证据、模糊问法允许返回 `no_relevant_character_data`，不能为了“有活人感”强行注入无关设定。

### 3.2 建议组件边界（名称为建议，并非现有 API）

```python
CharacterEmbeddingProvider  # 本地 CPU 模型加载、embed_query/embed_documents、模型身份
CharacterSemanticIndex      # 按 persona + version 管理可重建向量投影
CharacterCandidateRetriever # lexical + embedding 候选、稳定排序与来源信息
CharacterContextSelector    # 复用精确事实/依赖/预算/可见性，输出已选条目
```

建议 `CharacterRetrievalRequest` 至少携带 `persona_id`、`character_version_id`（或冻结版本数据）、完整 `query_text`、授权 Scope、scenario、检索上限和预算；`CharacterRetrievalResult` 至少提供选中项 ID、`origin_type=creator_setting`、命中来源（exact/lexical/semantic）、匹配分数或分数桶、模型/索引版本、降级原因和丢弃原因。

**注意：** 这些是边界契约，不要求机械创建四个重量级类或额外服务；具体代码结构应顺应现有 Python 代码风格和可测试性。

### 3.3 排序、依赖和预算

- 首选稳定的融合方法，如词法与语义候选的 **RRF（倒数排名融合）**；融合权重、语义阈值与 Top-K 必须由开发集调参并在独立验收集上报告，不能拿模型给出的 cosine 分值当成无条件置信度。
- 直接精确事实优先于所有可选条目；`lore.priority` 只在同等合格候选中排序，不绕过 `enabled/visibility`。
- 继续遵守 `character_context.py` 已有的 **Lorebook 最多 4 条、依赖最大深度 2、动态人设约 1,600 字符、整体角色块 3,000 字符**等约束；如果 M7.4 修改预算，则以实际已经验收的合同为准，不在 M7.5 偷改。
- 依赖组原子选择：一个主条目和其必要依赖必须同进同退；装不下时记录原因，不注入半个背景，避免语义误解。
- 设定知识、真实共同经历、公共世界知识属于不同语义域：**向量相似不授予数据跨域合并权**。角色设定不可被转写为“我们真实经历过的事”。
- 优先使用确定性的 `match_reason`、`selected_ids`、`removed`，避免任何不可复现的随机重排。

### 3.4 回退、观测与安全

- 缺模型 / 模型校验失败 / 向量索引损坏 / 超时 / 内存不足：**自动退回现有 M6 词法激活**，记录明确诊断，但不隐藏必要的角色事实或受理原始输入。
- 明确要求查某条精确资料时，如果其角色版本不存在、权限不足或事实字段未知，不能用最近似的候选代替；遵守现有失败/未知语义。
- 显式引用、档案 Scope、`creator_only`、版本快照、记忆撤回和正常 QQ 投递流程，不受 Embedding 分支影响。
- 模型失败与向量降级应分别报告；不允许检索失败触发额外主要 LLM 调用或私自提高费用上限。
- 将外部导入的角色卡与 Lorebook 正文视为**参考数据而非系统指令**，避免索引结果里的恶意文本改变权限、联网或工具行为。

## 4. 四个工作包及“唯一联合验收门”

### M7.5.1 — 轻量 Embedding 底座与索引生命周期（**施工，不单独验收**）

**本包必须真正接入 Embedding，不能只建立空实现。**

工作内容：

1. 核对 M7.4 完成后的基线、Python/Windows 架构、D 盘存储与已有依赖；编制模型/框架选型记录，验证 FastEmbed + BGE-small-zh-v1.5 可实际工作；固定模型修订、依赖版本和哈希。
2. 添加本地模型装载器、有限并发、离线运行、缺失诊断；避免在线请求被聊天隐式触发。
3. 定义角色源片段规范：优先 `lorebook.title/category/keywords/text`，选择性加入已允许的表达样例和公开的社交/背景字段；保留 `kind`、`id`、来源版本，避免长段截断改变含义。`creator_only` 和禁用条目不在普通查询索引内。
4. 增加 D 盘可重建缓存，能够为版本生成、读取、校验、失效并重建向量；支持角色编辑、导入、回滚、模型更换后的正确失效。
5. 实际生成中文测试向量，验证 512 维、有限数、同模型一致性和真实离线查询相似度；写最小单元测试与**一次本地模型冒烟记录**。

局部自检（**不构成阶段验收**）：本地模型能离线加载并给出真实向量；索引不写正式人格事实；模型缺失时词法旧路径可用；不跑项目全量、不发真实 QQ、不调用付费主要模型。

交付代码建议：`character_embedding.py`、`character_semantic_index.py` 与隔离缓存测试。文件名由 Codex 按现有结构决定。

### M7.5.2 — 语义候选、融合检索与 Lorebook 关联（**施工，不单独验收**）

工作内容：

1. 在已有 `select_context()` 旁建立候选召回接口，输入冻结角色版本、用户原文及必要场景；融合精确别名、关键词匹配与 M7.5.1 真向量结果。
2. 引入正负样例、阈值拒识和稳定排序，避免纯相似度导致“提到校园→硬激活所有学校角色”。
3. 对 Lorebook 实现实体别称、关联/依赖展开以及整组预算；严格保留现有 `enabled`、`visibility`、深度、数量限制。
4. 为表达样例增加可选语义候选（仅已启用样例），不让示例台词反过来成为角色经历事实。
5. 输出结构化候选结果及 `selected / rejected / removed / degrade_reason`，让 .3 可以无歧义组装。

局部自检（**不构成阶段验收**）：仅运行定向的语义同义句、同名误匹配、依赖缺失、禁用及 `creator_only` 测试；这一步不做付费模型/QQ 的正式联合对照。
