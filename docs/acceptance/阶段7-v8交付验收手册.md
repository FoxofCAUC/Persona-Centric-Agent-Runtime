# 阶段7 v8交付验收手册

当前结果以[交付记录](../阶段7-v8正式交付记录.md)为准。本手册不是已通过证明。

1. 只读核对目标、源schema、角色双入口、Bot分工、服务归属、未决状态。受保护证据保存D盘；不得先用会自动迁移的正式初始化。
2. 离线检查新建/原生导入/复制双入口v8、事务故障、关闭恢复、幂等、旧快照、历史关闭保护、用户选择冲突、桥接权限与投递。集中174项已有通过证据；工具改动另做定向补验。
3. 使用专用20→21核验器检查人工数据和正式隔离副本。故障回滚、重复升级、原表内容、导出17、无凭据、恢复后升级均必测。核验副本不联网、不接QQ。
4. 显式运行`plugins.release_acceptance`离线演练；完整关闭并重启真实Workbench，确认不自动重放。模拟只证明工程路径。
5. 同源码执行工作台5个真实位置和1次整理。更正使用全新人工储物柜事实；旧记忆源为人工用户事件。真实候选必须明确关联唯一旧记忆、人工更正来源有效；批准后核对旧版本superseded及新版本，再重启追问。若真实候选不合格，保留失败，不补造候选、不重放。
6. 独立人工角色、独立运行根和专用测试Bot运行QQ三位置。按工具冻结清单逐步发送；等当前回复投递结算再发下一项。普通、5秒合批更正、长文本分片和拼接分别核验。生成完成不等于QQ送达；至少要求平台消息ID和sent账本。
7. 结束测试Bot与隔离进程后给出正式切换预览。目标采用用户确认的数据库当前选中角色；另一登记私人角色不动。清点收集、队列、运行、整理和投递，未知效果阻塞，禁止重放。
8. 正式停机受保护备份；升级21；通过现有interaction.update按expected_selected/expected_version/operation_id切换双入口，来源release。两个入口都成功才恢复受理；部分成功则保持暂停并追加恢复版本。
9. P01工作台、P02原日常Bot各一个实际位置；检查v8请求快照、一次生成、工作台显示和QQ回执，请用户确认手机实际可见。不得把模拟或HTTP成功当用户确认。
10. 检查关闭恢复与其他角色未改；结束测试进程；按归属清理验收副本及私人派生导出，只保留无正文状态。正式业务记录和正常备份按原职责保留。
11. 工程、隔离真实、正式部署、用户可见确认分栏记录；M8.A交接、隐私检查、文档链接、源码指纹、差异通过后提交推送并核对远端。

错误角色或Bot、重复收费/投递、关闭失效、来源/权限异常、账目不明时暂停相关入口。政策回退仅影响后续受理；旧备份不得覆盖迁移后新增业务写入。固定成功位置不重放，新增位置须先登记真实失败或覆盖缺口及理由。

本轮实际完成工程、隔离真实、正式部署及手机可见确认。P01零派发权限失败后按用户明确授权新增P01R，不能将首次失败改写成成功；v2投递核验以分片账本为准，旧兼容占位不代表待重发。最终重启仅观察已有回复，不新增调用。删除清理被自动审批拒绝后转用户手动，现已完成并复核14个目标不存在。执行细节及已知用量见交付记录。
