## 真实环境验收步骤

1. **已完成（2026-10-27）**：运行库只读检查显示结构8。使用 SQLite 备份 API 将其复制到系统临时隔离目录，在副本执行8→9→10、检查38张既有表原列/记录一致及 `PRAGMA integrity_check` / `foreign_key_check`，恢复到8后再次升级到10。恢复和重复初始化通过，源库哈希/版本不变，临时副本已清理。报告：`D:\Persona-Centric Agent Runtime\exports\acceptance\M6.3-20261027\migration-copy-check.json`。
2. 使用独立测试人格生成超过 900 字的回复，检查其被拆成多个实际 QQ 发送片段；确认拼接后和完整回复事件一致。
3. 在工作台打开“回复投递”，确认每片有稳定顺序、尝试次数、SHA-256、状态和平台 message ID；完成发送后与 QQ 消息记录逐片核对。
4. 使用隔离故障注入，让前两片发送成功、第三片超时；检查前两片仍 sent，第三片 uncertain，后续片及同一目标后续回复均暂停，不自动重发。
5. 重启隔离服务，确认在途片转 uncertain；核对后显式标记已处理或跳过余段。分别验证单片显式重发会增加 attempt 并显示可能重复。
6. 检查旧插件/旧客户端不能把新批次转为全文投递；旧历史 turn 仍遵循原 delivery 记录。
7. 导出测试人格，确认格式 7 带投递记录但不含 claim token、配置令牌或模型凭据。

实际 QQ 投递需要事先确认测试目标、插件在线和既有额度；发送前检查现有服务状态。平台返回成功只证明接口应答，不证明对方已读。不要为了测试改变 M6.2 的默认回复模式。
