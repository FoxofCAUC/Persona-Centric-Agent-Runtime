## 真实工作台与模型检查

仅在测试人格和现有授权模型可用时执行；当前服务保持停止，执行前需先按本地生命周期规则核验归属、备份和正式/隔离环境。

1. 确认桌面与 QQ 两个入口初始显示“兼容全文”；普通请求仍为全文、一次主调用。
2. 在隔离测试人格的设置中，仅将桌面入口切为“情境全文”。发一条技术求助和一条轻松闲聊，确认提示有差异且不会增加第二次理解调用。
3. 设置一条 `technical_help` 表达样例，提交技术问题，确认选中样例只影响风格参考；发无关问候，确认该样例未激活。
4. 切换至“情境结构回复”，测试“更正：你刚才写错了类型，请按代码解释”及一条含代码块的技术请求。确认回复段数 1–3、代码围栏完整，工作台展示正文而非内部 JSON。
5. 通过可控测试模型响应验证额外字段、重复 JSON 字段、无效 JSON 和未闭合代码围栏被明确拒绝；确认仅一次模型调用、用量保留、没有 JSON 回复事件，也没有自动修复重试。
6. 在一个请求排队后修改回复模式，确认旧请求继续按受理时模式，新请求按新模式处理。
7. 以桥接令牌请求管理更新，确认 403；以管理员请求更新并重复同一 operation_id，确认幂等；旧 expected_version 保存应返回版本冲突。
8. 导出隔离人格，确认包含回复批次/段和关联索引，不含凭据；迁移/恢复只在副本验证并比对旧表数据。

真实模型调用连续失败达到第五次，或 QQ 明确掉线/服务中断，立即停止并记录，等待恢复；不盲目重试。工作台/模型验收与实际 QQ 消息送达分开记录。
