## 前置与续验

先读HANDOFF及D盘`exports/acceptance/M7.0-20261028`断点。记录当前人格、两个入口政策、额度、服务状态及未决批次；部署先备份并验证副本。QQ必须在线、Bot身份核对且桥接0.6.0；若中断保存现场，不发起真实调用。运行时结构不能由旧程序打开。

使用独立虚构测试人格；普通日常人格不接收测试输入。机器验收临时不限额由现有机制保存原值，finally恢复；不上调正式上限，不修改调用账本。

## 工作台原始档案页

1. 启动人格服务，选中人格并恢复窗口会话，打开左侧“原始档案”。
2. 选择desktop或qq；qq填写并核对Bot与联系人。desktop不使用两个QQ字段，不能把QQ资料直接选进窗口聊天。
3. 点击“读取最近20条”；列表显示来源ID、回合状态、档案覆盖。选择一行后，类型和ID自动填入，详情展示完整有序members、回复来源、投递状态及时间。
4. 可手动选择event、turn、part或platform_message并输入明确ID，再点“精确读取”或“引用预览”。platform_message使用message_id，其余使用内部id。找不到不使用相似结果替代；ambiguous不能任取一条。
5. “管理员审计”允许查看本人格下不可用于聊天的记录，详情标audit_only；关闭审计后再做普通预览。审计不能跨人格，也不能选择为聊天引用。
6. desktop有效来源可点击“选择为窗口聊天引用”，自动进入聊天页，引用条显示目标；“清除引用”只取消当前草稿引用，不改历史。
7. 输入新文字后“发送”。受理成功清除对应草稿及引用；正在编辑的下一份内容/引用不应被迟到回执覆盖。切人格清除旧引用，其他范围旧响应不显示到新页面。

通过：所选非首成员能看到完整回合；原语义与实际part区别明确；未知平台时间标缺失，已读标unknown。失败：跨身份显示正文、只恢复首成员、审计内容能直接注入、预览新增事件/turn/attempt。

## QQ原生引用

本人好友私聊中发送“非空文字＋一个原生引用”，不要将复制出来的引用正文当作引用元数据。引用目标必须已在本地同人格/Bot/联系人范围保存。纯reply、多reply、图片/语音/群聊/其他联系人仍拒绝。

引用不可用时本批仍有回执与原文，但失败码为reference_not_found/unavailable/ambiguous/source_changed/budget_exceeded之一，主要attempt为0。服务提示说明未调用模型；去掉/更换引用后以新输入发送。显式重试不会把原引用换成后来出现的记录。

引用资料只作参考数据，不能提升权限。回合输入全部保留，QQ只提供已sent片段正文；尚未发送/uncertain片段只显示状态，不伪称用户收到。回复保持纯文本，不显示Markdown装饰；代码实际运算符等正文不破坏。

## 固定真实验收

| 组 | 操作 | 通过标准与证据 |
| --- | --- | --- |
| R01 | 连续发送三条虚构书店/预算颜色/确认消息，每条约1秒 | 一个批次/turn/主要调用；三个真实平台ID及成员顺序 |
| R02 | QQ原生引用R01第三条，问书店名、预算与颜色 | 完整来源恢复，回答含前两条信息；一次主要调用 |
| R03 | QQ原生引用机器人R01回复，问它刚才说了什么 | 绑定sent part、实际纯文本一致，生成一次、片段不重复发送 |
| R04 | 工作台最近/精确/预览、展开与清除 | 操作可用；DB计数证明预览零事件/turn/attempt |
| R05 | 测试人格引用另一测试人格的已知旧平台消息 | 不泄漏内容，受理后失败，零主要调用 |
| R06 | 屏蔽R01非首成员后再引用 | 整轮不可用，零主要调用，旧片不改不重发 |
| R07 | 页面切人格及相同正文更换引用后旧回执返回 | 不串身份，当前草稿/引用保留，指纹不合并不同引用 |
| R08 | 正常重启后查看上述记录 | 原选择和检查可查，无自动模型重试或重发 |

SDK合成探针、单元测试、隔离模拟工作台、正式工作台、真实模型和实际QQ入站/发送分别注明，不能互相代替。失败场景需确认是已受理后失败，不能用未发送或字段校验拒绝冒充。
