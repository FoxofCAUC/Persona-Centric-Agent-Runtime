# 外部私聊历史接续验收

## 用户可见行为

新版 Windows 工作台提供新建角色带历史保存及已有角色接续两个入口。确认本人身份后，另一方对应目标角色，同时建两人只在对侧建立历史会话。来源模型与长期记忆用途分开管理。[用户操作](../user/历史聊天接续.md)

## 数据和回复依据

业务结构为 33。正式建角、旧活动会话封存、新会话、导入回合和本次提交回执在同一业务事务中保存。原文件仍可在本机私有区查核。每个气泡保留文件消息编号和范围，未知日期使用单独的缺失值。明确的助手身份不充当本人。历史写入本身产生零模型调用、零交付或已读回执。

桌面首条新输入使用正常接话链路。依赖历史来源的普通 v8 回复以及已启用场景的回复使用真实桌面呈现回执，保留已确认前缀。精确引用按事件定位，既有全文或召回索引用于查询，索引条目仍需回查当前业务证据。已允许的长期记忆沿用两阶段整理及按来源发布。

## 分项核验

- 用本地模型替身对照原生与导入路径。两组连续六轮的主模型可见角色、正文和顺序逐项相同。另验按事件引用、引文隔离、在途撤回、回复生成后尚未呈现时撤回。
- 场景路线核对用户连发与对侧连回、Jev 判别、查前发言先呈现再检索，以及查后主回复。发送给公开检索的内容仅含获准的公开问题。
- 两个隔离的 Windows WebView2 实例验过正式建卡、已有角色、旧原型原地复核、历史搜索引用、暂停整理、保持已显示结果、撤回未呈现内容和跨进程重开。控制台可见性不代替实际显示回执。
- 在获准副本上逐条比对 46,910 条历史的显示原文、位置和归属。首屏取末尾 80 条。大库的索引在后台按会话分页推进。另用同规模数字档、23,455 个回合测试后台记忆积压，同时发言优先。
- 人物模型变更、迁移副本、独立历史及非所选人物分别复核。迁移后恢复本机浏览，原话的云端用途重新确认。退出旧版程序或回退前留存新版业务数据，使用升级前备份恢复旧程序。

结项复测覆盖公历中不存在的日期和分钟越界的时区偏移。建卡与已有角色接续都能保留该气泡及原始日期标签，预览和模型证据将日期列为待核。已存草稿的预览端点含无效日期时，重开会重新计算可用日期范围。正常时间记录的分析计划指纹通过对照。

收尾从干净检出运行 401 项相关回归，400 项通过，1 项旧版私有回放因缺少单独素材跳过。检查范围涵盖建卡、历史接续、记忆、角色发言、迁移恢复、打包与发布保护。此次复验使用本地替身和既有回执，新增云端调用为 0。Windows 交付包的清单记录对应 Git 提交、业务库结构和文件校验值。

## 原时间装配

作者已批准将原时间用于发布版。当实际采用的导入正文具备可核验时间，主模型系统消息末尾附 history_recorded_at，按本轮消息位置列出原时间。Jev 的对应历史项可带 recorded_at。原气泡的角色与正文保持原样，缺失时间直接省略。已在普通 v8、超长裁减、Jev、查前和查后路径使用本地替身核对字段。首批 24 次主回复使用此前冻结的普通 v8。第二批使用经审阅的原时间与连发装配。

## 原生连发装配

首轮作者盲审固定位置 4/6、连续对话 1/6，严重问题 0 项，合计 5/12。两组系统人设相同，但旧导入路径逐泡传递历史，原生路径按同轮合并用户连发。作者核准了使用原生连发格式的完整候选请求。新版本在普通 v8 及场景主回复中按导入回合处理，单条正文原样使用，多条用户原话沿用原生输入包装，多条人物发言以两个换行分隔。工作台呈现、精确引用、Jev 与整理仍逐泡核对。每个有可靠时间的气泡指向实际承载它的请求消息，裁减后重新计算对应位置。第二批采用新的独立留出位置，账目及评分单独记录。

## 体验验收
