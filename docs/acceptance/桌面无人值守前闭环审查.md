# 桌面无人值守前闭环审查

2026-11-19。源码基线为 `ee79a52`，包含双人建卡、外部历史接续及真实 WebView2 聊天。本轮仅登记源码中可定位的断点、需用户决定的事项及待测风险。修补方案和正式 G-AUTO 留待后续确认。

用户侧目标是一次完成所需设置后，就能从聊天窗口长时间交流。运行中的暂时失败应有明确归宿，后台例行工作由程序推进。可恢复场景的管理介入目标为零。长时故障率、尾部等待时长和真实交互质量需要独立运行数据。

## 用户决定、外部条件和暂停范围

| 编号 | 边界 | 按实际状态记录 |
| --- | --- | --- |
| B01 | 首次配置与显式偏好 | 用户选择角色、设置可用模型和密钥、决定自动记忆或联网用途。日常交换消息沿已确认选项运行。 |
| B02 | 私聊导入与资料权利 | 本人身份、对侧归属、原话范围、接收模型、撤回和删除由用户决定。已有授权范围内的处理和撤回后失效传播属于系统责任。[历史来源与用途](../user/历史聊天接续.md) |
| B03 | 用途或接收方变化 | 迁移到新机、变更被授权的提供商或资料用途时有明确确认。后台维持原冻结范围，并记录等待原因。[迁移启用](../../persona_runtime/migration.py#L398) |
| B04 | 事实冲突及人格正典 | 证据足够的记忆修订由已有规则推进。真正无法判定的冲突可留在隔离状态。用户改变人物正典和确认来源须保留原归属。 |
| B05 | 请求效果或费用未知 | 已派发但效果未知的调用和未能确定的显示单独记录。已有可核验证据可用于续跑；新调用、显示及费用结算各自遵循证据。[派发证据与限次](../../persona_runtime/generation_retry.py#L164)、[任务恢复](../../persona_runtime/managed_organization.py#L630) |
| B06 | 凭据和环境的外部故障 | 吊销密钥、余额不足、供应商停摆、长时间断网、系统权限和外部端口占用按实际原因单列。已有配额跨窗口等待与短时退避按现有合同检查。[用户环境条件](../user/getting-started.md)、[额度回归](../../tests/test_m8a.py#L164) |
| B07 | 真实性与数据恢复 | 磁盘空间无法释放或库确实损坏时需要数据归属和备份版本决定。恢复前的隔离、可读性、故障记录和已有回执保全仍是系统责任。 |
| B08 | QQ 与可选主动能力 | QQ 按当前暂停安排，相关登录、掉线与投递人工处理留在对应阶段。主动问候和提醒沿用户明确启用与静默规则记录。[阶段衔接](无人值守陪伴-阶段门与验收矩阵.md)、[主动规则](../../persona_runtime/proactive.py#L49) |
