## 1. 准备

1. 保留所有现有数据，关闭旧窗口后双击 `启动人格工作台.bat`，确认标题M5和“人格与关系”页。
2. 先核对服务状态；需要时仅启动本项目人格服务。QQ项目仍从正常入口核对身份，不接管未知占用。
3. 故障排查备份数据库和加密配置，记录D盘路径；结构升级备份应有 `before-m5-*.sqlite3`。不要用清库解决版本问题。
4. 建议新建独立测试人格A并明确切换，避免改动正式人格。记录A的UUID、模型名称和原设定。每日周期开始时绑定当前人格，注意当前选择，不为验收改动每日预算。
5. 在D盘 `exports/acceptance` 建立本轮结果文件，复制末尾表格。测试文字均为虚构资料；截图不要包含密钥、令牌或私人聊天。

编辑、比较、回退、状态和关系建议本身不调用模型。主流程预计8–14次前台调用；真实模型对照是可选项，另外计数。后台每日调用也消耗全项目小时额度，额度不足分批执行，不为测试提高上限。无排队请求以模型超时加30秒为检查点，超时先查看状态，不连点重试。

## 2. M5 必测

### P01 同一人格编辑与导入区别

人格与关系点击“刷新人格与关系”，记下UUID和四类版本。点“编辑当前人格核心”，将名称改为“清和（M5虚构测试）”，其余字段保留，点“保存核心设定”。

通过：UUID不变、核心版本增加，原会话及有效记忆仍可查看，表达/关系版本未被一起改动。保存不调用模型。在另一个测试人格做JSON导入仍产生新UUID，不能覆盖A；不必为了本项重复导入正式人格。

证据：前后ID、版本和当前人格名称；没有独立执行导入部分须单列未执行，不用旧结论伪造新截图。

### P02 表达独立版本与自然度

点“编辑表达习惯”，填：

```text
自然、简短地交流；平常用一两句话，有必要时再展开。避免每轮重复自我介绍，不使用固定口头禅。
```

保存后新建聊天会话，依次发送：

```text
今天没什么特别的事，只是想聊两句。
我刚才那件事想听听你的不同看法，不用一味顺着我。
换个话题，你怎样看待保持好奇心？
```

点聊天“查看本轮记忆使用”，核对表达版本和核心版本。

通过：表达版本独立变化，核心不变，使用记录可追溯。分别记录是否自然、是否机械复述设定和是否无依据附和；代码记录正确不代表自然度自动通过，语气不满意要留具体例子。

### P03 版本比较和回退

人格与关系选择“核心设定”，点“读取版本历史”，选择初版，“与当前版本比较”，查看名称前后差异；再点“恢复选中版本”。

通过：产生新的恢复版本，旧修改记录仍在，UUID、会话及有效记忆保留。当前核心恢复到初版内容，表达版本继续是P02选择的版本，没有被整体倒回。恢复不复活已撤回记忆。

### P04 显式关系与有来源建议

1. 点“编辑关系说明”，填 `M5虚构关系：彼此尊重的手账交流伙伴，称呼用户为“同学”。`，保存并记下关系版本。
2. 聊天发送：

```text
M5虚构确认：我希望以后在手账交流时叫我“伙伴”，这条话只用于本轮测试。
```

3. 人格与关系点“从来源创建关系建议”，选择上面这条**用户发言**（不能选人格回复）；填写 `M5虚构关系：手账交流伙伴，称呼用户为“伙伴”。`，保存。
4. 刷新、查看建议与原文。此时不要确认，核对正式关系仍是旧版。
5. 点“编辑并确认关系建议”，核对文字后点“确认关系生效”。新会话发送 `我们在这轮测试里约定怎样称呼我？`。

通过：建议有准确来源，确认前关系不变，确认后增加版本并被新会话使用；创建/审阅没有产生额外模型调用。重复确认不重复建版本。创建另一建议后拒绝，正式关系不改变，原始事件不删除。

### P05 显式临时状态和到期

1. 记录核心/关系版本。有效小时填 `0.02`（约72秒），点“设置临时状态”，填 `本轮临时希望语气更简洁，只影响当前表达。`，保存。
2. 到期前发送 `请简单接着刚才的话聊一句。`，查看本轮使用记录，状态版本与期限应有值。
3. 等页面显示已到期后再次发送，查看本轮使用记录，状态版本应为空；核心/关系版本不变。
4. 也可重新设置有效状态，再点“结束临时状态”，检查后续不使用。测试后把有效小时恢复24，不必设置新状态。

通过：时间按实际日期生效，状态不会永久变成核心；旧状态历史保留。到期前已发出的调用不要求中断。实际回复变短只作辅助，必须核对使用记录。不要改系统时钟加速验收。

### P06 排队期间编辑的归属

发送一条较长测试请求，受理后再发第二条；两条都受理后去修改表达习惯并保存。完成后检查两条请求的使用版本，再发第三条。

```text
M5排队1：请写一段约300字的虚构散步日记。
M5排队2：请简单接续上一条日记。
M5排队3：请用现在的表达习惯打个招呼。
```

通过：前两条固定受理时核心/表达/关系版本，第三条使用新版；不改人格归属，不丢失用户事件。若修改前全部已完成，进行中部分记未触发，不能凭已完成记录代替。

临时状态有独立规则：调用开始时已过期则不使用，不要求它跟随排队时的状态快照。

### P07 关系来源撤回与复核

在独立测试人格/来源做，不破坏正式关系：给P04已批准关系的来源事件显式添加一条M4记忆，再撤回该记忆以触发来源屏蔽。刷新人格与关系，查看关系的待复核提示；新会话提问并检查 `relationship_requires_review`。

通过：原关系版本和历史保留，后续上下文不引用被屏蔽来源的旧关系说明；未审建议变为过期，旧关系版不能直接恢复。用户明确编辑关系并保存可建立新的人工说明；系统不自动猜测或改写关系。

若未做这组来源操作，记录未执行。仅撤回普通无关联记忆不能证明此项。

### P08 正常重启、QQ与版本解释

等待当前调用结束，正常停止并重启本项目服务，恢复A会话。本人QQ发送 `M5联合测试：按我们当前有效的称呼打个招呼。`；窗口再发一条短消息。

通过：当前版本、历史、关系和状态有效期保留；两个入口共享同一人格/关系，近期会话分开；没有旧请求重复生成/投递。已过期状态不因重启复活。M4的T09仍须按其完整标准补验，不能只做这一条就自动关闭全部T09步骤。
