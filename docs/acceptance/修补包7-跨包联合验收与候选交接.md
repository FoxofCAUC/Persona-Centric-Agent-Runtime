## 长历史与后台压力

R01 在同一台 Windows 机器上，以 50,000 条导入气泡叠加两档原生回合。每档分别测 100 次读取绘制、角色切换和点击发送至本地可见受理。P95 为从小到大排序后的第 95 项。发送样本在受理后取消，以便单独测量本地受理时延。

| 原生回合 | 读取并绘制一页 P95 | 切回原会话可读 P95 | 点击发送至可见受理 P95 |
| ---: | ---: | ---: | ---: |
| 1,000 | 120.5 毫秒 | 303.1 毫秒 | 211.0 毫秒 |
| 10,000 | 111.1 毫秒 | 272.7 毫秒 | 234.1 毫秒 |

两档均通过切换可读 1 秒、发送至可见受理 500 毫秒的门槛。另验证中文组词与旧消息阅读锚点。测量复用第 3 包的 `ui_continuity.py`，在新目录复制 `bench-1000` 和 `bench-10000`，将待测源码根目录设为 `PYTHONPATH` 后分别传入该目录和规模参数。原副本及驱动的摘要随本轮结果保存。[测量方法与原基线](修补包3-工作台连续使用与长历史验证.md)

R02 用两个角色交替发送，先让 1 个后台模型调用保持在途，再填满 8 个后台等待位置。100 次聊天输入均经正常工作台受理。记忆阶段复用已获准的导入测试夹具，运行实际提取和复核调度。两个角色分别覆盖 3 个原生回合和 1 个导入回合，待办清空。对凭据、争抢额度、自然跨窗和用户临时放行另用原合同回归。工作台计时、后台回执和模型费用分别统计。[联合压力驱动](../../tests/workbench_joint_pressure.py) · [额度合同](../../tests/test_workbench_call_limits.py) · [更正与自然跨窗](../../tests/test_m8d.py)

| 压力工况指标 | 实测 |
| --- | ---: |
| 100 次点击发送至可见受理 P95 | 158 毫秒 |
| 满队时另外 6 个正常回合完成回复，提交至进入本机模型替身 P95 | 297.67 毫秒 |
| 释放后台在途调用前，最老排队任务等待 | 41.22 秒 |

首批 100 次受理后由测试用户取消，以分开测量受理和模型等待。随后 6 个正常前台回合在同一后台队列仍满时完成。只对记忆调度器推进 601 秒到符合积压年龄的时点，再按实际执行结果检查覆盖。8 次提取与复核调用、8 次调度后，四个人物与来源组合均有产出，剩余后台任务为 0。时间为单机隔离工程样本，正式观测按真实供给、授权和用量登记。

## R04 正式观测设计

A06、A08、A10、A16、A19、A20 的工程材料包括本轮的强退、托盘、回滚及待核对账。A07、A18、A21 使用压力演练、额度合同与来源覆盖证据。A01–A05、A11–A15、A17、A22–A26 依各自合同复用工程材料，正式阶段补真实取用、真实呈现或作者体验。A09 的 QQ 专项继续暂停。

正式桌面 G-AUTO 由作者决定入场。冻结候选清单、批准的真实材料版本、人物、服务及费用预算。观察窗从双击打开、首次配置完成后起算，分别记录前台聊天、托盘后台、当日晚间完整退出、下次冷启动、断网与恢复。每项在原轮有归宿且下一条能继续时结束。正式跨夜验收按机器实际关机时长和原会话的话题接续判定。[现行跨夜判据](G-AUTO-自然跨夜观察.md#现行跨夜判据)

按原请求登记用户意图、已受理回合、实际派发和费用。只将具有全部所需呈现确认的回合计为完整可见回复。可用工况目标为 99.5%，报告原始分子、分母和样本量。用户取消、部分显示、已发待核、额度等待、外部故障和未受理分别记账。同步记录有效记忆覆盖、获准公开检索、用户是否被迫动设置以及外部阻塞时长。重复收费派发、静默丢失、错人显示或越权出现一次即保存证据并退回责任包。真实供应商可用率、费用和作者的美术与交互签收由这次实测填入。[A01–A26 正式矩阵](桌面无人值守-阶段0基线与验收矩阵.md)

## 复验入口

在候选源码根目录使用项目解释器运行。每项传入新目录，版本往返使用阶段 0 冻结基线目录及待测候选程序目录。模型端统一为本机替身。

```powershell
python -B -m tests.workbench_version_roundtrip "<阶段0基线>" "<候选程序>" "<新目录>"
python -B -m tests.workbench_daily_cycle "<新目录>" --joint-loss
python -B -m tests.workbench_joint_presentation "<新目录>"
python -B -m tests.workbench_joint_pressure "<新目录>"
```

本机证据目录为 `tmp/workbench-joint-1795093341839`，其中 `result.json` 记录候选包摘要、用例结果、窗口测量及分项对账。程序包包含新版和 Tk 两份启动入口，隔离数据库和运行日志保存在包外。

本轮 315 项不同的定向回归通过，按完整用例名去重。解压后的候选再核验逐文件摘要，并从包内程序复跑日常启停、三类副本的版本往返与关键回归。正式桌面 G-AUTO 的评审输入为这份候选及其对账结果，Flash 另行立项。

两轮替身回复可能恰好同文。联合演练以当前回合持久化的回复事件编号匹配窗口气泡，逐轮确认实际显示。
