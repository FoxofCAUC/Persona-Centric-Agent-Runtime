# 机器验收执行约定

2026-10-27起按用户授权执行。后续阶段沿用验收清单和 Markdown 手册，由开发代理操作与取证；不再要求用户亲自完成每项操作。

- 工作台聊天入口可代表本项目的QQ私聊验收入口。可关闭相应业务验收项，但结果应注明入口替代，不能声称执行了实际QQ登录、平台收发或送达测试。
- 用户已授权本项目开发全流程使用真实付费模型。使用已配置的模型与凭据，遵守现有前后台额度；离线回归仍使用模拟模型。真实调用、模拟回归、界面检查分别记录。
- 需要QQ扫码、登录验证或其他用户授权操作时暂停相应验收，说明所需动作，等待用户完成后继续。缺少必要配置或凭据时不得猜测或借用其他项目密钥。
- 连续五次以上模型调用失败，或明确检测到QQ服务中断、退出登录等情况，停止测试并等待人工恢复。可在第五次失败时保守停止；单项失败先保留现场，不循环重试。状态不明确时先只读核对，不靠继续发送消息探测。此规则不改变产品本身的重试策略。
- 使用独立验收人格与明确的测试资料。测试用关系确认、记忆修订只操作测试来源，不代表自动审阅正式人格中的冲突。
- 先备份，记录原人格、配置、服务状态和日程。正常排空后恢复原设置；不提高额度、不清库、不接管未知服务，保留所有调用账本及失败证据。
- 真正24小时、额度自然恢复等未观察到的条件项保留待验；不得改系统时间、回填调用时间或把立即执行等同于自然到期。
- 每项保存操作、ID、请求实际使用的版本、结果和限制。模型回答正确不能替代来源检查；模型遗漏或冲突漏判也不能被工程状态“完成”掩盖。
- Tk逻辑缩放与真实系统DPI切换须分别说明。模拟UI用例不能冒充实际服务链路；真实工作台按钮、后台任务、HTTP和模型回复的联合执行可作为机器界面验收。

证据及含个人内容的结果保存在D盘 `exports/acceptance`，源码仅保存脱敏结论和索引。用量采用提供商返回值；缺失记未知，不虚构货币费用。后续手册参照[通用模板](阶段真人验收手册模板.md)，增加机器执行方式与需要用户介入的步骤。
