# 修补包 6 · 巡检、备份、退出、安装与本地修复

工作台在慢备份期间可以继续聊天。本机聊天服务或存储发生故障时，窗口显示「修复中」，保存已有草稿和已受理的消息。修复通过后自动返回原会话。维修中也能安全退出，下一次打开继续核对原修复记录。本包在 Windows 隔离实例中验证 C17–C20 和 C21 本地流程，业务库结构为 33。[日常启停场景](修补包5-日常启停与消息恢复.md) · [施工范围](../product/桌面连续聊天闭环修补方案与健壮性评估.md)

## 用户操作与观察

| 工况 | 实际结果 |
| --- | --- |
| 慢备份时聊天，随后断开模型连接并结束本机聊天服务 | 备份仍在等待时，第一条消息已经显示回复。第二条在断网时受理。本机服务重启后，窗口在 3.42 秒内恢复原草稿与会话。 |
| 存储维修时恢复网络 | 窗口锁住发送和设置。直接向本机服务提交聊天、人物更改和连接设置均收到 HTTP 423。放行写入核验后，断网时已受理的那一轮在 1.83 秒后显示回复，模型接收端只收到一次。两处用时均从撤去对应故障条件起算。 |
| 模型已受理，存储维修期间收到回复 | 已在途的回复正常登记。维修窗口关闭后，可以在原会话中看到该回复。 |
| 在途时点两次退出 | 沿用同一退出请求。排空期间到达的回复只结算一次。另一次让排空到期，退出记录保留 1 个未取得回执的尝试编号，重开后原轮标为结果待核，接收端无重复调用。 |
| 显示「修复中」时安全退出，或直接结束工作台进程 | 分别重开，均接续原修复编号、恢复原草稿。工作台正常退出后核对实例租约、所属进程和服务端口。强退后由 Windows 回收所属服务。 |
| 工作台和旧版 Tk 分别双击启动 | 旧版运行时新版入口唤回同一窗口。两份新版启动器竞争时仅有一个工作台接管实例。中断补装后 Tk 仍可打开，离线补装完成后，公开 v0.2 可以再次读到原人物。 |

维修演练使用 6 个工作台进程。模型替身共收到 6 个不同请求，每个一次，其中 5 个完成，1 个保留结果待核。独立复跑上一包的前台、托盘、最小化和冷启动演练，9 条已受理消息中有 6 条完成、1 条主动取消、2 条结果待核。两组均使用真实窗口、独立服务进程和回环 HTTP 接收端，商业模型调用为 0。[维修与退出演练](../../tests/workbench_repair_smoke.py) · [三次日常启停](../../tests/workbench_daily_cycle.py) · [Windows 启动器演练](../../tests/workbench_launcher_smoke.py)

## 修复边界

| 项目 | 实现和异常处置 |
| --- | --- |
| C17 巡检 | 聊天服务健康检查独立运行。绑定、可选渠道、存储和备份分别调度，每类同时最多一个任务。日志暂时无法写入时保留内存状态。服务重启预算在实例内持久保存，短期内反复失败会退避。核验 Windows 监听进程与实例归属后才访问服务。 |
| C18 备份 | 在实例私有目录复制主库，校验 SQLite 完整性、外键及知识包依赖，再公布签名索引。复制、清单生成、索引发布前、轮换开始及轮换中途五处均做了进程强退。恢复时可读上一份已提交的完整备份，再接续中断的工作。 |
| C19 退出 | 一次退出依次停止新受理、等待已在途工作、保存已到结果和待核编号、释放所属进程并结束实例锁。正常排空上限 30 秒，暂时释放失败会自动复查。外部占用有明确状态，端口号本身不能证明进程归属。 |
| C20 安装 | 启动器先查正在运行的实例。自带环境缺少窗口依赖时，先取得离线保护，再按锁文件在独立目录补装，核验包文件和 WebView2 后切换。离线缓存损坏、安装进程中断、发布复验失败、自定义解释器和 Windows 短时文件占用均有针对性回归。 |
| C21 本地排障 | 同一实例一次只执行一项维修。已接入的两项动作是拉起本机聊天服务和复验本机存储。维修中暂停新增写操作和模型派发，允许原回执结算。接回已受理的工作时复用原身份、授权及回执。无法核验存储时显示只读状态并自动复查。存储故障标记损坏时，保留原记录并重新探测数据库和本机回执目录。工具调用 Agent 留在独立的后续评估。 |

维修记录只存实例、故障、归属、状态与编号。退出时按类别保存准确的未结数量，并保留每类至多 128 个编号供复核。关闭流程中的检查记录不包含聊天正文。[运行监督](../../persona_runtime/app_runtime.py) · [本地维修](../../persona_runtime/local_repair.py) · [退出对账](../../persona_runtime/shutdown_evidence.py)

网络刚开始重连探测时另做一次工作台强退。Windows 回收所属服务，检查到的残留进程为 0。重开后原消息和下一条新消息各被接收一次。安装方面分别在依赖准备和本地语义模型准备过程中结束安装器，两种子进程均随安装器释放。另从既有公开模型的离线副本完成一次正常准备，8 个锁定文件与模型指纹核验通过。

## 从备份恢复到独立目录

在工作台应用菜单打开「高级设置 → 本机备份与恢复」，可查看最近登记的备份时间。默认选「最近一份校验通过的备份」，也可以选定日期。点「选择恢复位置」并选择一个可写父目录。工作台在其中新建 `PCAR-恢复核对-…`，列出副本的角色、会话、事件和记忆数，以及能读取到的当前实例计数。演练通过这个入口找回 6 条事件，另用 PCAR 的实际读取接口从独立副本取回原角色、会话和消息编号。

使用项目解释器也能列出备份或恢复。目标填写尚不存在、且位于原实例目录之外的绝对路径。指定版本时追加 `--name` 和列表中的文件名。

```powershell
python -m persona_runtime --home "<原实例绝对路径>" data backup-list
python -m persona_runtime --home "<原实例绝对路径>" data restore-backup --destination "<新的独立目录>"
```

副本含主数据库 `runtime.sqlite3`、知识包依赖清单 `runtime.sqlite3.knowledge.json` 和核对结果 `restore.json`。核对结果包含数据库摘要、结构版本、人物、会话、事件、回合、记忆和模型尝试计数，以及外部知识包的摘要和版本。默认恢复按时间从新到旧核验完整性和依赖，选择最近一份可读且通过校验的副本。指定的版本损坏或被 Windows 独占时会提示错误。轮换时遇到独占文件会稍后复查，后续新备份继续生成。当前实例照常工作，副本供独立核对。

工作台运行时，相邻自动备份间隔至少 24 小时。签名索引登记最近 7 份本实例自动备份。轮换时核对文件身份和摘要，手工备份、旧版无签名文件、内容已变的文件均保留。清单损坏时优先使用上一份已验证索引。两份清单均无法验证时保留原文件，由当前数据库生成新备份。旧版无知识包的主库可在独立目录重新生成空依赖清单。[备份实现](../../persona_runtime/automatic_backup.py) · [中断与恢复回归](../../tests/test_workbench_operations.py)

自动备份保存在同一实例的 `backups/workbench-automatic`。签名校验使用该实例在当前 Windows 用户上下文中可解封的本机凭据。草稿、发送箱、程序与环境、凭据、原始导入文件和外部知识包实体按各自位置保存。同盘发生整盘故障时，可找回的时间点取决于已有的异盘副本。整实例迁移沿用迁移包流程。[桌面使用说明](../user/getting-started.md)

## 复验与交接

在源码根目录使用含 WebView2 的项目解释器。每次窗口演练传入新的隔离目录。BAT 演练另需项目依赖的离线 uv 缓存和公开 v0.2 的程序目录。测试按事件结束，排空到期演练把等待时间缩短到 0.6 秒，工作台默认值保留 30 秒。

```powershell
python -B -m unittest -v tests.test_workbench_operations tests.test_decoupling tests.test_desktop tests.test_workbench_webview
python -B -m tests.workbench_repair_smoke "<新隔离目录>"
python -B -m tests.workbench_launcher_smoke "<新隔离目录>" "<离线uv缓存>" "<v0.2程序目录>"
python -B -m tests.workbench_daily_cycle "<新隔离目录>"
```

523 项不同的定向回归通过，按完整用例名去重。覆盖运行监督、两种桌面入口、备份与迁移、受理与回复、模型限额、后台记忆和发布包兼容。上表窗口演练单独计数。本机结果保存在隔离证据目录 `tmp/workbench-operations-1795091157239/result.json`。本包测量的是所列故障恢复和数据结算。下一包汇总跨包组合、三类结构 33 副本的新旧版本往返与 R01–R04 证据，由作者决定正式桌面 G-AUTO 入场。自然跨日使用和真实供应商可用率在相应观测中登记。[阶段 0 矩阵](桌面无人值守-阶段0基线与验收矩阵.md)
