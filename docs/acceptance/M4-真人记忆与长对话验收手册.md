# M4 真人记忆与长对话验收手册

2026-10-27最新状态见[机器验收总结](M4-M5-机器验收总结.md)：用户授权后T07–T10、O04/O05已通过，O01–O03待验；当前0.5.0导出格式3，替代下方历史格式2断言。操作正文及空白表保留历史手册用途。

适用版本0.4.0、数据库结构5。2026-10-27状态：**用户确认T01–T06真人通过，T07及后续跳过待补验**。结果见 [M4补验跟踪](M4-补验跟踪.md)，不将部分通过写成全流程通过；下文保留为操作手册，末尾空白表是可填写模板，不是实际结果。测试用虚构内容，真实记录留在D盘 `exports/acceptance`，不提交Git。M2/M3已通过，不要求重做其全部用例。

## 1. 准备和费用

1. 关闭旧工作台，双击 `启动人格工作台.bat`，确认标题M4，出现“记忆整理”页。
2. 首页确认人格服务运行；真人QQ步骤需在“QQ连接”检查身份与OneBot。未知占用从原入口正常处理，不接管或强停。
3. 故障排查分别备份数据库、加密配置，记录D盘路径。不要清库或重装组件。
4. 在“人格与记忆”创建独立模板，明确切换为本轮测试人格A，记录ID。每日更新开始时会绑定当前人格，避免将验收内容和正式人格混在一起。
5. 模型页记录前台/后台模型名称及限额，不记录密钥。整理区可明确勾选复用聊天模型，或填独立兼容接口模型和密钥，点击“保存整理配置”。保存不调用模型；已经可用时不必额外点测试。
6. 保留默认后台小时6次、滚动24小时20次以及全项目小时30次。建议保留每日更新开启，空闲增量先关闭；T08前不要点击“立即执行一次全量更新”。
7. 记忆整理页刷新，记录下次本机时间、计划是否开启、模型是否就绪。若显示模型未配置，先完成第5步。

主流程含12轮长会话铺垫及若干查询，预计前台20–30次、后台4–8次，具体取决于批数与重试。前后台共同计入每小时30次，必要时分两轮或等待额度恢复，不为测试提高限额。后台等待额度是预期状态，不能误判为模型卡死。

除连续消息回归外，逐条等结果再发；默认模型超时60秒，以90秒为无排队请求的检查点。后台有配额等待时按滚动额度到期判断，不连点重试。

## 2. 必测流程

### T01 配置、日程与备份

按准备步骤完成配置和备份；“记忆整理”点“刷新整理状态”“每日更新详情与屏蔽来源”。

通过：下一次执行显示可理解的本机日期、时间和时区；模型就绪；范围说明为开始时的当前人格；没有因保存或刷新新增模型调用。首次计划约为初始化后24小时，若先前已经初始化，应保留原时间，不要求重新从现在算。

证据：版本、人格ID、下次时间、限额和备份路径。没有单独后台模型时必须明确选复用，程序不应默默代选。

### T02 建立长对话样本

聊天页“新建会话”，记下会话ID。先发送：

```text
M4验收虚构资料：我的手账项目叫“雨桥”，每周四晚上整理植物标本。这只是本轮测试资料。请简单确认。
```

再依次发送下面11条，每条收到回复后再发，避免前条失败影响成功轮次。可以复制并改数字：

```text
M4铺垫01：只回复“01收到”。
M4铺垫02：只回复“02收到”。
M4铺垫03：只回复“03收到”。
M4铺垫04：只回复“04收到”。
M4铺垫05：只回复“05收到”。
M4铺垫06：只回复“06收到”。
M4铺垫07：只回复“07收到”。
M4铺垫08：只回复“08收到”。
M4铺垫09：只回复“09收到”。
M4铺垫10：只回复“10收到”。
M4铺垫11：只回复“11收到”。
```

通过：至少12个成功轮次；第一条已超出接下来最近10轮窗口。还没有确认任何与“雨桥”有关的长期记忆。铺垫失败须处理后确认成功轮数，不把失败用户事件计作成功轮次。

### T03 手动摘要、来源与长对话接续

1. 记忆整理选择T02的窗口会话，模式“摘要与候选”，起终点留空，不勾选重建。
2. 点“预览整理范围”，应是最多10轮，记录来源序号、剩余批数；确认预览没有调用模型。
3. 点“提交本批整理（可能计费）”一次，任务完成后在“会话摘要”选中记录，“查看详情与来源”。确认摘要含“雨桥”和周四整理标本的证据；模型遗漏则记质量失败，不手改数据库。
4. 暂不确认候选。回到原聊天会话发送：

```text
我的手账项目叫什么？通常哪天整理什么？请按本会话已经提供的资料回答，不知道就说明。
```

5. 点“查看本轮记忆使用”，保存摘要ID、版本、覆盖缺口和正式记忆列表。

通过：早期资料通过本会话摘要进入请求，近期记录不重复拼入已覆盖范围；答案与证据一致。待审候选没有直接参与长期召回。只听到模型回答正确不足以通过，必须看到摘要使用记录。

### T04 候选确认、新会话召回

1. 记忆整理“记忆候选”选“雨桥”相关待审项，“查看详情与来源”；原文支持片段和事件ID应准确。
2. 点“编辑后确认新记忆”，必要时将文字改为清楚的虚构事实，点“确认生效”。保存失败时文字应保留。
3. 刷新，记下正式记忆ID；不要重复建立同一记忆。
4. 聊天“新建会话”，发送：

```text
我之前提到的手账项目叫什么？每周什么时候整理植物标本？没有已确认资料就说不知道。
```

通过：新会话没有继承旧会话摘要，但使用了已确认正式记忆及有效版本。答案正确、ID可追溯；窗口近期和QQ近期仍分开。

### T05 修订、撤回与旧来源屏蔽

1. 人格与记忆页检索“雨桥”，选择有效记录，通过现有“修订”操作改为 `M4虚构更正：手账项目改名为“晴桥”，改在周六整理植物标本。`，保存。
2. 检查历史版本、来源。记忆整理查看旧摘要状态和“每日更新详情与屏蔽来源”，旧来源轮次应被屏蔽，原始历史仍能查看。
3. 新建会话，问 `我的手账项目叫什么，什么时候整理植物标本？`；查看本轮记忆使用，确认只有有效新版。
4. 在人格与记忆撤回该记忆，再新建会话问同样问题；查看记忆使用记录，应无被撤回ID。

通过：更正生效，旧摘要失效；撤回后有效检索和后续上下文不含旧版本。不要在提问里写出“雨桥/晴桥”再凭模型复述判断。源事件仍可追溯，不被物理删除。

注意：保守屏蔽会影响同轮其他细节，不是故障。撤回不承诺模型从未在其他无关联来源见过相似内容；判定以实际使用ID和来源为准。

### T06 拒绝候选与恢复

在独立会话发送：

```text
M4拒绝测试：虚构偏好是收集紫色纸夹，请简单确认。
```

选择该会话“仅候选”，预览并提交。候选完成后点“拒绝并屏蔽来源”，确认提示。刷新后再预览原范围。

通过：候选为已拒绝，相关轮次被排除；范围只剩该轮时显示没有可整理成功轮次，不能换个措辞重新自动提出。关闭重开工作台后拒绝和屏蔽状态仍保留。

### T07 后台失败与显式重试

1. 记录原整理配置。为避免影响前台，暂时取消“复用聊天模型”，将独立整理地址设 `http://127.0.0.1:1/v1`、模型名填 `m4-failure-test`，保存，不测试。
2. 新会话发送一条虚构新偏好后，预览并提交“仅候选”。等待失败，记下任务ID及尝试数。
3. 不重试等待约30秒，刷新：不应自行增加尝试或发布部分结果。
4. 恢复原整理配置，选择失败任务，“显式重试（可能计费）”一次。更改配置会暂停已开启的自动功能，按页面状态处理，不连点。

通过：同任务新增一次尝试，固定来源不变；超时/网络失败可见，失败没有摘要或候选部分落盘，前台聊天仍可用。额度不足显示等待，不能标为重试失败。

### T08 每日全量自动生效和冲突授权

1. 保持测试人格A，另建会话发送：

```text
M4每日测试：我的虚构饮品偏好是桂花乌龙茶，每周五整理纸质手账。请简单确认。
```

2. 不手动确认这条记忆。记忆整理点“立即执行一次全量更新”，阅读费用提示后确认；记录开始人格和下次时间。
3. 等待全部会话逐批完成。若遇后台额度上限，保留“等待额度”和已完成批次记录，额度恢复后应继续原剩余范围；不要重开一轮。
4. 查看候选及人格与记忆：无冲突的相关记忆应自动生效，无需逐项批准；下一次计划应为本次开始后约24小时。
5. 新会话发送：

```text
M4冲突测试：我此前说喜欢桂花乌龙茶，现在明确更正为不喜欢桂花乌龙茶、只喜欢黑咖啡。请简单确认。
```

6. 上一周期完成后再次明确执行一次全量更新。等待模型将直接矛盾标成冲突；“记忆候选”查看冲突关联的有效记忆和原文。
7. 选择冲突项“修订已有记忆”，选旧偏好版本，编辑后确认。不要为了通过随便新建第二条互相矛盾的有效偏好。

通过：正常结果自动生效；冲突项保留待审，不静默覆盖；冲突批次摘要不先发布，其他正常项可继续。冲突待授权有可见状态，批准后版本链及来源保护成立。

若模型未标出明显矛盾，记为冲突识别质量失败，记录输入和现有记忆ID；不要把自动写入了矛盾内容当通过。大量旧历史可能需要较长时间，此项“全量完成”只能在剩余范围确实处理完后填写。

### T09 正常重启与私聊回归

1. 等待当前后台调用结束，首页正常“停止服务”，再启动；不要用强停。
2. 检查下次每日时间、摘要、记忆版本、候选和来源屏蔽保留。停止时未运行任务会中断，需明确处理，不应因重启自动付费重试。
3. 窗口连续发送两条简短测试消息，确认逐条有序。
4. 本人QQ发送 `M4私聊回归：我的饮品偏好现在是什么？请只使用有效记忆。`，确认回复及投递状态。

通过：M3受理、顺序、失败恢复和QQ单一路径不退化；没有旧任务自动重放、重复生成或重复投递。正式记忆可跨入口，摘要仍不跨会话混用。

### T10 备份与导出

故障排查执行数据库备份和人格导出，记录D盘路径。用文本编辑器查看导出文件结构，不上传或粘贴真实数据到Git。

通过：导出格式版本2，有摘要、候选、审阅和屏蔽记录；没有模型密钥、API令牌或凭据快照。完整备份包含日程和任务；独立打开、迁移回滚及恢复一致性由离线测试证明，真人未执行恢复演练不能另标通过。

## 4. 失败、证据与收尾

每项记录时间、人格/会话/任务/记忆ID、尝试数、用量、结果和证据路径；不截图密钥或令牌。状态分为通过、失败、未执行、受阻，不能把自动测试或入口可用当成真人全流程通过。

失败先保留现场，恢复原模型地址、复用方式和开关；不清库、不连续重试、不放宽预算。冲突不自动批准，先核对来源。后台失败不会回退另一模型。

测试结束切回正式人格，确认每日更新范围说明与下次时间。若暂不希望处理正式历史，可在模型页关闭每日更新并保存；开启/停用是明确的配置选择。恢复原模型、限额及空闲开关后正常保留或停止服务。保留结果及前后备份。

T01–T10按实际结果判定核心真人流程；O01的真实24小时日程、O02增量和长稳等未执行须单列。模型自然度、事实使用质量和工程状态分别记录。
