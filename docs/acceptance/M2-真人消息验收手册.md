# M2 真人消息验收手册

编写日期：2026-10-26。适用范围：当前人格工作台、窗口聊天、QQ 本人好友私聊、显式长期记忆和正常重启恢复。

这是一份操作手册，不是通过报告。历史上已确认首轮 QQ 私聊通过；下列项目需逐项执行、记录，不能自动勾选通过。

## 1. 验收结果怎么判

- **通过**：操作完成，满足本项全部标准，并记下结果或证据。
- **失败**：实际行为与标准不符，保留现场，不连续重试掩盖问题。
- **未执行**：还没做，不等于通过。
- **受阻**：例如额度用完、无法登录或没有另一账号；记录原因，不能当作通过。

必测项 T01–T12 全部通过，才记录为“M2 真人核心验收通过”。可选项 T13–T15 单独记录；未执行时，最终结论中明确保留这些限制。不要把真人核心通过写成所有异常场景均已验证。

验收使用虚构内容，不要填写真实隐私。主流程通常需要约 15–22 次模型请求；历史测试、失败尝试和重试也占滚动一小时额度。当前额度不足时分批执行，等待额度恢复，不必提高上限。

## 2. 开始前准备

1. 找到当前源码目录中的 `启动人格工作台.bat`，双击打开。若窗口在近期更新前已打开，先关闭窗口再重新双击；这一步不会停止后台服务。
2. 确认 D 盘 `D:\Persona-Centric Agent Runtime` 可访问。已有模型、账号和人格配置继续使用，不重新初始化、不重装组件、不清库。
3. 打开“模型”页，记下模型名称、接口地址、总超时和每小时调用上限。**不要抄录密钥**，不要勾选“明确清除已保存密钥”。已有模型已成功调用时，可跳过额外连通性测试，节省额度。
4. 打开“QQ 连接”页，核对 Bot QQ 和本人 QQ；使用本人账号向 Bot 发消息，两者不是同一个账号。不要在运行中更改账号或端口。
5. 记录正在使用的人格，本文称为 **人格 A**。在人格列表或“查看设定”中记下其 ID，后续凭 ID 区分同名人格。
6. 在 D 盘创建本轮结果文件，例如 `D:\Persona-Centric Agent Runtime\exports\acceptance\M2-真人验收结果-20261026.md`。可复制本手册末尾的结果表。截图也保存在该目录，不放源码目录，不截图密钥或带令牌的浏览器地址栏。

### 等待规则

一次只发一条测试消息，收到结果后再发下一条。正常验收期间不要让其他窗口同时请求同一人格。
等待“模型总超时 + 30 秒”作为人工检查点；例如配置为 60 秒，就最多等待约 90 秒。此时仍未完成，先记“失败／受阻”并查状态，不要连点发送或重试。

## 3. 必测操作与标准

### T01：连接与验收前备份

**操作**

1. 到“首页”查看当前状态。服务已运行就不重复启动；尚未启动则点击“启动服务”。如提示其他 QQ 实例冲突，先从其原入口退出，再重试本项目启动。
2. 需要扫码时点击“打开 QQ 登录页”，自行完成登录。
3. 到“QQ 连接”点击“检查连接”，等待本轮检查完成。
4. 到“故障排查”分别点击“备份数据库”和“备份加密配置”。记下底部提示中的两个文件路径，在资源管理器确认文件存在。

**通过标准**

- 人格服务、消息服务和 QQ 连接均可用；QQ 账号显示已核对，OneBot 显示在线。
- 状态来自本次刷新，不是旧截图或旧心跳文件。管理页可打开不能替代账号核对与 OneBot 在线。
- 备份文件均在 D 盘本项目目录下，操作没有修改旧 TRPG 项目。

**失败时**：停止后续 QQ 用例。记下哪项未连接、页面提示和时间；不要仅凭“模型测试成功”判定 QQ 已连接。

### T02：窗口聊天与近期上下文

**操作**

1. 到“聊天”页，确认选中人格 A，点击“新建会话”。
2. 发送下面第一条，收到回复后再发送第二条：

```text
这是 M2 真人验收。本次窗口会话的临时代号是“雾桥-731”。请确认收到，不要把它当作长期设定。
```

```text
我刚才给这段窗口会话指定的临时代号是什么？
```

**通过标准**

- 第一条获得正常文本回复；第二条能答出“雾桥-731”。不要求逐字使用固定措辞。
- 本轮用户消息和人格回复都显示在历史中，没有凭空多出一次相同问答。
- 等待过程中仍能切页、滚动和查看状态；不要求模型在固定几秒内返回。
- “用量”可为数字或“未知”；提供商没有返回用量时，不以“未知”判失败。

### T03：QQ 本人私聊与近期上下文

**操作**

使用已配置的本人 QQ，与 Bot 进行**好友私聊**，依次发送：

```text
这是 M2 真人验收。本次 QQ 会话的临时代号是“青舟-284”。请确认收到，不要把它当作长期设定。
```

```text
我刚才给这段 QQ 会话指定的临时代号是什么？
```

**通过标准**

- 两条均收到 Bot 回复，第二条答出“青舟-284”。
- 发送账号和回复账号正确，没有另一套 AstrBot 普通模型再补答一次。
- 长回复被分成数条连续消息是正常分段，不算重复；同一完整回答再次出现才记为疑似重复投递。

**注意**：手动再发一次相同文字会产生新的 QQ 消息 ID，系统可以再次回答。这不能用来证明或否定平台重复推送去重。

### T04：两个入口的近期会话隔离

**操作**

1. 在刚才的窗口会话发送：

```text
只依据这段窗口会话的历史：QQ 会话里的临时代号是什么？如果这里没有记录，请说不知道，不要猜。
```

2. 在 QQ 私聊发送：

```text
只依据这段 QQ 会话的历史：窗口会话里的临时代号是什么？如果这里没有记录，请说不知道，不要猜。
```

**通过标准**

- 窗口不应知道“青舟-284”，QQ 不应知道“雾桥-731”；应明确表示当前会话没有记录。
- 两个代号未被你显式添加为长期记忆。如果此前手动录入、引用或重复做过本用例，换一组全新代号重测，并同步替换 T02–T04 消息。

**失败时**：保存两边消息截图。先排除重复使用代号或其他人工提示，再报告疑似上下文串入；不要清库。

### T05：显式添加记忆，并在新会话召回

本项不通过聊天指令“记住”自动写记忆。M2 需要在界面显式录入。

**操作**

1. 到“人格与记忆”，确认人格 A，点击“显式录入”。
2. 在“选择来源事件”窗口，选择一个已有会话，点击“在此会话添加人工笔记”。粘贴并保存：

```text
M2真人验收的虚构饮料偏好：温梨水，不加蜂蜜。本条仅为测试数据。
```

3. 笔记保存、列表刷新后，选中刚才这条 `note` 事件，再点“选择事件”。
4. 类别选 `preference`，记忆正文填写与笔记相同的文本，点击“保存记忆”。
5. 在检索框输入 `M2真人验收`，点“检索记忆”。选中记录，点“查看来源与历史”，记下记忆 ID 和来源事件 ID。
6. 到“聊天”点击“新建会话”，只发送以下问题，**不要把答案写进问题**：

```text
M2真人验收的饮料偏好是什么？请依据已有记忆回答，不知道就说不知道。
```

**通过标准**

- 能检索到新记忆，类别正确；来源内容就是刚添加的人工笔记。
- 新会话能答出“温梨水、不加蜂蜜”，没有臆造更多用户事实。
- 新会话没有此前问答却能正确回答，才可作为长期记忆召回的真人证据。

### T06：长期记忆跨入口共享

**操作**

在 QQ 私聊中发送 T05 的同一个问题。此前不要在 QQ 里粘贴饮料答案或来源笔记。

**通过标准**

- QQ 也能答出“温梨水、不加蜂蜜”。
- 这与 T04 不冲突：长期记忆共享，近期会话分开。

若已重复做过本项，旧 QQ 上下文可能已经带有答案。这次只能记录为“重复回答正常”，不能独立证明再次读取了长期记忆；以 T05、T07 的全新窗口会话结果为主要证据。

### T07：记忆修订与来源追溯

**操作**

1. 到“人格与记忆”，检索 `M2真人验收`，选中 T05 的有效记忆，点击“修订”。
2. 在来源窗口选择会话，再添加一条人工笔记：

```text
M2真人验收的虚构饮料偏好已更正为：常温柚子水，不加糖。此前“温梨水，不加蜂蜜”已作废。
```

3. 选中新笔记作为来源。修订正文替换为：

```text
M2真人验收的虚构饮料偏好：常温柚子水，不加糖。本条替代此前的饮料偏好。
```

4. 保存后重新检索，选中新版本，点“查看来源与历史”。记下新旧记忆 ID。
5. 到“聊天”点击“新建会话”，再次发送 T05 的问题。

**通过标准**

- 新版本有新的 ID，修订号增加；历史保留旧内容和旧来源，新版本关联新笔记。
- 默认检索只返回当前有效版本，不把旧版当作另一条有效偏好。
- 新会话回答“常温柚子水、不加糖”，没有继续把温梨水说成当前偏好。

### T08：人格隔离与切回恢复

**操作**

1. 记下人格 A 的 ID，到“人格与记忆”点击一次“创建通用模板”，创建测试人格 **B**。模板可能同名，务必凭 ID 区分。
2. 选中 B，点击“切换选中人格”。检索 `M2真人验收`，再打开“关系说明”查看是否有记录，未填写就关闭，不必保存。
3. 在 B 的窗口会话中发送 T05 的问题。
4. 切回 A，再次检索 `M2真人验收`。

**通过标准**

- B 有独立 ID；B 没有 A 的测试记忆，关系说明未自动继承，窗口近期问答也不自动继承。
- B 不应知道“常温柚子水、不加糖”；如果它猜出或声称记得，记录失败，不能仅凭列表为空就忽略模型表现。
- 切回 A 后，修订后的记忆仍存在，原会话可通过“选择已有会话”重新打开。

结束时保持选中 A，后续 QQ 消息也会使用当前选中人格。

### T09：关闭窗口后，QQ 仍可使用

**操作**

1. 确认无进行中的模型请求，直接点击工作台右上角关闭按钮，不点击任何停止按钮。
2. 用本人 QQ 向 Bot 发送：

```text
M2窗口关闭验收：请回复“后台仍可使用”。
```

3. 收到回复后，重新双击 `启动人格工作台.bat`。

**通过标准**

- 关闭窗口后 QQ 仍能回复。
- 重开后能查看现有服务状态，当前人格仍为 A，不要求再次填写密钥或重建人格。
- 这只证明窗口关闭不停止后台服务，不等同于服务重启测试。

### T10：正常停止与重启后的连续性

本项在 T11 撤回之前做，此时 A 的有效记忆仍应为“常温柚子水、不加糖”。

**操作**

1. 在 A 的窗口打开或恢复一个会话，发送：

```text
M2重启验收：这段窗口会话的恢复标记是“松塔-592”。请确认收到。
```

2. 记录当前会话 ID：到“选择已有会话”查看并抄录，关闭选择窗口即可。
3. 等回复完成后，点击首页“停止服务”。等待人格服务和消息服务停止；默认保留 QQ 登录。不要用强停代替。
4. 关闭工作台，再重新双击打开，点击“启动服务”，检查账号已核对与 OneBot 在线。
5. 到“聊天”点“恢复当前会话”，确认恢复的是同一会话，再发送：

```text
刚才约定的重启恢复标记是什么？
```

6. 点击“新建会话”，发送 T05 的饮料问题；然后在 QQ 发：

```text
M2正常重启验收：请确认现在可以继续私聊。
```

**通过标准**

- 当前人格仍为 A，旧会话及内容未丢，能答出“松塔-592”。
- 新窗口会话能答出“常温柚子水、不加糖”，证明长期记忆未随服务停止丢失。
- QQ 可以继续收发，不需要重新创建人格或重填已有模型配置。
- 不自动重发先前已完成的回复；重启保留 QQ 登录时，不强制要求重复扫码。

### T11：记忆撤回与历史保留

**操作**

1. 到“人格与记忆”，检索 `M2真人验收`，选中修订后的有效记忆，先打开“查看来源与历史”并暂留该详情窗口或截图。
2. 点击“撤回”，确认操作，重新检索 `M2真人验收`。
3. 到“聊天”点击“新建会话”，再次发送 T05 的问题。

**通过标准**

- 默认有效记忆列表不再返回这条记忆。
- 新会话表示没有这条偏好记录，不凭旧版或新版本答出饮料答案。
- 先前的来源、修订链和原始对话不因撤回而被删除。可在 T12 导出后确认对应记忆状态为 `retracted`、旧版本为 `superseded`。

**解释**：撤回不擦除历史。不要在已经聊过饮料的旧 QQ 会话中问这个问题，再把它根据近期历史答出答案误判为撤回失效。

### T12：验收后备份、导出与结果保存

**操作**

1. 结束未完成请求，保持选中 A。
2. 到“故障排查”点击“备份数据库”“导出当前人格”“备份加密配置”。记下各文件路径并确认存在。
3. 用文本编辑器打开导出的 JSON，按 T05/T07 记下的记忆 ID 查找，仅查看本轮虚构数据对应记录。
4. 填写本手册第 6 节的结果表，保存到 D 盘结果目录。

**通过标准**

- 文件位于 D 盘本项目的 `backups`、`exports` 下；原有备份未被覆盖。
- 导出包含 A 的测试会话、来源事件和记忆历史，撤回与修订状态正确，不混入 B 的人格数据。
- 结果表逐项填写，有失败或未执行就如实标注。

测试人格 B、测试会话和笔记可以保留。M2 没有通用的人格/历史删除按钮，不为“清理验收痕迹”手工删除数据库。

## 4. 可选验证

### T13：可控失败与手动重试

本项临时修改接口地址，先确认没有其他正在进行或准备发送的窗口/QQ 请求。不修改模型名和密钥。

1. 在“模型”页把原接口地址完整抄到本地结果文件。
2. 仅将接口基础地址暂改为 `https://m2-acceptance.invalid/v1`，保存。这是故意不可用的测试地址。不要点击额外测试。
3. 在 A 的新窗口会话发送：`M2失败重试验收：请回复“手动重试已恢复”。`
4. 应出现网络失败。等待至少 15 秒，不点重试，确认没有自动变成成功或冒出人格回复。
5. 立即恢复原接口地址并保存，密钥框留空保留原密钥。
6. 回到同一失败会话，点击一次“重试最后失败请求”，等待结果。

**通过标准**：失败时用户消息保留、没有假回复或自动重复调用；恢复地址后，显式重试成功，同一用户消息不重复显示。不可用的测试地址不应产生实际模型推理；恢复后重试会请求真实模型并可能计费。

**恢复要求**：无论该用例成功或失败，结束前都确认接口地址已恢复。真人界面观察不能单独证明内部调用次数与事务原子性，这两项仍以自动化测试为补充。

### T14：不支持的消息与其他账号边界

1. 本人账号向 Bot 单独发一张普通图片，不附带文字，不使用真实隐私图片。
2. 等待约 30 秒，应没有人格模型回复。随后发送一条正常纯文本，确认文字私聊仍可使用。
3. 只有当你自己控制另一 QQ 账号且本来就是该 Bot 的好友时，才从该账号发送一条虚构纯文本；应没有人格模型回复。不必联系别人配合，不为验收增加群聊。

**通过标准**：图片和未授权账号没有进入人格对话，正常本人文本不受影响。没有另一账号时，将该子项记为“未执行”，不能用本人发文字代替。

人工的“未收到回复”还可能由连接故障造成，因此必须同时做正常本人文本对照。需要严格证明没有触发模型时，再请开发者只读核查本轮时间段的请求与调用记录。

### T15：紧急强停（仅在确实需要验证时执行）

这不是正常重启步骤。按钮会结束全部 QQ（包括普通 QQ）、NapCat，以及相关人格/TRPG/AstrBot 程序和其他管理窗口，不区分最初由谁启动。

1. 保存相关工作，停止发送消息，确认可以接受这些程序全部退出。
2. 点击“强制停止全部相关程序”，阅读并确认影响范围。
3. 等待结果，记录 D 盘 `logs/force-stop-*.json` 报告路径；不要只凭窗口消失判定成功。
4. 之后按 T01 重新启动本项目；需要时自行扫码，再用本人私聊做一次恢复检查。

**通过标准**：当前控制窗口保留；报告明确列出结果；若枚举失败、权限不足或仍有残留，界面不得声称完全成功；重新启动后不自动重试中断的模型请求或重发不确定回复。

无法安全满足第 1 步，就跳过并记“未执行”。不需要为了 M2 真人核心通过而破坏其他正在使用的工作。

## 5. 出现问题时怎么记录

先记录，不清库、不重装、不连续重复发送。新消息和手动重试都可能增加调用费用。

| 现象 | 先看哪里 | 应记录什么 |
| --- | --- | --- |
| 模型测试成功，QQ 不回 | 首页账号核对、OneBot；QQ 连接“检查连接” | 最新状态、发送时间、是否确为本人好友私聊 |
| 等待很久／超时 | 当前操作、模型总超时、错误提示 | 用例号、等待时长、是否有其他排队请求 |
| 未知偏好／记忆没用上 | 人格 A 是否选中、有效记忆、来源 | 当前人格与记忆 ID、检索词、是否新会话 |
| 修订/撤回后仍答旧答案 | 是否在旧对话、是否还有另一条有效同义记忆 | 新旧记忆 ID、会话是否新建、来源与历史 |
| 重复回复 | 是否普通聊天模型也在答、是否只是分段 | 同一条用户消息下的完整回复截图和时间 |
| 管理页按钮打不开 | 故障排查对应服务“打开管理页”及底部提示 | 是否未知端口占用、浏览器启动错误；截图隐藏令牌 |
| 发送结果不确定 | “查看 QQ 待处理请求”→“查看详情” | 请求 ID、生成状态、投递状态；不要盲目补发 |

报告时至少提供：用例号、操作、预期、实际、人格 ID、时间、界面错误、是否点过重试。只发送相关虚构测试消息；不要贴密钥、完整配置或带令牌链接。
