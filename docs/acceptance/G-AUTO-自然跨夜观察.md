# G-AUTO 自然跨夜观察

作者已批准在 2026-11-19 晚使用原验收实例和原会话连续聊天，保存并完全退出。2026-11-20 按正常入口重新打开同一会话并继续对话。允许正常聊天、查阅历史及按已有授权公开查找。以 r4.3 Windows 候选开始观察，晚间的输入缓冲更新沿原数据目录接续。保留更新前的数据库基线，并单独记录关闭和换版重开。实际输入由作者在工作台提供。

本次观察关闭应用内总额度、主模型、自动整理、整理模型及选择器的调用次数限制，解除验收专用传输拦截。按实际调用和回执记录用量及已知费用。冻结首批原始账本，接续数据以 PCAR 日志、调用表和各阶段回执为准。

## 计时与验收

- 最小化后唤回的回复按 **150 秒** 判定，沿用从原请求提交到最后一片实际可见回执的口径。另记唤回到完整可见的时间，有助于定位是后台处理慢、窗口唤回慢，还是已有回复迟迟未显示。其他工况按原登记的 120 秒观察窗取证。此前 130.312 秒样本保留实际耗时和当时的验收标准。
- 无限缓冲以「确认发送本轮」为提交边界。按该时点计回复用时，另记本轮加入的消息数、顺序、确认前调用数和出批数。换版验证沿同一组会话和旧回执核对，次日仍按真实退出和启动的时间判断跨夜结果。
- 跨夜关联晚间退出回执、所属组件释放、次日进程及原会话。比较原消息、回执和新回合，识别丢失、重复派发、串会话及后台工作无法接续的情况。用户正常聊天、搜索、关闭和打开属于日常操作。
- 查阅历史时核对范围、原话、顺序及来源状态。公开查找按原问题、查前提示、实际检索与最终可见答复对账。复用已有资料时核对引用与实际回答。
- 当晚及次日逐项记通过、未通过、未触发和证据不足。异常优先定位最早出现差异的环节。受理和发送异常核对请求 ID 与运输回执，冷启动异常核对进程、租约和读回位置，历史或检索异常核对来源范围、主回复输入、原稿及可见气泡。复验优先使用原回执或隔离环境，实际体验由作者确认。

本机私有观察目录保存基线、PCAR 日志起点、已保存消息指纹和窗口生命周期流水。最小化、唤回及退出只记录窗口和进程状态。会话内容与既有回执由原实例保存。次日从当前验收记录的 `overnight_baseline` 找到现场，按同一实例、人物和会话读取会话与日志。

隔离工作台换版测试使用本地模拟服务。旧版本实际回复显示后正常退出，新版本还原同一会话并保持原回复。把定时设置为 12 秒，两条消息间隔 6 秒，第二条加入后重新计时并合成一轮。另在无限模式暂存两条消息并退出全部组件，重开后保持待确认，确认按钮连续点击只提交一轮，第一条和第二条的顺序一致。
