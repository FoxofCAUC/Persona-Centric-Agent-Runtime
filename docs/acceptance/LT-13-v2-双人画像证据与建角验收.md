# LT-13 v2 双人画像证据与建角验收

## 使用路径

在新版工作台打开「新建角色 → 从聊天记录生成」，选择 Moect v1.3.0 微信私聊 Markdown 或逐条标明说话人的 Markdown。核对双方身份、排除项和日期，必要时逐条修订归属。创建分析计划后可以查看两个人的学习材料总量、选中批次、实际待发的脱敏片段及本地表达统计。初选每人最多六批，可以在批次清单中调整。

云端提炼取得相应用途和请求的批准后，由导入用户确认本次范围。每个分段独立保存首次回执，身份或外层结构错误隔离整批，单条观察的错误独立记录。对跨批的同字段观察可单独审阅汇总请求。已有回执支持本地恢复，发送结果未知的批次保留供核对。

切换两份草稿可查看适用情境、原话和对应原文。用户可手改、暂存、采纳或舍弃。通过证据校验的普通建议默认可采纳，包括单组支持的核心特征和推断。结论存在经校验的反例时，标为冲突待核。用户仍可编辑、舍弃或采纳建议，价值与边界逐项确认。本地统计反映选中范围内完整的本人发言。创建时选择一人或两人，指定空白聊天或按角色视角还原历史。另行核对归属、范围或装配版本会形成新计划；旧草稿可回查。

## 数据、请求与回退

业务库使用结构 33。导入计划、冻结的保留集、区间映射、分段结果、采纳记录和旧草稿快照在实例的私有导入库保存。开发和最终留出消息以及与其相连的去重组由本机排除。引用采用脱敏消息上的 Unicode 半开区间，至少完全落在本次实际发送的本人主片段内。界面通过私有坐标映射回查原件。资料撤回后，已显式还原的历史作为既有会话保留，角色资料标出关联的已采纳字段。

实例可在 `private/persona-import/contract-v2.json` 放置已审定模板。使用 `pcar-dyadic-import-v2` 版本、官方 DeepSeek 模型名、`extract_system` 和按需提供的 `merge_system`。开发审阅在隔离实例制作。下列命令分别导出提取请求或已经取得有效观察后的汇总请求，输出目录须为新的本机私有目录。原文件、模板和真实回执保存在私有工作区。

```text
python -m experiments.import_profile_request_review --home INSTANCE --output NEW_PRIVATE_FOLDER --stage extract
python -m experiments.import_profile_request_review --home INSTANCE --output ANOTHER_PRIVATE_FOLDER --stage merge
```

默认每人导出首个可审阅请求，`--batch` 可指定所选批次。审阅页给出完整模板、请求、传输正文校验值、批准用指纹与用途。批准信息单独记录到实例的 `approval-v2.json`，绑定 `decision`、`contract_sha256`、`purposes` 和逐笔 `request_hashes`。建议同时记录 `document`、`plan`、`source_id`、`base_url` 和 `model`。派发结束设置 `dispatch_closed`。模型参数、模板、范围和新汇总均按其实际请求核对。提炼、按人汇总与角色日常发言使用独立用途。

回退操作先退出新版工作台与本地服务，备份该隔离实例，再使用上一版程序打开同一结构 33 实例。正式人物与已还原的会话可继续读取；再次启用新版后从导入记录打开原计划和草稿。完整 Windows 演练使用空实例及含既有角色的结构 33 实例。 [原工作台历史接续合同](工作台双人私聊导入与历史接续.md)

## 画像盲审

取得同范围的两版首次回执后，从隔离实例准备评阅包。工具核对模型、每个目标实际看到的学习消息与字符范围，再生成乱序的建议、原话和评分页。评阅人打开 reviewer 目录的 HTML，填写证据支持、采纳和关键错误判定并保存评分。揭盲与复核使用 control 目录里的私有对应表。

```text
python -m experiments.import_profile_quality prepare --legacy V1_INSTANCE --legacy-requests V1_REQUESTS --candidate V2_INSTANCE --document DOCUMENT_ID --plan PLAN_ID --output NEW_PRIVATE_FOLDER
python -m experiments.import_profile_quality score --pack NEW_PRIVATE_FOLDER --ratings COMPLETED_RATINGS
```

若现有 v1 回执与 v2 实际选段有差异，先登记无法匹配的范围并安排同范围对照。样本不足、缺真实评分或关键错误均不能登记通过。

导入、工作台、语料、人物管理和打包的定向回归 126 项通过。Windows WebView2 分别在空实例和含旧角色、v1 草稿的结构 33 隔离实例完成操作。空实例导入 20 条标识消息并从原历史末尾发送，已有实例创建两份空白会话。旧版程序回读正式角色与双视角历史后，新版再次打开同一草稿。浏览器另以 1080 和 390 像素宽度检查了改选范围、字段保存、拒绝建议与引文定位。内部工程包完成逐文件 SHA-256 核验，解压后 33 项导入回归通过。

真实提取的首份私有审阅清单已生成，范围为两名说话人各一次提取，模型为 deepseek-flash，每次最多输出 8,192 tokens。两个请求各含 281 条脱敏输入片段。本轮对同范围 v1 原话和预算的离线核对显示，使用原有 v1 协议需每人两次提取，已有批准回执与这四个请求精确匹配的数量为 0。这四次旧版对照使用独立批准范围，本轮首批申请只含两次新版提取。真实画像评分在取得同范围两版回执和作者评分后登记。

作者审阅通过后，A、B 各派发一次，服务均返回 HTTP 200 并正常结束。A 有 9 项观察和 31 处引文，5 项进入可采纳区、4 项待核，耗用 10,947 tokens。B 有 10 项观察和 28 处引文，10 项进入可采纳区，耗用 11,364 tokens。两份首次回执按原字节保存，逐一重跑原话校验，与草稿存档一致。两次提取的派发范围已关闭，作者已通过首批画像审阅。

扩展计划沿用同一学习分区、模板与模型，补选中、后段各一窗，由双方分别提取。实核两份已审请求的字节和首次回执指纹后，在隔离计划中完成本地复用。作者审阅通过后，四份新增提取均已派发并保留首次回执。旧版按原输入容量分割同一批对话窗，逐一核对双方能看到的脱敏消息与字符区间。对照须新增 12 次 v1 提取，已存回执精确匹配为 0。两版盲审评分待同范围回执齐备后登记。

四次补充提取均为 HTTP 200，合计耗用 38,575 tokens。A 新增 17 项、B 新增 14 项观察通过原话校验。3 项观察被隔离，其中 2 项的引文超出本次送达的目标主段，1 项未通过引文逐字校验。包含复用回执在内，A、B 各三段合计 50 项观察及 147 处引文，六次提取共计 60,886 tokens。按人各一份汇总请求以 A 25 项与 B 23 项已校验观察为输入，经作者核准后各派发一次。

两次汇总均收到 HTTP 200 首次回执。A 通过 24 条汇总，1 条因关联的观察属于另一字段而隔离。B 的 23 条汇总均通过。保留分段建议后，草稿为 A 26 项、B 24 项，其中 A 10 项、B 2 项待核。47 条汇总建议各自只引用同一分段的支持观察，本轮跨段合并为 0。两次汇总用量为 12,632 tokens，v2 六次提取和两次汇总累计 73,518 tokens，派发范围已关闭。作者通过隔离草稿原有的全部 12 项待核建议，其中 A 10 项、B 2 项。采纳决定已写入隔离草稿，绑定原审阅页与两份首次汇总回执。 审核规则调整后，127 项定向回归通过，另在 Windows WebView2 隔离实例重验双人导入、创建、历史接续和旧版回读。
