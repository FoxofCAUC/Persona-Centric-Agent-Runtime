# M7.6.3-R06失败槽重试政策


日期：2026-10-31。依据用户新指令，替代本阶段此前“失败槽仅保留、不自动补验”的执行口径。适用对象仅为当前R06独立评测包，不改变日常运行时的重试设置。

1. 每个终结失败、没有可用输出的逻辑槽，在原失败之后有三次即时重试机会；第一次成功即记录通过，不继续调用。
2. 三次均失败时保留全部原请求、失败attempt、费用未知与补验原因，先执行其他槽。其他槽均终结后，对剩余失败槽逐轮重试，每轮先访问各失败槽一次。
3. 已成功槽不重放。已经完成但质量不合格的输出仍是质量评测结果，不能借本政策替换。running、fee_unknown和恢复未核对的请求不能直接重新提交。
4. 单次失败超过600秒、连续第五次实际模型失败及零模型供应商检查失败的停止规则保留。目录检查不是评测槽，不因本政策循环重试；健康成功也不清空实际失败计数。
5. 派发前拦截不计作实际模型调用，也不消耗一次模型重试机会；须保留登记记录并先排查修复，禁止无调用的失败循环。

## 执行与恢复

`retry-policy.json`固定政策身份；`retry-state.json`记录机会、阶段、父请求、操作号、实际派发及结果。现有评测台账的supplement审计保留原失败，成功后当前槽更新为通过；失败历史不会被覆盖。

每次重试采用新的稳定request_id与原生受理回执，在原人工人格、原入口的独立新Session中保存全部输入。人格、角色、模型与上下文政策六类快照指纹必须与原冻结请求相同，不能用最新作者资料替换。`retry-views.json`仅指向权威Receipt/turn，读取时再次校验，不是第二份聊天档案；原prepared与独立标签不改。

B/C继续使用原B请求已经选择的同一份候选材料，明确标记补验复用、原选择turn及attempt，不追加选择调用。C若按正式条件需要理解，新受理请求的理解独立留账，不冒称复用旧理解。当前人工集没有结构化原生引用；工具遇到未适配的原引用绑定明确停止，不剥离后发送。

本政策用于当前获准的官方API隔离评测，不授权重放成功槽或替换完整但质量差的输出。
