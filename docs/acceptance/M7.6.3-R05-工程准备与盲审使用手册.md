# M7.6.3-R05 工程准备与盲审使用手册

本页说明已实现的工具与后续人工操作。R05工程验证通过，不是人格质量或Live上线结论。

## 工程准备结果

见[阶段记录](../M7.6.3-R05-评测工具与Live工程准备.md)。工具模拟300槽/100审阅；无真实独立评测、用户偏好代填或收费调用。103项定向及随后9项/29项局部复验通过，重叠不累加；本次按用户决定不跑全量。

## 准备与载入

1. 后续独立集冻结后，由受控工具在D盘证据目录保存cases与binding，记录SHA256。使用scripts/evaluation_package.py create，显式给--home、--package-id、--fixture及--fixture-sha256。工具模拟必须带--simulated；不能拿工具样例当独立材料。
2. 生成器必须按台账稳定request_id受理。中断先用reconcile_runtime查询原Receipt/turn/attempt；成功禁止重放、费用未知不能直接补缺。明确传输失败的补验用supplement保留旧记录与理由，不得替换完整但质量差的输出。
3. 独立B/C输出齐备后，工作台进入“角色”→“人格倾向”→“独立评测盲审”。输入受控评测包ID及批次1–4，点击载入。服务端仅管理员可读写此目录，不接受任意文件路径。

## 人工盲审

每组展示场景、共同作者资料摘要与匿名左右正文，不展示模式、模型元数据、决策、时延或映射。回复按纯文本显示。

逐组填写左/右任务结果（pass、critical_error、uncertain），左/右主要动作（九动作或uncertain），自然度（left、right、tie）和理由。字段无默认答案；由用户本人判断，助手不代填。

保存后再到下一组。失败、冲突或丢失响应时保留草稿与相同operation_id，先找回旧结果；切换人格、评测包或批次后旧响应无效，须重新载入。关闭未保存内容需明确确认。

四批共100组保存后，“冻结并解盲”才成功；冻结后不能修改评分。未完成、无法判断与平局不缩小分母。机器再按映射计算C获胜及任务正确性，结合预先冻结标签进行全门判定。

## Live候选与回退

R05只有候选代码。普通实例的政策更新/执行均拒绝无准入Live；隔离工具按人工人格白名单传入进程准入验证。Assist隔离不因Live而放宽。

正式发布文件固定为运行目录exports/acceptance/disposition-live-release.json，由后续R07发布流程在全部质量/平台/作者确认门通过后安装，不是工作台开关自行创建。它绑定实例、运行路径、当前源码、目标、冻结盲审包及审核结果；缺文件不启用。新建/导入/复制/CLI同样受发布门约束，投影缺失显示not_configured并回M7。

回退时先在现有管理合同中将目标入口改为baseline或shadow，核对未决批次处置，保留作者与审计数据；再撤下发布文件并正常重启。不要在保留Live政策时直接删除发布证据。禁止用旧数据库备份盲目覆盖新输入；软件回退仍须考虑结构20与旧19兼容边界。
