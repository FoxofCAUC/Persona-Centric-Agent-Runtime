# 修补包 4 · 前后台调度与模型调用限额

## 用户操作

**新版工作台默认关闭模型调用限额。** 从「应用菜单 → 高级设置 → 模型调用限额」可以开启限制，填写过去 1 小时或 24 小时内允许的全部模型调用次数。填写 0 表示该项不限额。需要单独限制后台整理、角色选择与理解时，展开「单独设置自动调用额度」。关闭后保留表单中的数值，方便下次启用。

统一计数从本版本首次运行起记录，包括用户尚未开启限额期间的调用。达到本机限额时，PCAR 保留已经受理的消息和等待任务，并显示触发的限额与受影响的工作流数。

| 弹窗选择 | 用户可见结果 |
| --- | --- |
| 保留限额，继续等待 | 消息留在原会话。额度自然恢复或用户关闭限额后继续。用户可以点聊天区的「查看等待任务」，也可以从高级设置重新打开等待列表。 |
| 临时放行并继续 | 恢复弹窗列出的工作流。同一回合的查找、生成和后续表达共用这次放行，同一记忆批次的提取与复核也共用。新消息及新批次仍使用原限额。 |

放行后仍核验资料授权、接收模型、取消状态和已有回执。供应商的账户余额与服务限流由供应商执行。研究材料的逐笔批准、主动消息的发送频率和故障重试次数沿用各自的用途规则。

当前源码的 Tk 兼容工作台也可在「调用额度」中设置总额并处理弹窗。纯服务模式下，受阻任务保存在本机，打开桌面工作台后可以统一处理。

## 工程行为

| 改动 | 验证点 |
| --- | --- |
| C11 维护隔离 | 记忆、知识、索引、定期扫描和调度各自运行。持续故障按组件退避，最长 60 秒。高级诊断可查看重试时间。注入三项维护故障及诊断记录异常，前台查找和健康的扫描仍完成。 |
| C12 前台容量 | 十个等待名额中为对话依赖预留两个。服务按原回合及依赖绑定认定前台任务，分别核对前后台的执行者、代次和回执。八个后台工作排队、另一项后台调用在途时，前台仍完成查找。单槽配置下前台等待在途调用结束，随后继续。 |
| 调用计数与恢复 | 在本机 SQLite 写事务中竞争额度。重试按新的调用计数。累计额度覆盖主回复、选择与理解、场景判定、表达、受管任务及导入建卡等路径。到达限额时保存工作流标识，只放行本次确认的等待项。 |
| 历史配置 | 新实例各类次数额度均为 0。升级时将与旧出厂值完全一致的一组配置按默认值处理，保留可识别的自定义额度。新版和阶段 0 冻结程序在同一隔离副本往返，结构 33、限额记录、完整性及外键检查通过。 |

## 复验入口

423 项不同的定向回归用例通过，覆盖调度、额度、消息受理、模型阶段、导入建卡、工作台与结构 33 兼容路径。下列两次独立的真实窗口演练另行计数。

- Windows WebView2 通过真实聊天框提交三条消息。先启用每小时一次，第二条选择等待，再从等待列表放行，第三条重新触发原限额。三条均取得独立受理记录和回复，本地模型替身共调用三次。[窗口演练](../../tests/workbench_quota_smoke.py)
- 另从空白窗口导入双人记录。在第一次角色分析后触发限额，确认一次即完成另一方分析和角色卡合成，随后走通历史接续、精确引用、撤回及重开。[导入窗口演练](../../tests/workbench_import_v2_smoke.py)
- 工程用例覆盖同一额度被多个执行者争用、小时和日窗口、受理后重启、同时恢复前后台、关闭限额唤醒、检索后返回主回复，以及记忆提取后继续复核。[定向用例](../../tests/test_workbench_call_limits.py)
- 用户操作、等待状态及单次放行通过本机管理接口处理。额度表只保存时间、调用类别、工作标识及决定。聊天内容和密钥继续由原业务记录管理。[额度与等待实现](../../persona_runtime/call_limits.py) · [受管调度](../../persona_runtime/managed_organization.py)

本机隔离证据位于工作区的 `tmp/quota-scheduling-1795085582902`。窗口、配置往返以及按用例去重的回归结果见该目录的 `result.json`。本包使用本地模型替身，真实模型调用为 0。正式 72 小时验收留待后续联合验收。
