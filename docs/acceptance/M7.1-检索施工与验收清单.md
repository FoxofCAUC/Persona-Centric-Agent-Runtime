## 4. 来源快照、缓存与恢复

| ID | 故障/竞态 | 必须观察到的结果 |
| --- | --- | --- |
| I01 | 完整快照A中途预算不足/读取异常 | 不发布半份语料，不返回完整no_matches |
| I02 | 快照A与B间新增完成turn或发送确认 | 指纹变化，index_stale；不因旧索引无结果漏报当前新增内容 |
| I03 | 非首成员撤回但max(Event.seq)不变 | 指纹变化，整轮不能由旧缓存复活 |
| I04 | 分词/写缓存时核心新写入 | 核心读事务已关闭；没有跨库原子承诺，B复核捕获变化 |
| I05 | 缓存写满/锁忙/事务故障 | 权威受理和投递不回滚；派生失败可解释，旧代次不称fresh |
| I06 | 写documents/FTS/meta中任一步崩溃 | 派生事务整体回滚，不出现正文与generation错配 |
| I07 | 重建或查询并发 | 维护锁/代次隔离；只有完整代次可读，不同请求不串Scope |
| I08 | 相同operation_id同参/异参、过期expected_generation | 返回旧完成结果/冲突；不重复发布新代次 |
| I09 | 缓存损坏、丢失或版本变化后旧UI操作 | 新cache_instance_id；旧令牌冲突，不将新0代当旧实例 |
| I10 | 原文/hash/时间/成员顺序/资格或发送状态变化 | 相应来源摘要变化；不能仅靠新Event序号判fresh |
| I11 | FTS不可用、词法版本变更 | 同快照完整有界降级或明确不可用；路径/语义标记，无伪no_matches |
| I12 | Windows读者持连接时发布新Scope代次 | 通过派生事务，未替换正在打开的DB文件；读者所用代次可解释 |
| I13 | 服务停止/重开 | 未提交缓存不发布，无自动续建、模型调用或确认片重发；显式重建可恢复 |
| I14 | 缓存路径注入或误指主库/其他项目 | 只操作已验证的本项目cache路径；拒绝任意路径和越界删除 |
| I15 | 无缓存的结构11副本恢复及导出8 | 原身份/档案/引用/投递完整，缓存可重建，导出无缓存正文/凭据 |
| I16 | 来源变化后重新查询/详情/工作集预览 | 所有使用入口再校验，旧响应不是永久授权 |
| I17 | 同Scope不同session/all/recent_50分区并发 | 分区代次及操作令牌不串用；recent_50只展开窗口内回合，窗口滚动触发指纹变化 |

I02/I03/I09以一致性行为验收，已废弃“必须新增核心变更登记/消费500条日志”的旧断言。本阶段基线无主库新表；若设计另有变化须更新本表及迁移门。

正常流程使用人工数据/独立测试人格，预期0次模型调用、0次QQ发送，不开启临时不限额。实际按钮名称由实现后的验收手册补齐，当前按钮及步骤已整理在实际界面验收手册。

| --- | --- | --- |
| U01 | 记录初态，载入人工三成员回合与QQ实际片段夹具；普通未知字段留空 | 基线版本、fixture_revision、Scope与调用计数；不导入私人聊天 |
| U02 | 在工作台查第三成员词、单字、英文标识、phrase/all_terms | 命中目标正确、三成员完整，模式与排名可解释 |
| U03 | 切四种时间轴及上海日期边界 | 命中文档时间正确，组外时成员仍完整，缺轴可见 |

| U08 | 故障注入缓存满/损坏/锁忙/FTS缺失，显式重建 | 可解释状态、受限降级，旧完整代次/核心数据安全，操作幂等 |
