## 2. G01–G05功能专项

| ID | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| S01 | query为空/过长/超过32词项 | 仅有时间条件可空查；其他明确拒绝，不截断 |
| S02 | 输入OR、引号、冒号、SQL/FTS样式文本 | 仅字面数据，不扩语法/权限，不执行脚本 |
| S03 | 阅读角/预算/单字/英文下划线 | 中文片段及短词路径可解释，不丢字符 |
| S04 | NFKC与casefold改变字符长度 | 命中正确，原文不改，不用归一化坐标切原文 |
| S05 | all_terms词项分散与phrase连续原句 | 两种模式区别明确，结果与合同一致 |
| S06 | 同词跨人格/渠道/Bot/peer | 禁止范围无正文、数量及存在性泄漏 |
| S07 | 他人格有更高分文档 | 不影响本scope候选或BM25统计，结果稳定 |
| S08 | 当天0点、次日0点、未知平台时间 | 半开区间正确；缺时间显示覆盖缺口，不套received冒充 |
| S09 | query/日期相同但切换时间轴 | 过滤按所选轴，结果带明确轴和UTC边界 |
| S10 | 命中三成员中的第三条 | 命中ID准确，展开三成员原文及顺序齐全 |
| S11 | 同turn多个成员/语义段/平台part同时命中 | 组去重，实际part正文与原语义文本区别可见 |
| S12 | 旧Event无RawEvent/平台ID/账号归属 | 不补造；归属不确定不进入普通scope查询 |
| S13 | 新事件仍collecting/queued/failed/cancelled | 不当成功经历；状态转completed后增量才纳入 |
| S14 | 输出generated/sent/uncertain状态变化 | 按来源类型和有效性更新，不假装已读 |
| S15 | 撤回非首成员 | 整轮及相关回复退出，旧缓存/详情再查不能复活 |
| S16 | 查询与撤回、同步与撤回并发 | 明确读取快照边界，后续读取不得使用失效源 |
| S17 | 候选200/结果字符/单字扫描/时间预算超限 | 返回限制原因，不将不完整扫描标完整no_matches |
| S18 | 冷/热查询排序平局 | 固定ID排序可复现；没有伪分页按钮或不稳定cursor |

## 3. G04/G08存储与恢复专项

| ID | 故障 | 必须观察到的结果 |
| --- | --- | --- |
| I01 | 来源提交后缓存写入失败 | 权威来源不丢，查询明确stale/unavailable或正确降级 |
| I02 | 核心变更登记写入失败 | 主业务事务整体回滚，不能成功受理却漏变更 |
| I03 | 中断500条增量中的一批，再继续 | 结果无重无漏、revision准确，不依赖模型 |
| I04 | 重建中崩溃/服务重启 | 半成品不发布，显式继续幂等，不覆盖活动文件 |
| I05 | 重建期间有新输入或撤回 | 新generation追平再发布，source/hash/范围核验通过 |
| I06 | Windows读者持文件时切换generation | 关闭句柄后发布manifest，不替换打开中的SQLite文件 |
| I07 | scope哈希路径、重复/冲突operation_id | 只操作核对过的本scope目录；幂等与冲突明确 |
| I08 | FTS不可用、缓存损坏、磁盘满、锁忙 | 区分故障/降级状态，不报历史不存在，受理/投递不被长锁堵住 |
| I09 | 日志断档、缓存比源更新、词法版本变化 | 拒绝冒充fresh，显式重建，旧索引不混用 |
| I10 | 新库/旧受支持库升级/重复初始化/失败恢复 | schema正确、旧原列/ID不变、外键和完整性通过 |
| I11 | 无缓存备份恢复/人格导出 | 原文可恢复，缓存可重建，包不含凭据/私有缓存文件 |
