# 滚动合批与分条使用手册

当前版本0.7.5.dev6、桥接0.7.1。日常使用不需要在消息中要求纯文本、分条或去标点。新建、导入、复制人格默认启用新版自然策略，明确选择兼容模式的旧入口保留选择。

1. 打开PCAR工作台，在“输入与缓冲”核对目标人格/入口，显示“最后一条后五秒，无时间上限”。窗口发送一条并收到受理即可继续输入，不必等回复。
2. 每次有效新增输入重置五秒倒计时。重复提交不续期。容量、手动“立即回复”、身份/会话/冻结设定变化仍可能提前封批；工程详情显示原因。
3. 自然模式下，每条展示消息独立呈现；QQ按展示消息节奏发送。原生成、展示、平台片段分别可查，不能用生成完成代替送达完成。
4. 代码、网址、邮箱、路径、数值与引用数据保留必要符号。超过12条普通展示消息或无法安全处理时整批失败，不能发半批。技术/代码/引用保全规则不等于全文删标点。
5. 模型连接/等待响应故障查看请求诊断，确认原回执后再决定手动重试；没有自动补发。当前主模型总等待180秒，较慢不代表丢失输入。
6. 回收站身份保持删除，恢复后可沿用已升级策略；私有原体不用于验收，升级只改技术政策，文学与经历不变。

## 后续必要复验

已有合批和投递证据无需因重启重做。确需补验时使用独立通用人格和本机登记的专用QQ测试账号，禁止日常账号。先确认服务/身份、原配置、调用预算及未决工作，再让测试者按0、4、8、12、16秒发五条自然补充；输入不能附加格式要求或工程编号。

分别检查：实际平台入站跨度超过15秒且相邻小于5秒；同一批完整五成员；最后输入后约5秒封批；一次主要请求；原生成自然表达；每条展示/实际片段、平台ID及一次发送记录。用户已读无证据仍未知。故障或时序不合格保留原记录，不能重放已确认片段来掩盖失败。

计时边界、系统时钟变化、容量、CAS、取消和重启采用隔离测试；真实QQ不能由HTTP注入或改时钟代替。整理、私有原体及历史质量集不在本手册复验范围。结束恢复原账号、人格、额度、每日整理和服务状态，保留经确认的正式技术升级。
