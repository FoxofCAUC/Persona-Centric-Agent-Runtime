本包覆盖 C01、C08、C09、C10 和长会话风险 R01。验证入口为 Windows 新版工作台。正式桌面 G-AUTO 与 72 小时连续使用留待联合验收。[施工方案](../product/桌面连续聊天闭环修补方案与健壮性评估.md) · [阶段 0 冻结环境](桌面无人值守-阶段0基线与验收矩阵.md)

## 用户操作和恢复行为

| 场景 | 窗口行为 | 核对方法 |
| --- | --- | --- |
| C01 服务晚启动或中途失联 | 聊天区说明正在重连，可继续编辑草稿。窗口按原实例身份探测，退避上限 8 秒。服务可用后核对发送记录并恢复原会话。 | 服务在窗口打开 32 秒后才启动。另在用户阅读旧消息时停止并重启服务，核对角色、会话、草稿和首条可见消息。替换实例身份后，旧窗口不能向新实例写入草稿或阅读位置。 |
| C08 从 A 翻看 B | 人物资料、原生历史与导入历史按指定人物和会话读取。浏览不会切换工作实例的当前人物。明确发送或保存人物变更时才按相应写权限处理。 | 用两个角色来回切换并核对服务中的当前人物。单独检查封存会话、空白人物和 QQ 会话的读写边界。 |
| C09 写到一半，或停在旧消息 | 草稿、引用标识、阅读锚点及偏移按实例、人物、会话加密保存在本机。发送确认只清除当时提交的草稿版本。恢复引用时重新核对来源。 | 切换角色、重开窗口及重启服务后检查草稿和位置。另验中文组词时回车、旧确认晚到和引用来源撤回。 |
| C10 发送等待或失败 | 聊天区显示受理、排队、等待额度或等待核对。最近一轮遇到认证错误时可就地更新模型连接。翻旧消息仍能看到当前故障。高级诊断给出本机状态、回合标识和脱敏原因。 | 注入认证失败，核对唯一操作入口，保存新凭据后自动返回原会话。未知错误只输出通用诊断代码。 |

## R01 长历史测量

在阶段 0 的 Windows 机器上使用隔离副本。每档含两个人物、50,000 条编号导入气泡，另加指定数量的原生回合。按同一窗口中的实际绘制和受理状态计时。每项每档 100 次，P95 取升序第 95 个观测值。

| 原生回合 | 读取并绘制原生页 P95 | 从另一人物切回长会话可读 P95 | 点击发送至可见受理 P95 | 使用中服务重启后恢复 |
| ---: | ---: | ---: | ---: | ---: |
| 1,000 | 175.6 毫秒 | 315.2 毫秒 | 242.2 毫秒 | 1.156 秒 |
| 10,000 | 184.9 毫秒 | 339.3 毫秒 | 284.2 毫秒 | 1.234 秒 |

切换计时含人物选择、草稿与阅读位置读取、原生和导入消息绘制。发送计时从聊天框提交到窗口显示相同内容的已受理气泡。每次在本机确认受理后取消仍在收集的数字输入。两档均达到切换可读 P95 ≤ 1,000 毫秒、发送至可见受理 P95 ≤ 500 毫秒的门槛。在服务晚启动 32 秒的专项中，服务就绪后 4.500 秒接回原会话。本轮真实模型调用为 0。

原生历史每页最多 60 个回合，序列化卡片合计以 384 KiB 为预算，单个超大回合保留完整内容。窗口原生缓冲最多 120 个回合。轮询只取有变化的回合。活动序号失效或变化量超限时重新读取阅读位置附近的页。导入记录独立双向分页，每页 80 条，窗口最多保留 160 条。发送新消息时只查询可能需要取消的结构化回复，避免逐条扫描导入回合。[历史读取](../../persona_runtime/workbench_timeline.py) · [窗口与阅读位置](../../persona_runtime/workbench_web/persona_import.js) · [草稿及受理记录](../../persona_runtime/workbench_submissions.py)

## 回归与证据

实际 WebView2 另从已有角色和空白实例走通历史接续、精确引用、来源撤回及重开。两次重开还注入了迟到的受理回执。核对期间，同一版本的草稿仍可见，连续按发送只产生一次提交。编辑下一条后收到旧回执，新草稿仍保留。回执与当前版本一致时才清空输入框。窗口复验将测试窗置于前台，继续用 Windows 命中测试核实气泡实际可见。

270 项不同的离线定向用例通过，其中 10 项是本包新增。范围涵盖连续使用、消息受理和恢复、可见回执、导入历史、会话权限及发布包。QQ 历史验收驱动另有 1 项在设置旧版回复格式时遇到 `companion_format_conflict`，相同用例在阶段 0 冻结源码复现。[连续使用用例](../../tests/test_workbench_continuity.py) · [窗口历史接续用例](../../tests/workbench_import_v2_smoke.py)

本机证据位于工作区的 `tmp/workbench-continuity-1795080825475`。其中 `result.json` 记录去重计数与分组，`ui-1000.json`、`ui-10000.json` 记录窗口计时，`ui_continuity.py` 留存测量步骤。下一包处理 C11–C12，验证后台维护故障及容量竞争下的前台聊天。
