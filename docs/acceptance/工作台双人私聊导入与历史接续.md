# 工作台双人私聊导入与历史接续

本候选面向 Windows WebView2 工作台。微信 Moect v1.3.0 私聊 Markdown 和发言者标题明确的通用 Markdown 可以从「人物 → 新建角色 → 从聊天记录生成」导入。通用文件每条消息以二至四级标题写说话人，标题末尾可带方括号包围的日期时间。证据编号对应原文件中的消息顺序。

## 从目标人物开始聊天

1. 选择本地文件。核对双方名称、条数及时间范围，按需要排除其他发言人。重名时可在「逐条核对或修正」把指定消息分给另一人。
2. 准备脱敏片段和两份草稿。查看分析范围，已审模板就绪且用户确认云端用途后，可开始真实提炼。等待期间可以退出，重开后从新建角色列表找回记录。草稿可以手动编辑，也可主动使用现有通用模板补齐必填项。
3. 选择目标说话人，或同时创建双方。**从空白聊天开始**时，记录用于本地证据和获准的表达学习。**还原这段历史并接着聊**时，目标人物的原话进入人物一侧，另一方的原话进入用户一侧。两人同时创建时各有独立身份和会话。
4. 在恢复后的会话翻看原始气泡，从末尾继续发送。后台按文件原序保存来源、时间和逐条事件，无原始时间的消息在界面标为日期待核。历史导入和角色创建在同一事务中完成，历史消息没有模型调用或费用回执。
5. 人物资料可开启或暂停自动记忆。原历史作为已有会话的整理来源，沿用当前人物的渠道、后台模型、提取及复核政策。记忆是否形成可从实际整理记录核对。风格来源的撤回作用于提炼、选样及未呈现的来源依赖发言。用户显式恢复的聊天记录属于已建立的会话。

## 模型输入审定与证据

本机实例的 `private/persona-import/` 保存原件、草稿、证据版本和模型回执。参考装配文件为 `contract.json`，批准记录为 `approval.json`。文件由作者按下述合同审阅和提供。私人原件及这两份文件留在实例目录。

| 文件 | 需要核对的内容 |
| --- | --- |
| contract.json | `version` 为 `pcar-dyadic-import-v1`。`analysis_system` 为作者审定的提取模板，`model` 为获准的官方 DeepSeek 型号。可另给 `merge_system`，用于汇总已经核对过的建议。 |
| contract.json 的发言设置 | `style_prefix` 为获审的参考材料引导文字，`reply_model` 为 `deepseek-v4-pro`，`similarity_min` 为经开发样本校准的余弦相似度下限，取值大于零且至多为一。 |
| approval.json | `decision` 为 `approved`，`contract_sha256` 是获审文件原始字节的 SHA-256，`purposes` 分别列出批准的 `analysis` 和／或 `style`。修改文件内容后需要核对新版本。限定分段时可用 `request_hashes` 列出准许的完整请求指纹。 |

分析使用系统模板和一个 JSON 用户数据对象，字段为 `target` 与 `records`。原话记录含消息编号、匿名说话人、脱敏正文和片段编号。响应字段为 `claims` 和 `samples`。每个建议包含 `field/value/evidence`，其中每条证据为目标人物的 `id/quote`。表达样例以 `id/act/polarity` 指回目标人物原句。发言作用可取 share、request、question、comfort、close、other，倾向可取 positive、negative、neutral。跨段汇总沿用相同外层数据结构，输入记录为已提炼建议，证据限于本批支持原句。提取采用 JSON 输出，作者提供的模板应符合官方 JSON 输出合同。

发言前先核对本角色和版本，再用本地向量模型比较当前输入与样例的上文。最多选两段，样例作为独立的用户资料消息放在本轮输入之前，内容为获审前缀与原话 JSON 数组。模型容量不足或匹配不足时可以空选。每次实际采用的编号可从消息反馈查看。历史导入与风格取样分别由用户选择。

「用已收到的回执预填」只读取同一文件、模板、模型与输入版本的首次回执。部分分段的结果显示已采用的覆盖数量，手动改过的字段保留。

## 验收范围

隔离实例已逐条核对授权文件的 46,910 条记录和两种人物视角。重开后核对记忆整理输入中的原始事件编号及顺序，下一条消息的实际主回复输入包含导入记录的末尾。Windows WebView2 窗口通过真实本机服务走通选文件、预览、角色保存、历史还原和连续发送。发言端使用本地替身。导入、语料、原有发言、呈现和人物管理相关的 120 项检查通过。

隔离工程验证覆盖单文件解析、同名分配、双草稿保存、两个相反视角还原、档案与记忆来源、下一轮接续、已接收回执和来源撤回。真实人物效果须使用获准模板、冻结的留出片段及独立会话，对两名人物分别开展六个固定前文和六轮连续对话的开启／关闭取样盲审。工程替身结果与作者读感分别记账。

作者在首批审阅中批准 A、B 各一个分段。两次首次提取均取得有效回执并通过证据校验，已在独立研究实例按原回执恢复两份部分草稿。原文、私人画像和具体模板存于本机私有审阅页。作者已通过首批画像。首批语料含 A 的 2 条和 B 的 9 条表达样例，以原相似度门限检查 1,230 个开发与留出位置，均无命中。本期修复 other 样例条件，并使用当轮全部向量分块比对。沿用首批模板，从学习分区选出 A、B 各三段作为补样候选。真实发言盲审单独验收。

### 下一轮风格对照

补样用开发分区相近的对话组选定旧模板下的完整脱敏请求，最终留出组不用于补样选择。程序可从读过的请求清单和作者批准记录启动独立研究实例，复制已有两份回执，保留补样首次回执，再以成功回执预填部分草稿。

作者批准的六个补样请求均收到 HTTP 200 首次回执，五个通过证据校验。A 的一份回执引用与目标人物原话不符，保留原回执并排除。补样实际用量合计 75,070 tokens。合用首批回执后，A 草稿采用 3/130 段，包含 25 项画像建议和 8 条表达样例。B 草稿采用 4/130 段，包含 30 项画像建议和 18 条表达样例。两份部分草稿的必填项均已齐备。

本机使用现行语境筛选和分块评分，复查 24 个冻结位置。每处均有语境兼容候选，四组均为 0/6 命中，最高相似度 0.5675。门限 0.82 下取样开关尚无样例差异，真实发言对照留待取样具备可比较条件。

最终留出输入已冻结 12 个固定位置和 12 个连续位置。六轮连续输入由同一有效对话组沿两名人物的相反视角取得，开关两边需要分别接续各自的实测回复。真实发言前仍需核对两人的完整人设、预计使用的样例和本轮输入。没有实际采用样例的位置按空选记录。

### 低分复核与来源修复

同句从样例和本轮两条编码路径比对，相似度最低为 1.0。定位到预筛与提取之间的来源脱节。六个请求按开发组取分数最高的对应回复，共 16 个位置，回执仅保留其中 1 个。预筛清单现保存具体的对方发言、人物原话和开发位置编号及分数，能够逐项核对回执是否保留该样例。

回执解析另修复了同一人连发样例漏收。限定同一请求、同一片段、原始编号连续，用已有有效回执恢复 A 的 4 条和 B 的 6 条原话。来源审阅另列 A 的 9 对和 B 的 6 对待审配对。两种修复都保留原回执和原请求，复算过程中没有新增模型调用。

门限为 0.82 时，A 的开发命中从 1/234 升至 9/234，B 从 1/341 升至 7/341。24 个冻结位置仍为 0 次命中，最高分从 0.5675 升至 0.6847。连发合并与放宽场景筛选的开发诊断未显示稳定提升。作者已审阅 12 个开发配对，认可其中 2 个。逐项标注保存在本机审阅档案，后续校准按作者指令接续。

回退风格时在人物资料暂停取样或恢复已采用的版本，日常回复回到已有的人设路径。测试新的历史还原功能时使用独立实例。旧版程序回退使用升级前备份，新候选保存的原件及业务库保留备查。
