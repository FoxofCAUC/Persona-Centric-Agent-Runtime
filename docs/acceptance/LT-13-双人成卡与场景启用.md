# LT-13 双人角色卡合成与使用

## 已固定的发布提示词

2026-11-19，作者批准将已审的通用提示词用于后续工作流和发布版。提取、汇总、双人成卡模板收在同一份可导入的 JSON 文件，版本 `pcar-import-prompts-v1`，发布 SHA-256 为 `72aa23bcda484a474c746e8634b0601b8fb8e43f266677e3ec851d5e36e97df6`。发布包根目录提供 `双人角色卡提示词.json`，工作台从同一版本自动加载。应用在用户确认分析用途和发送范围后派发。后文逐笔导出和审批属于研发实测流程。[用户操作](../user/双人聊天生成角色卡.md)

## 发布版工作台实装验收

新版工作台从「导入提示词文件」读取本包的 JSON，或直接使用相同的内置模板。用户在一个入口确认脱敏材料和调用范围，PCAR 随后填好 A、B 两张卡。保存一人时只检查该角色，保存两人时一起校验并创建。资料不足时可继续填写已有草稿。

- **直接保存。** 在干净的 Windows WebView2 实例中，导入提示词，设置测试连接，分析双人 Markdown 后直接创建两人。两张卡均无需手工改动，各自从空白会话开始，可以立即发送消息。
- **冲突处理。** 在已有角色的实例中，B 的年龄字段出现冲突，弹窗可定位到具体字段并查看依据。用户可更正或明确留空，普通建议照常预填。服务在保存时检查所选角色的冲突状态，关闭弹窗保留待处理项。
- **回放正式回执。** 用已获准的第二版首次回执在本地复验。每人自动填入共通提示、四种场景、兜底、Jev 说明与五项判据，共 12 项发言文案，各保留 8 条核对过的本人原话。生成文案标明来源类型，年龄和身高留空。此次复验新增云端调用为 0。
- **恢复和兼容。** 使用本地模型替身验证重开草稿和回执复用，在结构 33 的旧版读取器回读新建角色。工作台覆盖 1080 和 390 像素宽度下的弹窗与表单，空白会话中仅记录新产生的发言。

## 从文件到可用角色

新版工作台的「新建角色 → 从聊天记录生成」支持 Moect 私聊和带明确说话人的 Markdown。用户确认归属与发送范围后，PCAR 按人提取和归并观察，随后用一份额外请求合成 A、B 两张角色卡。已有画像可直接进入成卡。每个导入文件最多产生一次实际成卡请求。重复点击、重开和恢复使用同一份首次回执。

两张卡分别显示基础人设、可选身份与外貌资料、语言风格、关系、表达样例和各项出处。普通发言按 PCAR 原生人格字段装配，表单可以预览当前人设正文。角色共通提示、日常交流、情绪与关系、明确求助、收束、日常兜底，以及 Jev 总说明和五项判据都可以编辑。确认创建时可选择一人或两人，从空白会话开始。后续工作台包已增加可选的历史接续及长期记忆入口。[历史接续验收](LT-13-外部历史接续验收.md)

源观察和引用使用各角色独立的编号。模型输出的事实、描述和场景材料按字段核对依据。年龄、身高等资料须有明确的本人陈述，数值与单位由本地核验。资料不足处留空；无法沿引用找到原话的样例进入待补区。原有手工字段和采纳信息有对应的修订记录。任务进行期间用户继续编辑时，迟到的候选可单独查看。

## 保存与发言

基础人设通过现有必填校验后可以保存角色。年纪、身高、职业等可选项可以保持空白。服务在一次事务中保存选中的角色、资料版本和本机卡片绑定，操作编号用于重试。每份正式卡保存当时确认的完整版本及出处，业务库使用结构 33。

普通发言使用现有主模型。用户可在创建时或稍后在人物资料中核对并启用场景。启用需要完整的共通提示、五个场景正文、Jev 说明和五个判据，以及已配置且用途获准的 Jev 和 DeepSeek Pro。Jev 读取本轮语境及判别材料；主回复读取共通提示和选中场景。现有五选一概率阈值、超时兜底和逐泡呈现合同继续生效。缺配置或材料时可以先使用普通会话。来源撤回、角色版本或连接变化时重新核对场景绑定。

## 研发实例的模型输入和产物审阅

在采用逐笔审批的研发实例中，成卡模板由实例私有目录的 `contract-card.json` 提供，格式版本 `pcar-dual-card-v1`，字段 `model` 和 `system` 固定本次模型与文字。用下列命令将完整待发请求导出到新的本机私有目录。审阅页附模板、完整双人材料、模型参数、请求字节和指纹。模板内容改动后重新导出。

```text
python -m experiments.import_card_request_review --home INSTANCE --output NEW_INPUT_REVIEW_FOLDER
python -m experiments.import_card_result_review --home INSTANCE --document DOCUMENT_ID --output NEW_RESULT_REVIEW_FOLDER
```

开发实调用 `approval-card.json` 绑定作者通过的文档、计划、源修订、源内容摘要、模型、端点、模板摘要、compose 用途及单个请求指纹。成卡批准独立于提取、汇总和日常发言。服务交付时，模板如已明确获准用于用户自行选择的导入，可在对应实例使用单独的 `user_confirmed_import` 模板授权，固定模板摘要、模型、端点和用途，并由用户确认本次资料。逐笔实验授权保持其原范围。请求截断、结果未知或来源过期的状态留档，可继续手工补齐或核对候选。

## 验收与交付

工程验收覆盖双人一次派发、重复提交、输入超限、未知回执、取消、来源撤回、字段证据、手工编辑及保存回退。在 Windows WebView2 空实例和已有结构 33 实例中，通过实际本地服务和接口替身检查导入、双卡预填、普通人设和场景预览、手工补填、双人创建与空白会话后的首次发言。旧版回读、恢复草稿和场景路由另设回归。真实验收从已完成的 A 26 项、B 24 项观察起步，保留两个说话人的独立证据。候选交付依据作者对实际成卡版本和用途的审阅结果，包中提供源码、清单和回退说明，私有原件、角色正文、模板审批及云端凭据保存在实例中。旧版画像对照在本阶段之后安排。 [双人提炼与归档](LT-13-v2-双人画像证据与建角验收.md) · [场景发言与回退](../expression/E.N6-场景发言接入与回退.md)

## 第二版研发候选实测与作者确认

按作者要求，第二版合成模板重写了角色取材与表达部分。两版的用户资料、模型和输出预算一致，旧版模板保留供回查。第二版以 16,116 个输入字符向官方 deepseek-flash 派发一次，HTTP 200 并正常结束。回执报告输入 8,115、输出 3,519，合计 11,634 tokens。

模型给出了两套人设、四个场景、兜底、Jev 的说明和判据。它采用分组结构，普通文字字段普遍缺少所要求的来源编号。本地程序从同一份首次回执复核原话编号，每人恢复八条本人样例。基础人设可以从已有观察回填。缺少逐字段出处的候选文字另存，供用户核对并明确填入，生成或回放均不会把缺少出处的具体身份、职业、外貌当作已核实的事实。程序保留原回执、旧候选及本地重新校验的摘要。

作者已核准两人的人设、表达和场景／Jev 文案用于本地候选，A、B 各 18 个文案字段按人工确认保存。A 的 12 项及 B 的 11 项无出处扩展资料留待用户核实。两张实际角色卡在隔离结构 33 实例通过正式创建入口保存，重复请求返回原角色编号，两人均从空白会话开始。共通提示和五个场景可在人物资料预览，场景启用由使用者核对相应配置后选择。当时的审阅材料、私聊、首次返回及两张真实角色卡保存在本机审阅区。后续获准发行的三段通用提示词单独封装。

该次研发候选完成 163 项定向回归。Windows WebView2 在空实例和已有角色的结构 33 实例中分别走通原生窗口。浏览器检查覆盖宽窄窗口、八类恢复状态、逐字段人工确认和批量采纳角色文案。批量确认只处理人设和发言文案，缺少出处的基础资料仍可留空。角色资料允许回到对应草稿补全场景，并按当前版本重新确认启用。
