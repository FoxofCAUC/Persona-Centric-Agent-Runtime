## 1. 产品决策与新顺序

作者已经观察到：继续只调整主回复模型和外围工程，难以稳定达到期待的真人交流效果。新增一个独立的**表达改造环节**，专门把主模型已经完成的内容转化为角色实际说出口的话，覆盖语气、表达习惯、信息展开方式、气泡组织和节奏。工程正确服务于这一体验目标，最终收益由作者实际读感验收。

本方案使用“表达改造E0—E6”作为工作包标识，不占用原M10的导演与演化编号，也不回写M9/M9R结项为未完成。新主线为：

```text
M9／M9R完成
  → 召回优先级配套0—3
  → 消息输入、内部处理、主稿输出的阶段性封口
  → 表达改造E0—E6（本方案，G-AUTO前必做）
  → 工作台重写
  → 无人值守自动运行闭环收尾
  → G-AUTO当前桌面范围联合验收
  → M8.B/C → M10.A/B → M11
```

工作台重写在这里明确进入主线；它消费表达层已验收的接口，避免UI先定死气泡，再迫使表达机制迁就。E4只做现工作台最低限度的呈现适配，用于验证节奏与打断，不提前展开整套界面重写。

一键安装、完整多模态和QQ恢复继续各自规划。新表达环节是作者本轮新增的产品必需项；阶段完成后再准备G-AUTO，不能仅凭工程用例全绿跳过表达体验验收。

## 2. 对 MaiBot 的研究结论

### 2.1 可借鉴价值很高，但收益来自一组机制

MaiBot普通路径的核心不是单个“人性化开关”。它把回复意图、真实会话、角色表达、可用表达习惯交给独立Replyer，再经过后处理与发送。表达库支持从真实语言材料学习适用情境和说法，按当前场景选择少量候选，也允许不选。

这正好补足PCAR当前“主回复一次成稿”的局限。PCAR应最大程度复用这些已存在的组件、数据形状、选择逻辑和测试，再适配为自己的表达用途，而不是重新写一组更长的人设指令。

上游的实验性“超级创意”另有前级生成→后级翻译的两段调用、独立记录和发送前汇合，可作为后置再制的工程参考。但是普通Replyer并非通用答案润色器；把它整个挂在主稿后面，还会携带上游Planner、群聊历史、模型服务和全局配置依赖。

“仓库有实现、回归与评测工具”和“移植后更符合作者读感”是两件待分别证明的事实。本轮确认前者，后者由E1及E5验证。

### 2.2 复用优先级

| 机制 | PCAR采用方式 | 价值与必要适配 |
| --- | --- | --- |
| 情境—表达习惯资产、来源关联、去重与示例污染处理 | 优先抽取模块与对应测试；接PCAR来源及角色范围 | 高；能提供具体、可选择的语言经验，避免只有抽象“自然一点” |
| 表达候选检索、相关性／多样化、合法ID及空选择 | 复用纯计算和候选合同；小库先接现有本地检索 | 高；不同场景选不同说法，不强行塞口癖；大索引按实际规模扩展 |
| Replyer真实会话组织、私聊模板结构、风格装配 | 抽取并改造成独立表达适配器 | 高；保留PCAR角色身份、当前用户输入和已说内容，去掉上游人物默认值 |
| 前级正文→后级转换，独立attempt与用量记录 | 复用工作阶段设计与测试思路，接PCAR受管任务 | 高；允许主稿完成后独立再制，失败不重跑主模型 |
| LLM断句的“不拆分”、原文边界映射与重组检查 | 抽取纯处理逻辑与合同 | 高；保护表达稿到气泡的完整性；首选一次再制同时提出分段，不默认增加第三次模型调用 |
| 发送节奏、按成功发送登记效果 | 复用计算与反馈思想，接桌面呈现回执 | 中高；上游平台发送成功不能直接当桌面已呈现或用户已读 |
| 表达学习、审核及向量索引维护 | E2建设受限表达资产流程；复用筛选与来源机制 | 中高；不引入第二套人格／记忆权威库，不把自己的输出循环学成新习惯 |
| 超级创意的跨语言往返 | 只作为E1有限备选，不列首选默认 | 未证实PCAR收益；会额外增加调用且改变前级生成，和本次冻结目标有冲突 |
| Mai Replier专用模型适配 | 记录为独立可选方向 | 当前只支持官方DeepSeek生成；复用仓库不等于已配置专用模型或获准新增供应商 |

“最大复用”在E0形成具体上游文件、函数、版本、依赖和适配清单：能直接移植纯组件就移植；需要去全局依赖的先抽取适配；不另造一套功能等价但难以追踪上游的实现。每个未采用组件写清原因，不以“保持现状”为由把本环节缩成几条正则。

## 3. 阶段性封口与允许的改造范围

召回配套完成时，冻结当时已经验收的输入受理、消息身份、人物／会话范围、记忆来源、联网分工、任务账目和恢复语义；保存运行版本、数据结构、配置、回归集及可回退基线。此后到G-AUTO前不再为风格反复改这些内部业务规则。

表达改造是作者本轮明确批准的新扩展，因此在封口记录中预先列出以下接点：主稿持久回执、表达上下文投影、独立再制任务、实际发言事件、气泡呈现与回执。必要时可以拆分旧M至M9代码中的职责、替换输出组织流程、增加兼容数据结构；不要求沿用旧函数或旧气泡算法。

需要动到封口核心时，区分两类：

1. 本方案已列明的表达兼容改造：按独立补丁和定向回归实施，保持核心语义；属于本次排期范围。
2. 数据丢失／串角色、权限泄露、受理消息丢失、成功或未知调用重放等致命问题：立修复单，修复并重新关闭受影响项。不能把普通风格不满意、换算法或整理代码都归为致命问题。

E6后再次封口表达协议。工作台和无人值守开发只使用这些稳定接口；发现致命问题仍按上述流程处理。核心身份、作者设定、关系权威及后期长期演化继续由PCAR管理。

## 4. 建议架构：一个表达系统，首版一次再制调用

“Gate”可以作为内部名称，但职责是**表达再制与组织**，不是重新判断是否联网、裁决资料真伪或给主回复反复打分。

```text
用户输入 → 已封口的输入／召回／联网／主模型
                                      ↓
                              完整主稿回执落盘
                                      ↓
         获准角色表达设定 + 必要真实对话 + 已说原文 + 少量表达候选
                                      ↓
                        表达再制（独立DeepSeek用途）
                                      ↓
                    表达稿 + 分段建议 + 原稿追踪关系
                                      ↓
                    本地合同校验／保护片段／呈现计划
                                      ↓
               人物实际发言 → 桌面气泡 → 呈现回执 → 后续对话
```

首选主稿完成后一次表达模型调用，同时完成措辞、取舍、顺序和语义分段。候选预选优先复用本地能力，模型在再制时自行使用适合的候选。是否另加精细选择器或分句模型由E1消融结果决定，不默认形成选择→评分→重写→审核的长链。

可改：服务式开场和结束、机械复述、过度铺垫、信息展开顺序、转折、语气、句式、重复内容、气泡结构，以及结合当前互动的自然接话。认真任务可以充分展开，简短回应可以保持简短；模型可以决定原稿已经合适而少改或不改。

需保持：用户本轮实际任务、人物立场与关系边界、必要条件与否定、明确承诺、资料已取得／未取得状态、精确引用、代码／命令／公式及指定原样内容。删掉冗余不等于删掉必要答案。首版不让表达模型联网、写记忆、调用外部动作或改核心设定。

### 4.1 输入合同

下列是程序数据合同，具体字段名在E0冻结，不把本方案的研发解释直接塞入模型提示。

| 内容 | 要求 |
| --- | --- |
| 根交互身份、角色和范围、政策版本 | 继承原任务；表达用途权限由PCAR验证 |
| 主稿ID、原文及完成状态 | 接受完整且已保存的最终主稿；不把推理、签名、隐藏过程当正文 |
| 用户当前消息、必要真实对话 | 优先当前交流和实际已发言；不默认复制全历史或隐藏档案 |
| 角色表达投影 | 来自已获准可见的人设与表达层；不是另一套独立人格 |
| 已发查找前发言、呈现进度 | 避免再次说“我去查”或重复已说建议；不得改写已发内容 |
| 必要内容与保护片段 | 原稿中的代码、引用、命令、约定及当前任务要求；由现有任务资料和明确结构提取，不另调审核模型补造事实 |
| 表达候选及版本 | 每条有来源、适用语境、角色范围、状态，可为空 |

用户并未要求“仅正文”输入。若不给必要语境，再制层无法可靠知道反讽对象、亲疏、已回应内容和角色差异。仍坚持最小必要授权范围；跨模型用途授权沿用明确合同，不能暗中扩大资料范围。

### 4.2 输出、气泡与时序

输出保存完整表达稿及可还原的气泡计划。每个气泡有稳定身份、顺序、正文类型、与完整表达稿的对应关系，以及是否为可取消补充；需要时附程序解释的节奏建议。运输层JSON不显示给用户。

借鉴MaiBot分句映射，把分段结果还原为表达稿原始片段，防止分句步骤再次改写内容。代码、公式、逐字引用和必须整体阅读的内容可保持整块。已取得可独立确认的完整表达稿、仅分段或呈现计划校验失败时，用该表达稿单块呈现。若整个输出合同／运输JSON无法解析，则按第6.2节降级已保存主稿，不能把原始包体、内部字段或模型前言直接显示给用户。不丢尾段、不按固定字数截断。

字数、句号数、问号数、错字率和固定气泡数均不作为自然度目标。模型输出容量、UI承载和等待范围是工程预算，不是每轮必须满足的说话模板。

现工作台目前在完成后一次插入全部消息，不能直接实现节奏。E4新增可恢复的桌面呈现队列：先显示首条，后续按计划呈现；新输入到来时，只撤销尚未呈现且确属可省略的补充。用户要求的必要回答不能随意取消。重开会话展示历史不再次模拟打字，切换角色不把旧角色队列投到新角色。

节奏避免把模型已花费的等待再完整叠加一遍；从实际就绪时点计量，快速可读和自然停顿一起评估。呈现回执只证明应用已显示，不冒充用户已读。

### 4.3 联网前发言

保持Jev判web后、真正开始搜索前先由人物接话的既有顺序。首版把表达资产及选材机制用于这次原有生成，主稿再制接收其已说原文；不默认给查找前发言再串一次收费改写，使搜索迟迟不开始。

如果E5发现预告与查后口吻明显脱节，再单列候选比较该短发言的表达适配，费用、延迟和取消语义一起验收。不能用固定台词取代，也不能为“已经说过了”而重写历史。

## 5. 表达资产：借鉴习惯，不复制人格

E2优先建立角色可控的表达资产：作者提供或获准的公开材料、人工创作样例、用户明确授权的学习范围。抽取“适用情境—表达方式—原始来源—角色范围—版本／状态”，借鉴MaiBot来源ID校验、SELF排除、去重及提示示例污染处理。

允许学习停顿、接话方式、简略程度、幽默手法和具体表达习惯。不能把材料中的真实姓名、私事、关系、立场或作者身份变成本角色经历，也不能默认所有人物共用同一口癖。用户更正、禁用或撤回某来源时，资产及派生索引一并失效。

第一版采用固定版本资产做实验，再启用受限学习；不要求用户逐轮审批。授权范围内的普通学习可由既有后台计划分批处理，表达候选的质量过滤与当前人格兼容检查在资产流程中完成，不成为每轮回复的审核长链。

主稿、再制稿、自己的历史回复、维护摘要和测试答案都不能循环变成新的独立学习样本。表达库更新不是人格演化；后续Director仍按G-AUTO之后的规划。

已有本地Embedding可用于候选缩小，不为小表达库先搬入上游全部向量服务。真正需要大规模索引时，再抽取其不可变代、原子发布及损坏恢复能力；PCAR仍是角色、来源和权限的唯一权威。

## 6. 恢复、账目与记忆消费

### 6.1 必须先持久主稿

E3前，PCAR主模型成功后才在后段提交人物事件；生成账目已有状态／指纹，但新增Gate前缺少可恢复的完整主稿。直接插入第二次模型调用，会在Gate失败时陷入“主调用成功禁止重放、原稿却不足以继续”的缺口。E3现已通过供应商任务内的完整回执保存接点补齐，见本阶段验收记录。

新增完整主稿回执后再启动表达阶段。状态至少可区分：主稿已保存、表达准备／派发、表达成功／已知失败／未知／取消、呈现待发／部分已发／完成。表达输入、模型、资产和政策均冻结；崩溃恢复只从已有回执推进。

既有“成功或未知物理调用不重放”继续有效。本轮新增的表达调用是预先定义、独立记账的新产品阶段，不是把成功主调用换编号再跑。人工验收比较也明确登记新的表达位置，原主稿只读复用。

### 6.2 失败策略

首版默认：Gate明确失败或结果不可用，且尚无任何表达内容呈现时，采用已有完整主稿走原v8呈现作为有记录的降级；不重新调用主模型。Gate结果未知先保留原attempt并停止自动重发；若同轮决定降级发布主稿，使用单一发布权封口，迟到Gate结果只入证据，不再发第二份。

表达稿已成功但分段失败时，只回退到该表达稿的完整呈现。已经呈现部分内容时，保留已发边界，不能改用另一份整稿从头发送。取消、来源撤回或权限变化优先终止未派发／未呈现部分，不能借降级绕过当前权限。

禁止在线反复“重写到像真人为止”。已知传输失败沿既有有界政策处理；成功但读感欠佳留给固定对照与后续版本改进。

### 6.3 记忆与费用

分别保存：主稿证据、表达产物、实际人物发言、呈现状态。后续聊天应接续用户真正看到的表达，不能用户看见B、系统却把未说出口的A当共同经历。完整表达稿保存不等于全稿已经说出口；新输入到来时，历史快照只纳入当时具有桌面呈现回执的片段。生成完成与呈现完成分别记录，未呈现、取消及未知内容保留任务状态，不自动写成已交流事实。

一次根交互中主模型与表达层使用同一记忆，沿召回配套的消费身份合并结算，不双倍强化；不同气泡也不产生多个独立记忆。表达改写不增加来源独立性，不能凭自己说过就把内容认定为用户事实。

主回复、查找前发言、原生检索、表达生成、可选表达选择／分句及学习调用分别记账，未知不填0。默认增量为每个主回复一个表达请求；本地候选和本地呈现不新增云调用。报告首次可见等待、完整回复等待、tokens与费用增量，不预先宣称更快或更省钱。

## 8. 体验验证方案

### 8.1 比较设计

先用获准公开人工主稿建立24个开发场景：闲聊、安慰、玩笑、不同角色同题、关系边界、更正、联网后追问、代码／引用、详细步骤和无需多说。复用完整原稿，所有候选面对同样用户语境与角色快照。

比较A原v8、B仅分段／节奏、C表达再制＋表达资产＋分段，判断收益究竟来自措辞还是气泡。再在8个固定诊断场景比较C与关闭表达资产的再制，辨认表达库的贡献；不把多种变化的总成绩直接归于某个算法。

实现时先离线和模拟，E1最多准备24＋8个新的表达生成位置；若B使用LLM分句则额外最多24个位置并单列账目，默认本地B不收费。实际供应商和价格在E0核对，调用失败预算及停止规则一并冻结；不因效果不佳追加同题抽样挑最好。

开发样本选型后，E5用12个未参与调参的场景及两段各15轮的连续新对话检查迁移效果。该数量是本方案建议的有限首批规模，不足以声称长期体验已经证明；最终结合作者审阅和实际缺口安排必要补验。

### 8.2 评价与准出

自然度看整体：是否愿意继续聊、是否听懂当前互动、角色口吻是否稳定、是否仍像客服模板、是否乱塞梗／装熟、详略是否合适、气泡是否帮忙而不是打扰。随机隐藏方案名，允许“都不好”和“没有区别”，保存作者逐例理由。

“没有Markdown”“比较短”“气泡较多”只能描述现象，不能替代体验通过。机器分数若使用只做辅助，不能盖过作者明确不满意。工程零关键缺陷、开发／新场景整体有收益、连续使用作者通过，三者同时成立才能E6结项。

工程测试重点：主稿成功后崩溃、表达派发前后中断、未知与迟到、降级发布竞争、部分呈现后新输入、角色切换、关闭与重启、来源撤回、保护片段、表达资产跨角色污染、双倍记忆强化、账目遗漏。语义保持测试检查固定材料中的必要条件／否定／承诺和代码引用，不恢复在线逐数字或来源权威审判链。

若C的收益不足，先定位是候选资产、上下文装配、模型表达能力还是呈现节奏；只替换有证据的问题组件。可在作者允许的工作流兼容范围内重组表达层，不能靠降低验收标准宣布成功。
