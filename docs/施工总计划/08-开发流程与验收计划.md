## 1. 每次开发的输入和交付

先读 AGENTS、STATUS、HANDOFF、本套相关规范和当前代码。锁定实际基线提交及本地未提交改动，核对任务是否仍处在当前阶段。按“一个可验证能力/迁移/协议变更”拆分提交，不为了整套未来设计一次性重写全部 Runtime。

每个任务至少交付：问题与目标、当前代码证据、接口/状态/字段变化、数据迁移与兼容、预算/授权影响、故障处理、实际测试结果、未执行项、界面手册与下一步。复杂设计用 ADR 写清背景、决定、替代方案、迁移和回退；日常小修不强制大文档。

测试以公开合同与真实风险为对象：并发封批、来源撤回、部分发送、旧格式、版本冲突和迁移需要测试；纯文档措辞或低影响展示变化不写镜像测试。本套计划只做文档验证，**未重跑运行时测试**。

## 2. 分支、提交和审阅

当前远程只有可见 main，无现成开发分支。实施任务可按仓库约定新建短期 feature 分支；名称由实际任务确定，不在本计划假装已有。仓库未设根许可证，外部代码复制先走许可登记。用户未要求时不自行发布 Release、合并 PR 或推送运行数据。

建议拆分顺序：数据合同/迁移→读取兼容与服务接口→调度/投递→UI→故障验证与手册。每次提交保持可检查；迁移、核心和桥接互相依赖时明确最小部署组合，不留下会双发的中间版本。

审阅重点：是否新增第二权威写入、是否全入口执行同一政策、是否扩大自动付费/自动写入、是否遗漏批次非首条来源、是否能在失败状态恢复、是否把派生结果写成事实、是否误变默认模式。

## 3. 授权与操作边界

继承 AGENTS 最新有效规则：用户已允许开发全流程使用已配置的真实付费模型，并允许工作台代表 QQ 业务入口验收；不因旧规划“需本次授权”反复询问。仍遵守现有限额、用途和证据；不能据此新增供应商账户、抬高预算、猜模型名或默认启用自主搜索/主动发消息。

真实 QQ 扫码/登录等需要用户参与时暂停该项；连续模型失败第五次可保守停止，明确 QQ 掉线/退出等服务中断立即停止等待恢复。单项失败记录后不盲重试。适用范围是已授权验收，不意味着运行时自动重试政策改变。

本次编制计划没有发起真实模型、QQ 收发、服务启停或正式库迁移。后续实施可自主完成已授权的隔离代码、可逆修改与检查；需要用户决定的仅保留会改变默认体验、扩大持久写入/对外行为或缺少必要信息的事项，见决策登记。

## 4. 测试层级与证据

| 层级 | 能证明 | 不能代替 |
| --- | --- | --- |
| 静态合同/文档检查 | 链接、字段、状态与代码对照 | 实现已运行或真实模型质量 |
| 单元/可控时钟 | 分批/状态/排序/权限等确定性逻辑 | 真实等待、用户输入节奏、24小时 |
| 隔离集成 | HTTP、SQLite、适配器和恢复组合 | 正式库部署、真实 QQ 到达 |
| 真实模型验收 | 指定模型在指定样例下的生成与费用证据 | 全局自然度、跨模型绝对一致 |
| 工作台真实操作 | 实际按钮、保存/错误、业务入口流程 | QQ 实际网络收发和用户已读 |
| 实际 QQ 验收 | 指定账号/好友的接收与平台投递 | 所有联系人、多设备或长期可用 |
| 长时与迁移演练 | 实际环境的一段运行及数据恢复 | 未执行时段、未来所有故障 |

运行器当前为 `scripts/test.ps1`，实际调用 D 盘 Python 的 `-B -m unittest discover -s tests -v`。测试准备与缓存路径遵循项目 D 盘规则，禁止把测试库指向正式数据库。需要新增组时沿用现有 unittest/模拟 Model 与 Fake QQ 结构，不无理由更换测试框架。

现有九文件覆盖 M1–M5 与 UI/集成/紧急停止/NapCat 配置。M3 基准和 M4 固定 8 例检索评估可作旧基线，不足以证明新的自然度/语义召回已达标。新阶段用针对性回归后再执行一次必要全量；无新增变更和失败时不重复跑相同全量。

## 7. 质量评估集与门槛

### 确定性硬门

所有已定义的幂等、权限、时间过滤、来源失效、顺序、迁移完整性和版本并发用例必须通过；数据丢失、跨域泄露、虚假原文引用、自动重复收费和误投递出现一例即阻断发布。固定精确 ID 集要求 100% 正确命中或正确不可访问/不存在，不得以总体检索得分抵消。

### 检索评估

首轮建议建立至少 100 个脱敏或合成 query/证据标注对，覆盖精确、时间、中文专名、近义、无答案、纠错、跨 Session。区分开发集和保留集，固定同一档案快照比较规则召回、FTS 和混合；不把多问法高度重复样本当独立规模。

初始目标建议：有答案的非精确检索 Recall@10≥0.85、Precision@5≥0.70；无答案样本错误给出确定证据比例≤0.05。它们是本计划验收起点，不是已测结果或普适标准。M7.0 先报告旧基线与样本难度，再冻结最终门槛；不能看完结果后为过关随意降标准。Thread 候选关联首版精确率优先，建议保留集有效链接 Precision≥0.95，覆盖不足可保留待审但必须报告。

### 活人感与角色一致性

建议约 100 个单人私聊情境，覆盖闲聊、调侃、求助、情绪表达、反讽、指代、纠错、连续短消息、旧话题、角色事实和技术回答。同一角色/模型/上下文控制 A/B，打乱顺序盲评：回应是否切题、语气是否合适、是否客服套话、是否过度追问/附和、事实与角色是否一致、技术内容是否完整。

机器可辅助标注，不能独自证明用户主观体验；已授权机器验收可先给可复现评分和实际样例，主观偏好仍由用户反馈校准。发布初始建议：成对比较新版本不劣于旧版比例≥80%，无重大事实/角色错误；报告胜/平/负和样本数，不仅一个总均分。所有百分比都标明评估者与方法，不吹成群体统计结论。

### 延迟、成本与资源

分别报告缓冲、排队、上下文、生成、首段发送、末段确认的 P50/P95；同时记录输入消息数、逻辑 turn 数、模型 attempts、token、用量缺失、后台 calls 和磁盘/内存。静默五秒带来有意等待，不许以“模型速度未变”隐藏总延迟。

初版确定性定时测试允许≤100 ms 的调度误差目标；实际机器定时抖动单列，不能假定真实环境满足。对非缓冲运行开销，先测 M5 基线，M6.0 冻结硬件与回归预算。成本比较以相同完整语义任务为分母，不能按原始条数不同做虚假节省。usage 不全时费用写未知，不估成零。

## 8. 迁移和恢复演练

1. 记录版本/解释器/配置 hash，读取旧库 schema 与数据统计；验证备份能打开和通过完整性/外键检查。
2. 在 D 盘隔离副本升级，检查每张旧表的主键、原列逐行内容摘要、来源关系和导出结果；新表计数单列。
3. 注入事务中断、缺磁盘/权限、旧版本不兼容、部分回填失败，验证不留下“表新、version旧”或相反状态。
4. 新应用读取旧历史、旧 PersonaSpec、旧 delivery；旧应用读取新库必须按支持范围明确拒绝，不能猜兼容。
5. 正式部署按归属核对停止写入，持实例锁，备份，事务迁移；恢复时还原一致数据库与必要配置，不复制单表掩盖 schema 不兼容。
6. 新功能开关回退后验证旧路径；已经创建的批次/片段仍要有新应用可读的清理/继续方案，不能用旧程序丢弃。
7. 记录迁移前后证据及恢复演练结果。真实数据库/聊天/ID 不入 Git，脱敏总结和通用手册可入库。

不修改 `D:\QQ_Bot_2` 或其他 TRPG 项目。正常停止不接管未知端口；紧急强停是既有独立入口，绝不作为普通测试步骤自动调用。

## 9. 阶段验收手册与记录模板

每次阶段交付仍在 `docs/acceptance/` 提供 `.md` 操作手册并更新索引，依据真实界面按钮编写，不预先杜撰按钮。按现有“阶段真人验收手册模板”保留真人/机器可执行属性；本次施工规范不是已经存在的新 UI 手册。

单项记录格式：

| 字段 | 内容 |
| --- | --- |
| 用例ID/版本/提交 | 固定版本与入口 |
| 前置条件 | 隔离数据、角色/模型已配置、账号/额度和开关 |
| 操作 | 实际按钮路径、可复制虚构消息、等待/故障注入 |
| 期望 | 可观察状态、数据、调用数与恢复结果 |
| 实际 | passed / failed / skipped / blocked，禁止预填通过 |
| 证据 | D盘本机路径、截图/JSON/账本，不带凭据 |
| 成本 | 尝试数/usage/金额已知或未知 |
| 收尾 | 恢复设置、测试角色、任务/服务状态及残留 |

每阶段收尾需明确必测是否通过、可选/条件项为什么跳过、缺陷是否闭环、上线默认是否变化。未达到的发布门保持阻断；不相关可选项可延期，但进入 HANDOFF。
