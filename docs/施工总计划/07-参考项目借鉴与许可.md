## 3. 即时交互参考：学习点和不采用内容

### MaiBot

已读固定版本的 [防抖控制器](https://github.com/Mai-with-u/MaiBot/blob/062d45cf8bd4272ac57d7ec03fcf405e5a458211/src/chat/debounce/controller.py)、[规则说明](https://github.com/Mai-with-u/MaiBot/blob/062d45cf8bd4272ac57d7ec03fcf405e5a458211/src/chat/debounce/README.md) 与 message_adapter.py，并检查 chat_loop_service.py 入口。

可借鉴纯计时控制器、单调时间、批次等待硬上限、变更事件唤醒。它的自然档有安静开批 2 秒、活跃开批 5 秒、同人续发 2 秒，整批上限 8 秒；这些是该版本参数，PCAR 初始五秒静默/十五秒硬上限来自自己的讨论方案，不能混称为同一实现。防抖上限不等于模型回复耗时保证。

不照搬群聊换人/@/图片规则；PCAR 当前只有单用户文本私聊，也不采用其“模型忙碌时继续消费同一上下文缓存”替代本计划的不可变封批。GPL 来源若直接移植需先处理适用许可；优先按本计划合同独立实现并记录思想来源，不逐行翻译后伪称独立原创。

## 6. 复用方式和合规门

允许三种明确记录的方式：学习公开设计后独立实现；抽出许可允许的小型纯函数并改造；引入有边界的第三方依赖。三者都先说明为何比本地实现更省维护成本，不能为了复用某个插件而让 PCAR 反向迁就其数据库/事件模型。

- MIT：采用代码时保留版权和许可声明，记录改动、来源和文件范围。
- Apache-2.0：按许可核对全文、版权/变更声明及适用 NOTICE，检查文件级例外；不要只保存 SPDX 字符串。
- GPL/AGPL：若复制或改造受覆盖代码，需先确定拟分发/提供服务形式与 PCAR 整体许可兼容方案；不能把“自用”当作以后公开分发的豁免，也不能认为 Python 改写或伪代码逐行翻译天然消除义务。具体范围以实际组合和许可为准。
- 许可不明：不复制、不分发，保留研究清单，取得可验证授权或换实现。
- 资源/数据/模型：代码、权重、表情、角色文本和真实语料分别核对，仓库总许可不能一概覆盖第三方内容。

现有 AstrBot 作为独立组件经薄桥接调用，与把其内部 AGPL 代码复制进 Runtime 是不同技术动作；两者都应按实际依赖和发布范围记录，不在此作笼统“天然兼容”结论。
