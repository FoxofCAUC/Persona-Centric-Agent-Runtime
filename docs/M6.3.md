## 已实现

- 模型回复完成时，同一数据库事务保存 ReplyBatch、语义段、QQ 传输片段与待投递记录。默认每 450 字一个传输片段，段号指向原语义段。
- 同一人格/用户/QQ Bot/联系人共享有序投递 stream，防止跨批次乱序；其他身份无法读取或领取。
- 桥接每次领取使用独立操作号；不同实例在同一修订并发领取时，CAS 只允许一个成功。若看到片段已处于 `sending`，桥接不重放发送；超时或进程恢复后由服务将其置为 `uncertain`。
- SQLite 写事务串行化领取；每片独立修订号、claim token、hash、平台消息 ID和发送时间。独立尝试表逐次记录状态、attempt序号、结果、平台消息 ID、错误及起止时间；token失效时迟到结果被拒绝。
- 重启把 `sending` 改为 `uncertain`；uncertain 不自动重发，并阻塞本 stream 后续自动发送。显式重试仅重发单片并增加 attempt；跳过只作用于当前回复批次余段。
- 桥接 0.5.0 按健康能力选择协议。后台投递循环逐片发送、保存平台返回 ID；旧 turn API 不会领取已有 M6.3 账本的回复。
- 工作台增加回复投递列表、片段状态、尝试次数、消息 ID、内容/哈希与显式核对、跳过、暂停/释放和可能重复重发操作。
- 结构 9→10 迁移保持事务及升级前备份；旧数据不回填虚构投递记录。导出格式 7 包含账本/处置审计，清除 claim token，不携带模型凭据。
