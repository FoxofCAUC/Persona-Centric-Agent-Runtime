# SnowCat 持续跟踪与 QQ 恢复开发指导

采纳日期：2026-11-15。状态：公开进展跟踪已安排，QQ专项开发及实际接入仍暂停，待作者明确批准后以SnowCat恢复支持。

作者本轮补充的背景为：受腾讯政策及律师函影响，SnowLuma转为私有、NapCat删库或停止原有公开维护，两条既有路径已无法作为稳定支持基础；社区SnowCat接续两者能力。上述上游事件作为作者提供的方向调整依据，持续跟踪时按可取得的上游公告核对，不以单次404推断删库、私有或法律事件。

## 1 已确定的项目与当前观察基线

跟踪对象固定为[DandanLLab/SnowCatQQ](https://github.com/DandanLLab/SnowCatQQ)，避免与其他同名Snowcat项目混淆。它作为QQ客户端与协议连接候选，PCAR继续持有人格、记忆和业务权威；不因上游推荐其自身智能体生态而替换PCAR。

## 2 持续跟踪范围

已设置每天北京时间09:00跟踪公开进展。日常检查和比较记录保存在本机所选数据目录的`private/monitoring/snowcat-progress.json`，不把每次无变化检查提交到源码仓库。跟踪任务不修改正式配置、不自动提交推送、不在上游发表评论。

| 关注项 | 对PCAR的意义 |
| --- | --- |
| 仓库公开性、归档、停维、迁址与维护者公告 | 判断候选项目是否仍可持续获取和维护 |
| Release、标签、默认分支与可下载包 | 区分已发布能力和仅在主分支出现的变化，固定可评审版本 |
| QQ和Windows支持版本、启动与崩溃修复 | 确定后续隔离部署的可复现环境 |
| OneBot v12、v11兼容及Milky变更 | 评估PCAR现有OneBot v11／AstrBot桥接是否可复用，是否需局部适配 |
| 私聊、引用、消息标识、断线恢复和发送回执 | 保持PCAR的去重、来源、连续聊天和不确定投递行为 |
| 已证实故障、公开账号受限信息、维护政策及许可变化 | 为作者决定是否恢复提供具体材料，用户报告与维护者确认分开 |

报告聚焦会改变PCAR接入判断的实质变化，附日期、来源、影响范围和待验证项。星数、宣传口号、戏谑Issue或单次访问失败不作为成熟度结论。无法核实时保留上次有效基线并记录本次缺口，不把旧资料写成最新验证。

## 3 恢复开发的授权与范围

**当前授权覆盖公开资料跟踪与开发指导维护；QQ专项实施仍须作者明确批准。** SnowCat更新、自动跟踪运行、普通“继续开发”或M9R通过都不自动恢复QQ。

批准前可完成可评审的兼容性分析，明确拟采用的SnowCat提交／发行版、QQ版本、协议、最小改动、账号使用范围、验收与回退方案。不得安装运行、扫码登录、启动QQ组件或发送测试消息。

作者批准恢复后，按已批准范围连续推进，不为同一已经授权的步骤重复索取批准。首先只恢复本人好友纯文本私聊和必要引用，沿用现有身份、消息、记忆、授权与投递机制；群聊、多联系人、主动外发及上游额外动作不因客户端具备而自动开放。

SnowCat对外声明MCP能力，不等于需要向聊天模型开放全部QQ动作。优先研究既有OneBot桥接的最小接入；若v11兼容退役或不能满足要求，再比较协议适配方案。QQ的渠道选择不改变“云端模型仅DeepSeek、Jev判断例外”的研发原则。

## 4 批准后的实施顺序

| 步骤 | 交付与退出条件 |
| --- | --- |
| 固定接入合同 | 确定提交／发行、QQ和Windows版本、协议及许可边界；对照当前PCAR消息与生命周期合同 |
| 隔离部署和连接 | 按批准的账号范围建立独立验证环境；确认真实版本、连接身份、鉴权、私聊收发与回执 |
| 复用现有业务链 | 接入现有人格、Jev／DeepSeek、记忆和上下文；客户端只负责渠道，不复制新的人格存储 |
| 定向故障与体验验收 | 验证引用、去重、分段、不确定发送、断线、重启与正常退出；未知片段不重发，人物文本由用户审阅 |
| 正式启用与交付 | 在批准范围内切换，更新配置迁移和操作手册；失败能停用候选并继续使用工作台，发布按当次授权 |

这是一项独立的“QQ恢复／SnowCat”工作包，不占用原M阶段编号，不阻塞M9R桌面主线。G-AUTO当前仍按桌面适用范围组织；QQ恢复后补充该渠道的联合验收，不能把旧QQ通过记录直接算作SnowCat通过。
