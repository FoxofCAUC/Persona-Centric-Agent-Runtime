# 项目目标与开发路线：私聊陪伴优先

修订日期：2026-10-26。依据：用户明确要求将主要开发重心放在高完成度的私聊服务上，群聊复杂且不是 AI 伴侣的重点。

本文件替代此前“完成 M2 后优先开发群聊”的路线。M1/M2 已实现及通过验收的结论保留；下述 M3 以后均为待开发规划，不代表功能已经上线，也不自动启用额外模型调用。

## 1. 产品目标

为同一位用户提供一个能长期相处的 AI 朋友：人格稳定、交流自然，记得重要经历与关系变化，能够接上长时间跨度的交流；出现错误时可以解释、纠正和恢复。

“人格中心”保持不变：人格、经历、关系和知识属于运行时，模型负责不同能力，换模型不应变成另一个人。多模型分工服务于效果、成本和可维护性，不以增加模型数量或 Agent 数量作为阶段成果。

主要使用入口为本人 QQ 好友私聊与本地工作台。两者延续同一人格，长期记忆共享，近期会话继续分别保存；是否增加显式跨入口接续，由后续独立需求决定，不默认混合。

### 高完成度的具体含义

| 维度 | 可验证的目标 |
| --- | --- |
| 记忆 | 重要事实和经历有来源、能被适时召回，错误可纠正，撤回后不被后台重新写回 |
| 连续性 | 长对话、隔天交流、换会话、重启和换模型后仍保持人格及已确认经历 |
| 表达与关系 | 表达风格稳定、自然，关系变化来自实际互动，不编造共同经历或把猜测当事实 |
| 私聊体验 | 连续发消息、等待、取消、失败与重试行为清楚，不重复回复，不悄悄漏接 |
| 可控性 | 能查看记住了什么、为何记住、用了什么；后台整理和前台聊天都有明确预算与开关 |
| 可靠性 | 正常启停、备份恢复、升级及长期运行可验证，数据和凭据继续优先保存在 D 盘 |

不能只用“模型成功返回文本”或一次愉快聊天判定整个产品完成。

## 2. 范围调整

- **主线**：本人私聊、长对话连续性、记忆整理、人格与关系维护、交互体验、长期可靠性。
- **后续增强**：有来源的世界知识补充、按需搜索，以及用户确有需要时的语音、图片等输入输出。
- **退出主线**：群聊、多参与者权限、群间信息共享、群发言决策、其他联系人私聊和社交网络模拟。不给这些能力预留主线里程碑，也不为了它们提前重构身份系统。
- **保持关闭**：未授权联系人及群消息继续被当前入口拒绝；本次路线调整不更改任何运行权限。
- **保留扩展点**：继续维护渠道适配器和业务分层；保留旧群聊准备文档为历史参考，但不执行其中的策略。

自动记忆不是模型训练或权重更新；本路线中的长期变化首先通过有来源的存储、检索、版本和上下文实现。

## 3. 重新编排的里程碑

用户已进一步明确：**M3 优先私聊体验与稳定性，重点是响应速度、连续发消息和失败恢复。** 据此调整如下。每阶段应独立可用、独立验收，不把所有“成长”能力一次性塞进 M3。

| 阶段 | 主目标 | 主要交付 | 退出条件 |
| --- | --- | --- | --- |
| M0–M2（已完成） | 可用的单人私聊底座 | 人格与显式记忆持久化、窗口/本人 QQ 对话、独立工作台、启停与恢复 | 已由用户确认 M2 真人全流程通过；保留回归基线 |
| M3（下一阶段，优先级已确认） | 私聊体验与稳定性 | 分段耗时与状态观测、连续消息处理、等待与取消、失败恢复、QQ 分段与投递体验 | 连续消息不漏接或错序；等待原因可见；失败可恢复而不重复生成/投递；按实测基线评估延迟改进 |
| M4 | 长期记忆与长对话连续性 | 会话摘要、带来源的候选记忆、审阅纠错、可重建召回及独立后台预算 | 新会话能用已确认记忆；长对话不只依赖最近 20 条事件；修订/撤回/重启不丢失或复活错误记忆 |
| M5 | 稳定而自然的人格与关系 | 人格核心/可变状态分离、表达校准、共同经历与关系更新候选、版本恢复 | 多种私聊情境下风格连续；换模型仍维持身份；关系更新有真实依据且可撤销，并完成文本私聊版本联合验收 |
| M6 | 可信世界知识与按需学习 | 本地知识补充、显式搜索、来源时间与失效管理、知识冲突处理 | 常见已存知识无需重复搜索；新信息可追溯和纠错，不污染私人经历或人格设定 |
| 后续可选 | 陪伴方式扩展 | 在需求明确后选择语音、图片、主动问候或其他单项能力 | 每项另定授权、成本、交互及验收，不默认捆绑发布 |

私聊的阻断性缺陷不推迟到后续阶段：任何阶段发现漏接、重复投递、丢数据、弹窗无法保存或服务不可恢复，应优先修复后再继续该阶段。M3 的稳定性结果是 M4–M6 的持续回归门槛。

## 4. 各阶段的开发切分

### M3：先让私聊顺畅且可靠

1. 为短时间连续消息确定“逐条回复或显式合并”的规则，保持原始事件和可见结果，不能静默丢消息。
2. 整理等待提示、取消、超时、重试和投递状态；窗口是否逐步显示与 QQ 是否完整生成后分段发送分别设计，不拿窗口的部分文本充当已成功投递。
3. 提供适合普通用户的诊断和备份恢复引导，完成隔离环境升级/回退演练。
4. 先采集基线，再约定响应、失败恢复、费用和持续运行标准；不预先承诺未测得的毫秒响应或零错误率。

详细起点和开发拆分见 [M3 开发准备](M3-开发准备.md)。模型本身的生成速度、窗口首字出现和 QQ 最终送达分别测量，不能以“请求已受理”冒充对话已经完成。

主动问候和自主发起私聊不作为普通回复优化自动加入；需要单独约定开启方式、静默时段和频率。

### M4：从“手动记忆”走向可管理的长期记忆

按“可观察的数据合同 → 会话摘要 → 候选提取 → 审阅写入与纠错 → 召回评估”实施。首版建议自动生成候选、人工确认生效，不让提取模型直接覆盖既有正式记忆。
基于 M3 的后台任务状态、预算与恢复能力开展，不把记忆整理塞进每次回复的阻塞路径。自动生效规则、批处理频率、处理历史范围和后台预算属于实现前待确认项，不由本文件直接开启。

### M5：从“有设定”走向稳定的人格与关系

1. 将稳定核心、表达习惯、当下状态、共同经历和关系说明分层，不让临时情绪改写核心人格。
2. 增加人格设定的版本管理与同一身份的显式修订；仍保留“导入全新人格”的原行为，不能把它悄悄改成覆盖。
3. 让关系或偏好变化形成带证据的候选更新，支持审阅和回退。对话策略不依赖简单的好感度数值替代实际经历。
4. 建立重复问答、话题切换、意见不同、记错后纠正和隔天续聊等对照场景，由用户评价自然度及一致性。
5. 联合复验 M3 的长期运行稳定性与 M4 的长对话/记忆能力，形成高完成度的文本私聊版本，再投入知识增强。

M5 不默认允许人格自行修改不可变核心，不把模型自述、虚构背景或提议自动登记为已发生的共同经历。

### M6：让知识增长有依据

优先补充紧凑、可检索、可更新的本地知识；再做按需搜索与新知识入库。区分长期常识、时效信息、用户资料、共同经历和不确定推测。
先验证有来源的导入、过时和更正，再决定是否需要热点订阅；不因“自主更新”默认启用持续爬取、大规模下载或无限后台调用。

## 5. 全阶段通用流程

1. **锁定问题**：明确本阶段要改善的私聊体验和不做的内容，读取当前交接与上一阶段收尾。
2. **形成实现计划**：列出接口、存储变化、兼容/预算与会改变用户体验的选择；未确认的自动化策略继续保留关闭。
3. **独立实现与回归**：复用已验收能力，先在 D 盘隔离数据上测试；迁移前备份，保留已有本人身份、人格和历史。
4. **交付真人手册**：在 `docs/acceptance/` 提供实际按钮、复制消息、通过标准、失败处理及结果表，不以设计文档替代操作手册。
5. **用户真人验收**：实际结果和截图留在 D 盘，区分模型表现与数据事实，不把未执行项记成通过。
6. **阶段收尾**：记录版本、真实缺陷闭环、剩余边界及下一阶段起点，再进入下一阶段。

M3 以后仍保留 M2 的全部回归和真人验收基线；新功能不得以牺牲现有可用私聊为代价。

## 6. 当前决定与待确认内容

**已由本次用户要求确定**：私聊陪伴是主线，群聊退出 M3 及后续主要里程碑；M3 优先响应速度、连续消息和失败恢复；当前 M2 已验收，不重做、不清库。

**本次提出的后续切分**：M4 补记忆和连续性，M5 做人格与关系及文本版联合验收，M6 做可信知识。实施前仍需阶段级设计，尤其是连续消息合并、取消、自动写入、额外调用和主动行为。

本文件记录目标与阶段顺序，具体工程合同在相应阶段实现计划中冻结；尚未选择的策略不自动写入运行配置，也不把群聊重新作为任何阶段的前置条件。
