## 1. 目标与当前缺口

在窗口和本人QQ私聊中，使同一人格的身份、表达与关系随长对话、换会话、换模型和重启保持连续；需要改变时能明确查看、批准、更正和回退。

当前已存在人格设定中的名称、自我介绍、特征、表达习惯、价值边界和初始背景，以及显式关系说明、长期记忆和来源摘要。代码核对的缺口：

- `PersonaSpec`仍为格式1，设定创建后没有同一身份的编辑版本链；导入一直创建新UUID。
- 关系说明通过业务服务直接覆盖当前文字，尚无单独的关系版本和回退。
- 前台已记录记忆/摘要使用，但未记录独立的人格与关系版本，也没有可变状态的有效期。
- 日常表达依赖当前设定和模型，尚未建立跨模型、一致性与自然度的成组验收。

M5首先做好“明确设定与可控变化”，不以好感度条替代关系、不把模型自述或虚构背景当成真实共同经历。仍不开放群聊、其他联系人、主动问候、联网搜索、语音或图片。

## 2. 建议的分层合同

| 层次 | M5建议责任与边界 |
| --- | --- |
| 身份 | 人格UUID持续不变；模板/JSON导入仍为新身份，不合并或继承历史 |
| 核心设定 | 背景、价值与边界等显式版本；只由用户明确修改，不由每日记忆任务改写 |
| 表达设定 | 语言风格、篇幅、称呼等独立可解释的设置；避免靠一句提示强制所有情境相同语气 |
| 可变状态 | 当下状态及有效期，与稳定核心分开；来源、修改人和到期行为可查 |
| 关系 | 当前显式关系、称呼及边界版本；变化保留证据、审阅与撤销历史 |
| 经历和记忆 | 继续复用M4来源、有效版本和屏蔽策略；不能复制出另一套无来源的“人格经历”事实库 |

回退人格或关系版本只改变后续使用的设定，不删除已经发生的聊天，也不自动恢复被撤回记忆。恢复旧设定时仍执行当前记忆有效性和来源屏蔽规则。

M4每日自动生效授权仅用于既定记忆类别；不延伸为自动改变人格核心、关系标签、称呼规则或临时状态。关系候选的触发、生效、预算和允许类别需在M5实施计划中另定。

## 3. 建议实施顺序与退出条件

### M5.1 基线与版本合同

先根据补验清单核对将被复用的任务、恢复、备份与人格隔离能力；保留114项全量与47项针对性历史结果，不混同为新回归。确定人格、表达和关系版本之间的关联，明确旧设定迁移映射和回退语义后再定结构版本。

退出条件：旧人格不换UUID、原事件和记忆不重写；旧关系以已有文本作为初版，创建时间如无依据就标迁移时间，不虚构历史。迁移前备份、事务升级和失败回滚可验证。

### M5.2 同一人格的显式编辑与回退

工作台增加“编辑当前人格”和版本比较、查看、回退入口；保留“导入全新人格”原操作并清晰区分。编辑使用预期版本检查，保存失败保留文字，重复提交不产生重复版本。

退出条件：同一UUID改设定后旧会话仍属原人格；切换人格期间的请求不被改派。模型调用开始时记录所用人格/表达/关系版本，已开始的请求不被后续编辑改写；恢复旧版不恢复无效记忆。

### M5.3 显式关系版本与可变状态

先实现用户显式维护和回退，再考虑带来源的关系建议。关系更新应能查看旧值、新值、证据与影响；可变状态提供显式设置和失效说明，不自动编造情绪或让临时状态覆盖核心。

退出条件：新会话与窗口/QQ读取同一有效关系；临时状态在到期、重启和回退时按约定处理；过期状态不继续进入请求。没有证据的关系推断不能自动成为已确认经历。

### M5.4 表达连续性与候选更新

调整上下文分层，避免关系、记忆、摘要与核心设定出现含糊的覆盖顺序。建立候选的来源、审阅和回退；先确定是否实现自动关系提取，未确认前不接入每日后台任务。

退出条件：能解释某轮使用了哪个设定版本和有效状态；候选未确认不改变正式人格/关系；来源被撤回后相应未审候选失效，有效关系的处理规则需明确且不能静默改写。

### M5.5 文本私聊联合验收

用固定虚构场景验证问候、话题切换、意见不同、记错更正、隔天续聊、换模型与恢复旧设定。数据归属和版本正确由自动测试验证；自然度、措辞与陪伴感由用户实际评价，不以“模型返回成功”代替。

退出条件：M3稳定性不退化，M4长对话/记忆与M5设定/关系闭环联合成立；对M4待验项逐项补验或明确保留范围限制。没有补齐的关键路径不能写成全功能文本版验收通过。

## 4. 实施前待冻结的选择

| 选择 | 建议起点 | 需明确的内容 |
| --- | --- | --- |
| 正式人格内容 | 沿用已有设定，允许同身份显式修订 | 用户何时提供正式内容；不强制重建身份 |
| 版本粒度 | 核心/表达/关系分别版本，调用记录有效组合 | 修改和回退的最小单位、并发检查与导出兼容 |
| 可变状态 | 先手动设置、显式有效期，不自动推断情绪 | 字段范围、时区、默认期限、到期与重启行为 |
| 关系候选 | 建议人工确认，默认不自动提取或自动生效 | 手动触发还是增量任务、证据类别、与既有M4记忆冲突时的处理 |
| 后台费用 | 不默认增预算，优先复用已明确的用途预算 | 新调用是否需要、如何计数、是否与每日任务共享来源与去重 |
| 表达评估 | 先用现有模型建立基线，再按用户需要对照另一模型 | 维度、样例、费用及不满意时如何调整；不自动收费切换模型 |

这些是准备建议，不是编码授权或已生效默认项。M5详细实施计划中冻结后再实现，不能因每日记忆已允许自动写入而直接放开人格更新。

## 5. 验证和交付要求

- 兼容：新身份导入不继承、同身份编辑不换ID，结构5迁移/回滚/独立备份恢复，导出不带密钥。
- 一致性：编辑/回退时有进行中请求、两个入口同时使用、人格切换、旧版本查看和重启，记录的版本组合可追溯。
- 来源：关系候选伪造来源、跨人格引用、撤回来源、重复确认与冲突版本处理，防止把模型虚构当经历。
- 状态：过期、不合法时间、重启跨过有效期、核心与状态分别回退；不改变每日日程和预算原合同。
- 体验：编辑失败保留输入、缩放下操作可达；自然度场景和确定性数据事实分别判定。
- 联合：M4的T07–T10和O01–O05保持编号、实际执行状态和证据；真实24小时、额度触发和可选项不以模拟代替。
