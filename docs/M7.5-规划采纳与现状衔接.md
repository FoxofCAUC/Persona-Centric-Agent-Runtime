## 3. 现有代码与需要明确的解释

本轮只读核对[character_context](../persona_runtime/character_context.py)、[context_m4](../persona_runtime/context_m4.py)及[cognitive](../persona_runtime/cognitive.py)。

| 问题 | 当前事实及本阶段处理 |
| --- | --- |
| 激活现状 | select_context使用字段别名、关键词及scenario；没有本次要求的角色Embedding实现。保留词法路径用于A/B与故障回退 |
| 实际预算 | 当前身份锚点800、动态事实/设定1600、样例600，总角色块3000字符；Lorebook数量/依赖沿用既有合同。selector默认样例2条，但context_m4在情境模式传入example_limit=4，不能机械假定所有模式都是2条；M7.4收尾后重新冻结 |
| 旧版本与编辑 | 当前从turn.character_snapshot读取。被已受理请求固定的旧角色版本仍合法；“旧版本违规”指串用最新正文、错误版本或已失去资格，不是禁止所有历史快照。编辑/回滚建立新版本索引，不能让旧请求偷读新版本 |
| 精确事实与语义候选 | read_fact/别名处理精确事实与未知值。向量补召回不能补造未知字段、覆盖明确事实或取代档案引用资格 |
| 多成员输入 | query源覆盖全部有序成员。模型token上限与程序字符预算不同；开工需冻结分块/逐成员编码和融合，保留覆盖/裁剪原因，不让编码器静默只读第一条或截尾导致遗漏 |
| Recall@5与注入数量 | Recall@5/MRR@5评价候选召回；最终正确激活率、依赖完整性和误激活率另评。候选Top5不等于向Prompt注入5条，仍受最多4条及现有预算约束 |
| 模式与快照 | lexical/hybrid为角色检索政策，不等于legacy_full/context_full/context_structured回复模式。启用/排队/重试须与现有政策快照兼容；旧请求无新政策时有明确词法兼容，不读取最新开关偷偷变更 |
| 事务与Manifest | CPU推理、索引维护在主库写事务外；调用前复核权威版本/可见性并持久Manifest。缓存不是授权，不把完整设定、向量或Prompt复制到清单 |
| 索引准备 | .1–.3不需等待M8任务底座，可用现有进程内有界预处理；不得借“后台索引”创建新常驻宿主、第二收费调度或破坏控制台生命周期 |
