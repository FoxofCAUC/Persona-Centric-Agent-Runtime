# 自然分条结构协议修复

2026-10-30。运行时0.7.5.dev5；主库16、导出13、配置2、桥接0.7.0不变。本次保留上一轮默认开启成果，不自动提交推送或开工M8。

## 事故与证据边界

自然模式启用后，最近五个实际QQ回合中前两次完成、后三次在主模型返回后以reply_schema_invalid失败。三次候选选择均成功；失败发生在生成输出结构校验，尚未保存回复事件、ReplyBatch或发送片段。它们不是QQ投递失败或60秒超时。

原实现只给主模型提示词，没有请求接口层response_format；同时只保存失败输出指纹，未保留字段级诊断和供应商finish_reason。因此能够确认失败阶段，但不能从哈希还原旧输出，不能将旧失败具体断言为某个错误字段，也不追补虚构诊断。

## 修改

- 自然结构模式请求pcar_reply_v2严格JSON Schema，旧context_structured请求pcar_reply_v1。legacy_full/context_full、整理、候选选择及旧连通性测试保持原接口行为；不建立额外模型调用或运行配置权威。
- Schema限定已知键、类型、枚举和1–3条消息；本地继续复核正文完整性、容量、依赖表达语义和可取消性，不能用供应商声称合规替代本地检查。
- 格式合同移到系统消息内参考资料之后，说明历史assistant记录是聊天正文、不是本轮协议范例。确认与独立追问分别放入messages，不用空行代替独立消息；文学字段不改。
- 调用前的ContextManifest增加reply_output_contract：协议版本、模式和Schema哈希。实际HTTP请求使用相同合同；保存失败不调用模型，旧Manifest不改。
- 调用后在兼容上下文记录增加reply_provider和reply_validation，记录结束原因、字符数、接受/拒绝、安全回退及白名单原因码。错误JSON只记录位置，不记录正文、未知字段名、异常文本或凭据。
- 截断与供应商过滤输出停止发布；保留已发生用量。畸形结构仍拒绝，已有安全正文回退合同保持。不去围栏拼补、不正则修复JSON、不自动补发或降回全文。
- 控制台错误说明和进度恢复提示指向结构诊断；上下文检查继续展示历史记录。仅人格服务下次正常启动加载新代码，不要求为修复恢复QQ或强关其他组件。

接口依据：[供应商结构化输出说明](https://docs.x.ai/developers/model-capabilities/text/structured-outputs)。本项目实际使用兼容接口，其是否正确接受参数单独通过探针核对；不能仅凭官方说明推断中间网关的实现。

## 通用探针及费用边界

管理员POST /v1/model-test保留旧空请求行为；可显式提交reply_mode（natural_structured或context_structured）与稳定request_id做一次结构协议探针。探针正文由程序固定，不接收私人测试正文，persona/session均为空，不创建聊天Event、投递或选择调用。重复request_id返回原结果，切换探针模式须使用新操作；桥接令牌不能调用。

结构探针与普通回复一样先保存attempt/Manifest，再调用模型，计入项目额度。HTTP 400等不支持情况只记录一次失败，不自动改成JSON Object或再请求一次。模型或供应商不支持时应明确处理兼容性，不以关闭新功能掩盖。

本轮使用现有供应商和主模型进行了两次固定通用探针，均completed：finish_reason=stop，v2校验accepted、无回退，实际4197 tokens，金额未知。没有候选选择、评分、修补、私人原体验收或真实QQ消息；没有使用日常或测试QQ账号。两例仅证明本接口接受参数且样例合规，不证明所有后续私聊都能合规，也不证明代理层必然强制解码。
